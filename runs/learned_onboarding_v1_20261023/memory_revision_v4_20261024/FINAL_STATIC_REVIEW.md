前序发现的 direct CLI 初始化问题已经修复：`resource_plan()` 在检查回执运行时前调用 `learning._setup()`，使干净进程中的四线程和确定性设置与独立验证一致。主代理报告候选完整 63 项测试通过；本轮没有重复运行这套真实候选验证。

`run_chain.py` 由 Popen 自身 wait 回收其直接子进程，psutil 只等待后代，避免先被 psutil 回收而把 ECHILD 误记成返回码 0。完成观察与终止请求分别记录，资源终止不会被标为自然完成。该修改没有自动重试或恢复逻辑。本轮对此进行了静态检查，没有新建进程回收实测。

## 验收脚本本轮修复

`SOURCE_VALIDATION.json` 的写入早于诊断最终状态和进程退出，原先见文件即接收存在终态竞态。现验收脚本以普通程序有界等待独立诊断退出，要求 unit 为 inactive、MainPID 为 0、Result 为 success、ExecMainStatus 为 0，最终 status 为 PASS，并拒绝任一资源或验证异常文件与 PASS 并存。它随后检查完整证明、当前代码集合、FIT 行数、源侧范围和实际峰值，才安装远端内存证明。

独立 preflight 服务保留 16 GiB 硬限，增加 RuntimeMaxSec=600、TimeoutStopSec=15 和 KillMode=control-group。客户端异常或超时时写失败回执并仅清理本脚本新建的 preflight unit，避免等待客户端退出后留下无界服务；不会停止或重启源验证或正式实验。

仅实际 preflight 返回 0、plan 为 READY、完整源证明为 VERIFIED、证明 SHA 与实测峰值匹配、估计峰值符合 8 GiB 守卫，以及本地候选代码和已收回证明均一致时，才安装本地证明。失败时脚本非零退出，保留现场且零重试。systemctl show 对不存在预检 unit 的非零返回只有在有效 LoadState=not-found 时允许，其他查询失败仍拒绝。

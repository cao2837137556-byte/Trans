## 1. 外部复现必须绑定的数学与实现合同

- 使用已冻结的 RECENT 前端、E3 编码器、q14 适配器、源 normalizer、27/127/227 三个 head、三头算术平均 ensemble、源 cut/scale/geometry；列绝对路径、版本、SHA。阈值比较严格为 `score > cut`。
- `s=clip(1-second_joint,0,1)`；`second_joint` 来自两个不同合法组件的联合距离，不能把重复点算第二组件。`g(s)=1-(1-s)^3`，`g(0)=0`；单头扣除 `.25*scale[j]*g(s)`，保留原乘法与集成顺序。
- 全设备统一守卫 `q14[0]==1 and q14[2]==1 and q14[5]==0`，即当前 TCP SYN=1、ACK=0；命中保持 RAW。它不等于“连接一直未收到确认”。不得新增设备白名单、端口豁免或攻击类型专用规则。
- 外部本设备库按 `partition/device/protocol` 匹配。源 donor 矩阵是源安全核验语义，不能将 LEARN/A/B 的 donor 或参考库直接作为外部设备入网库；同协议不等于同设备。
- 几何不存在、参考少于两个不同合法组件、银行尚未可用、零支持等情形，保留原 RAW 回退并逐原因记数，不删除这些困难查询。
- 所有协议处理和合法端点规则保持原定义。真实不支持的 Bluetooth、非 IP 等流量只计范围外，不能转为零告警样本拉低 FPR。

## 2. 从 C1—C4 映射到新设备：不要偷换材料合同

实际 C4 是“保留旧库 + 从已准入历史正常合法端点中按固定物理哈希最多补4096点/设备/协议”。固定盐值 `C4_HISTORY_SAMPLE_COVERAGE_V1_20261101`。它不是“把同一2小时窗直接取8192点”，也不是用未知的新设备清单自动复用四台 UNSW 的旧库。

外部草案应分清下列材料：

|材料|允许的用途|要求|

|同设备历史可信正常|历史参考补充|官方正常来源依据；真实时序早于外部查询；单独登记 source SHA/物理包身份/截止；不得从攻击文件中筛出“模型认为正常”的包|

正常历史若存在，应预先把输入角色与原 C1/C3/C4 规则绑定：原 C1 组件轮询/时间均匀选点、C3 小合法银行全取、C4 固定哈希补点。容量、盐值与截止只根据原规则和材料确定，不能由外部误报标签决定。旧实现中的80%有数据UTC日期 HIST_REF、剩余 HIST_DEV 是既有历史流程角色划分；如果外部没有同类跨日历史，不可伪造日期或把一晚短捕获强拆成同一历史实验。是否沿用该历史划分、独立可用历史范围应在评分前写入清单。

外部 p 已固定，不再用外部 HIST_DEV 选 p；原四台设备特定“Netatmo必须改善、Samsung/Power合计改善”是开发接线门，不能移植为通用外部放行门。

## 3. 时间、身份及分割合同

1. 每设备列真实 MAC/身份映射、所处捕获、时区/epoch、t0、7200秒截止、bank_end_frame；原接口 t0 是实际首帧时间，必须读完整不预过滤的源流并证明窗已关闭。设备在该窗口是否真的在线需单列，不能用全网跨度掩盖个体缺样。
2. 历史来源与入网来源均须有可信正常依据；真实捕获先后必须得到 timestamp/官方时间表支持，目录 `train/test`、文件创建时间和发布年都不能替代。
3. 主视图只含严格晚于该设备截止的查询；同捕获另需 `query.frame > bank_end_frame`。银行各参考不得晚于自身查询。full 保留全部可评价查询，但窗口内按冻结因果规则 RAW 回退，不能用未来完整银行修正过去查询。
4. 引入唯一不可变物理身份 `(origin_raw_sha256, origin_packet_ordinal, owner)`；UID、canonical_key、component_id 均以冻结规则生成。检查历史/入网/终评间物理重复、UID重复、捕获重复；压缩/改文件名不能逃过排重。不能拼不连续短包或平移时间戳伪造2小时。
5. 相邻包不随机拆分参考和查询；上下文仍读完整原捕获，遵守原 idle/reset 与 RECENT 窗口。若官方捕获拼接导致状态界限不清，标记资格失败或明确独立捕获边界，不能凭运行方便选择。
6. 真实设备和数据来源与源LEARN、A/B、历史补库资产做 MAC/来源/内容排重。CICIoMT同属CIC实验室，只能根据实际血缘声称相应级别的外部独立；基础编码器预训练血缘无法完全核实则保留限制。

## 4. ACK/UDP 攻击必须有标签与方向证据

“目录里有TCP/UDP攻击”不足以证明当前守卫盲区被测试。资格表必须列：官方类别、攻击者与受害者映射、协议、区间、方向或官方包/流筛选条件、实际类别计数。

- TCP 至少报告实际攻击向的 ACK-only（flags=16）、PSH+ACK（flags=24）与其它 ACK=1/非守卫 TCP，不能仅凭 TCP Flood 名称猜实际 flags。若某类为0，保留0，不补造。
- UDP 至少有官方可定位的攻击向 UDP 包；反射/放大等机制必须按其官方攻击方向定义，不机械等同“来自某攻击源IP”。
- SYN_NO_ACK、非守卫TCP、UDP 分层的攻击人口、RAW TP、C5新增FN、召回均公开。非守卫 TCP 又按 flags 拆分，防止大量守卫 SYN 稀释真正风险。
- **反向受害者响应单列审计**；不能因为攻击抓包整段标恶意，就声称所有返回ACK是恶意攻击发起；也不能擅自把返回包改为正常参考。保留发布方原标签及标签语义，并给独立可证实攻击向分账。
- 若只能得到整场景标签、无法定位攻击向/时段，则最多是事件窗压力证据；不能满足严格ACK/UDP攻击保护的主确认要求。攻击者/受害者/方向有歧义的行列为 unknown/context，不用于伪造正常真值。
- 同时核正常样本中的 SYN_NO_ACK、ACK-only、PSH+ACK 和 UDP 分布，优先确保有正常连接发起/重试行为的设备；这是已知 C2 源 Amcrest 副作用的覆盖要求，不根据模型分数挑设备。不得从 SYN 标志直接断言是重传。

## 5. 指标、权重和成功/失败口径

必须输出 RAW 与最终 C5 同人口、同UID、同标签、同权重、同head/cut的四头对比；至少包括主/full视图、池与逐设备逐样本FPR和加权FPR、召回、原始FP/FN、每设备/协议/活动/事件新增撤警、资格/支持/回退覆盖、参考数与距离/内存/耗时。

**工程上尚无现成可直接用的新外部权重入口。** 当前 `metrics.py:21–25` 只接受三个既有pool名字：UNSW正常层级为device/component，攻击为device/annotation/component；CIC层级为device/activity/capture/session。不能伪称CICIoMT是CIC_DEV、也不能把缺失字段全填UNKNOWN后称同权重。须先用元数据登记一个外部pool与明确的权重层级/缺失分组规则，在任何模型分数揭示前封存。建议把逐样本率作为主要告警负荷指标，完整并列预先确定的加权/设备宏平均率。

保护规则可沿用原四头逻辑：相对RAW累计撤警；设备损失≤1pp、活动/可用annotation损失≤5pp、低RAW召回组零TP撤回，以及原99%召回保护口径。外部组缺少真值/人口时记NOT_EVALUABLE，不能空门算PASS。须明确哪些是逐样本目标、哪些沿用加权门；不要把“16门”机械带到一个新池，实际为池数×两视图×四头，再乘已定义分组审计。

2%池逐样本FPR与99%召回是待检验目标，所有设备2%不是已验证保证。失败仍输出，不能看外部结果再调p/λ/cut/半径/选库。相邻包不当独立试验，正常按设备/捕获/日期、攻击按事件/时段说明覆盖与不确定性；不把简单Wilson区间套到加权指标。

## 6. 基线与一次性执行边界

- 必做 RAW：相同冻结检测器、不使用参考修正。它是收益/攻击代价基线，不是“同信息预算强基线”。
- 建议必做固定 p=1 的同库/C2 对照：同参考、同计算路径、相同cut/scale/λ，仅kernel为线性，可隔离C5凹核必要性；其外部结果也不能用于改p。
- 强参考利用基线必须拿到同一可信正常信息与相同可用时序/容量；若其算法需要拟合/阈值，必须在既有源侧合法材料上先选定，不能拿外部确认数据调参。此轮授权不含训练，不能把尚未选定实现/源校准的基线写成已就绪。
- 外部第一次评分前一次封存：文件/设备/角色/时间/标签/权重清单、方法与所有基线版本、超参数、查询UID、资源上限与故障恢复规则。候选文件选择只依资格与预先顺序，不依预计得分。
- 资格核验可以读原包计数/时间/协议/标签并报告，但在通过前不得跑检测分数、support或评价指标。外部登记/下载、原包资格、模型评价是三项不同状态。
- 最小流程：目录/说明→定向原包获取→只做资格检查→固定设备/材料与外部适配器→工程验证与执行卡填实→唯一授权评价→保存所有预测与独立验收→外部结果锁定。此刻只到准备草案。
- 冻结的是方法搜索；后续若因纯工程错误中断，保留现场和哈希，在固定数据与配置下续算。预算不足或科学合同改变不自动重投；结果暴露后改方法则该外部集转为开发，不能继续称确认。

# Paper04 同服务正常登录小试

以本机 Ubuntu 24.04 WSL 的五个网络命名空间构成一个内部以太网。一个命名空间只放虚拟桥，服务与三个客户端分别有独立的 veth、IPv4 地址和 MAC。接口只有内部网段路由。AF_PACKET 在服务端 veth 接收双向原始帧，以内核纳秒时间戳写 Ethernet PCAP。

三个客户端每 20 秒轮换场景。成功场景提交一次标准表单。输错场景在同一 HTTP/1.1 TCP 连接依次得到 401、200。重连场景先完成成功登录，再用 TCP RST 模拟连接中断，随后在一条新连接再次登录。密码是临时测试值。服务端认证结果与客户端场景各自进入 JSONL。表单与包内没有场景标记。

采集持续 600 秒。PCAP 和四份源日志共用 100 MiB 容量门，写入每条记录前核对实际文件长度及挂载盘剩余容量。余量达 2 GiB 或下一次写入会跨过上限时停止，回执写实际用量和结束条件。用独立的 5 秒短片核查权限、方向、两种 TCP 连接关系及认证对齐。

用 TShark 的 TCP 流与 HTTP 重组结果绑定三份客户端日志及服务的认证日志。绑定条件包括有向端点、连接内请求序号、原帧和时窗。SYN、SYN-ACK、最终 ACK 序号由另一条 PCAP 解析路径核对。60 秒计数使用上轮的冻结脚本和同源 IP、同服务端口的因果前缀，并逐请求比对独立握手账。请求帧取 TShark 解析到完整 POST 的原帧。模型输入从该帧及其完整早期前缀生成。

冻结输入验收用独立封存的 ToN 前端、已验收运行包、清单 SHA 匹配的冻结 NetFound 权重、源 E3 和设备状态归一化参数。在本机 CPU 生成每条请求的 768＋14＋8 维输入，核对有限性和 UID 顺序。输入验收和场景审核不使用分数或告警。

D 盘 data_external/login_pilot 下每次采集使用独立子目录。PCAP、JSONL 和场景 CSV 原样保存在该目录。ACCEPTANCE.json 和 SHA256SUMS 绑定结果。此次模拟样本和将来的两小时建档、独立正常评价分别存档。

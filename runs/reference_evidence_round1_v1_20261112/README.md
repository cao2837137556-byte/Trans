# 正常参考补证首轮 D／M／C0／C1

本目录承接执行说明。D、M、C0、C1 只使用冻结的 UNSW 查询与参考母池。CIC、Edge 从 p4 验收复用，原阈值、基准尺度、保护、头顺序和两小时窗口按原证据绑定。

- 状态以 LOCAL_PROGRESS.json、本地 received 回执、远端 Slurm 回执为准。PACKAGE_RECEIPT.json 表示本地封包，不能当提交或实验验收。
- CONFIG.json、INPUT_PINS.json 和 PACKAGE_MANIFEST.json 分别固定方法、缓存来源和包字节。vendor 为已验收实现的 LF 快照。evidence 保存原评价对照和适用的 Edge HT 记录。
- 先 SHA 核验缓存。参考选择独立进程从参考白名单加载，审计钩子拒读查询路径。M、C0 候选先封存，评价进程才读取查询特征和分数。C1 进程只从 C0 取得候选与通过标记。
- 第一个 AMD 作业在已有 Python 3.11 和 NumPy 2.0.1 环境中验证真实缓存、真实距离、四头分数/判定和指标，再生成全量 D。它在原资格下复现两小时支持，并核验完整库、两小时、RAW 的逐查询分数和全部原指标。缓存解析和 UID 对齐为本轮起点，无原始 PCAP 解码重做或模型前向。
- 后继作业按真实切片的分设备/协议距离耗时、D 全量耗时及峰值内存申请资源，按生产分块上限逐组重放 M、C0、C1。C0 数值等价及判定核验通过后才生成 C1 精确保留量和代表点。C1 判定翻转照常留存。只凭同一批查询验收，不改完整主库。
- 资源记录区分工作项、阶段耗时、进程峰值和 Slurm CPU、内存、I/O。启动不依赖 /usr/bin/time。调度器在提交前查询现有目录、队列及账单，并执行 sbatch --test-only。已有作业或未解析提交意图阻止盲重试。
- 项目既有 SSH 转发由用户建立。在已登录的超算终端运行 .private/HPC_TERMINAL.sh 的内容启动本批接收程序。该程序只监听远端回环。Windows 后台客户端复用已有转发上传、读取进度、收取验收。进度页 http://127.0.0.1:18807/。连接断开后可用同一启动文件恢复接收和已验证的分块，已有作业不会重交。
- 结果入口由已通过的远端验收生成。取回后读 received/RESULTS_FOR_PAPER.md 和 received/FINAL_ACCEPTANCE.json。小指标、改变 UID、资源回执、清单与 SHA 自动回传。参考成员映射、完整诊断行和逐查询连续值留在超算。

## 文件与入口

- `worker.py`：正式入口，必须同时通过完整工程卡、独立复核、实际Linux恢复门和绑定卡SHA的用户评价授权。草案卡不能启动。
- `streaming.py`：按原协议/形状、UID排序组批，每批最多16逻辑点；singleton仍复制16物理行并要求输出逐字节一致，不做张量去重。
- `checkpoint.py`：128点/64MiB有界快照块、完整role准入、原子编码批与身份校验。只缓存轻量索引，按点读取正文。
- `evaluate.py`：RAW、C5/p3、同库p1、独立kNN-5共用查询UID；128行评价块落盘。按编码批顺序读取，最后仅重排小型预测表，避免共享盘随机反复读特征。
- `reporting.py`：样本比例、正常组件等权、已知全N的HT估计分列；HTTP ACK/PSH、SYN外与UDP单列；固定60秒块/2000次条件时间敏感性区间。
- `engineering_gate.py`：一次有界Linux新worker验证，真实编码/中断恢复、源CAL保存特征至检测头一致性、原序重放、batch16形状吞吐、真实距离代码的合成大库微基准；不计算外部效果。
- `build_cards.py` / `prepare_delta.py`：生成复核草案与本地交付增量，不登录、不上传、不提交作业。

完整role快照和已原子提交的编码批可复用；不完整批不能复用。评价也按已提交查询块复用。

若在某角色的原包重放中途退出，该角色必须从原始起点重建因果状态，不能从任意帧跳过前序包。已完成的其他角色与编码批仍保留。工程gate与正式卡可共享同一套科学输入绑定的完整快照；模型编码/评价另绑定具体执行卡与源码SHA。没有自动重投或自动追加预算。

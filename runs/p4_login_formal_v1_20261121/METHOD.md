# 同一登录服务的正式正常评价

先从封存小试的实际帧复算 150 条请求的 UID、790 维输入、握手计数和冻结分数。已有封存密码场景只读抽取少量带标签的输入和旧判决，核对三个源阈值、三头和集成的 RAW 与原 CCNR 判决。用小试的前后真实片段测试可执行链路。

在 Ubuntu WSL 的隔离虚拟桥内保留一个 HTTP/1.1 服务进程、一个测试账号、一个服务端口和三个固定 IP/MAC 客户端。两期采集分文件，采集设备及同一进程身份均写入回执。主机使用活动期间的系统休眠请求支持长录制。采集以 D 盘 2 GiB 可用余量为护栏。

建档计划种子为 2026112101。各客户端间隔均匀抽样为 32–89 秒，成功、同连接重试、跨连接重试和已登录后重连的分布权重为 76、12、5、7。从首个合格入站 TCP 帧的真实时间起算。保留第一个严格跨过 7,200 秒的合格原帧，前缀里时钟不晚于截止时间的实际冻结前端合格帧可以进入参考候选。使用冻结 v12 的两小时参考选择器，保留 B2 锚点及同一上限下的稠密位置。建档回执分别报告候选、封存和同服务组件数。截止后的真实帧只作边界及标签证据。

评价计划种子为 2026112102。每客户端执行 12 轮成功、12 轮同 TCP 输错后重试和 12 轮重建 TCP 后重试，打乱顺序及间隔。每个 1、3、5、8 次／分钟速率分配给三个客户端各一个 60 秒块，块之间有空档，次序打乱。块开始前的一次登录计入成功组。块内只有该客户端主动重连，按 PCAP 中的真实 SYN 核验每分钟次数，以 TCP RST 模拟连接中断。输错后跨连接重试使用正常关闭。两期无登录流量的间隔超过 60 秒后开始评价。所有请求均是正常行为，服务端和客户端日志只用于离线核实连接、序号、结果和场景。每次完整表单对应一个真正完成重组的原始入站请求帧。

RAW、冻结 v12 CCNR、R2＋U1、v12 相对握手距离共用一批 UID、三种子及其等权集成、源阈值、原旁路、p=4、λ=0.25。修正使用同一两小时参考库。R2＋U1 按角色过滤并对服务器限制相同服务端口。相对握手距离沿用三个原空间和新增 abs(log1p(h_q)−log1p(h_r))/log(3) 的最大值。采用严格距离小于 1 的不同两组件支持。入站计数按设备、同源 IP、同端口进行，出站参考对应同一入站分组。未见足够合法参考、合法参考充足但相容组件不足、匹配成功后仍报警分别记账。

连接级以其任一纳入请求告警计一次。连接出现多种告警原因时先归于匹配后仍告警，其次归于无相容组件，最后归于合法组件不足。小表给出请求和连接的计数、分母、三种子及集成。全部文件存 D 盘正式目录，两期各自校验及汇总。

Windows 推理中的单样本批仍按 16 个相同输入计算，并核对输入张量的哈希。出现复制行舍入差异时，重复前向以核验第 0 行逐字节可复现，同时核对其余行与第 0 行的最大绝对差不超过 64 个 float32 机器精度。进入参考库的逻辑记录取原第 0 行。用上批原包完整重放封库及四组打分，在通过后启动新的两小时采集。

进度文件遇到 Windows 读取占用时跳过该次更新，采集和服务继续运行。封库失败会暂停结果流程并保留原 WSL 服务，恢复时在 WSL 核对启动批次、命名空间和进程身份。

## 1. 正常端口，已完整流式计数

目标为文档 Raspberry Pi MQTT edge `192.168.0.128`，同一观测 MAC `dc:a6:32:fb:69:b5`；本轮只称一台边缘设备，不扩大为传感终端或多台受害设备。

正常目标 IP 记录共 **1,335,645**，TCP **1,332,428**，UDP **2,430**，其他协议 **787**。TCP 目标本地端口只有 **1883:1,330,654 / 502:1,745 / 44252:29**。HTTP 攻击的目标本地 TCP **80 为 0**，UDP flood 的目标本地 UDP **0 为 0**；首 7,200 秒及之后也都为 0，连“任一端点使用这些端口”的正常计数亦为 0。正常本身有 UDP，不能写成 UDP 协议从未出现。

首窗目标记录 **114,494**，其中 TCP **114,408**、UDP **28**、其他 **58**。全文件首窗后 **1,221,151** 仅是原始全局切口后的总体，**包含间隙与晚于攻击的 Dec20 段**，不得不加说明地当同一连续评价窗。

## 3. 攻击方向规则与 S4

HTTP 可固定为该 HTTP 原包内 `src=.170 & dst=.128 & TCP & dport=80`，共 **152,352** 包。其 SYN 无 ACK **61,641**，ACK 无 SYN **88,262**（其中纯 ACK **7,817**，PSH+ACK **77,043**，FIN+ACK **3,003**，FIN+PSH+ACK **399**），另 RST **2,449**。旧 **88,280** 是宽泛文档来源集合，混入公有地址向目标本地 `42162` 的 **18** 条 ACK；此方向另有 1 条 SYN+ACK，总共 19 条，不属于 `.170→.128:80`，须排除并披露。

UDP 原包中 `dst=.128 & UDP & dport=0` 完整命中 **2,898,830** 包，即所有发往该目标的 UDP。不能用论文列举的四个源 IP 过滤：它们只匹配 4 条，作者明确说明 hping3 的伪造来源。HTTP 与 UDP 规则均来自采集场景描述和实际包头的交叉核对，未看模型输出。

**S4 的原文并不要求官方逐包载荷真值。** 作者明确 HTTP 攻击来源和 slowhttptest GET 场景，原包中可解析的 **19,076** 个 GET 起始包均指向 `.128:80`；UDP 的伪造来源洪水与全量定向 `UDP:0` 群吻合。可以预登记“研究者重建的 attack-associated 方向/会话标签”，用于可复现的包级人口，同时写明证据等级。纯 ACK、FIN、握手是该攻击会话的控制包，不能包装为独立恶意载荷，也不能把 HTTP flood 改名为 ACK flood；GET 数是未重组的可解析下界。

非命中包（反向回复、ICMP、背景、公有来源不匹配会话）排除于攻击和可信正常分母，但原始上下文保留。HTTP 目标向外 IPv4 包 **76,641**、UDP 目标向外 IPv4 包 **316,686**，不算直接攻击。主报告按包；目前仅能确认两类场景抓包，不能将包/连接数当独立攻击事件数。

## 4. 范围条件与上下文边界

- S1：文档 edge 角色与同一观测 L2/IP 身份满足当前条件；不额外要求不存在的硬件序列号。
- S2：原始包、真实整数时钟、完整容器成立；同时保留时间回退事实。
- S3：四个事前分段各有 7,200 秒跨度和之后正常；分段/参考/查询归属须在执行卡固定，不跨 gap 拼接，也不拿 Dec20 补攻击前参考。
- S4：可构造有文档及原包支持的方向标签；满足可复现包级判定，证据等级有限，并非官方逐包载荷真值。
- S5：两类洪水为网络可见威胁，适用。
- S6：本子任务未完成全项目 owner/预训练血缘核对，由根代理单独处理；不以同源名不同就默认通过。

正常/HTTP/UDP 捕获序回退分别 **119 / 1,146 / 3,489**。原始顺序不能排序。按根代理核查的 `Contexts` 合同，跨不同 key 的捕获序微回退与同 `(owner,capture,key)` 的时间倒退不同；后者会 poison 该 namespace。不能由119个capture级回退推导119个非法特征或整文件失败，也不能假称上下文审计已完成。精确重复、逐 namespace 上下文与血缘结果由根回执合并。

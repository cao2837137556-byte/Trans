# v12 原模型三项补证

ACI、SHARP 的轻量资格结论见 [资格报告](EXTERNAL_ELIGIBILITY.md)。[实验卡](EXPERIMENT_CARD.json) 在新评价前固定了设备 × 协议阈值、空组和小样本回退、单组件准入与端口审计的分母。[封存回执](RULE_FREEZE.json) 保留原 UTC 时间和 SHA。负责人随后在原交接单中加入协作约定，打包检查仅接受该段插入，实验规则沿用原封存。

阈值对照复用 183937 的正常参考分数。在设备 × 协议组内按采集、组件和记录分配权重，排除旁路参考后归一化。没有可用参考或有效参考量小于 100 时，主对照采用原源阈值，敏感性对照采用原测试床级带旁路阈值。阈值拟合先在独立的参考数据步骤完成并写入回执，再读取本次评价查询。每个测试床、种子、集成和视图均保留双向配对、样本级率、分层加权率与适用的 Edge HT 估计。

单组件与供体审计复用 184893 的完整开发对照库缓存和原始 UID 顺序。单组件取最近合法参考，分别计入新获正支持和已有双组件支持增强的查询。供体审计区分两个合法组件和两个相容组件，核对原来排名前两位的参考。相同协议、相同 IP 对且端口组合不同，可确认这两名供体的组件划分由端口区分；存在其他合法组件时，原缓存只保留前两名。角色证据来自冻结的 Edge 目标映射或逐参考的正常包头。可核实的握手方向与设备侧、对端侧分别统计，操作系统是否实际分配临时端口列为未知。

超算先提交同运行时的真实预检，从三个 CIC 短采集重做原批次的解码、编码，在三个测试床逐条校验联合距离、供体和判决。封存阈值、真实切片和原基准通过后，Slurm 分别提交阈值、单组件和端口审计作业，三者可并行运行。预检申请 4 核、12 GiB、45 分钟上限，每项正式作业申请 4 核、12 GiB、2 小时上限。实际时间和资源以各自的调度回执为准。

超算保留参考索引、逐查询改变清单及数组。程序将回传结论、配对指标、关键诊断和 SHA 清单写到本目录的 `received`。右侧进度页使用本机 18813 端口，接收程序仅通过用户已建立的 SSH 隧道工作。[负责人交接](../mainline_docs/collab/20261118_paper04_v12_next_experiments_handoff_codex.md) · [数据角色更正](../mainline_docs/collab/20261118_paper04_dataset_roles_correction_codex.md)

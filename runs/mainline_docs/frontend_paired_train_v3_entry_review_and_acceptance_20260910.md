# 双臂执行器 V3：入口链路审查与验收

2026-09-10。用户要求提高审查深度，并明确授权：修复版真实准备通过后直接执行
冻结双臂训练及终点检查；异常停止、不重试。本记录是执行前实现证据，不是科学结果。

## 审查结论与修改

V2 已修正 F4 前缀哈希封装，但过去的微型 40 轮测试直接调用训练函数，未覆盖
完整独立 worker 及最终监督验证器；成功日志中的部分动作计数还使用常量，
失败时无法直接知道已读取量与当前失败目标。这些都是实现验证与观测的缺口。

V3 保留模型、普通 BCE、AdamW、seed2705、40 轮、名单、初始权重、分组与科学门槛。
plan.json、bound_recipe.json、initial.pt 和 initial.receipt.json 与 V2 字节相同。
模型/优化源文件仍直接复用同一冻结版本。具体变更：

- runner/最终验证器从已封存 plan 读取目标数、更新数和每轮步数，避免两处硬编码漂移；
  真实入口同时固定 PLAN_SHA，不允许运行时换名单或改变这些数字。真实值仍是
  18,266 目标、197 步/轮、7,880 更新/臂、两臂共 15,760 更新。
- 保存真实动作计数：读取/写入字节、读取/写入上下文、通过的前缀数、已完成优化器
  步数、各臂拟合/检查次数。优化器 post-step hook 在实际 step 返回时计数，
  后续有限值检查报错也不会漏掉已经完成的更新。
- 失败终态保留这些计数、当前上下文/目标及阶段，空输出不再意味着“零数据访问”。
- 报告保留 training_covered 的“整个配对训练池覆盖”含义，并新增
  arm_supervision_covered：A 臂的 B 目标监督始终为 false。增加相应覆盖分组，
  原能力保持、B 增益和回退门槛不变。

## 完整生成集成链路

新增 fixture driver 只接受系统临时目录下 paired_generated_ 前缀且有明确生成
标记的目录，所有输入/模型/输出均为生成数据。它绑定独立进程内的临时命名空间，
不会改真实模块文件或真实工作目录。真实入口本身没有开放测试覆盖参数。

测试通过生产用 readiness、Windows 单 worker Job、worker、终态验证器和 seal：
两个小生成特征文件 → 准备及旧 F4 oracle 前缀核验 → 准备封存 → 两臂各40轮 →
末轮候选屏障 → 一次训练拟合/共同检查 → 标准库重算结果 → 最终监督封存。
没有 mock 训练内核、优化器、准备函数或最终判定函数，没有为了通过省略40轮。
fixture 的目标/上下文数更小，对应每臂40次更新；不能称为真实资源试验或性能结果。

fixture 内含用于 readiness 分支测试的最小模拟 acceptance receipt；其中数值
仅是测试输入，不计作已运行测试。fixture 调用完整真实验证分支，因而其内部
supervisor.synthetic=false；外层 GENERATED_FIXTURE 标记和测试 receipt 明确
表明它是临时生成测试，不能当作本项目真实执行。真实命名空间保持隔离。

新增 11 项集成/失败账检查包括：真实准备与最终校验、真实训练与最终校验、
实际更新/前向账、候选轮次和磁盘哈希、分臂监督覆盖、旧新报告判定一致、
模拟receipt计数矛盾拒绝、固定plan漂移拒绝、真实命名空间未改、
首前缀失败时读入量/失败UID/零模型账、step已完成但后续检查失败时的计数。
原47项核心检查、8项固定旧 F4 oracle 检查、10项独立监测器检查绑定V3回归。
共 **76/76** 生成检查通过，两个 V3 PowerShell 脚本解析 **2/2**。

真实特征未在本次实现审查中读取；没有优化器作用于项目数据、原始包重放、
旧教师前向、HPC、K、设备入网或新资源试验。已有失败记录/冻结文件保持原样。

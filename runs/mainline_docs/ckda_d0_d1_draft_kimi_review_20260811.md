# CKDA D0/D1 设计草案 — Kimi 审查意见

**总体结论：草案通过评审，七项开口项全部关闭（六项接受、一项给出裁定方案）。可转 FROZEN D0 协议；仍不授权写码/下载模型/解码 PCAP/HPC。**

## 1. 对三项关键修正的回答

1. **I1 的 `CONSTRUCTIVELY_HELD_OUT` 条件（§3.2）**：接受。我 Round 2 的"构造性零污染"措辞过强——tokenizer/bucket/normalization/encoder 全部只用 fit 良性才可标记，正确。这正是我要的防自欺口径。
2. **"非参数几何探针"更名**：接受。kNN/类中心会构造参考状态，属于拟合；我"零训练"的提法不准确，撤回。
3. **`NO_ACTIONABLE_SIGNAL_UNDER_FROZEN_PROBES` 替代 `NO_INFORMATION`**：接受。封口范围精确到"当前候选+tokenizer+prefix+探针集合"，不外推——措辞严谨。

## 2. §9 七个开口项逐项裁定

1. **I1 定位（候选兼受控基线、不自动越级）**：**接受**。领域匹配是假设不是证据；成熟度/复现风险/训练成本作为劣势计入，词典序第 7 条固定顺序兜底，防的就是"偏爱自研"。
2. **几何探针更名与拟合承认**：**接受**（同 §1.2）。
3. **裁决命名**：**接受**（同 §1.3）。
4. **词典序 + 固定 backup 能否防 cherry-picking**：**基本接受，补一个条件**。词典序第 2~6 条（污染、覆盖、因果、成熟度、成本）都依赖**测量**，而测量方法本身必须在测量前冻结——否则可通过调整测量口径间接选模型。要求：D0 的每个测量项（覆盖率怎么算、成本怎么估、成熟度打分依据）使用**固定表格模板**，任何平局裁决必须附证据链接写入审计表。加上这条，防 cherry-picking 完备。
5. **五态裁决是否需要单一 `GO_D2` 标记**：**不需要合并五态**（五态信息量有价值），但加一行机器可读别名：`GO_D2 ≡ CKDA_D1_ACTIONABLE_PROBE_SIGNAL`（状态 2 是唯一触发器）。一行解决，不动五态结构。
6. **16 族与 12 族的唯一字典**：引用 `ckcz_attack_family_scope_clarification_20260809.md`（commit `97adfe0`）——该文档已冻结：16 个报告 family 用 `GLOBAL_ATTACK_PRESERVATION` 244,050 全角色分母、rows≥15、≤2pp 门；support 69/69 独立硬门；future-only 用 131,391 分母；12 族仅属 CKBW 训练历史。**CKDA 的 FROZEN 直接引用此字典，不得新造映射**。
7. **I1 最小语料规模：现在冻结还是 D0 后冻结**：**现在冻结下限规则，D0 只报告实测数字**。理由：D0 测量后再定门 = 先看到数据再定标准，有事后合理化空间。建议现在冻结保守绝对下限（预声明、先验）：**合法 fit 良性可解码 session 数 < 5×10⁵ 或 token 总数 < 10⁷ 时，I1 在 D0 直接淘汰、不训练**；达到下限仍须过成本测量门。数值可在 FROZEN 讨论中调整，但"先冻结、后测量"的顺序不能反过来。

## 3. 全文一致性检查

- §4.4 "D0 不生成任何性能 embedding、不按可分性选模型" ✓ 与词典序自洽；
- §5.2 九项因果合同测试覆盖我 Round 1 的 lookahead 单测要求（future mutation invariance）✓，prefix-vs-full trap 禁令 ✓；

**“见过的攻击还只有约 97%，需要先推到 99%”不是准确基线。** 旧 97.3698% 是含缺失处理的混合攻击总体率；同名族且有效输入的现有检出已为 99.9931%。但这部分有效覆盖仅 101,130 / 163,848 = 61.7218%，不可外推成所有已见攻击或全部协议均达到此水平。

这里的 seen 按原完整 18,398 fit 的精确攻击族名判断，包括原 missing 行的标签曝光；不是按未来增强的 11,529 replay 反推。未出现的六个字符串为 C&C Communication、CoAP Amplification、Reporting、TCP Scan、Telnet Brute Force、UDP Scan。旧 fit 有 ToN 扫描、凭据暴破以及 Merlin/Mirai C&C 监督，因此“没有同名族”不等于“攻击机制完全未见”。future_query 也是另一条时间／角色分层，不能与未见族互换。

## 2. 四个 OOD 当时有没有训练过

**对原 P2 的梯度训练、normalizer 拟合和原阈值选择，四池都没有参与。** 元数据审计覆盖原 18,398 fit、7,069 select 和 18,000 OOD report，按 UID、抓包身份、source_group、规范化精确设备族核对，各项交集均为 0。证据为同 run 的 `ood_exposure_audit.json` 与侧车。

容易混淆的是角色名 `ood_val`：原 FIT 的 2,604 条来自 building-monitor；REPORT 的 3,000 条同名角色来自 hydraulic。角色字符串相同不表示同一数据参加过训练。

因此这次四池反映的是旧 P2 在未纳入其训练／选择的正常来源上的表现，不能用来直接断言“训练见过的 OOD 仍然有 76% 误报”。同时它们已经在研究中反复查看，并非未触碰 FINAL；外部 E3 预训练的完整排重未知，street 与训练过的 museum 摄像头也可能有行为相似性。“旧 P2 未训练这些来源”比“整个系统从未接触任何相关信息”更准确。

## 3. 把每个正常池误报都压低，攻击还能检出多少

本次预先声明两种排序：原生 float32 sigmoid 概率和固定 P2 的 raw logit。约束是熟悉正常、hydraulic、street、predictive、stream **每个池**都不超过误报上限，总正常参考 19,078 条；不是五池平均，不包含 ID fit。整数误报预算、同分整组、无插值。

| 每池经验 FPR 上限与分数 | 全部攻击检出 | future 检出 | 同名族已见检出 | 同名族未见检出 |
|---|---:|---:|---:|---:|
| 1%，原概率与 raw logit 一致 | 164,004 / 180,378 = **90.9224%** | 83,126 / 94,403 = 88.0544% | 99.9693% | 79.3774% |
| 0.1%，原概率 | 0% | 0% | 0% | 0% |
| 0.1%，raw logit | 69,075 / 180,378 = **38.2946%** | 28,952 / 94,403 = 30.6685% | 47.8730% | 26.0713% |

1% 点五池误报数依次为熟悉正常 19、hydraulic 0、street 2、predictive 79、stream 8；最差是 79 / 7,916 = 0.99798%。0.1% raw-logit 点只有 stream 3 / 3,000 误报，其余为 0。

原概率的 0.1% 零检出有明确数值原因：69,819 条攻击和 4 条正常的 float32 概率都饱和为 1。这个同分组无法在所有池的 0.1% 预算内报警，只剩全不报警端点。raw logit 保留组内次序，所以仍有 38.2946% 检出。不能把原概率零检出直接解释为模型完全没有尾部区分信息；也不能把恢复 logit 顺序写成新训练提升。

这些是已曝光开发池上的经验工作点，**没有为部署选择新阈值，没有证明独立数据上的 FPR 保证**。原固定阈值不变。此前 A/AB/U1 等的正常池范围、缺失分母不同，不把这里 90.9224% 与旧 TPR@1% 直接横比成训练增益。

## 6. 对下一步的实际影响

当前旧底座值得保留：已有同名攻击族能力很强，street/stream 的未纳入训练正常来源也有低误报。主要短板更具体了：凭据暴破等跨来源迁移、熟悉正常的误报，以及 hydraulic/predictive 等困难正常变化；独立 ID 与入网后的攻击保持证据也缺。

已封存的两摄像头 570 TRAIN / 281 CHECK 小增强仍是一个有边界的候选：Hydra 与 Telnet 共享凭据暴破行为，有补充迁移监督的合理性，但服务与来源不同，不能保证迁移；新正常材料没有直接覆盖 hydraulic/predictive。普通 BCE 与同设备 ranking 的匹配对照可检验新增约束是否比单纯加数据更有效，不能提前称为解决 OOD 的机制。

建议下一项实作接回该小增强的实现与合成验收，保护旧已见族优势，分别报告攻击迁移、熟悉正常和四池变化。实现必须验证从 decoder 到实际 E3 forward 的未来扰动不变性，以及 TRAIN/CHECK 依赖隔离；容器存在 duration 不等于模型消费 duration。此次账本不改变封存 recipe，也不授权增强真实特征准备／训练／CHECK。

历史补学现已形成 `legacy_core_attack_ood_history_review_20260915.md` 与 `project_route_knowledge_index_20260915.md`，包括原路线的正信号、失败机制、被过度外推的解释、数据角色和 HPC 经验。后续方案先查最接近的已有尝试，说明新增可学习信息／约束；涉及新机制再做针对性文献核对，不重复从零搭流程。

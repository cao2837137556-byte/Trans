## 2. 实际数量：正常与攻击非常不均衡

| 来源 | 捕获数 | 原始包 | 审查候选目标 | 含候选的观察会话数 |
|---|---:|---:|---:|---:|
| 正常交互 | 219 | 52,792 | 52,421 | 1,113 |
| 攻击捕获 | 76 | 27,261,047 | 24,240,338 | 102,250 |
| 合计 | 295 | 27,313,839 | 24,292,759 | 103,363 |

“候选目标”是满足本轮来源、设备归属、旧输入字段/因果前缀检查的包位置；攻击另经过方向和请求/数据语义筛选。它们**还不是最终标注、去重和 E3 编码后的训练行**。会话数是各捕获中观察到的 transport stream 次数，同一连接可能跨捕获反复出现；不能直接当作独立样本数。

219 份正常捕获的时长累计只有 **60.04 分钟**，是各设备短片段相加，并非连续一小时的全网部署观察。每台设备合计约 **1.77–12.31 分钟**，分布在 1–4 个日期的零散片段中；日期按包时间戳转 UTC 统计，不将跨日期自动视为独立重复。

## 4. 比数量更重要的两个语义问题

### 4.1 正常与攻击存在很强的服务差异

新增洪泛中，观察到的发向设备的 TCP/UDP 流量均打向 **80 端口**。在九台拥有完整新增正常交互核查的洪泛设备上，正常与攻击的“入站协议＋设备端口”集合没有交集。SimCam 的三个新增 PHOTO 片段亦无交集，但其其余正常材料和旧 Hydra 未纳入这个新的方向比较，不能扩大该结论。

这证明现有材料缺少同服务正常对照，**没有证明模型已经依赖端口，也没有证明删除端口就能修好**。旧前端不改。若未来模型表现好，仍需排除仅靠服务或捕获来源差异分类的解释；R/Q/M/C 公平比较也不能凭空补足缺失的反例。官方正常采集说明与攻击者侧采集说明的视角差异仍未消除。

### 4.2 HTTP 文件夹不等于观察到了 HTTP 请求

18 份 HTTP 目录捕获中，只有 HeimVision 的 1 份及 Netatmo 的 2 份解析到请求，共 54,358 个请求候选。其余 15 份没有解析到 HTTP 请求，许多是大量 SYN 连接尝试及 RST/无响应，不能当作丰富的 HTTP 应用层攻击监督。本轮保留所有原捕获和统计；零 HTTP 候选不等于无攻击，后续如要用于 SYN/连接尝试洪泛，须按其实际行为明确标注。

当前 LEARN 的 HTTP 目录没有合格 HTTP 请求候选；实际请求出现在 DEV 和保留设备。LOIC 的 TCP/UDP/HTTP 选项也不能直接宣称三个独立未知攻击机制。Hydra 仍仅在两个已开发的 LEARN 摄像头上。现有材料不能支持严格跨设备未知暴力破解机制的结论。

同一攻击模式通常只有三个捕获，个别只有一个或两个。数百万包不等于数百万次独立攻击。对单个 SYN 而言，洪泛语义可能依赖跨连接频率；旧同会话前缀是否含足够区分信息仍是一个限制假设，本轮没有借此启动前端改造或断言它是历史失败根因。

## 5. 因果、重复与证据边界

- 295 个成员没有整文件 SHA 重复。207 个新增正常成员中有 25 组跨文件相同捕获字节；各文件首次出现时间的比较未发现 1ms 内跨文件重合。不同时间的相同字节可能是协议重复，不能一律删除。
- 指纹时间比较仅使用每份文件中该字节序列的首次出现，旧 18 个成员复用封存元数据、未重新读取原始包。因此不能宣称完成所有历史材料的全局逐包去重。`raw_exact_repeats=1,315,750` 也不是独立样本扣除数。
- 参考只使用已观察到的先前正常信息。真实连接终止、跨捕获连续上下文、同连接延续是否允许，仍需在新协议中明确；角色和标签保持未分配。
- 旧前缀保留包集合的变化次数不是独立 E3 表示数；持续时长等字段仍可变化。没有生成表示或读取模型分数。
- E3 外部预训练与候选材料的重合尚未证实排除；三台保留设备只能提供有限设备范围证据，不能自动变成普遍新设备保证。

## 6. 合理的数据量：本轮给出的具体准备目标

我的建议是**先补正常覆盖和必要对照，再冻结一次完整比较**。不应先用当前短片段跑一轮模型来发现这些已经能够确定的材料问题。

数量需要随所要支持的结论而定。若真实正常误报约 1%，在独立同分布二项近似下，要估到约 ±0.5 个百分点的 95% 精度，所需量约为 `1.96²×0.01×0.99/0.005² = 1,522`。零错误时，95% 单侧上界低于 1% 需至少 299 个独立观察；低于 0.1% 需 2,995 个。**这些不是当前相关包/会话的置信区间，也不是期刊录用门槛。**

为使下一次材料准备有明确终点，建议以下初始预算，均是本次审查建议，尚未冻结：

| 项目 | 准备目标 | 使用限制 |
|---|---|---|
| 正常时间覆盖 | 同批候选设备至少覆盖 7 个日期的正常观察，优先同时包含 Idle 与 Active；保留已取得的细分交互 | 7 天是实际准备预算，不是独立性或充分性的统计定理；核实设备在场、时序和实际时长 |
| DEV 正常查询 | 每台约 2,000 个按会话/时段分散的合格查询，2 台约 4,000 个 | 报实际会话、日期和活动；不能称 2,000 个独立样本 |
| 保留设备正常查询 | 每台约 2,000 个分散查询，3 台约 6,000 个 | 按设备分别评价；低活动或长连接设备如达不到有效覆盖，保留缺口和不确定性，不复制凑量 |
| LEARN 正常材料 | 使用补充范围内全部合格正常会话，平衡设备、日期、活动；同样以每台约 2,000 个分散查询作为起始准备预算，6 台约 12,000 个，允许保留更多有用观察 | 这是准备预算，不是训练数量上限，也不是训练充分性的证明；长会话按未来封存规则抽样 |
| 攻击材料 | 保留现有合格行为和各次运行，先完成实际机制标注与同服务正常对照；暂不再增加同类洪泛包 | 当前运行数不支持很窄的攻击非劣区间；缺少必要反例时不能用大包数替代 |

约 2.2 万个分散正常查询的准备预算，是为了让设备之间的覆盖更均衡；当前已存在的 5.2 万个候选集中在极短捕获和少数连接中，二者不能只比较总数。实际所需原始包通常更多。入网时“少量正常参考”与离线学习/检验所需数据量是两回事，参考预算仍需另行确定。

正式就绪还需要三个条件：有合法先前参考及后续正常/攻击；有足以检验服务/来源捷径的反例或明确收缩相应主张；分组后的估计不确定性与目标相称。若 7 天范围仍不足，则根据已量化缺口作一次明确扩展或收缩主张，不能把达到包数当 PASS。三台设备和同一攻击采集项目的外推范围限制继续保留。

## 7. 补充来源与下一步边界

已取得的官方 README 明确：`2-Idle` 是整个 40 设备网络在夜间无交互状态的 30 天/30 个 PCAP；`5-Active` 是白天有零散主动/被动交互的 30 天/30 个 PCAP。它们是比继续增加当前洪泛包更有针对性的候选补充。不能预先保证每个设备都有足够行为，也不能保证其中包含所需同服务反例。

本轮只读核对了官方根目录入口；新打开的 Active 子目录显示 Registration required，未取得其可靠的文件日期/大小清单。**Active/Idle 原始补充尚未下载，下载字节预算尚未确定。** 上述已审查 295 个成员全部来自原有本地归档；补充材料将是新的获取范围，两者不能混说。

下一实质动作：核实这两个目录的日期、大小和成员组织，按上述目标形成一份有具体文件与字节上限的最小补充清单；优先选足以覆盖同批设备多天正常活动的材料。取得原始材料后核实 MAC/设备在场、时间顺序、必要正常服务反例与跨角色重复；全网捕获中涉及多个角色设备的同一包/连接不得重复进入学习与保留用途。前端只取各查询之前的上下文。

当前不授权新下载、模型训练、调整冻结阈值/seed/损失或打开未列明评估。新协议如需要修正参考连接规则，先说明语义与影响，不改写历史实验。后续可把确定的补充获取、资格检查和满足就绪条件后的完整实验写成一次清晰授权范围，避免逐文件索要许可。

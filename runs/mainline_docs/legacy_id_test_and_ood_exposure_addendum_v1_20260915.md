## 核心成绩与数据用途

用户首先需要同一次终点、固定 R/B/C 上的三类成绩：**ID 正常误报率、攻击检出率、OOD 正常误报率**。OOD 再区分训练覆盖过和未覆盖过的环境，并逐来源列示。攻击的族／时间泛化、负翻转、经验低误报曲线随后作为解释，不替代主表。

ID 以原问题中的正常域为锚点；当前 `id_calib` 元数据指向 `iotsim-combined-cycle-tls`。不能因为加入其他正常域训练，就把所有这些域重新命名为 ID，使 OOD 目标消失。“已见 OOD”指原 ID 外、训练已覆盖的正常环境；测试目标仍必须与训练和阈值选择隔离。

7.953% 是旧辅助正常阈值选择集的有效输入误报，并非纯 ID 测试率。该池包含不同正常来源，仅作开发诊断，不填入核心 ID 测试格。原 fit 的 0/760 也不填入独立 ID 格。

## ID 资格初查：已知事实与没有证明的部分

只读原 fit/select 元数据及本地 Gotham ZIP 中央目录中精确匹配的 ID 正常成员名；没有打开 PCAP 内容、特征、模型、分数或其他 FINAL 内容。

本地档案恰有五个 `raw/benign/iotsim-combined-cycle-tls-*` PCAP 名称，与当前原模型的 ID 域对应：

| 文件编号 | 原 P2 已有目标用途 | 目标数 |
|---|---|---:|
| 1 | aux_fit | 600 |
| 2 | aux_select／阈值选择 | 600 |
| 3 | id_calib／fit | 270 |
| 4 | id_calib／fit | 270 |
| 5 | id_calib／fit | 269 |

因此五份文件都包含已接触目标，**没有可直接整文件宣布未参与 fit/select 的 ID 抓包**。这不是“所有包或会话都被训练过”的证明，也不证明合法后续 ID 测试不存在。ZIP 成员 CRC/大小只定位档案条目，不充当 PCAP 完整 SHA 或会话资格证明。

各类 `target_index` 语义不能混用：辅助源目标序号不自动等于原 PCAP 包位置。不能依据“index 大于 599”之类裸序号直接选一个安全后缀；须用实际 decoder 对齐、时间与完整因果上下文核验。

## 已授权补入本次实验的 ID 测试要求

1. 从上述原 ID 域的已有本地数据优先寻找未用于原模型／normalizer／阈值选择和本次优化器的独立目标、会话或后续时间块。整抓包隔离是更强证据，但不强加为唯一合法 ID 测试方式。若只能构造同抓包时间留出，明确命名与依赖范围，不声称跨抓包／跨设备独立。
2. 先建立旧模型实际训练及选择目标的 raw 身份、时间与上下文曝光账本，再审查候选。同 UID 不重叠不够；检查共享前缀／会话、训练目标是否晚于同来源测试、模型输入是否只含决策时刻已到达信息，以及后续其他路线的开发曝光。若历史学习路径无法排重，保留对应限制，不将其自动提升为未触碰终测。
3. 标签需有明确正常来源和目标身份；不能用“攻击标签没匹配到”补集推断正常。不把新 OOD 摄像头改名成原 ID 填空，也不拆原 P2 已拟合的 760 行重新叫测试。
4. 目标数、合法会话数、完整／有效／缺失分母在看模型分数前冻结。此时尚未合格的数量保持未定，不虚构 3,000 等固定规模；不能按是否误报选择目标。前端范围和实际输入失败均保留完整覆盖账本。
5. 在同一新增 ID 目标上比较固定 R 与本次 B/C 终点；全部使用原概率阈值，无 ID 再校准，无用测试挑训练轮次／损失／模型。保存原始误报数、分母、逐来源／会话结果及 R→B/C 翻转。不把相关包数当独立观测数许诺显著性。
6. 新 ID 是本次增强的显式评估扩展，旧 B/C 训练配方及 570/281、11,529、旧报告分母原件不改写。精确 ID 名单／准备预算与执行器采用新版本补充工件；用户这次要求已授权这项补充及必要资格核查，无需再次询问“是否加入 ID”。本轮尚不具备真实 ID 评分输入，旧小增强训练也尚未启动。

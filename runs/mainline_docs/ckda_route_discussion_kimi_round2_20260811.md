## 1. 想法一：D0 增加第四候选——域内自监督预训练编码器

三个现成候选（ET-BERT/YaTC/netFound）的预训练语料是通用互联网流量，与我们 IoT/ICS 域存在显著分布差，且预训练语料重叠风险永远需要审计（Round 1 加固点 2）。

第四候选：**用合法良性流量自监督训练小型序列编码器**——流表示为 token 序列（方向、包长、协议、IAT 分桶），做 masked-token 或 next-event prediction。性质：

1. **构造性零污染**：训练语料就是合法池，无"见过测试分布"问题；
2. **域匹配**：直接学习设备行为语法；
3. **自带异常分**：next-event 预测惊讶度（perplexity/误差）本身是 51D 记录特征中不存在的新信息来源；
4. 代价：需自训（小规模，小时级），故作为 D0 第四候选并列审计，不替换现成模型；
   D0 评估维度对四候选一视同仁：因果截断能力、输入需求、PCAP 覆盖、显存/算力、许可证——第四候选额外评估"合法良性语料规模是否足够"。

## 2. 想法二：D1 增加零训练信息检查档

D1 原设计是线性探针（+ Round 1 建议的小 MLP）。建议再加最便宜的一档：**冻结 embedding 上的免训练几何可分性检查**（kNN 一致性、类中心余弦距离分布），完全不拟合任何参数。判定阶梯：

1. 免训练几何检查有分离 → 强信号；
2. 探针有信号但几何无 → 弱信号（存在但需学习才能提取）；
3. 几何 + 线性 + 小 MLP 三者皆无 → 才判 NO_INFORMATION。

使 D1 的死刑判决更稳，且第 1 档完全无选择自由度。

## 3. 明确不主张的方向

在 51D 序列上直接叠序列模型（LSTM/Transformer 吃 51D 序列）：51D 是有损摘要，CKBQ 的 32-event MiniRocket 已探过该方向，边际新信息弱，不建议占用 D0/D1 名额。

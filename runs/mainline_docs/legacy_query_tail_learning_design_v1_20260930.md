# 当前包证据与低误报区学习修复 v1

日期：2026-09-30。状态：**设计完成，可进入实现；真实 P/T/K 未启动、未新增授权。**

这次只推荐一个主候选：保留已验证的 RECENT 因果输入和冻结 E3，在同一个攻击头中加入当前包的明确证据，并用源侧困难正常样本训练分数间隔。内部名称 `QUERY_TAIL`。先证明这个攻击头本身能在低误报时保住攻击，再讨论参考库如何介入。当前方案不是一套已经有效的新设备入网方法。

## 1. 为什么现在做这个

Job177891 已经修好了“后续包没有实际进入表示”的输入错误。但使用正常源侧校准阈值，RECENT 在 UNSW 上攻击召回 99.9849%、正常误报 21.2832%，二者没有同时达标。即使用已经看到的 DEV 标签给每台设备事后选一个最有利阈值，误报不超过 1% 时攻击上界也只有 96.6038%；放宽到每台 2% 也只有 97.5301%。所以单调阈值调整不足以修好当前分数排序。

重叠诊断发现：UNSW 的 72,553 条攻击查询都是入站 TCP SYN 且无 ACK；低误报工作点剩余正常误报中，90.38% 的加权误报来自当前包为 ACK／数据的正常通信。三个 seed 共同漏掉 1,169 条攻击，占原攻击权重 2.2040 个百分点。当前包阶段、近期上下文与最终评分之间的关系值得直接学习；这仍是可证伪假设，不是已经证明的根因。

不使用“SYN 就是攻击”或“ACK 就是正常”的判断规则。正常 SYN 必须作为负例保留，原有 TCP、UDP、Hydra 等攻击也必须保护。包级阶段不是攻击标签，当前包类型也不代表整个窗口。

## 2. 本轮新核对的训练事实

依据封存 `inputs/LEARN.jsonl.gz`，重算了实际 `device → activity → capture → session → row` 类内权重。原训练正常、攻击各占总损失 1/2。

| 源 FIT 范围 | 条数 | 占本类权重 | 设备 / capture / component |
|---|---:|---:|---:|
| 正常全部 | 134,493 | 100% | 6 / 136 / 15,778 |
| ACTIVE_UNANNOTATED 正常 | 131,823 | 17.9479% | 6 / 7 / 15,650 |
| 其余正常活动合计 | 2,670 | 82.0521% | 非互斥实体数不相加 |
| 攻击全部 | 483,415 | 100% | 6 / 33 / 25,566 |
| TCP 活动攻击 | 429,350 | 41.6667% | 5 / 15 / 23,815 |
| UDP 活动攻击 | 53,594 | 33.3333% | 4 / 12 / 1,652 |
| Hydra 活动攻击 | 471 | 25% | 2 / 6 / 99 |

这是有意的分层平衡，不凭条数认定它错误。它说明“80.54% 的 TCP 攻击原始行带载荷”不能推出“80.54% 的训练压力用于载荷攻击”。权重集中度的 ESS 为正常约 1,315、攻击约 2,870；这只是权重诊断，不是独立样本数。大量相邻包也不能冒充大量独立攻击场景。

因此本版**保留原训练权重，不增加 SYN 专项倍增，不改评估权重**。精确的 SYN/非 SYN 加权质量仍需要远端已封存 snapshot；将其合并进下一包的 P 预检，一次完成，不另起一个漫长诊断实验。

## 3. 同一个检测头看两种证据

结构为：`已验证的因果 RECENT → 冻结 E3 的 768 维表示 z`，与 `当前包 14 维确定性描述 q` 拼接，经过 `Linear(782,128) → ReLU → Linear(128,1)` 输出一个攻击 logit。总参数 100,353，比原头多 1,792；没有第二个投票头、相似度否决头或设备专属门槛。

`q` 从每行封存 snapshot 中精确定位 `provenance.query_frame` 所对应的包。不能直接拿最后一个 burst 或最后一个数组位置代替。顺序固定为：

1. 是否 TCP，1 维。
2. FIN、SYN、RST、PSH、ACK、URG、ECE、CWR、NS，9 个独立二进制位；UDP 全为 0。
3. 当前包在旧 token 语法中的 IP 长度值，`log1p(value)/log(65536)`，1 维。
4. TCP window，同样的固定变换，UDP 为 0，1 维。
5. UDP length，同样的固定变换，TCP 为 0，1 维。
6. 当前包方向相对本窗口首个保留 IP 源，与现有 E3 的方向定义相同，1 维。

这些是已有包头信息的直接读出，不是重新发明前端或读取未来。长度明确指旧语法的 16 位编码值，不能据此推算真实 TCP payload 长度；不增加 TTL、原始序号、地址、端口、设备名、数据集名、绝对时间、label 或攻击起始时刻。所有输入范围和非有限数必须检查，不自动补零处理解析失败。

E3 的 768 维继续用 Job177891 源 FIT normalizer；q 只用上述固定变换，不拟合外部数据。每个 seed 从与原 RECENT 相同的初始权重开始，新增 14 列初始化为 0，保持初始函数一致；不是把完成训练的 RECENT 再多训练 40 轮。

选择这种小读出，是因为其信息已存在于已验证快照且可直接审计；抽取另一个 E3 token 表示需要重新编码，并增加表示选择。若小读出无效，不据此断言整个 E3 表示不可分。

## 4. 训练直接约束低误报区的分数间隔

普通 BCE 会优化所有训练样本的平均分类；它不会直接要求攻击分数高于最容易误报的正常通信。借鉴部分 AUC／CVaR 的训练目标，在原 BCE 之外加入一个困难正常样本排序项。

令 `w_i` 为原 FIT 训练权重（正常与攻击分别合计 0.5），`p_i=2w_i` 为攻击类条件权重，`n_j=2w_j` 为正常类条件权重。每轮开始时，用当前小头对**全部源 FIT 正常**打分，根据 n 的权重取最高分的 1% 正常质量，归一化为本轮负例分布 `h_e`。这是训练端困难样本选择，不是部署阈值，更不读取 DEV 标签。

边界有并列时，按原 n 比例分配该并列分数块需要的剩余质量；不得随便按行号丢掉一部分并列。选出的是 1% 加权质量，不是条数最高的 1%。全正常并列时分布仍然合法，等于 n。

本轮目标：

`L_BCE = sum_i w_i · BCE(s_i,y_i)`

`L_tail,e = sum_(i:attack) p_i · E_(j~h_e)[softplus(s_j − s_i)]`

`L = (L_BCE + L_tail,e)/2`

BCE 保留全部正常与攻击约束；排序项同时降低困难正常分数、提高相邻攻击分数。SYN 正常、载荷攻击等都不能被固定规则放行。所有原 FIT 行每轮仍出现一次，不下采样、补造或换标签。没有针对 Samsung、某端口或某个漏检 UID 的训练规则。

实施约定：原 256 行随机 batch、每 seed 40 轮、AdamW 及学习率/衰减/betas/eps 沿用父设计；每个 batch 另从 h_e 有放回抽 128 个正常样本，独立的固定随机流，正负两边都重算当前 logit 并反传。排序项 batch 估计为 `N/b · sum_(batch attack i) p_i · mean_j softplus(s_j−s_i)`，无攻击 batch 为 0；不能在 batch 内重归一化 p，否则改变目标。每轮完整刷新一次正常尾部分布，记录 UID/权重 digest、尾部实体数、ESS、最大权重、阶段分布及抽样摘要。

**这是基于 pAUC 的按轮困难样本优化，不是照搬论文 SOPA，也没有论文的收敛保证。** 本轮尾部在轮内固定，会有滞后；256 行 batch 内直接选最高 1% 则只有很少正常样本，本版避免这种批内分位近似。1% 来自既定低误报目标，等权两项与 128 负例为一次性固定选择；不运行网格、试多个权重或按 DEV 选训练终点。

本法不能凭空学会源侧没有的攻击证据，也不保证源端低误报会自动迁移到外部；这正是下一轮对照要验证的边界。

## 6. 数据、泄漏与 P 预检

沿用原 FIT 617,908、CAL 148,819、CIC DEV 179,886、UNSW DEV 148,316 条及其 UID、完整 component 分割和评估分母。源侧 CAL 只负责终点后的校准与报告，DEV 不进入训练、normalizer、困难样本选择或阈值校准。已消耗的两个 DEV 池仍为开发证据，不能改称独立确认。

本轮不使用目标 reference，不扩充观察库，不训练入网适配器。冻结的独立 ID 与历史 holdout 继续关闭；不能因此称 ID 已达标或入网贡献已经得到确认。

P 从 Job177891 只读复用以下产物：RECENT 特征、源 normalizer、原端点与已保存基线分数、输入元数据以及 `spool/snapshots.sqlite`。先核对 spool 完整 SHA、P_COMPLETE 绑定的 features/SHA256SUMS 和每个实际用到的 feature 文件；原目录禁止写入。**不从有问题的旧 early-prefix cache 取新特征**。

快照扫描只做确定性读出与源支持统计，不做 raw PCAP 解码、E3 前向或优化器训练。q 处理范围共 1,094,929 行（LEARN+CIC_DEV+UNSW_DEV），不需要读取 271 条 reference 的内容。参考记录只可从数据库中跳过；没有新的参考训练用途。

源支持统计需逐 FIT/CAL、label、协议与互斥旗标组报告：行数、原类条件权重、设备/capture/session/component 数、最大行权重、ESS；互斥顺序 `UDP → TCP_RST → TCP_SYN_NO_ACK → TCP_SYN_ACK → TCP_FIN → TCP_OTHER`。同时统计实际保留包数、burst 数、窗口覆盖时长与同/反方向，不能把 FIRST_KEY 标记当作当前行只有一个包。重现旧 support.json 能直接重现的计数；其 payload 原始字段没有保留，标为不可重现，不从长度猜造。

P 的结构性 STOP 条件：源 FIT 的 TCP_SYN_NO_ACK 正/负类任一为空，或任一只来自 1 台设备/1 个 component；TCP 非 SYN、UDP 任一类别完全缺失；原权重/UID/计数守恒失败；q 无法精确定位当前包、未来包进入窗口、role 串线、输入 seal 不符。至少两个实体只是防止明显的单实体监督，不是样本充足的统计证明。报告稀疏组后不得静默加权/抽样补救。完整源阶段质量目前 **PENDING_REMOTE_SNAPSHOT**；这是已明确的预检项目，不伪称审计完成。

## 7. 怎样才算进步、怎样才算通过

每个新头只用原源 CAL 正常做 1% 加权 FPR 的严格 `score > cut` 校准；每个头各算自己的 cut，算法、预算和来源完全相同。ensemble 也只用源 CAL 的平均 logit 定 cut。不引入每设备阈值，不用 UNSW/CIC 标签修 cut。

主候选必须同时满足原核心目标：

- 每个 DEV 池 ensemble 加权攻击召回 ≥99%；每设备 ≥97%；每 seed 每池 ≥97%。
- 每个 DEV 池加权正常 FPR ≤1%；每设备 ≤2%。
- CIC 历史 Q 的未加权召回回退不超过 0.1 个百分点，口径沿用原协议。
- 新增保护检查：源 CAL 的 TCP/UDP/Hydra 活动攻击，以及 CIC 的每个非空攻击协议组，相对 R0 同算法工作点，条件加权召回下降不得超过 0.1 个百分点。报告整数 TP/分母，不能用提高 SYN 掩盖其他攻击退化；这些检查用于判定，不用于再选模型。

保存全量每行分数、决定、UID 和阈值来源，给出每设备/协议/速率的加权与未加权结果。原 R0 对照、所有 seed 和全部新臂同表报告。可报告事后 1%FPR 的全局/设备 ROC 诊断，但它不等于可部署结果，不触发再训练、再校准或换主候选。

原 v3 的“学习否决新增漏检为零、入网增益至少 30%”是参考模块门槛。本版未运行参考模块，标记 **NOT_TESTED**，不能写成 PASS，更不能因本版通过而宣布整套新设备入网系统通过。ID 和未参与设计的设备确认仍待以后补齐。

## 8. 文献依据、创新边界与风险

已核对 Zhu 等 ICML 2022 的 pAUC/DRO 原文与 2026-05 修订的网络 normality-shift 研究，详见本 run 的 `research_notes.md`。前者支持把训练压力放到低 FPR 区的成对分离，并明确批内分位估计的困难；后者提醒适配正常分布时必须保留攻击知识，但其伪标签、数据预处理与指标不能直接套用本项目。

“加包头特征”“困难样本排序”“pAUC”本身都不是本项目的原创发明。当前是有证据、有对照的修复机制；是否形成论文贡献，要看与统一入网机制的后续结合、严格同预算基线和独立设备确认。即使本轮修好 UNSW，也只能先称开发迁移修复成功。

风险按优先级：新正常行为仍可能没有源侧负例约束；源权重可能让少数正常活动支配 1% 尾部；当前包读出可能学到仅适合某种攻击的捷径；按轮尾部刷新有优化滞后；短窗口可能仍缺少需要的行为信息。上述风险均有源支持/尾部审计、R1/R2 对照与跨池保护检查，不预先许诺 99%。

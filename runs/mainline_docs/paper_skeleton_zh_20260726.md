## 标题（候选）

- 主：*Suppress What You Trust, Rescue What You Recognize: 低告警预算下面向
  良性漂移的开放世界 IoT 入侵检测*
- 备：*当单一决策面不够用时——用不对称过程证据分离未见正常与未见攻击*

## 摘要（结构，待数字回填）

真实部署的 IoT 入侵检测面临一个被普遍回避的子问题：网络环境、设备与正常
流量持续漂移，高召回检测器会把大量**未见但良性**的流量误报为攻击；而一旦
抬高阈值压制这些告警，**未见的攻击**也随之被压掉。我们（1）将其形式化为
**低告警预算下的良性-OOD 漂移检测**；（2）证明在冻结的无泄漏协议下，单一
决策面**结构性无法**同时满足 OOD 抑制与攻击保持（890 个静态边界的完整枚举
无可行解）；（3）提出**不对称证据框架**——可迁移正常性证据只做单向抑制、
可迁移攻击过程证据只做单向救援、无证据时默认保留告警；（4）在
source/family-held-out 与跨数据集条件下验证。【待 seed-27：主结果一句话】

## 关键词

开放世界入侵检测；良性 OOD 漂移；低告警预算；保形/选择性判定；
跨数据集泛化；IoT 安全。

## 1. 引言（现在可写）

- **部署现实**：IDS 上线后遇到的几乎都是训练时未见的正常（新设备/新业务/
  新协议）与未见的攻击（新变种），且无标签、告警预算有限。"对见过的类别
  分得好"在部署里价值有限。
- **核心张力（本文命题）**：良性 OOD 和攻击都"远离训练分布"，任何单一分数
  必然混淆二者；压 OOD 与保攻击在单决策面上不可兼得。
- **与标准跨数据集迁移的区别（重要，划清 novelty）**：典型 train-A/test-B
  工作测的是**已知攻击类别**换环境后决策边界是否迁移、报聚合 AUC、且训练集
  benign/attack 均有标签。它们**不隔离**"未见正常 vs 未见攻击、无标签、固定
  告警预算"这个子问题。本文正面处理它。
- **贡献列表**：问题形式化 / 结构性无解证明 / 不对称证据框架 / 无泄漏跨环境
  跨数据集验证 / 可复现协议（阈值来源、support 使用、GO 判据全部预注册）。
- **诚实边界预告**：数据为仿真测床（Gotham）与已知有标签质疑的 ToN-IoT，
  主张范围限定在 testbed 级并在 §8 展开。

## 2. 背景与相关工作（现在可写，复用 5 月资产）

- Kitsune/AfterImage：轻量在线无监督前端，115D 统计表示（本文保留为成熟
  前端，非创新点）。
- 漂移/OOD 检测：CADE 等——定位为"发现漂移"，不区分漂移的良恶。
- 保形/选择性判定：Transcend、Transcendent——"不确定就弃权（reject）"，
  把未见样本交人工，**不对未见空间行动**。本文与之最近亲，区别是我们用
  不对称证据在未见空间里**部分行动**（抑制/救援/保留三态）。
- 少量标注异常的半监督异常检测：DeepSAD、DevNet——对应我们 385 条 support
  的设定，将作为受控基线。
- 方法学警示：Arp et al.《Dos and Don'ts》十大陷阱、TESSERACT 的时间划分
  批判——§7 用一张对照表说明本文协议如何逐条免疫。

## 3. 问题形式化（现在可写）

- 记号：来源 s、角色（fit/select/report/held/sealed）、告警预算 α、
  硬告警（hard）判定、攻击保持约束（相对 C1 锚点召回降幅 ≤ 0.5pp）。
- 目标：在四类 held 良性-OOD 家族上各降硬告警 ≥5pp 且 ≤90%，同时总体攻击
  召回相对 C1 降幅 ≤0.5pp、主要家族 ≤2pp。
- 严格协议：fit/select/report 隔离；阈值只来自合法 select；sealed 最后开封；
  review=0；seed 纪律。

## 4. 单决策面不可行性（现在可写，全篇最硬的一块）

- **C1 锚点**：高召回攻击候选（总体攻击硬召回 91.300%），但四类 OOD 硬告警
  接近或达到 100%（IP-camera 100%、predictive 100%、stream 100%、
  hydraulic 72.367%）。
- **CKBQ 正信号**：静态正常性分支首次同时压低四类 OOD（→ 8.100 / 57.589 /
  29.700 / 45.700），证明**可迁移正常性证据存在**；但代价是总体攻击召回
  91.300 → 84.354（-6.945pp），正式判 NO_GO。
- **无解证明**：对全部 890 个静态边界事后精确枚举，**不存在**任一阈值组合
  同时满足四类 OOD 改善与攻击保持约束。⇒ 不是调参问题，是结构问题。
- **损失的定位**：被压掉的攻击 97.97% 集中于 future-query；家族级
  Telnet Brute Force -21.198pp、TCP Scan -12.966pp、Merlin C&C -9.299pp、
  Merlin UDP Flooding -8.837pp；根因为 385 条 support 缺乏这些机制的覆盖。

## 5. 不对称证据框架（现在可写设计逻辑，指标待回填）

- **总原则**：正常性证据越强越该抑制；攻击过程证据越强越该救援；两者都无
  可靠证据时默认保留 hard（fail-closed）。抑制与救援是**单向**的，互不
  越权。
- **C1 攻击锚点**：不被替换，负责初筛（为什么初筛不用过程证据——见 §5.4）。
- **正常性抑制分支**：可迁移的 source-local 正常过程证据做单向抑制
  （CKBQ 已证明有效信号来源）。
- **攻击过程救援分支**：统一 51D 因果过程表示（decode→emit(仅用历史)→记录
  可用时间→update，严格 past-only、无数据集/来源/设备身份、无标签、无原始
  IP、无连接终态），只在 C1 已报警且过程证据强时把被抑制的攻击救回。
- **§5.4 为什么过程证据只能救援不能初筛（关键，用今日预演数据支撑）**：
  机制过程签名在**跨环境**下高度可分（本地保守预演：scan vs 跨文件正常
  AUROC=0.977、credential-bruteforce=0.9997），但在**同环境**下与正常背景
  高度重叠（scan=0.589、bruteforce=0.686）——说明过程证据不足以单独当
  检测器，只能在 C1 锚定的候选内做二次确认。这从数据上解释了非对称决策的
  每个设计决定。（预演为保守下界：本地无 TShark 故 TCP 序列/时序维度置零，
  完整字段的正式过程头分离度只会更高。）

## 6. 实验（骨架，数字待回填）

- 数据：Gotham（30 source / 325,067 target）、auxiliary（31 source /
  18,600 target）、ToN-IoT pilot（12,000 合法行，scan/bruteforce 机制监督，
  injection/MITM 保留不用）。
- 协议：seed 27 先行；support 385 全用；held/report/sealed 零泄漏。
- **主结果**【待 seed-27】：C1 / CKBQ / 最终系统在四类 OOD 硬告警 + 总体/
  家族攻击召回上的三方对比；九条 GO 子条件逐项。
- **机制救援地图**【待 seed-27】：过程头按机制（scan / bruteforce / flood /
  C&C）的 AUROC 与家族级救援幅度——预期 scan/Telnet 救回强、C&C 弱，并给出
  机理解释。
- **受控基线**【待基线】：Transcendent / CADE / DeepSAD / DevNet / 代价敏感
  分类器 / Kitsune，同一 fit/select/report 协议、同 support 预算、

- **消融**【待】：去掉救援分支 / 去掉抑制分支 / 去掉 fail-closed 的退化。
- **跨数据集外部验证**【待第三数据集】：第三 IoT 数据集 report-only 推理，

## 8. 局限（现在可写，主动披露）

- Gotham 为仿真测床，主张限定 testbed 级、不外推真实骨干网。
- ToN-IoT 标签质量在文献中有公开批评——机制监督只声称通用
  scan/credential-bruteforce，不声称与 Gotham 标签等价。
- 攻击保持侧无分布无关保证（保证只给抑制侧），由 support 约束与救援分支
  经验兜底——此不对称与系统的不对称决策同构，作为诚实边界陈述。
- 同环境下过程证据与正常背景重叠（§5.4 数据），故对无明显机制签名的攻击
  （如低速 C&C beaconing）救援能力有限。

## 9. 结论【待 seed-27 定调】

- 若 seed-27 GO/部分成功 → 主打"不对称证据框架把开放世界的双目标从
  结构性无解推进到可测量可达"。
- 若救援侧整体失败 → 收缩为"问题形式化 + 结构性无解证明 + 失败机理测量"，
  前八节主体不变（这是本骨架刻意让 §1–§8 不依赖结果方向的原因）。

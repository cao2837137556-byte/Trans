## 已补学的超算教训（使用前仍须核对当次环境）

- 环境：历史标准入口是 `scripts/00_env_issue27ckc.sh`；实际 Python 3.9 兼容性
  必须覆盖 vendor 与标准库 API。只做语法编译不足以发现 `Path.write_text(newline=...)`
  这类运行时不兼容；登录节点成功也不保证计算节点二进制/动态库可用。
- 打包：唯一版本化包、LF 字节审计、干净解包、完整依赖闭包及内外 SHA 校验；
  不假设远端是 Git 仓库，不覆盖字节不同的冻结文件，防止重复提交。
- 传输：区分本地 PowerShell、WSL 与远端 Bash。大文件断点续传后必须验字节数和 SHA。
  台账第 25 节最后更新证实该账号仍拒绝已安装公钥，不能采用较早的“免密已成功”假设。
  历史成功路径是一次密码支持的 WSL rsync `--append-verify` 完成传输；未来无人值守
  传输需管理员确认的密钥路径或站点支持的服务，不能保证现有免密可用。
- 监控：`sbatch` 接收、心跳持续或 CPU 忙都不等于有效进展。需观察包/事件/成员完成量、
  阶段、CPU/I/O 和实际 stderr；监控器必须匹配真实输出目录。
- I/O：大 CSV 用流式临时文件写出、核对 schema/行数再同文件系统原子改名。
  历史整块大写入曾卡在 Lustre `osc_extent_wait`；不能只靠加资源或延长时限处理。
- 恢复：保留失败记录，只有经身份和内容校验的 checkpoint 可复用。
  若计算已结束而尾部校验/打包失败，仅修复尾部，不自动重训；调度器 FAILED 与
  恢复后有效的结果分别记录。历史双分区作业隔离经验不构成新双提交授权。
- 交付：给用户的命令按执行终端分开且可直接复制；保留终端、持久日志、明确退出码、
  状态与拉回入口。当前没有启动或连接 HPC，也没有复验远端实时状态。

# Qref 确认后的诊断与下一步方向审查

日期：2026-09-24。分支 `codex/exp-mainline`；HEAD `4b28747b09480471e2bac1beb3a9badf27280efb`。

状态：**已有结果诊断、文献核查、方向审查完成；未训练、未做新模型前向，未冻结新的真实执行协议。**

## 1. 决策

当前不建议直接重训 Qref、换前端或扩大训练轮数。下一步应实现一次有明确终点的**入网参考覆盖与攻击输入语义预检**，解决两个具体问题：

1. 用真实较早的可信正常行为，能否给缺少参考的协议提供有效支持，而不删除困难测试案例、借用未来数据？
2. Q 漏检时，当前攻击的信息是否真正进入编码输入，还是被旧传输流的上下文、早期截断等因素遮住？

预检不运行优化器。它应给出可执行的合法开发输入与唯一后续分支，不能成为无休止的诊断循环。**补参考主要解决 OOD 误报；提高原 Q 攻击检出还需要独立的攻击修复路径。** 现有 FULL 只能撤销 Q 报警，从结构上无法救回 Q 漏掉的攻击。

这不表示推翻已做工作：Q 的攻击底座、Qref 在 DEV 的正向证据、Borun 的收益均保留。但 job174666 的冻结科学门槛仍为 FAIL，不能改成通过。

## 3. OOD 侧：多数错误没有进入纠错模块

原 Q 加权误报质量的 **99.773391%** 位于必须退回 Q 的部分。即使把全部可纠错误报清零，原资格下的总体加权收益上限也只有 **0.226609%**。这是事后诊断上界，不是新门槛，也不是新的推断结果。

| 设备 | 原参考真实覆盖 | 误报定位 | 结论 |
|---|---|---|---|
| Borun | TCP 20、UDP 21 个不同组件 | 30→9 | 当前有明确纠错收益 |
| Netatmo | 3 个 LAN_WATCH 文件，140 个合法候选；8 个候选端点合并成 6 个组件，全是 UDP；记录流量合计 78.05 秒 | 5 条全为 TCP、出站、对端 443，都是该组第一个合法候选 | 缺的是 TCP 正常参考；不是 64 条上限截掉了 TCP |
| Ring | 3 个文件、89 个合法候选，仅 1 个重复连接键组件；记录流量合计 4.51 秒 | 16 条中 15 条为 UDP、出站、对端 53；1 条 TCP 对端 443 | 只补第二条 TCP 仍解决不了主要误报，UDP 参考也缺失 |

端口只是事后定位信息：这里没有解析这些请求的应用语义，更不能据此加入端口白名单、设备名单或放行规则。不同组件也不自动代表统计独立样本。

审计现有完整元数据目录后，原截止时刻之前没有漏选的更早正常会话。Netatmo 的 TCP 首次出现在后来的 Active 记录；Ring 更早的多次 LAN/WAN 操作持续复用同一键。日志间有多天缺口，**不能解释成必须观察几天或几十天才能入网**，只能说现存早期记录没有所需覆盖。

训练侧也有类似不足：Amcrest TCP 仅 1 条，Atomi/Globe 各协议各 1 条；DEV 的 HeimVision TCP 仅 1 条。因此可以在 LEARN/DEV 研究覆盖问题，不必拿刚消费的确认设备反复调模型。注意：训练允许 singleton，不等于推断可绕过至少两组件规则。

原设计事先知道若干协议会退回 Q，但没有充分区分“是否具备适应机会”和“适应模型是否有效”。这是设计审查需要补强的地方；不以此抹去原失败，也不倒推事先知道误报的具体分布。

## 4. 攻击侧：不是一个统一的 1,080 条问题

所有漏检都来自 Netatmo 的 TCP/HTTP，且全部处于 Q 退回路径。没有证据表明它们是本次参考纠错造成的。

- TCP：551 条，来自 84 个规范化连接键组；5 组全部已评估查询漏检，共 61 条。其中一组只抽评了 63 个合法候选中的 32 条，故仍不能称原始全部包都漏检。458 条漏检发生在首个已保存报警之前（包含上述完全未报警组）；另外 93 条发生在其后。这是位置诊断，不是新的时延指标。
- HTTP：529 条，每条都是“2 个合法标注候选中的第 2 条”，第 1 条 Q 曾报警。但这 529 个规范化键组中，329 组包含 2 个传输流，200 组包含 3 个传输流。**同一键组不等于同一次 TCP 连接，不能称 529 次攻击已经检出，更不能用报警锁存把它们全部算成修复。**
- 811 条为三个 seed 共同漏检；225 条只有一个 seed 检出，44 条有两个 seed 检出。固定 ensemble 不变，不挑 seed。
- 原 Q 漏检距固定 logit 门槛的中位差为 -2.815；最深约 -53.0。不是全部紧贴门槛的随机波动。这里只复核既定阈值，没有试验新阈值。
- R 能检出其中 629 条，包括全部 529 条 HTTP；但 R 在同一正常池误报 114,184 条，其中 114,136 条是 Q 没误报的。**不能简单把 R 与 Q 取并集作为攻击修复。** R 的信息原本已是 Q 的输入之一，此发现也不能证明还存在一个未被利用的独立传感器。

代码复核发现两个需要区分的事实：

1. 当前前缀按 owner、capture、双向五元组隔离，不按 `tcp.stream` 重新初始化。
2. 冻结 E3 保存每方向最早 12 个 burst、每个 burst 最早 6 包，最多 144 包；时间长度继续更新。因此“截至当前、没有看未来”不等于“当前包一定被保留在 token 中”。

这提供了**可检验的语义/可观测性假设**，没有证明它导致了这 1,080 条漏检。本轮没有解码 PCAP、没有读取逐错误 token，不能宣布前端故障或未来数据泄露。也不能在未验证前又换一套前端。

## 5. 排除一个会制造假进展的捷径

额外盘点了既有 LEARN/DEV 的第一份 Active 正常捕获（约 8.005 小时），未物化新参考或改变角色。

它与原参考合并后，8 台 LEARN/DEV 设备在目录层面均能达到 TCP/UDP 各至少两组件。但若直接将这段数据全作为新入网参考、只保留其后的测试，旧 DEV 的 **357 条 Eufy WAN_WATCH 误报会全部被排除**，只剩 17 条 HeimVision 误报。更晚的参考不可能因果地修复更早的错误。

因此不能把“晚一点开始测试”带来的低误报宣称模型提升。未来新协议必须：

- 原困难回归集合单独完整保留，仍按当时合法参考评价，不用未来参考；新入网情景另列分母。
- 若设计在线参考更新，应按时间先后冻结每版参考，并由独立可信正常流程确认；不能根据检测标签或低分自动吸收入库。当前不是已实现的自动在线学习。
- 同时报资格覆盖、未就绪比例、真实观察时长/数据量、独立组件数、完整总体误报和攻击损失。不能只报已适应部分。

这份现有数据可用于开发，但“现有 34 万条确认查询已用过”这一事实无法靠重新切分抹掉。新独立确认所需的未消费设备/时段仍须另行证明。

## 6. 推荐的唯一下一阶段：有限预检，而非盲目训练

### A. 入网覆盖预检

在 LEARN/DEV 上实现按时间与角色约束的参考候选审计，保留最小两组件、同协议、严格过去、正常来源等约束；输出参考覆盖、实际时长和数据单位。缺参考时保持原退回，不能复制 singleton、借另一台设备充当本设备参考或挪用未来查询。

具体工作产品是一个**来源/角色/时间可核对的候选清单和机会报告**，不是立即把所有正常流量加入训练。使用已有已保存的开发错误检查未来试验是否确实具有修复机会；阈值、模型分数不得决定哪些正常记录进入参考。没有足够机会就停止，不再安排一次注定无法回答问题的训练。

第一份 Active 文件仅作为本轮可行性审计的自然边界，**8 小时不是已经冻结的最优观察预算**，更不是搜索出来的模型参数。正式候选窗口要由实际部署成本、连续记录边界和 LEARN 侧覆盖共同确定；不在确认设备上选到效果最佳。

### B. 攻击输入语义预检

实现一个可复用的审计器，针对已保存 UID 追踪：目标帧和流边界、目标包是否进入保留 token、保留上下文来自哪些过去传输流、prefix 截断、合法标签依据。若未来获准读原始流，仅在封存的诊断清单及匹配的正确样本上做一次有界核查；无需 E3 前向或优化器。

比较样本应来自相同设备/捕获/模式和相近候选位置，先确定抽样规则再看 token；不能只展示漏检的异常形状。确认设备只用于解释已消费结果，不作为新的损失、阈值、参考选择或模型选择依据。任何拟合机制只由 LEARN/DEV 建立，未知确认机会另行准备。

### C. 预检后的分支预先固定

| 一次预检的结果 | 技术决策 |
|---|---|
| 有合法新参考、开发错误覆盖足够，当前攻击信息也可见 | 先做一次冻结 Q/校验器/阈值的参考覆盖开发比较，检验更合格的支持是否真正改善误报且不新增漏检；不先重训所有模型。新参考扩大了证据范围，旧保护 cut 不保证安全，必须实测攻击损失。 |
| 证实当前攻击信息被截断或跨传输流语义混合，且错误比匹配正确样本更集中 | 保留原 E3/Q 主通道，设计仅补充当前流/近期因果证据的攻击修复路径；再做独立新协议。不是无证据重建前端。单靠保留旧报警不能解决首次漏检。 |
| 信息可见，但原 Q 仍不能区分；参考覆盖比较也无联合收益 | 才进入训练侧留设备错误驱动的纠错学习设计，检验监督/任务覆盖；不能靠继续拟合同一批已全对训练样本解决。LEARN 当前没有 HTTP 模式这一覆盖事实也需纳入，不把模式迁移都归为欠训练。 |
| 合法较早参考或可评估开发机会不足 | 明确数据缺口与最小补充需求，停止真实实验；不调低门槛、不倒灌未来正常、不把旧确认池再包装成独立测试。 |

这一阶段结束必须交付“能否进入哪一个有限实验证明、具体缺口是什么”的决策；不以产出文档数量或合成测试数代替科学进展。下一次真实执行仍需相应明确授权；建议届时一次覆盖明确的预检与合格后的固定链条，避免逐环节重复询问。

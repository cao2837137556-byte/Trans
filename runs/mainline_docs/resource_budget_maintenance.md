# 资源预算维护约定

2026-10-17 根据用户反馈确定：资源配置要与实际任务相称，维护预算不应每轮重新开展全面审计。

- **复用已有预算。** 数据规模、输入形状、批量、并发、算法与驻留方式未变时，引用上一版阶段预算及其证据，不重新读取全部代码、长日志或重复推导。
- **只更新受影响阶段。** 上述条件改变时，说明变化项，重算相关阶段；全流程结构变化或出现无法解释的资源异常时才扩大审查。脚本退出码、文档等修改通常不触发重新核算。
- **用实测逐步替换估计。** 首次真实运行后，从阶段监控与 Slurm 记账提取峰值RSS、并发、耗时和输出大小；末尾RSS不得当峰值，单进程局部量测不得当整链实测。超限先定位原因，不自动加资源。
- **验证按变更选择。** 运行必要的受影响测试，复用未改部分已有结果；不把继承的测试数写成本轮重跑数，也不为节约token省略关键失败场景。
- **控制给模型的输出。** 量测和完整日志留文件，通常只读取阶段汇总、失败片段和确有需要的源码。执行时间与模型token消耗分开描述，不承诺固定token费用。

当前可复用基准：QUERY_TAIL v2r3为16CPU/20GiB；入网v1及交付补丁v1r1为8CPU/16GiB，均仍含完整阶段估计。前端重建任务尚未定值，不能套用入网额度。

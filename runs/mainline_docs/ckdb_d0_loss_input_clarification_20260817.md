# CKDB D0 loss-input governance clarification

Date: 2026-08-17  
Authority: user clarification

The user did not state that the advisor would provide, or must provide, an exact
loss formula. CKDB D0 must not wait for such an input.

Accordingly:

- an advisor-provided loss is optional future evidence, not a launch blocker;
- CKDB owns the responsibility to define and preregister any global
  domain-robust objective it proposes;
- if no advisor formula is available, that candidate is simply absent rather
  than recorded as a failed hard gate;
- CKDB D0's controlling hard gates are fresh unseen benign evaluation data and
  identifiable legal training domains;
- no implementation or training is authorized by this clarification.

This clarification supersedes any wording in the round-1 discussion that could
be read as requiring the project to wait for the advisor's formula. It does not
change CKDA's `WEAK_ONLY` verdict or authorize CKDB beyond read-only D0 audits.

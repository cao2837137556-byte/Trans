# 统一新设备入网规则 v1：定稿与实施边界

日期：2026-09-24。状态：**规则定稿并封存，可进入实现；真实预检、训练和独立确认均未执行。**

机器规则：`runs/legacy_commissioning_policy_v1_20260924/commissioning_policy.json`。规则 SHA 在本轮可行性统计之前记录于 `before_availability_counts.json`；后续没有按统计结果调整时长、数量或设备规则。

## 1. 本次决定及所支持的问题

采用一套对所有设备相同的、有时间预算的正常入网观察流程。它收集设备自身较早的正常参考，不更新模型参数。协议覆盖不足的流量继续使用既有检测，不能直接放行。后续要验证的贡献是：冻结模型和规则后，在未参与训练与设计的新设备上，正常参考能否降低误报并保持攻击检出。

这是可信正常入网条件下的跨设备适应。它不等于完全零样本泛化，也不等于已解决入网阶段本身受到攻击的情形。“一个小时”“64 条参考”和“同协议两组件”分别是操作预算、存储上限和原校验器最低适用条件；都不是完整行为覆盖、统计独立性或安全性的定理。

本规则是看到先前失败后提出的新开发版本，公开承认这一点。Borun、Netatmo、Ring 已消费，只保留原诊断和结果，不用于选择窗口、阈值、参考或模型，更不能再当作未知设备确认。旧门槛、旧 FAIL、旧分母不修改。

## 2. 观察一小时，功能按统一类别覆盖

观察开始前登记设备身份、可支持功能类别、已知协议、采集视角及正常性依据。t0 为预先记录的入网观察开始时间；t1=t0+3600 秒。观察满固定预算结束，不因已覆盖而提前停，也不因某设备仍不够用而自动延长或重启。

| 时间 | 操作类别 | 目的 |
|---|---|---|
| 0–5 分钟 | 启动或适用的安全重连 | 覆盖正常联网阶段 |
| 5–15 分钟 | 待机 | 覆盖心跳、常规后台通信 |
| 15–30 分钟 | 主要本地功能 | 如本地控制、观看、状态查询，按事先登记的适用功能执行 |
| 30–45 分钟 | 主要远程功能 | 如设备实际具备的云端或远程交互 |
| 45–50 分钟 | 正常状态切换 | 如开始/结束常用操作，不强制制造协议或流量 |
| 50–60 分钟 | 稳态运行 | 记录恢复稳定后的通信 |

各时间段左闭右开，最后一段包含 t1。无此功能的时间段标记 N/A 并保持待机，不把时间挪给其他操作；无法完成但本应适用的操作标记 UNAVAILABLE，不能写成 N/A。操作日志记录计划、实际执行、起止时间和未完成原因。功能类别对所有设备一致，具体动作由设备说明或预先配置决定，不根据测试误报定制。

一小时的理由是先给出一次可承担、可复现的操作预算，不是文献证明的一小时最优方案。实际评估应同时披露这一小时的成本与覆盖缺口。本版本不搜索其他窗口。缺口若使问题无法验证，需要正式的新数据/设计决定，不能悄悄追加观察直到成功。

不执行恢复出厂、改凭据、改安全配置或不安全的物理操作。设计本身不授权操作现实设备。设备本来不用的协议不强行生成；HTTP、HTTPS、DNS 等服务行为与 TCP/UDP 传输协议分开记录，传输协议齐全不代表行为齐全。

## 3. 正常性和因果边界

- 正常来源须由独立的可信观察环境或数据发布方的正常采集说明支持。模型低分不能认证正常，也不能读取后续标签再挑出一段“干净”参考。
- 正常性无法确认或整段被污染时，该候选参考库整体无效。不得删除可疑行后重新声称已获得可信正常阶段。
- 参考只能来自本次固定窗口内、截止时实际已观察的目标帧；记录每个源的 cutoff frame。查询严格晚于 t1，且满足源内顺序。不能用后来完整会话算出的特征代表早期参考。
- 前缀保留原 owner/capture/双向五元组因果规则及原 E3，不在本方案中改为新的流切分或近期窗口。查询可使用截至自身时刻的合法过去上下文；不含未来帧、其他设备或其他捕获。
- 截止后可离线完成参考编码，但所有输入必须封闭在截止快照内；编码完成前保持原回退，真实部署要报告额外准备延迟。
- 采集缺口不拼接为连续观察，也不能仅凭“这一段没包”推断设备处于待机。采集健康未知就写未知。

同一个规范化组件的过去参考与未来查询可以构成合法的持续连接场景，但要单独报告；不能把它当成独立新连接或独立统计样本。transport stream ID 只作审计信息，不能直接作为新的在线前端重置指令。

## 4. 参考选择与资格

仅使用原前端合格的 TCP/UDP 目标。其他协议、字段不全、归属不明和共享 DHCP 等继续遵守原支持边界；本入网规则不扩展前端协议范围。

1. 在固定窗口内，按既有依赖组件去重。每组件只保留截止前最后一个合法目标及其当时的因果前缀。同时间按 capture_id、frame、UID 确定唯一顺序。
2. 分 TCP/UDP 排列组件，按固定盐 `commissioning-reference-v1-20260924` 与 component_id 的 SHA256 排序。
3. TCP、UDP 交替各取一条，某类用尽则跳过，最多取 64 条。两类都充足时各最多 32 条；稀少协议不会被大量另一类流量完全挤掉。
4. 不按标签、模型分数、embedding 距离、已知错误、设备品牌或后续查询选择参考。正常性来自整段来源认证，不是逐行看查询标签。

每协议输出 `NOT_OBSERVED / OBSERVED_NO_LEGAL_REFERENCE / SINGLE_COMPONENT / REFERENCE_AVAILABLE`。最后一种仍要求至少两个不同组件，沿用校验器条件；不复制同一连接凑数。

分别报告：原始合法候选数、组件数、传输流数（若可知）、选择前后协议/方向/操作阶段覆盖、真实采集时长、参考大小、丢弃原因。功能覆盖独立标记 `VERIFIED_APPLICABLE_OPERATIONS / PARTIAL / UNKNOWN_PASSIVE`。

所谓“当前已覆盖的范围”，仅指观察前声明的协议加观察中出现的协议。未知声明保持未知；没有出现某协议不能证明设备以后不用它，也不能宣布所有未来行为已覆盖。

## 5. 回退与模型身份

| 条件 | 路由 |
|---|---|
| 截止前、正常来源不可信，或没有合法自身参考 | 原冻结 R |
| 正常来源可信且至少一条合法自身参考，完成注册；查询协议参考不足两组件 | 原冻结 Q |
| 完成注册，查询协议至少两组件 | Q 加原冻结正常参考校验器 |
| 注册后首次出现观察期未覆盖的协议 | Q 回退；不自动吸收入库 |
| 原前端不支持的输入 | 原支持/回退合同，单列覆盖与默认决策，不能计成模型学会的攻击检出 |

比较组使用相同的注册条件与状态，不能把“内层空参考”误做成“未注册→R”，以夸大 Qref 收益。

E3、R、Q、FULL、RAW、阈值、seed 27/127/227 与 ensemble 算法继承已经验证的冻结身份，见 `frozen_detector_contract.json`。本版改变的是新情景的正常观察与参考选取，不训练模型、不重估 normalizer、不调设备阈值、不选择最优 seed。

新参考可能令原来未被撤销的攻击报警被撤销；旧 CAL 针对旧参考的保护不能自动覆盖新参考。保住攻击需要独立实测，不能从“Q 不变”推出“最终攻击检出必然不变”。

这些端点来自原整捕获抽样清单，只能给出可用性下界。正式新参考必须从窗口内完整合法事件选择，不能沿用使用整捕获未来候选总数产生的稀疏抽样，也不能用会话最后时间晚于截止的全会话特征。这里没有物化新参考 UID、特征或改变原数据角色。

更重要的是：Active 缺少逐项操作日志，不能证明执行了上表的主动功能流程。它仅支持 `UNKNOWN_PASSIVE` 开发投影；不能把将来在它上的成绩称为完整主动入网验证。两台 DEV 的 TCP 仍不足，本轮不会据此扩大到八小时来获取通过。

现有分配名册为 6 台 LEARN、2 台 DEV、3 台已消费确认设备，**其中没有新的未消费确认设备**。这不是说全项目其他资产必然没有，而是尚未核实新的同设备“先正常参考、后正常和攻击”配对及未参与设计的身份。完整迁移确认目前不具备开跑依据。

## 7. 验证安排：不靠改分母获得进步

原 DEV 困难回归池及其原参考、UID、标签、权重完整保留。新增更晚参考不能用于更早查询；旧 357 条 Eufy 困难误报不能通过移动检测起点消失后被算作修复。新入网情景另列分母，严禁跨池比较 headline rate 宣称提升。

未来合法情景中的三组主比较为：同注册状态的 Q、相同参考库的 RAW、相同参考库的 FULL。可在相同未来查询上附原合法参考库作为锚点，以区分“换了参考”与“学到了更好的关系”。正确/错误设备参考若要证明个性化贡献，必须事前封存同协议、同数量、时间合法的匹配对照，供体不足如实 NOT_RUN。

必须完整报告各设备的正常误报、攻击检出、零新漏检保护、资格覆盖、全回退人群、活动/协议/捕获差异。正常基线零误报的设备留在结果中，但不能替它制造一个修复收益。每个 seed 对比自己的 Q，不以全局平均掩盖某设备攻击损失。

独立确认前还须封存新设备名册、采集批次、同设备攻击配对、样本量/估计精度和复制成功标准。目前没有数据身份就不编造一个“一区所需设备数”。不能使用相关包数量构造虚假的窄置信区间。相同设备的新时段只证明时间迁移；外部 E3 预训练排重仍另行披露。

独立 ID 仍 NOT_RUN。分别采集正常/攻击的联合指标，不等于真实同时混合流证据。现有 FULL 只撤警，不提升 Q 原漏检；本方案不以正常参考收益冒充攻击学习创新。

## 8. 攻击语义预检一并定好，不执行真实读取

保留同一有限阶段的攻击审计器设计，优先使用已开发的 LEARN/DEV。

- 纳入原 DEV 已保存的全部 11 条 Q 攻击漏检；每条配最多 2 条同捕获、协议、模式、候选位置桶的正确查询，组件不同，按固定 hash 选。找不到匹配如实缺失，不临时放宽条件。
- 加入事先分层的 DEV 正确/结构样本：设备、模式、协议、单/多传输流、位置桶，每层 hash 前两组件。不能只检查已经错的样本。
- 追踪目标帧是否被前缀保留、是否在 tokenizer 阶段被截掉、保留帧来自哪些过去传输流、标签依据、饱和程度和时序。不能只看 `target_in_prefix` 就宣称模型看到了目标。
- 不以“是否保留目标”“是否混流”来匹配正确对照，否则会把待检假设人为配平掉。没有足够信息时输出 INCONCLUSIVE。
- 实现可用合成输入检验。真实源的一次有界读取、tokenizer 审计仍需真实执行授权；不调用 encoder、不训练、不改前端。确认设备继续仅用于已有结果诊断，不能参与模型选择。

如果发现原始字段确实不可见或混流，仅形成有对照的机制证据，再决定是否设计补充当前流信息的修复。若信息完整而判别失败，再研究训练侧留设备攻击错误监督；不靠继续拟合已全对的 LEARN 或把 R/Q 直接取并集解决。

## 9. 研究依据、审查结论与下一步

沿用本会话已经核实的 [ICLAD](https://arxiv.org/html/2603.19497v1)、[DIDS-MFL](https://ieeexplore.ieee.org/document/11112665)、[Group DRO](https://arxiv.org/html/1911.08731)、[Conformal Risk Control](https://arxiv.org/html/2208.02814)、[DIoT](https://www.computer.org/csdl/proceedings-article/icdcs/2019/251900a756/1ezRWmRMECs) 和 [近期 few-shot NIDS 综述](https://arxiv.org/html/2609.11275v1)。阅读范围沿用已封存研究记录，不声称本轮重新读了付费全文或做了新检索。

这些文献支持有条件适应、查询与参考隔离、攻击保护和谨慎泛化，不为一小时、两组件或 64 条提供性能保证。历史 CKDE 的无配对/伪独立教训、正常服务对照缺口也已纳入，没有回到失败过的单纯设备阈值校准。

本轮审查结论为 **DESIGN_READY_FOR_IMPLEMENTATION / REAL_VALIDATION_NOT_READY**。规则、回退、选择算法和实现边界已经具体；主动操作证据、新独立确认数据以及未来实验的完整分母仍待落实，不能用“规则写好了”替代这些条件。

下一步是实现协议校验器、候选参考规划器、覆盖报告及攻击语义审计器，并做合成边界验收。实施需要保留这些硬边界：未来帧不能改变过去快照；采样选择不读测试分数；稀少协议不复制凑数；旧模型/阈值/结果字节不变；元数据阶段不得调用真实解码或模型。具体真实执行链条准备好后再按授权运行，不重复索要链条内机械步骤的许可。

本轮没有生产执行器改动、原始数据读取、新模型前向、优化、校准、下载或 HPC。已有无关修改保留。方案、统计支撑、审查与 SHA 见 `runs/legacy_commissioning_policy_v1_20260924/`。

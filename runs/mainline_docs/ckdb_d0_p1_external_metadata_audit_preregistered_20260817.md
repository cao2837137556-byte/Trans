# CKDB D0-P1 external benign corpus metadata audit — FROZEN preregistration

Date: 2026-08-17

Status: `FROZEN_PREREGISTERED`

Authority: CKDB round-3 convergence (`7a10dfc`) and Kimi independent review
(`117c93f`).

## 1. Purpose and hard boundary

D0-P1 decides whether two external benign-corpus candidates have sufficiently
clear provenance, legal use, benign boundaries, domain diversity, and
small-metadata evidence to justify a later large-PCAP download request.

This FROZEN protocol authorizes **no execution by itself**.  If execution is
separately authorized by the user after freeze review, it remains metadata-only.
It does not authorize:

- any PCAP or full-dataset archive download;
- training, embedding generation, fitting, probing, calibration, or threshold
  selection;
- opening CKDA report labels beyond already-published aggregate evidence;
- opening cooler-motor, seed 37/47, or any other FINAL asset;
- HPC submission;
- adding an arbitrary third corpus after observing candidate results; the only
  permitted future corpus amendment is the pre-frozen industrial-domain
  deficiency remedy in Audit 5, under its own review and authorization;
- choosing a representation window from hydraulic metrics.

The two frozen candidates are:

1. `UNSW_IOTRAFFIC` — consumer/home IoT, physical devices, lab capture;
2. `CIC_MODBUS_2023` — industrial/process control, simulated substation.

The second candidate is included through the domain-type taxonomy, not because
it resembles hydraulic.  Both candidates face the same audit schema.

## 2. Frozen source identities and permitted files

### 2.1 UNSW-IoTraffic

Primary identities:

- official page: `https://iotanalytics.unsw.edu.au/unsw-iotraffic.html`;
- repository DOI: `10.5061/dryad.w0vt4b94b`;
- descriptor DOI: `10.1109/IEEEDATA.2025.3602010`.

Tier A permitted objects:

- Dryad landing/file inventory HTML;
- `README.md` (published size about 11.19 KiB);
- `device_pcap_summary.csv` (about 1.84 KiB);
- `protocol_diversity_prevalence.csv` (about 384 B);
- descriptor-paper bibliographic metadata and device table.

Tier B permitted object, only after the Tier A gate passes:

- `flows.zip` (published size about 95.51 MiB), because it is published as
  derived per-device flow metadata rather than raw packets.  If inspection after
  extraction shows per-packet records or payload bytes, quarantine the entire

Explicitly prohibited in D0-P1:

- `pcaps.zip` (13.92 GiB compressed);
- `UNSW-IoTraffic.zip` (full archive);
- `protocols.zip`, `scripts.zip`, payload samples, or any duplicate archive.

### 2.2 CIC Modbus 2023

Primary identities:

- official page:
  `https://www.unb.ca/cic/datasets/modbus-2023.html`;
- official cited paper and official download-portal inventory reachable from
  that page.

Tier A permitted objects:

- official dataset page HTML;
- official paper bibliographic metadata;
- official download file/folder inventory;
- README, data dictionary, manifest, checksums, or device/source list when
  individually exposed outside a PCAP archive.

Tier B permitted objects, only after the Tier A gate passes:

- existing derived benign flow tables or compact flow summaries, if official,
  separately downloadable, and not generated by opening PCAPs.

Explicitly prohibited in D0-P1:

- all benign or attack PCAP chunks;
- full-dataset archives;
- attack logs or row/event labels beyond folder-level boundary metadata;
- generating flow tables from PCAPs.

If CIC exposes no suitable Tier B object, horizon/long-TCP fields remain
`PENDING_NO_SMALL_FLOW_METADATA`; the project must not open PCAPs to fill them.

## 3. Download and evidence safety contract

1. Use only HTTPS primary-source URLs or a DOI redirect to the primary host.
2. Store every object under a new candidate-scoped directory; do not overwrite
   any previous corpus or run artifact.
3. Record request URL, final URL, retrieval UTC, HTTP status, content length,
   media type, local bytes, and SHA-256.
4. Download to a temporary filename, verify nonzero size and expected media
   type, then atomically rename.
5. Reject HTML login/error pages masquerading as CSV/ZIP/PDF.
6. Tier A cumulative payload must remain below 20 MiB per candidate.
7. Tier B cumulative payload must remain below 128 MiB per candidate and may
   contain no PCAP magic or `.pcap`/`.pcapng` member.
8. Archive members must be listed before extraction; reject absolute paths,
   `..`, links, encrypted members, executables, or unexpected nested archives.
9. Extraction uses a new empty directory and produces a full member SHA-256
   manifest.
10. Network failure produces `INCOMPLETE_DOWNLOAD`, never a scientific verdict;
    resumable transfer is allowed only for the same URL and expected object.

No credentials, cookies, tokens, MAC addresses, raw IP addresses, or payloads
may be committed to Git.  Evidence tables may use corpus-published device names
and aggregate counts.

## 4. Frozen domain-type taxonomy

Each device/source group receives exactly one value for every dimension below.
Unknown is an explicit value, not silently imputed.

| Dimension | Allowed values |
|---|---|
| usage domain | `CONSUMER_HOME`, `INDUSTRIAL_PROCESS`, `ENTERPRISE_GENERAL`, `UNKNOWN` |
| embodiment | `PHYSICAL`, `SIMULATED`, `MIXED`, `UNKNOWN` |
| source unit | `DEVICE`, `ROLE`, `CAPTURE`, `NETWORK_AGGREGATE`, `UNKNOWN` |
| benign boundary | `BENIGN_ONLY_FILE`, `BENIGN_ONLY_FOLDER`, `MIXED_WITH_EXACT_BOUNDARY`, `MIXED_UNRESOLVED`, `UNLABELED_NORMAL_CLAIM`, `UNKNOWN` |
| transport evidence | `TCP`, `UDP`, `ICMP`, `MIXED`, `UNKNOWN` (multi-valued columns permitted) |
| time evidence | `EXACT_CAPTURE_RANGE`, `PARTIAL_RANGE`, `PUBLICATION_ONLY`, `UNKNOWN` |
| collection relation | `KNOWN_DISJOINT`, `NO_KNOWN_OVERLAP`, `POSSIBLE_OVERLAP`, `KNOWN_OVERLAP`, `UNKNOWN` |

`KNOWN_DISJOINT` requires positive manifest/time/device evidence.  Merely finding
no match is at most `NO_KNOWN_OVERLAP`.

## 5. Eight frozen audits

### Audit 1 — source identity, license, and integrity

For every candidate, record:

- official owner, landing page, dataset and paper DOI;
- research-use, redistribution, and citation terms;
- published object names/sizes/checksums;
- retrieval and local SHA-256 evidence;
- whether access requires an account, form, or manual approval.

Hard fail:

- no primary-source identity;
- research use is prohibited or materially ambiguous;
- downloaded identity cannot be tied to the official inventory;
- an object fails type/archive safety checks.

### Audit 2 — collection and pretraining lineage

Build a timeline and overlap matrix covering:

- candidate capture dates and devices;
- ToN-IoT/UNSW sources already used by this project;
- existing CKDA/CKCZ source families;
- netFound's documented pretraining corpora and dates;
- any known derivative/repackaged form of the candidate.

Required route-specific conclusions:

- I1 external self-supervision versus existing fit/select/report sources;
- E3 control versus netFound pretraining;
- future cooler-motor final versus all external candidates.

Hard fail for a route:

- `KNOWN_OVERLAP` with that route's supposedly unseen evaluation domain;
- provenance cannot support at least `NO_KNOWN_OVERLAP` after the permitted
  metadata are inspected.

`POSSIBLE_OVERLAP` cannot be upgraded by inference; it remains a claim caveat
or blocks a disjointness-dependent route.

### Audit 3 — benign-use boundary

Freeze the smallest file/folder/capture units that are explicitly normal.

- UNSW interactions/background traffic are not automatically attack-free merely
  because no event annotations exist; record the dataset authors' exact claim.
- CIC benign and attack trees must remain separate; no attack PCAP/log may be
  used to infer or repair benign content.
- mixed or unknown units are excluded rather than filtered using row labels.

Hard fail:

- benign status is only recoverable by reading attack/event labels later;
- benign and attack material cannot be separated at a pre-open file/folder
  boundary;
- the unit would introduce report/FINAL traffic into training.

### Audit 4 — device/source census and domain independence

Record per source unit:

- published device/role name and stable pseudonymous audit ID;
- physical/simulated status;
- capture interval;
- packets and flows when published;
- whether multiple files are repeated days from the same device;
- whether device groups share the same simulated controller or collection
  network.

Repeated days/chunks from one physical device do not create new domains.
Simulated IED/HMI roles sharing one generator are reported separately but also
clustered under the common simulator for bootstrap and LODO planning.

### Audit 5 — consumer/industrial coverage matrix

Produce a common matrix across both candidates with:

- consumer versus industrial coverage;
- physical versus simulated coverage;
- protocol and transport mix;
- per-device/role packet and flow counts;
- explicit `long_bidirectional_tcp_evidence` state:
  `PRESENT`, `ABSENT`, `PENDING`, or `NOT_MEASURABLE`.

If Tier B flow metadata exist, `PRESENT` requires a preregistered, corpus-global
descriptive definition:

```text
bidirectional TCP flow AND
(packet_count > 256 OR duration_seconds >= 300)
```

Report prevalence and quantiles for every domain; do not use hydraulic values
to change this definition.  Long-TCP presence is descriptive and **not** a
per-corpus inclusion requirement.

For this gate, `independent domain` is counted **after** Audit 4 clustering:
repeated days/chunks from one physical device count as one domain, and all roles
sharing one simulator/generator count as one domain.  Raw device/role rows may
be reported but may not inflate this count.

Route-level coverage gate for asking permission to download large PCAPs:

- at least one metadata-eligible consumer corpus;
- at least one metadata-eligible industrial/process corpus;
- the consumer side contributes at least three post-clustering independent
  domains;
- the industrial side contributes at least three post-clustering independent
  domains;
- no claim that simulated industrial traffic equals physical industrial
  traffic.

A CIC horizon or scale state of `PENDING_NO_SMALL_FLOW_METADATA` does not by
itself block this route-level gate: Tier A device/role evidence determines the
post-clustering domain count.  It remains a named uncertainty for later census.

If at least one industrial corpus passes metadata eligibility but the combined
industrial count is below three, the overall verdict is mechanically
`CKDB_D0_P1_PENDING_METADATA`; the named missing evidence is
`SECOND_INDUSTRIAL_PROCESS_CORPUS`.  If no industrial corpus passes metadata
eligibility, the verdict is `CKDB_D0_P1_NO_IDENTIFIABLE_CORPUS_MIX`.

The deficiency remedy is frozen now, before candidate evidence is opened: a
future amendment may add one second industrial/process corpus only to bring the
combined post-clustering industrial count to at least three.  This is not the
prohibited arbitrary third-corpus addition.  The amendment must be
preregistered, must apply the same eight audits and taxonomy, must not use
viewed hydraulic/CKDA outcomes to select the corpus, and must receive separate
user authorization before any metadata or large object is downloaded.

### Audit 6 — 256-packet horizon coverage

Using only published summaries or permitted Tier B flow metadata, report per
domain:

- packet-count and duration quantiles;
- fraction of flows with packet count greater than 256;
- fraction satisfying the frozen long-bidirectional-TCP descriptor;
- whether a 256-packet current-inclusive prefix omits the start of long flows;
- availability of causal accumulated-state variables at inference time.

No alternative window is evaluated.  Audit output is one of:

- `PREFIX_256_COVERS_MOST_OBSERVED_FLOWS`;
- `PREFIX_256_TRUNCATES_MATERIAL_LONG_HORIZON`;
- `PENDING_NO_SMALL_FLOW_METADATA`.

This is a design warning, not a model-selection result.

### Audit 7 — scale and future census feasibility

Record published packet/flow counts and estimate only bounded engineering
resources:

- expected compressed/uncompressed bytes;
- resumable transfer support;
- expected decode and storage order of magnitude;
- whether published counts can possibly clear I1's inherited minima of
  500,000 benign sessions and 10,000,000 benign tokens.

Published packet/flow counts are not substitutes for the later causal session
census.  The only permitted verdicts are:

- `SCALE_PLAUSIBLE_PENDING_EXACT_CENSUS`;
- `SCALE_IMPOSSIBLE_UNDER_PUBLISHED_UPPER_BOUND`;
- `SCALE_UNKNOWN`.

### Audit 8 — mechanical verdict and later-download allowlist

Each corpus receives one status:

- `CORPUS_METADATA_ELIGIBLE`;
- `CORPUS_METADATA_INELIGIBLE`;
- `CORPUS_METADATA_PENDING`.

An eligible corpus must pass Audits 1–4.  Audits 5–7 may contain explicit
`PENDING` fields where no small metadata exist, but every pending field must
name the exact later evidence needed.  Audit 5's route-level coverage gate must
pass before the overall verdict can become:

`CKDB_D0_P1_LARGE_DOWNLOAD_ELIGIBLE`

Otherwise the overall verdict is one of:

- `CKDB_D0_P1_PENDING_METADATA`;
- `CKDB_D0_P1_NO_IDENTIFIABLE_CORPUS_MIX`;
- `CKDB_D0_P1_ENGINEERING_FAILURE_NO_SCIENTIFIC_VERDICT`.

The allowlist names exact official objects, expected sizes/checksums where
published, destination identities, and intended use.  It is evidence for a
future user authorization; it does not itself authorize download.

D0-P1 execution must produce all of the following:

1. `ckdb_d0_p1_retrieval_manifest.csv` — URL/final URL/bytes/type/SHA/time;
2. `ckdb_d0_p1_corpus_identity_and_license.csv`;

7. `ckdb_d0_p1_horizon_and_scale.csv`;

Empty and unknown values use explicit reason codes, not blank cells.

## 7. Fail-closed ordering

Execution order is frozen:

1. validate protocol hash and empty output root;
2. retrieve and verify Tier A objects for both candidates;
3. complete Audits 1–4 from Tier A evidence;
4. if a candidate fails Tier A, do not retrieve its Tier B object;
5. retrieve and verify only approved Tier B objects;
6. complete Audits 5–7;
7. generate Audit 8 verdict and allowlist;
8. validate schemas, boundaries, member hashes, and prohibited-file counts;
9. package the metadata-only result.

Any engineering failure creates no corpus or scientific verdict.  Partial
objects remain quarantined and are not inputs to another run unless their
identity and hash are revalidated.

## 8. Pre-execution contract tests

The implementation review must independently verify at least:

1. Tier A/Tier B byte caps;
2. PCAP magic/member rejection;
3. HTML-as-data rejection;
4. archive traversal/link/nested-archive rejection;
5. temporary-download and atomic-rename behavior;
6. resumed-download same-identity enforcement;
7. exact SHA manifest generation and readback;
8. explicit unknown/reason-code handling;
9. candidate-count exactly two;
10. equal schema for both candidates;
11. no cooler-motor/seed37/seed47/report path in any input allowlist;
12. no label, training, embedding, threshold, or model import;
13. Tier B cannot run after Tier A fail;
14. route-specific overlap verdicts cannot overclaim `KNOWN_DISJOINT`;
15. repeated files/days do not inflate independent domain counts;
16. long-TCP descriptor is literal and not data-adjustable;
17. missing Tier B evidence yields `PENDING`, not zero/absence;
18. final verdict cannot authorize large download.

The code must be Python 3.9 compatible if Python is used.  Runtime API checks
must accompany syntax compilation, reflecting the CKDA D0 failures already
recorded in the repository.

## 9. Freeze closure and authorization boundary

Kimi review `117c93f` closed all four draft questions:

1. the 128 MiB Tier B cap and the published 95.51 MiB UNSW flow archive are
   accepted, subject to the per-packet/payload quarantine rule;
2. CIC may remain metadata-eligible with explicit horizon/scale `PENDING` when
   no compact flow table exists, and that pending state alone does not block
   the Audit 5 device-domain gate;
3. the 3+3 gate is accepted only for post-clustering independent domains, with
   the second-industrial-corpus remedy and verdict mapping frozen in Audit 5;
4. the global long-TCP descriptor (`>256 packets OR >=300 seconds`) is accepted
   as descriptive coverage rather than a success gate.

This FROZEN document and its SHA-256 sidecar authorize no implementation or
download.  D0-P1 metadata-only execution requires Kimi freeze verification and
then explicit user authorization.  Any large PCAP/full-archive download, HPC
submission, training, embedding, threshold work, or FINAL contact requires its
own later authorization and is outside this protocol.

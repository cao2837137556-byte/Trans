# Post-N2 breakthrough strategy review

Date: 2026-09-08. Status: STRATEGY_PROPOSED_NOT_FROZEN_NOT_EXECUTABLE.
Authority: the user requested careful reasoning on how to break the inheritance
impasse and whether the frontend failure requires starting over. This review
uses existing documents and source text only. No new numerical diagnostic,
feature/head decoding, checkpoint loading, fitting, tests or experiment occurred.

## Decision

Do not infer that the existing frontend or the entire research project must be
rebuilt. Prefer designing ONE prospective conservative joint repair on the fixed
N1 representation, with complete declared retention, before choosing a new
encoder or carrying out an expensive teacher-history reconstruction.

This is a proposed new development-learning question, not permission to rerun
N1/N2, not a rescue of F5, and not an executable continuation of their protocols.
Its purpose is concrete repair feasibility, not causal identification or a new
generalization result. An executable protocol, input/exposure contract, resource
and action caps, numerical certificates and explicit authority are still needed.
No constants, gates, labels, seed, loss or original split were changed here.

## What has and has not been lost

The old deployed detector and its recorded results remain intact. F4's selected
field preservation and the causal event interface remain reusable engineering.
The fixed GRU/head_hidden representation already admits the N1 head that gets
all 8,660 training judgments right. These are specific reusable achievements.

N2 did not update parameters. Its 846 protected development errors exactly match
the original terminal reference, with zero new errors and zero repairs. This is
failure to extend a training repair, not another training-forgetting event.
The three A misses are one context, not three independent attack experiments.

The current inheritance gate also contains unseen-behavior transfer demands:
its literal attack-family names do not occur in F5 training. Old E3 had netFound
pretraining, richer headers and different history; F5 initialized a new GRU and
provided only training-side scalar teacher evidence. Preserving the selected
19 L1 fields does not preserve all of those inputs or transfer pretrained
knowledge. Copying more fields alone would not transfer that knowledge either.

Historical F5 epochs 1, 2 and 18 detected the three A development attacks, but
no epoch passed the joint gates. This does not establish useful joint
separability and does not authorize selecting a historical checkpoint.
Neither persistent errors nor the fact that they follow a reset proves missing
history caused them. flow_duration is not an actual old E3 model argument.

## Proposed conservative repair question

Freeze the event projection, GRU, head_hidden/activation, semantic state, input
semantics and numerical runtime. Consider only the existing 65-parameter final
linear head. Predeclare the complete following development requirement once:

| Required judgment set | Targets | Reason |
|---|---:|---|
| All original F5 training targets | 8,660 | Preserve every N1-correct training judgment |
| All original protected development targets | 1,484 | Repair errors jointly without sacrificing already-correct protected rows |
| All N2 B-benign targets already classified normal | 2,567 | Preserve all currently observed B target releases |
| Total disjoint constrained targets | 12,711 | One prospective sufficient repair condition |

Preserving all 2,567 released B targets preserves each of the 2,238 previously
all-B-benign-normal contexts, and therefore every original per-key floor.
This implication must be verified against the actual context membership, not
assumed by summing group counts. The two development A0W targets remain
report-only. The other B targets must still be reported; no error is hidden.

This is an explicitly NEW, stronger development retention condition. It is not
an algebraic restatement of the original B floors. A simple LP on only the
10,144 train-plus-protected-dev rows could destroy B utility. Conversely,
requiring all 3,720 B-benign targets normal would add an unnecessary stronger
goal. Exact optimization of the original count/context floors would introduce
discrete conditions; it is not silently approximated as ordinary linear signs.

The 2,567 B membership is outcome-defined from the already exposed N2 result.
It must be frozen as a prospective development-retention set before any next
fit. It is not a holdout or independent confirmation set. Using the 1,484
development protection labels to generate a candidate also makes them fitting
evidence for that candidate. Original F5 membership and its failed outcome stay
unchanged; a new view must honestly record this new learning use.

| Future outcome | Permitted conclusion and consequence |
|---|---|
| A fully verified witness | These known protected failures can be repaired while preserving all declared training/B judgments without changing this encoder or input. Keep the small repair; broader inheritance remains unproved. |
| Exact scoped infeasibility | This fixed last-layer problem cannot satisfy the new conservative constraints. Inspect the certified conflicting constraints before choosing the next mechanism question. It does not prove the weaker original floors impossible or prove raw inputs inadequate. |
| Timeout, precision disagreement, incomplete verification or access failure | No feasibility conclusion; stop the attempt. Do not alter a subset, margin, seed or head family and retry. |

The N2 protocol says, "Do not run a sequence of head searches under this roadmap."
That boundary remains in force. This proposal requires an explicit newly
reviewed research purpose and development-learning scope; it cannot be enacted
using old authorization or a renamed N1/N2 run. One complete prospective problem
and a terminal decision are intended, not successive fits to whatever fails next.
The proposal is not yet a numerical specification and is not ready to launch.

## Why this order, and where history diagnosis fits

Three read-only reviews considered the alternatives. Two preferred a fixed-old-
teacher history restriction; one preferred the conservative joint repair. All
agreed on the evidence limits. The primary agent selects joint repair DESIGN
first because a positive witness directly answers the user's immediate question
about whether these known failures require changing the frontend.

A teacher-history contrast remains a useful conditional diagnostic. Existing
source review already establishes a history-contract difference, but a lawful
UID/source/member/old-session/target-cutoff bridge and token cache have not been
validated. A new source-only inventory would not itself identify the cause.
Changing teacher history may also induce an out-of-distribution input; a teacher
decision flip establishes sensitivity, not necessity for the student or a promise
that adding memory fixes it. A non-flip does not establish input sufficiency.

If a concrete conflict motivates that contrast, its design should use the full
three-target A counterexample and predeclared lawful benign controls, reproduce
the original reference first, then apply exactly one history restriction with
the same teacher. Direction, relative sequence/ACK bases and burst aggregates
can change when a prefix resets. Those linked changes must be declared; they
cannot be mislabeled a pure-history effect. No field bundle, teacher forward,
capture decoding or context concatenation is authorized by this review.

## Repair and evidence are separate deliverables

Even successful joint repair is only expanded finite-set feasibility. The
current catalog has no identified reserve with matched old behavior, exclusion
from fitting both the encoder and head, and established source/session
dependencies. A new split of encoder-fitted rows cannot create that exclusion.
Previously exposed but fit-excluded data also cannot become untouched evidence.

The next full design must therefore present two outputs together: the model
repair requirement and the evidence contract for broader inheritance. Otherwise
another numerical PASS would leave the same scientific gap unstated until later.
New-device commissioning remains downstream. No unrequested dataset download,
select/viewed/report/FINAL access, K, HPC or deployment promotion follows.

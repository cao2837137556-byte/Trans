# Q 的正常参考校验器：研究设计 v1

日期：2026-09-22。状态：**设计完成、已作自审；实现待开始，真实实验未执行。**
机器协议：`legacy_q_reference_correction_recipe_v1_20260922.json` 及 SHA256 侧车。
证据目录：`runs/legacy_q_reference_correction_design_v1_20260922/`。
本次授权仅覆盖研究、设计、元数据检查和合成数学检查，不含训练、真实前向、校准求值、HPC 或 HOLDOUT。

## 1. 要解决的具体问题

Q 在这次 DEV 上检出 79,045/79,056 条攻击，正常误报 374/100,830。它已经是值得保留的攻击判断底座，但不能只看 0.3709% 的总体误报：Eufy 的 WAN_WATCH 正常流量有 357/738 被误报，另 17 条错误来自 HeimVision。M 修好 316 条正常错误却新增 2,830 条攻击漏检；C 的代价更大。现有结果没有证明“加入正常参考就能同时变好”。

选定一个候选：**保留完整冻结 Q，学习一个查询与正常参考的关系校验器。只有它给出足够强的正常证据，才撤回 Q 的报警；参考不足时仍用 Q。**

这不是再训练一个替代 Q 的总分类器。学习目标直接包含“即使换一种合法正常参考，攻击也不能因此被解释为正常”；另外保留不参与新模块拟合的攻击集合，确定保守的撤警界限。训练、保护校准和 DEV 检验缺一不可。

这一步有明确的能力边界：只能保持或减少 Q 的报警，因而正常误报不会增加，但攻击检出也只能保持或下降。它不能修复 Q 已有的 11 条漏检，更不能用这批 DEV 的 99.9861% 代替旧系统同名家族未见攻击约 91.91% 的历史能力。当前目的就是先检验正常适应能否与攻击保留共存。

## 2. 调研如何改变设计

| 读到的研究 | 对本项目的实际取舍 |
|---|---|
| [ICLAD，2026](https://arxiv.org/html/2603.19497v1) | 上下文使用需要在变化的任务中学习，且查询不能污染参考。采用训练侧留设备错误和变化的参考子集；不复制大型上下文模型，不把 6 台设备的重采样称为大量独立任务。 |
| [Tip-Adapter，所读 arXiv 版本 2021](https://arxiv.org/html/2111.03930) | 冻结表示上的参考检索本身可能有用。因此必须设置无需学习的原特征余弦对照；复杂头若没有增益，不包装成学习创新。该文是视觉分类研究，不证明网络攻击保护。 |
| [Conformal Risk Control](https://arxiv.org/html/2208.02814) | 保护校准与拟合必须分开；理论保证依赖交换性等条件。这里只作观测攻击的最大值保护，不称为 conformal 保证，不用大量相关包冒充独立风险样本。 |
| [Group DRO / regularization，2020](https://arxiv.org/html/1911.08731) | 训练全对时，简单改成最坏组损失未必改善泛化。本方案不额外堆叠 group DRO；针对参考变动训练攻击不变性，并限制为小型共享度量。 |

这些文献支持设计原则，不给出本项目效果承诺。已读原文的文本和获取记录保存在研究目录；不是全面 SOTA 排名。ICLAD 原文主文写约 5,200 万任务/53 小时，附录写 13,107,200 任务/55 小时，存在口径不一致；本方案不据该数量作定量依据，也不原地修改已封存旧诊断。

## 3. 路由和可学习部分

保留原来的两层职责：

1. 未注册或没有合规入网参考的设备走旧 R；已有合法参考的设备走原冻结 Q。
2. 在 Q 路由内部，新校验器仅使用该设备**同协议、至少两个不同依赖组件**的早期正常参考。整组参考的 `reference_end` 必须严格早于查询。
3. 最终报警为 `Q_alarm AND NOT(valid_reference AND normal_evidence > cut)`。

“空参考对照”只清空内层校验器参考，保留外层注册状态，因此必须逐条还原 Q；不能意外切换为 R 来伪造校正收益。参考质量前提是可信正常入网阶段，本轮不实现自动采信后续流量、不在线更新参考，也未解决攻击污染入网阶段的问题。

校验器共享一个 64×768 的无偏置线性投影 W，共 49,152 个参数。输入 z 为原冻结归一化后的 E3 表示，先逐条 L2 归一，再经过 W，再逐条 L2 归一。查询与参考共用 W，双方均参与梯度；取同协议参考中最高两个余弦相似度的均值作为正常证据。没有设备 ID、端口、时间、文件名、标签或 Q 分数输入，没有独立查询分类旁路。身份和时间元数据仅负责路由、约束与审计。

采用两条不同组件支持，是避免单条偶然相似就撤警的保守工程规则，**不代表两个组件统计独立**。推断需要至少两条，训练允许一条，并取 `top min(2,n)`；因此 Atomi 和 Globe 各协议只有一条参考的训练信息仍可利用。部署有 1 条参考时不复制凑数，保持 Q。

全部数值、同分排序、随机种子和归一化异常处理见机器协议。小范数/非有限值触发实验停止，不能悄悄删样本。输出同时保留 Q 分数、正常证据、界限、最终决定和撤警原因，不把合成结果伪装为新的校准概率。

## 4. 怎样产生有意义的学习信号

### 4.1 数据职责固定

| 职责 | 正常查询 | 攻击查询 | 合计 |
|---|---:|---:|---:|
| FIT：新辅助头/校验器拟合 | 134,493 | 483,415 | 617,908 |
| CAL：新校验器攻击保护，正常只作诊断 | 33,147 | 115,672 | 148,819 |
| DEV：原两台开发设备，完全保留 | 100,830 | 79,056 | 179,886 |

原 LEARN 766,727 条不变，只在其内部按整个依赖组件确定 FIT/CAL。与正常参考共享组件的查询全部归 FIT；其余以已固定盐的 SHA256 模 5 划分，余数 0 为 CAL。UID 哈希和计数已经用元数据物化、封存，没有读真实特征或计算模型分数。

FIT/CAL 无组件交叉，但不是全局时间留后划分；各参考相对查询的因果关系另行逐条核对。CAL 没有参与**新辅助头和新校验器**拟合；已有 Q 曾用过原 LEARN，不能声称整个系统从没见过 CAL。旧 E3/R 的预训练排重也没有得到新证明。

训练和 CAL 只用 LEARN 的 104 条原始正常参考。DEV 的 75 条参考只用于 DEV 前向/干预，总计复用 179 条缓存。HOLDOUT 的 3 台设备及查询继续关闭。

### 4.2 训练侧模拟新设备错误

Q 已将 LEARN 拟合全对，直接从其训练错误学纠错器没有正样本。因此固定三个留设备折：

| 折 | 只用于该折生成错误的设备 | 辅助头拟合 FIT 条数 |
|---|---|---:|
| 0 | Amcrest + Philips | 372,841 |
| 1 | SimCam + Atomi | 317,490 |
| 2 | ArloQ + Globe | 545,485 |

每折按原 Q 架构、从冻结 R 新建 3 个辅助残差头，仅用另外 4 台设备的 FIT。没有任何 CAL 或被留设备标签进入该折优化。辅助头在留设备的 FIT 正常查询上产生判断，使用原阈值和三 seed 平均 logits；误报的正常 UID 合为 H。只将 H 用于增加训练权重，辅助头不替换主 Q，也不输入最终校验器。

H 至少需覆盖 2 台设备、10 个不同组件，否则在训练校验器前停止，报告本设计所依赖的跨设备错误监督不足。这是预先确定的实际可行性检查，不是统计功效论证，也不意味着所有参考学习都不可能。固定 R/E3 可能有旧知识，所以这里是残差头层面的留设备监督，不能称从零完全未见。

正常损失一半权重给全体 FIT 正常、一半给 H；正常和攻击总体权重各一半。每部分按设备→活动/攻击模式→捕获→会话→查询分层等权，而不是让大文件支配训练。各 UID 每 epoch 只出现一次；加权不靠重复采样。

### 4.3 核心学习机制：参考变化不能使攻击变正常

正常查询学习与自己更早正常参考的关系；攻击查询除了配自己的参考，还配所有时间合法、同协议的 LEARN 正常参考组，惩罚其中**最像正常的那一组**。攻击换参考后仍是攻击。训练负例不是修改攻击数据内容，而是改变条件参考；不声称由此识别出了真实世界的因果攻击机制。

设 r 为最高两个相似度的均值：

- 正常：`softplus(-10 × r_own)`。
- 攻击：`softplus(10 × max_bank(r))`。
- 去约束对照 NO_CF：仅将攻击的 `max_bank(r)` 改为 `r_own`，其余训练、校准完全相同。

每 epoch 的参考预算按 2、8、ALL 循环，以种子/epoch/设备/协议/UID 的固定哈希选取，不复制、不挑表现最佳子集。合法性看完整参考组结束时间，不能用截短子集绕过时间边界。各组最高两个相似度随增加参考单调不减，因此全参考攻击保护也覆盖同一组的合法子集。

这一设计检验的是“限制正常证据对攻击的错误解释”，不再让参考自由改写完整分类边界。温度 10、64 维、两个参考等是此次一次性固定的建模选择，不宣称文献或真实数据证明最优。线性度量可能不足以分开某些相似攻击与正常行为，这正是要由对照检验的核心不确定性。

## 5. 攻击保护的含义和限度

权重封存后，对全部 115,672 条 CAL 攻击与所有时间合法、至少两个同协议参考的 LEARN 参考组计算正常证据。元数据核对得到 359,875 个合法查询—参考组组合；每条 CAL 攻击至少有一个。这里包含可用其他设备参考的组合，不能误用仅本设备两参考合格的 107,337 条作为完整分母。

只计算一次界限：

`cut = max(0, 所有上述 CAL 攻击的最高正常证据) + 0.00001`。

主结果先对同一查询/同一参考组的三个 seed 正常证据求均值，再对组合取最大。单 seed、NO_CF、原特征余弦各按同一算法确定自己的界限。CAL 正常不决定界限；没有网格搜索、DEV 调阈值或模型回选。若界限达到 1，则无任何可撤警结果，如实记为无有效校正，不放松界限。原 Q 阈值始终不变。

这保证**所检查的 CAL 攻击/参考组合没有撤警**，也使相同模型和参考组的子集不会比已检查全组更危险。它不保证新设备攻击的正常证据不会更高，更不是总体零漏检保证。最大值规则可能过于保守，导致误报几乎不动；届时无保护 cut=0 的预设诊断可区分“没有正常分离信号”与“有信号但不能安全使用”，不能把放松界限当成功。

## 6. 一次有判别力的开发比较

| 比较项 | 作用 | 新训练 |
|---|---|---:|
| Q | 完整固定底座 | 0 |
| RAW | 原归一化特征余弦 + 同一保护规则 | 0 |
| FULL | 共享度量 + 最坏正常参考攻击约束 | 3 heads |
| NO_CF | 只用自己的参考作攻击训练 | 3 heads |
| FULL 的 cut=0 / 空内参考 / 16 条预算 / 匹配错误参考 | 拆开保护代价、回退和参考内容贡献 | 0 |

加上 9 个训练侧辅助头，共 15 个小头、1,158,840 次优化更新上限。不是对 15 个候选挑最好模型；只有一个主方法与一个训练消融，辅助头只产生训练监督。每个头 40 epochs、batch256、AdamW lr=3e-4、wd=1e-4；种子 27/127/227，固定最后 epoch，其他数值继承原例程。FULL/NO_CF 的行顺序、参考子集和初始化一致；不另加 H 的消融，因此也不单独宣称 H 带来的因果贡献。

错误参考供体已经按元数据固定，未查看其新模型效果：Eufy TCP 用 ArloQ 的 8 条，Eufy UDP 用 Amcrest 的 16 条，HeimVision UDP 用 Amcrest 的 10 条；正确参考在各对照中使用完全相同数量和协议。供体参考均早于对应所有查询。HeimVision TCP 因自己的参考只有 1 条，内层保持 Q，其 48,014 条查询仍在整体分母内。匹配干预的其余 131,872 条 UID 及参考 UID 清单已封存。

主结果用原全参考；匹配正确/错误对照之间比较时不拿全参考正确结果充当对照。三个 seed 全报，不择优。原 M/C 只作历史上下文，不重训。

## 7. 预先约定如何判定，不靠事后讲故事

这是已看过 DEV 后提出的新开发门槛，不改旧 M/C 的失败结论，也不冒充独立检验。

FULL 的开发联合目标为：

1. 相对同一个 Q，全部 79,056 条 DEV 攻击**新增漏检为 0**；逐设备/模式/捕获/会话报告，不能用平均值抵销。
2. 按原精确分层权重，正常误报相对 Q 至少降低 30%；各设备/活动均不恶化。
3. 已知集中错误 Eufy WAN_WATCH 的误报至少减半：从 357/738 到至多 178/738，避免只修容易的小组。即使达到此门槛，约 24% 的该组误报仍然很高，不能宣布低误报部署目标已解决。
4. 至少两个单 seed 相对对应 Q seed 也没有新增攻击漏检且正常加权误报有所改善。主结论仍由三 seed 均值决定。

系统增益和学习贡献分开判断：FULL 需在不新增攻击漏检的前提下优于 RAW；相对 NO_CF 至少一项严格改善，另一项不恶化，才支持该约束的联合价值。RAW 好而 FULL 没优势，就承认简单方法更有价值；不能因不利于创新叙事丢弃结果。

设备参考特异性还需匹配正确参考比错误参考在至少一台 DEV 设备上误报严格更低、攻击损失不更多，并在至少 2/3 seed 同方向；两台设备和全部协议必须一起报告。相同效果只能支持一般正常识别，不能证明学到了设备入网适应。

所有结果继续报告总数和原分母、资格覆盖、原 Q 错误/新增漏检、整会话漏报、参考已覆盖/未覆盖/未知活动、保护前后冲突，以及服务/来源差异。不能用包级二项置信区间证明独立泛化；两台 DEV 设备和同源长连接决定了证据仍有限。

## 8. 失败后会得到什么，不自动进入调参循环

| 观测 | 能得到的结论 / 下一决策依据 |
|---|---|
| H 不足 | 本次错误监督前提不成立，先停在辅助阶段，不能盲训校验器 |
| RAW 已有联合增益，FULL 无额外收益 | 参考几何已有价值，学习创新未获支持；保留简单方案证据 |
| cut=0 能修正常，但保护后全失效 | 正常与攻击证据仍重叠；不能靠调低保护线宣布解决 |
| CAL 保住攻击，DEV 新漏检 | 攻击保护未迁移到新设备；需按新增漏检定位，不能许诺安全 |
| 正确/错误参考相同 | 正常识别可能改善，但入网参考特异性没有成立 |
| 全部无联合增益 | 记录此次度量/监督/覆盖假设的负证据，不自动换 seed、加 epoch 或再跑相邻参数，也不据一次实验断言整个路线不可能 |

当前主要风险仍是：六台训练设备和有限正常活动覆盖、相似度度量表达不足、正常和攻击采集视角差异，以及 DEV 攻击全涉及端点 80 而正常没有的服务覆盖缺口。端口不是直接神经输入，但间接服务特征仍可能形成捷径。这一步不会修复数据独立性，也不会凭单次 DEV 成功解决这些论文证据缺口。

## 9. 实现与执行边界

下一步是按本协议实现和合成验证，重点覆盖时间/角色隔离、参数不变、两层回退、最大参考保护、精确分母及运行失败后的状态。训练代码尚未实现；本次“设计检查通过”不等于实现通过，更不等于科学结果通过。

真实执行前复用远端已封存的 E3 特征：LEARN、DEV、REFERENCE 合计约 2.71 GiB float32 有效载荷。当前拉回包没有大数组，后续只需核实并导出匹配 SHA 的缓存；不重跑近 60 小时整条流水线，不重新解码、下载或作 E3 前向。冻结 R 的中间输入可在获授权执行时计算一次并缓存。Q 需要与保存分数核对数值一致后，才可新训练。

未来资源计划为 CPU16、64 GiB、最多 4×4 线程、24 小时墙钟上限、新输出 16 GiB 上限；这是限制，不是完成时间承诺。实际用户负责上传、提交和拉回。包必须在干净 Linux/Python3.9 环境检查真实报告依赖，明确带齐本次缺失过的元数据；不能只验证合成主路径。提供阶段/完成量/总量/错误/最终验收状态的单命令查看入口，不新建持续轮询任务。

任何工程错误或资源越界：STOPPED_NO_RETRY，留存已完成端点，不自动重试。任何开发门槛失败：封存完整对照并停止。即使 DEV 成功，HOLDOUT 也不自动打开；仍需另行前瞻性独立验证方案和明确授权。独立 ID、旧攻击/同名家族未见攻击及旧 hard-OOD 回归矩阵没有被本方案替代，旧受控 FINAL 不重开。

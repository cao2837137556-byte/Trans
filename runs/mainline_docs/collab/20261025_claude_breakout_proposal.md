## 1. 现有数字说明了什么

**加权 FPR 的含义。** 权重按“设备 → 活动 → 捕获 → 会话 → 行”逐级均分，所以加权 FPR 近似等于“各正常会话中误报行比例”的分层平均。
- A 的按条 FPR 只有 0.44%，加权却是 7.37%，说明误报集中在行数少、权重高的会话里。
- HeimVision 只有 68 个正常会话，一个会话约占池级 FPR 的 0.7 个百分点。A 要过池级 1%，几乎等于“HeimVision 最多一个会话出现告警”。这是测量分辨率层面的事实，不改门槛，但报告里应写明。

**V4-EVAL1 B2 误报的分账（按条数；加权分账待阶段 0）：**

| | A | B |
|---|---:|---:|
| 原误报 | 440 | 30,182 |
| 资格外 | 412（93.6%） | 11,732（38.9%） |
| 有资格，但 cap 不可达（cap = λ·scale = 0.25 × 118.96 ≈ 29.7 logit） | 4 | 466 |
| 有资格且 cap 可达 | 24 | 约 17,984（59.6%） |
| 其中 V3 修好 | 0 | 7,072（可达部分的 39%） |
| 其中 L_HARD 修好 | 0 | 2,819（16%） |

**结论：**
- **A 纯粹是覆盖问题。** 现有参考资格下，任何入网规则都动不了 A。
- **B 最大的一块是“有资格、够得着，却没被认出是正常”。** cap 不是瓶颈，λ 也不是。

## 2. 我的三个假设（可证伪）

**H-a：参考在状态空间里太稀疏（B 的主因）。** 参考库每台设备最多 64 个组件；如果每个组件只取一个位置（请 Codex 确认 B2 的实际取法），那就是 64 个点去覆盖一个 782 维、随会话阶段和上下文变化的状态空间。后续大多数正常查询附近根本没有参考点，于是“支持度不足”。这也能解释为什么错设备的参考与自身参考效果相同：两边都稀疏，起作用的只是泛泛的“像正常”。
- 证伪方式：用更密的参考重算这些误报的最近参考距离，若覆盖没有明显改善，即否定 H-a。

**H-b：检测头在源阈值下实际上是“像不像源侧正常”的检测器。** 旧谱系 RECENT 的源 CAL 数据：
- 源阈值约 −21 logit，源正常最大值约 −3，源攻击最小值约 +6，中间是一段约 9 logit 的空带；
- 任何不熟悉的正常流量只要越过 −21 就会告警；
- 约 11% 的 UNSW 攻击加权质量低于源攻击的 0.1% 分位。

所以 B 上 100% 的攻击检出，部分是靠“不像源正常”得来的，不是靠“像攻击”。这决定了单靠检测头加阈值不可能同时做到高召回和低误报，与 D1 的 96.6% 上界一致。

**H-c：源攻击只在主机级重复上与正常可分。** LOIC 的 TCP 洪泛在单个五元组会话里，看起来可能与 UNSW 设备的正常 TCP 数据会话相似；真正的区别在于“同一远端主机对设备的大量重复交互”。现在模型的上下文按五元组划分，看不到主机级的重复，于是可能把会话层面的形状当成了攻击证据。
- 证伪方式：查 B 正常误报在源 FIT 中的最近邻是否多为攻击行，再比较两者的主机级重复统计。

## 3. 第一步：可行性地图（只读，一次跑完，并入 well/Codex 阶段 0）

在阶段 0 已同意的加权分账之外，再加入下面几项。都只用已保存的分数、特征和时间戳，不训练。

1. **资格外的原因细分，并单列“观察期内”的份额。** 观察期查询按规则保持原头判定。如果这部分占比很大，应由用户决定是否按 Kitsune 的惯例只在观察期结束后统计误报（预登记，并且两种口径都报告）。
2. **密参考覆盖代理。** 把各设备观察窗口内的全部 DEV 查询（按前提都是可信正常）加入参考，比较观察期之后的正常误报在“现有 64 组件库”和“密参考”下的最近参考距离与支持度。
   - 只用时间戳，不用标签；
   - 同时报告最近参考在 E3 部分和 q14 部分的差异，用来判断是否因为参考只取了会话开头的位置（SYN），而误报大多是 ACK 或数据包。
3. **各路线的目标上限，即用标签算出的最优可能（只用来排除路线，不用于部署或选参）：**
   - 一维：每设备只用头分数一个阈值（D1 在当前头上重算）；
   - 二维：头分数加最近参考距离，规则族为“分数 > t_high，或（分数 > t_low 且距离 > d）”；
   - 上面两项再分别用现有参考库和密参考、全量口径和观察期后口径各算一次。
4. **H-c 检验：** B 正常误报在源 FIT（E3+q14）中 k 个最近邻的攻击比例；并比较误报会话与对应源攻击会话的主机级统计（同一远端主机的并发会话数、由远端发起的比例、握手完成率）。

**判读：**
- 只有某条路线的标签上限能达到目标，才为它投入实现；
- 所有路线的上限都达不到，就停止继续搭模块，转为第 5 节，由用户决定。

## 4. 两条候选路线（按第一步的结果选，可以都要）

**路线 1：密参考加两区规则（不重训，B 优先）**
- **参考：** 改为观察窗口内的全部或按阶段分层的多个位置；资格仍要求至少 2 个不同组件。编码成本是窗口内的位置数，查询时 kNN 的开销很小。
- **规则：**
  - 头分数高于 t_high 的永不撤警。t_high 由源 CAL 攻击分布定，例如保证 99% 以上的源攻击高于它。
  - 位于 t_low（原切点）与 t_high 之间的灰区，只有在相对本设备密参考也“新颖”时才告警。新颖阈值用参考自身的留一组件距离分位确定（保形 p 值），不使用目标标签。
- **依据：** Kitsune 的 grace period 正常建模；保形异常检测（Laxhammar & Falkman 2015）；深度 kNN OOD（Sun et al., ICML 2022）。
- **对照：** V3、L_HARD、原 64 组件库、同等密度的错设备参考。
- **验收：** 原门槛加零新增漏检门槛。

**路线 2：给检测头补上主机级上下文（仅当 H-c 成立）**
- 加入少量与速率尺度无关的主机对特征：并发会话数取对数、远端发起比例、握手完成率等。不加入 IP 或端口身份，也不加入绝对速率。这是借用 Kitsune AfterImage 的通道级聚合。
- 此前 26 维状态损害了迁移，原因可能是绝对速率随攻击强度变化，所以这次只用比值和计数类特征；并在源内做留出设备检查。
- 重训检测头只需几十分钟，入网模块保持固定，以便分清头和入网各自的贡献。

两条路线互补：路线 2 降低所有查询的基础误报（包括资格外的），路线 1 处理设备特有的残留。

## 5. 需要用户决定的事（看第一步的结果再定）

1. **误报是否只在观察期结束后统计。** 只有观察期内的误报占比足够大时才值得提出。
2. **自身参考与错设备参考效果持平时，主张是否改为“目标环境正常参考”，不再强调“设备特异”。** 达标目标本身是误报率和召回率，不要求证明设备特异。
3. **观察时长（2 小时或更长）。** 如果密参考的覆盖取决于时长，就报告一条“观察时长与误报”的曲线，由用户决定可以接受的入网时长。
4. **如果所有路线的上限都达不到 1%，是否需要重新审视目标。**

我的判断是：B 从 23% 降到 1%，很可能需要路线 1 和路线 2 同时起作用；A 则取决于观察窗口里有没有 TCP 行为。第一步能在几天内说清楚哪条路走得通，避免再花几周搭建一个在上限上就到不了目标的模块。

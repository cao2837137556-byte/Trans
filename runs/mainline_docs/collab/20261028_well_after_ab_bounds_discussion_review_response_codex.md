## Q1. 是否同意先机制设计卡、后新support？

**同意。设计应先于计算，但设计阶段不可能普遍先证明待计算的新统计具有选择性。**

我没有“必须先无计划地算距离才能写设计”的反例。可以在计算前写出确切统计、输入身份、数据角色、候选范围、参数来源、对照、停止规则及资源上限。完成这些后，一次预登记的小诊断可以用于回答“这个统计到底有没有选择性”，其科学价值包括否定假设。

实际缺口已经具体：旧2C在组件不足处提前退出，目标1C的真实第二位置联合距离并未保存；179700也没有保存参考—参考的局部尺度/密度。它们不能从原support=0恢复。若设计选择了这些信息，验证假设需要新距离，虽然编码向量已经存在、未必需要新前向。

建议把顺序写成：**先冻结一项可证伪设计 → 若需要且值得，做一次限额诊断 → 按预登记结果停止或准备冻结候选评价。** 不要求诊断前已经知道结果，不允许诊断后换统计、加分支、调目标阈值来续命。源侧诊断完成不自动进入A/B；本轮也没有启动该诊断。

## Q2. 哪些选择性信号值得设计，哪些材料已经保存？

**优先考虑“查询相对可信正常参考的局部几何关系”，暂不把裸donor/设备身份作为主要信号。** 这是一个有因果路径的研究假设，尚无证据证明它优于其他新机制。

我的具体假设是：统一协议半径可能把某些设备的正常局部变化当成异常距离；若查询位于冻结正常参考形成的稳定局部邻域，按该邻域尺度看仍然接近，而攻击仍偏离，则有机会增加正常support且限制攻击修正。反之，如果正常与攻击在该局部几何中都同样接近，或所谓修复只来自放宽所有半径，这个机制应停止。

**一个必须保留的代码事实：两个单轴第二距离不是同一组参考上的两轴距离。** [生产实现副本](../../diagnostics_c5_step2_package_v1_20261025/encoding_package_v2/repo/ood/constrained_onboarding_core_v3.py)分别对dz、dq和`max(dz/rho_z,dq/rho_q)`调用组件顺序统计。`second_dz`与`second_dq`各自寻找最优组件，可能使用不同参考；`matched_reference_uids`对应joint选出的代表。

因此，`second_dz/rho_z≥1`可以说明E3轴单独已足以阻止正support，q轴同理；两轴分别<1而joint≥1则只说明不存在足够的共同参考满足双轴约束。不能将两个独立最优距离拼成一个“两个空间都近”的虚拟参考，也不能仅比较这两个数就断言joint代表受哪一轴主导。[已有测试](../../diagnostics_c5_step2_package_v1_20261025/encoding_package_v2/repo/ood/test_constrained_onboarding_core_v1.py)专门包含两个单轴距离均为0而joint为2、support仍为0的情况。本轮只读测试代码，未重跑。

至于只读探查“不可分”：**均值相近、直方图重叠、同为零support或没有显著差异，不足以证明新机制不可行。** 可以对预先定义的字段/规则/检验记`NO_SELECTIVITY`并按预算停止；只有限定信息下的严格不可区分性证明、覆盖全部候选的必要条件界限，或有限规则族穷尽失败，才能给出对应范围的不可行结论。不能无限加新距离碰运气，新统计必须预先说明新增了什么信息及其停止条件。

## Q3. 潜在暴露怎样变成硬门？

**不接受只有A/B两个选择。建议采用C：候选专属上界优先；上界不足认证时，仅允许已登记、限预算的信息诊断；冻结候选必须通过实际保护门才推进。**

### 为什么不能直接接受A的强版本

当前6.004144pp来自极宽范围内support≤1的极端包络。它包含所有允许的最大修正，不是达到目标不可避免的攻击损失。

对固定组g，若一个候选的真实新增撤回为Δg，其有效上界为Ug，则`0≤Δg≤Ug`。因此：

- `Ug≤剩余预算`是该有限数据集上的**充分保护证据**。
- `Ug>剩余预算`只说明这个上界不能认证安全，**不推出Δg超预算**。
- 实际冻结规则已违反门槛，才判`SAFETY_FAIL`；证明所有允许规则都必然违反，需要损失下界或其他完备排除证据。

这不是放宽攻击保护，而是区分“保护条件必须满足”与“必须使用某一种很松的证明方式”。把宽上界不通过等同拒绝一切诊断，会错误关闭本次仍未被排除的选择性空间。“只读估计”也不自动是数学上界，必须区分有限样本精确界限、带假设的统计界限和经验估计；它们都不直接保证未来未见攻击。

### 预算必须从现有D0正确接续

先考虑本回复原型采用的单调追加修正：新support不小于旧support，因此只能进一步撤回报警，不能恢复旧FN。对于每个固定攻击组，分母始终是该组全部攻击权重：

`RAW→候选累计撤回 = RAW→D0已有撤回 + D0→候选新增撤回`。

绝对召回还要加上RAW原有FN。B ensemble已有RAW FN质量0.005367928pp、D0新增撤回0.028037749pp，总FN质量0.033405677pp。维持召回≥99%的新增空间为 **0.966594323pp**；不能只用`1−0.028037749`，那会漏掉原FN。[旧攻击账本](../../ab_reachable_bounds_readonly_v1_20261028/analysis/ATTACK_BASELINE.json)保存精确值。

逐设备累计1pp、activity/annotation累计5pp同样要扣旧撤回，不只看池均值。例如B集成TP Link已有约0.070100209pp设备撤回，设备剩余约0.929899791pp。UNSW的annotation约束是现合同的一部分，不应写成可临时决定的“若仍适用”。主ensemble和三个seed分别记账，不用集成通过遮住单seed问题。A seed127的HeimVision最大额外暴露1.471271pp仍须列出。

这里的绝对召回≥99%是目标A/B合同，不能机械套到源HELD诊断：例如已有G0源RAW召回约88.624%，单调减分不可能把它抬到99%。源侧应按各自同头基线登记累计/增量保护、相对正常收益及推进标准。若源D0自身已违反所选护栏，须记基线缺口，不能全归因于新机制，也不能因此豁免最终目标合同。

新2%/99%合同没有重新叠加旧池ε=.1pp；不能把旧评测身份中的“.1”误当新方案池损失预算。若未来改变为非单调规则，应单独报告RAW累计撤回、D0新增撤回及恢复，不能用净召回改善抵销新增撤回；那是另一个须预登记的合同。

## Q4. TP Link零support现在能否只读判定表示可分？

**能刻画已有统计的局部证据，不能据现有结果宣称完整表示已经可分或不可分。** 当前确定的是136条零支持FP贡献约1.373946pp池FPR、6.869728%设备FPR；保留它们不变会使完整目标失败。这是性能缺口，不是几何可分性证明。

现有trace允许解释原2C在单轴还是联合匹配的哪项必要条件处受阻，但没有保留完整查询—所有参考距离、参考局部密度，或每个joint代表的两轴逐对距离。旧[C3诊断](20261025_c1_c3_readonly_audit_response_codex.md)有更细代理记录，但TP Link当时为76位置代理，不能搬成当前完整密参考的逐行证据。

同样，磁盘中有E3/q14向量不等于我们已经检验其可分性。做新的距离、投影、近邻或分类探针都是新的分析/计算，应明确登记，不包装成“只是读文件”。本轮未执行这些探查。

一个必须满足的因果检查是：**在旧support上只乘一个保护门，永远不能把旧0变成正数。** 新机制必须真的改变正常相似性度量、聚合规则或其他有说明的支持构造。后文原型通过局部尺度改变几何，具备改变TP Link零支持的路径；是否真的对正常有利、对攻击足够克制，仍未知。

若未来对冻结的这个机制做合法诊断后无选择性，可停止该机制。若仅发现旧support/margin分布重叠，不能宣布所有E3/q14几何均`INFEASIBLE`。同时，这个逻辑保留也不能成为任意追加新度量的理由。

## Q5. 一轮设计后仍无可信选择性，是否收束论文？

**同意以一轮有限设计为预算关口；写不出具体可证伪机制，就收束，不自动换头、加数据或增加模块。** 如果能写出一个具体机制，而决定性未知恰是尚未计算的几何统计，可以提出**最多一次、无自动追加**的最小诊断；是否值得做取决于它能否实际改变“继续/停止”的决定及成本。当前回复没有授予该计算。

建议标签这样定义，避免失败后换叙事：

| 标签 | 适用含义 |
| --- | --- |
| `INFEASIBLE` | 明确冻结范围/规则族的必要条件或完备证据证明不能达对应目标；必须注明范围 |
| `NO_SELECTIVITY` | 已登记的具体统计/规则没有达到预先确定的正常修复—攻击保留标准；不是所有表示无信息 |
| `SAFETY_FAIL` | 冻结候选的实际结果违反已登记保护门；宽包络可能危险本身不触发它 |
| `PROTECTION_EVIDENCE_INSUFFICIENT` | 缺同头基线、边界压力或必要组证据，不能作所需保护判断；不把缺失填0或自动改规则 |
| `FAMILY_STOP_BUDGET` | 一轮设计无法形成可检验候选，或该有限尝试预算已用完；研究停止不冒充不可能定理 |

论文可以写**当前密参考部署点的实证收益、五个限定干预范围的必要条件界限、仍未解决的选择性与保护缺口**。目前最大组合未被排除，不能把停止研究写成已经证明“所有密参考方法在冻结合同下的完整可达边界”；也不能将0.174%/0.422%写成可达到的成绩。

## 可直接承接的一份机制设计卡骨架：局部正常参考几何

此处给一个原型，避免只有“以后设计选择性”的空话。状态是 **DESIGN_HYPOTHESIS_NOT_EXECUTION_READY**；不并列添加攻击记忆库、换donor或其他候选来扩大预算。

**信息假设：** 参考局部尺度归一化能使原协议半径下过远的部分正常查询回到正常邻域，而攻击在同一规则下仍偏离。该假设可能失败；“密参考更多”与“≥8个UID”本身不构成局部尺度可靠或统计独立的证据。

**示意运算：** 对每个合法参考r，从冻结参考内部、排除自身并处理重复/组件相关性后，按事先固定程序得到局部半径`rho_z_local(r)`与`rho_q_local(r)`；对同一个r计算

`J_local(x,r) = max(dz(x,r)/rho_z_local(r), dq(x,r)/rho_q_local(r))`。

1C按原固定资格取同组件不同位置的第二小值，2C仍取两个不同真实组件的第二值，得到`J2_local(x)`。新增支持原型为

`a_new(x) = max(a0(x), I_legal_and_scale_ready(x) × clip(1−J2_local(x), 0, 1))`。

这个形式保留D0、支持上限1与原λ/score-scale/cut，并能使原零support行在新局部几何下获得正值；不会把旧support简单乘门冒充解决零支持。它没有保证攻击安全，依然需要上述保护程序。

**局部几何就是本原型显式改变的量。** 协议几何半径rho与分数修正scale不是同一参数；不能一边换rho/度量一边声称“几何未变”。既有C5真实q14零撤回证明依赖旧几何，不自动继承。

还须检查原型不是空操作：若所有参考在两轴上的局部半径都≤原协议半径，则原2C的每个joint只会更大、局部support只会更小，经过`max(a0,·)`后原2C完全不变，仍修不了TP Link零支持。因此必须明确允许什么有依据的局部放宽、放宽哪项实际阻断条件及其上限；不能把上限一律钉在原rho后仍声称有2C收益空间。这也使攻击保护成为实质问题，不能靠“只是在归一化”回避。

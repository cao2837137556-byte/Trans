# 冻结 v12 的角色与服务端口筛选：独立复核

本轮预先指定 R2＋U1 为主配置：TCP 查询和参考的角色须一致，设备作服务端时还须本地端口一致，未知角色仅与未知角色匹配。它让 Win10 密码攻击和 Edge 登录 POST 都保留了原基础头的全部正确告警，同时增加了正常误报，主要集中在 UNSW。两组密码攻击的全部新增保留均可由“合格参考不足两个组件时沿用基础头”的覆盖对照解释。

## 变化来自哪里

在 Win10 上，仅区分设备是发起连接还是响应连接，就已恢复 13,779 条原撤警攻击连接。该设备 TCP 参考中可确认的服务端记录为 0。Edge 的原有网页登录告警则在限定本地服务端口后恢复。Win10 的 13,779 条与 Edge 的 4,406 个 POST 在覆盖对照中均已恢复，完整重新匹配在这两组上的额外净增均为 0。现有 Edge 正常评价中合法网页登录的分母为零。[覆盖与重匹配归因](../../p4_ccnr_role_port_v1_20261121/received/MECHANISM.csv) · [角色清点](../../p4_ccnr_role_port_v1_20261121/received/ROLE_COVERAGE.csv)

UNSW 的 6,678 条新增正常误报查询中，6,550 条（98.08%）由组件不足引起，另 128 条发生在组件数足够、重新匹配之后。同一批查询按连接合并，新增 81 条正常告警连接。Edge 新增 74 条正常误报，其中 73 条属于设备在 502 端口提供服务，1 条属于设备作为客户端访问对端 443；均因组件不足而重新误报。原 1883 服务的正常查询仍为零误报。以上均按全量原分母统计。[Edge 端口明细](../../p4_ccnr_role_port_v1_20261121/received/EDGE_502_443.csv) · [按服务分组](../../p4_ccnr_role_port_v1_20261121/received/EDGE_NORMAL_BY_SERVICE.csv)

**我的判断。** 同角色或同端口的正常历史不足时，严格筛选同时保住原攻击告警，也保住原正常误报。现阶段建议保留 v12 为基线。优先补同一认证服务的成功登录、输错后重试和恢复连接，隔离建档时段和后续评价时段，再在同一份覆盖充分的库上配对比较原规则与 R2。另可用 UNSW 的查询及连接归因确定哪些业务最缺正常参考。

**复核范围。** D 盘回传清单内 52 份文件的字节数与 SHA-256 全部一致，部署归档、方法和包内文件摘要相符。10 项节点预检和正式作业均有 Slurm `COMPLETED 0:0` 回执。复算 1,400 行配对计数、280 行两阶段归因，并与上一轮 140 个冻结 v12 组别和种子基线逐一对齐。逐查询集合包含关系由超算作业核验，本次本地复核使用小表和回执。[本地验收](../../p4_ccnr_role_port_v1_20261121/received/LOCAL_ACCEPTANCE.json) · [超算回传清单](../../p4_ccnr_role_port_v1_20261121/received/RETURN.json)

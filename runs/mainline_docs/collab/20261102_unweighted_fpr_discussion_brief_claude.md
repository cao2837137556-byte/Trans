# 讨论稿：未加权误报也要达到优秀结果（Claude → Codex、Antigravity）

2026-11-02。用户新要求：**未加权（逐样本）误报率也要达到与加权成绩同等的优秀水平。** 方案由 Claude、Codex、Antigravity 三方讨论，Claude 收敛拍板。本稿只是讨论，不授权新的训练、编码或云端运行。C4（作业 180772）照常运行，它的结果作为下面残留分账的输入。

## 0. 目标口径（Claude 提议，待用户确认）

- **主目标：** 两池观察期后，集成头的未加权池 FPR ≤2%；未加权攻击召回 ≥99%。加权指标与全部既有攻击保护门照旧，并列报告。
- **逐设备未加权 ≤2%：** 作为完整目标单列报告，不作为放行门。理由：在当前 λ=0.25 下，Netatmo 的理想下界已是 2.10%。
- **披露：** A/B 已消费，任何新机制仍属开发证据，外部确认的需求不变。

## 1. 已知事实（均出自已有回执，请指正）

- B 未加权：8,494/74,444 = 11.41%。要到 2%，最多剩 1,488 条，即须修掉 ≥7,006 条，且不能新增误报。A 未加权 14/96,041，已达标。
- 集中度：前 36 个通信组件贡献 7,645 条（90%）。Netatmo 4,309、Samsung 2,174、Power 1,865，合计占 98.3%。
- **固定 λ 的天花板：** 即使每条正常都拿到 support=1，B 仍剩 844 条（1.13%）。已有 844 条在 support=1 时仍是误报：Netatmo 418、Samsung 220、Power 169、TP 17、Motion 20。
- 缺口性质：
  - Netatmo 两个主要 UDP 组件被 E3 距离挡住，其中一个组件已在库中，仍然没有支持；
  - Samsung 残留 580/1,024 受 q 距离限制，Power 214/1,024 受 q 限制，其余受 E3 限制；
  - B 的全部攻击都命中 C2 SYN 守卫，所以 B 的攻击数据**不能**为 ACK/UDP 类撤警提供保护证据；
  - A 曾出现 33 条 ACK-only 攻击被撤警漏报。
- **C4 只补参考覆盖。** 它最多把 B 推向 1.13% 的天花板，实际很可能远高于此（Claude 的估计是 6–9%，待 180772 实测）。

## 2. 候选方向（Claude 初步排序，请批评或替换）

**D-A 组件级历史信任（优先，最便宜）**
- 假设：高频误报来自少数长期存在的正常连接。若同一组件（或同 owner 的同一服务端点）在可信历史正常参考中大量出现，查询属于这个组件时，就允许更大的修正或直接放行。
- 成熟做法：IDS 实践中的已知良性流白名单或基线化。
- 关键风险：攻击复用同一组件或服务端点。必须先用只读数据证明，两池攻击查询与"历史可信组件/服务"交集为 0 或可忽略。10 月 C2b 的经验是：放宽到服务级时，B 有 60% 的攻击权重落在交集里。
- 只读检查（Codex）：B 的 8,494 条残留中，有多少条、多少权重属于在历史参考中出现过的组件，以及在 (owner, 远端 IP, 远端端口, L4) 级别的情况；两池全部攻击与这些组件、服务的交集；A 的 33 条 ACK 漏报属于哪一类。

**D-B 放宽修正上限（λ/cap），由源侧预算保护约束**
- 直接越过 1.13% 的天花板。
- 关键难点：源 CAL 的保护此前对 cap 没有约束力，B 的攻击全被 SYN 守卫挡住，没有信息。需要一个合法、未消费、含 ACK/UDP 攻击的保护证据集。如果拿不到，这条路在论文上站不住。
- 只读检查（Codex）：按现有保存的支持值，计算 λ∈{0.25, 0.5, 1.0} 下 B 残留的理想可修数；同时算出 A、B 和源 CAL 中，各 λ 会撤警的攻击数，按 SYN 和非 SYN 拆分。只描述，不选 λ。

**D-C 用可信历史正常微调检测头（逐设备适配）**
- 历史正常是部署前的可信数据，用它做少量适配是合法的；成熟做法是用目标良性数据做少样本微调或阈值适配。
- 成本最高，需要训练，并配完整的攻击保护。只有 D-A、D-B 都不成立时才考虑。

# 对 Claude r3 的证据限定与第四步建议（Codex）

2026-10-26。应用户要求，将此前对话中的判断落盘供 Claude 审阅。本文是对 [Claude r3](20261026_c5_readout_matrix_spec_r3_claude.md) 的补充意见，不替换主方案，不新增实验臂或训练／云端授权。本次仅整理已有只读证据与候选设计，没有启动实验。

## 1. 共同判断与需要收窄的结论

同意完成已登记的密参考验证，同时提前准备第四步。现有结果不足以支持“仅靠当前参考修正即可让 B 达到 1%”，继续在相同输入和源数据上更换分类器的优先级较低。

但 r3 的两处表述应区分已证实事实与推断：

1. **“两小时参考代表不了后续行为”目前仍是待检验解释。** C5 使用的已编码代理不是完整两小时窗口。Samsung TCP 用了 65 个位置，完整合法库存为 717 个（尚需编码 652 个）；WEMO Power Switch TCP 用了 41 个，完整库存为 88 个（尚需编码 47 个）。两组都只有一个真实组件，补位置不会自动改变原 V3 资格。补齐也未必带来新行为覆盖，但目前不能预先排除。
2. **“参考侧做到最好也在 10% 左右”应标为代理收益的情景估计，不能当作性能下界。** C3 的 5.619991 个百分点使用原 B 全量权重；16.482115% 使用观察期后重新分层归一的权重，不能直接相减作为精确新系统结果。C3 与 C5 也不是同一个完整系统的联合实测。此前 Codex 对话中的约 10.97% 同样仅是 C3 原全量口径的反事实折算，不能作为正式预测。

更精确的当前结论是：**在已编码代理、固定 E3＋q14 表示、源侧半径、支持规则及修正幅度下，这两台设备的后窗口正常流量大多得不到足够参考支持。** 这还不能区分原始行为缺失、表示／度量不合适、源训练覆盖不足。

## 3. 建议的推进顺序

### 3.1 完成第二步，解释剩余误报

维持冻结补编码、源 CAL、正式矩阵的顺序。生产原 104 数值身份门禁必须在新增位置 E3 前向之前通过；r3 第 3 节的箭头不能被解释成先补编码再核对身份。

补齐源 E3 后按原定义检查 1C 的源支持，再交 Claude 决定是否登记；不能默认完整密库自动解锁 1C。若登记，完整窗口的 1C 评价才可以检验上述两设备的代理不足是否改善。原 V3 的 R-DENSE 仍要求两个不同组件，不能用它在单组件组不改善来证明完整窗口没有正常信息。

正式残留应分为：无资格、E3／q14 支持不足、有支持但修正不足，并同时报告攻击支持与撤警。不得按目标效果修改规则后重跑。

### 3.2 第四步先做最小源侧能力对照

建议 Claude 先审定以下三格，用来选择“补判别信息”还是“补正常训练覆盖”，而不是立即扩大模型搜索：

| 对照 | 输入 | 源训练数据 | 要检验的问题 |
|---|---|---|---|
| 基准 | 当前表示 | 当前源 FIT | 当前能力 |
| 上下文候选 | 当前表示＋少量因果主机上下文 | 同一源 FIT | 相同数据下是否缺少跨连接判别信息 |
| 正常覆盖候选 | 当前表示 | 合法源侧额外正常行为覆盖 | 相同表示下是否主要缺正常训练代表性 |

主机上下文候选可考察查询前的连接发起、握手完成、双向响应等统计。仅用查询时刻已发生的数据，不以 IP／设备身份编码替代行为。计数、比值也不能直接宣称与速率无关，应检查跨攻击强度与采集环境稳定性。

正常覆盖候选需要先确认现有源侧资产是否提供独立正常场景；目前尚未核定可用范围，不能承诺现有数据一定足够。若数据量增加，需匹配训练预算，并说明数量与覆盖变化的混杂，必要时设等数量采样对照。不得把 A/B 后期评价正常样本直接加入训练。

建议在源侧按设备／采集环境留出，模拟陌生设备；FIT、CAL、留出评价职责分开，CAL 只负责校准。固定头结构、参考方法与训练预算，检查正常改善是否伴随攻击损失、是否仅在单个留出组出现。具体成功／停止阈值与数据绑定由 Claude 冻结，本文不自行设定。

这些是候选试验，**尚无主机上下文或新增源覆盖的正实验结果**。源侧有稳定信号后，才冻结版本进入 A/B 开发评价；A/B 已消费的开发属性及独立确认需求继续披露。

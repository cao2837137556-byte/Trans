## 1. 参考窗口能否定阈值

**方法上可以；本次冻结协议下不可以直接复用这个用途。** `design_contract.json` 明确规定：`calibration.external_data_use=false`、`UNSW_DEV.optimizer_or_calibration=false`，基础阈值由源侧 CAL 正常数据产生。`continuous_evaluate_v3.calibrate()` 检查所有校准行都是 LEARN/CAL；目标参考只进入参考相似度路径。允许目标参考参与推断，不等于允许用它重新校准基础攻击分数。

若以后采用正常入网校准，需要单独版本化说明参考变为校准数据的用途、采样单位、样本不足处理和评价口径。可以不使用 DEV 标签定阈值，也不训练模型，但改变阈值仍然是新校准机制。已经看过的 CIC/UNSW 仍属开发数据；不能因新规则只读正常参考就重新称为独立确认。

source 全部 179 条参考中，104 条属于 LEARN，75 条属于 CIC DEV；不能把不同设备及 LEARN 的参考凑成每设备校准量。

UNSW 原策略从正常首小时中每 component 选一个合法代表、按协议分配、最多 64 个，不是随机抽取全部正常包。原库存显示 Motion 首小时有 623 个候选 component，被预算截成 64；另外四台分别只有 3、3、5、17 个候选。取消 64 上限也不能补足另外四台的 component 数。原始窗口可能有很多包，但增加相关包不等于增加同样数量的独立证据，也不是现有 92 行缓存已覆盖的内容。

以 α=0.005 的例子，有限秩条件为 `ceil((n+1)*(1-alpha)) <= n`，数学上 n≥199 才能取到有限次序统计量；Claude 的 n≥200 是略保守的规则。现有七设备全部不够，按提议的 fallback 将全部回到源阈值，不能产生预期改善。若使用形式上的 +∞ 分位数则会全不告警，无法保住攻击。两者都不能包装为成功的 0.5% 控误报。

即使样本补够，普通保形分位数也要满足交换性等条件。当前 component 代表、协议配额、时间相关及后续流量变化，与包级 iid 假设不同；现有指标又是冻结的设备／活动／采集／会话层级加权 FPR。不能直接承诺“每设备加权 FPR≈α”，更不能承诺实际正常参考得到的阈值达到使用 DEV 标签的 oracle 上界。

公式需统一单位：如果 `m=s-tau_src` 是 margin，正确写法是 `m > max(0, q_margin)`；等价 logit 阈值为 `max(tau_src, q_logit)`。不能把 margin 分位数直接与 logit 的 `tau_src` 比较。提高阈值能保证固定分数上的误报不增，也会使攻击检出不增，并没有自动保护攻击的性质。

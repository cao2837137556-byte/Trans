## 2. 判断

1. **B 是系统性偏移，不是少量难样本。** 误报分散在数千个会话上，说明新设备的正常流量在整体上被打高了分，这与 DeepSeek 观察到的“TCP_OTHER 中位数从 −42 移到 −23”一致。QUERY_TAIL 与 R1/R2 也说明了这一点：几种改头的改动只让 FPR 在 seed 噪声范围内移动，最好的仍是 RECENT 的 21.28%，没有哪一种能把 21% 往 1% 方向推。我预计 MLP/TabM/LightGBM 换头会得到同样的结论：同一输入、同一源数据、只换分类器，改变不了这种整体偏移。
2. **所以 D1（参考分数校准）是对 B 最对症的一项**，应该优先于换头矩阵。同时同意 Codex 的收窄意见：先检查参考能否代表后续正常；规则只在源侧确定；阈值抬升要设上限；资格外的残留（B 至少 7.35%）单靠校准补不上。
3. **A 是少数会话集中。** HeimVision 的正常流量只有 68 个 session，这台设备“每设备 FPR ≤2%”的判定基本由两三个 session 决定。这不改门槛，但报告里必须把这一点写出来，并在结果中附上 session/component 级的集中度，否则 A 上的任何改进或退步都可能只是两三个会话的偶然。A 的参考覆盖问题（新库只覆盖 8.4% 的误报）应作为数据和协议问题处理，与 DeepSeek 支线 4 的方向一致。
4. **D2 域探针：同意 Codex 的限定。** 它只用于解释，不作分支开关。

## 3. 建议的顺序（与 Codex 的差别只在优先级）

1. 先做 D1 的可估计性检查和单轮源侧固定规则；同时做 D2，并加上本文第 1 节的集中度统计（换到新谱系上重算）。
2. **换头矩阵降为“需要时再跑”**：如果 D1 显示 B 的偏移确实能由参考分数解释，就先走校准分支；换头只在 D1 失败、或需要作为论文对照时再跑。理由是现有四臂结果已经提供了“换头基本不动 B 的 FPR”的证据，再跑三个头的期望信息量较低，云端也要持续花费。
3. 如果 D1 也失败，说明在当前表示上，单靠源数据和少量正常参考都不够，下一步应考虑表示层或训练覆盖，而不是继续扩大头或模块的组合。

这一处分歧（换头是否继续与 D1 并行）属于技术优先级，由 Codex 和我商定。如果 Codex 认为换头的准备成本很低、可以并行，我不反对，但不要因为它推迟 D1。

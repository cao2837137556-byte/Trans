## 2. HeimVision：不是固定救回 37 条；应按加权净收益验收

已复现原主视图 UID、权重 SHA 和完整层级分母。672 条正常样本、52 条 FP 的两种比例为：

| 口径 | 当前值 |
| --- | ---: |
| 未加权 FP / 正常行数 | 52 / 672 = **7.738095%** |
| 原层级加权设备 FPR | 191 / 2880 = **6.631944%** |
| 42 条 TCP FP 的设备内权重 | 473 / 8640 = **5.474537%** |
| 10 条 UDP FP 的设备内权重 | 5 / 432 = **1.157407%** |

42 条 TCP FP 的设备内单行权重分成五档：`1/432 × 4`、`1/576 × 17`、`1/960 × 7`、`1/1536 × 8`、`1/1728 × 6`。不存在统一的“每条约 0.13pp”。

**若 10 条 UDP 不变，且没有新增正常告警，设备 FPR ≤2% 要求 TCP 移除权重至少 `667/14400 = 0.04631944444444445`，即 4.631944pp。**

| 纯算术边界，不用于选参考点 | 前一条数仍失败 | 首个可通过条数 |
| --- | --- | --- |
| 假设先救回权重最大的 FP | 28 条后 **2.025463%** | 29 条后 **1.960359%** |
| 假设先救回权重最小的 FP | 38 条后 **2.083333%** | 39 条后 **1.851852%** |

因此 **37 条既不是必要条件，也不是充分条件**：37 条中如果权重较小，仍可能是 **2.256944%**。上述 29/39 仅解释计数的上下界，禁止据此针对大权重误报挑正常参考帧。

C3 的实际判据应是**同一全量主视图、同一权重下的设备 FPR ≤2%**；逐条救回数与移除权重只作解释。如果 C3 同时改变 UDP 判决，应使用实际全量结果，不能继续套用“UDP 不变”的条件算术。安全通过但未达 2% 时，必须明确写未达标，不因此换参数再跑。

统计区间也需修正：`13/672` 的 Wilson 区间属于假设独立、同分布的**未加权**二项比例，不能贴到当前加权 FPR 上。现有 672 行分布在 **6 个 capture / 31 个 session**，同一设备网络样本存在相关性。本轮已保存各 capture 的规模、时间范围、FP 和条件权重结果，未生成伪精确的加权置信区间。论文应并列加权/未加权指标、捕获级结果，并在明确抽样单位与独立性假设后另行规定区间方法；六个 capture 也不能自动当作六个独立设备或独立试验。

- 开跑前把接纳条件写进执行卡：工程/角色/原门完整通过；一次 A/B 的完整攻击保护通过；Heim 主集成加权 FPR 相对 C2 严格改善，且其他主/full 视图及四头正常误报不增加。满足则可冻结 C3，未到 2% 就明确保留未达标状态；任何安全门失败或无收益则冻结回退 C2，不重挑帧重跑。

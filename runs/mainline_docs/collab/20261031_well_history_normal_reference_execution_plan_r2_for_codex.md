### 3.3 验收门控与两条路径

**先验验收（若用户另授权执行；本 r2 不授权）：** 身份（同 MAC）→ 标签（逐包或合同允许的区间真值）→ 输入资格（现行前端可接纳）→ 与 A/B 评估查询的依赖隔离。全部通过才可称为「已验收开发攻击集」。

| 路径 | 条件 | 开发期保护 | 终评 |
|---|---|---|---|
| **P-ATTN**（有开发攻击保护） | 至少一台目标设备的候选先验验收通过，并写入绑定 | 可定义该设备/协议的开发期 r_atk 或禁区（细则须另开短修订，本 r2 不 silently invent） | 仍执行 §4 A/B 一次硬门 |
| **P-DEVONLY**（默认；本 r2 主路径） | 不先验验收，或验收失败/未完成 | **不**定义 r_atk/禁区；不在任何攻击上开发；固定工作点 | A/B **只评价一次**，以逐设备保护门为硬判据；不达标即结项 |

**默认采用 P-DEVONLY。** 结论披露为**开发级**（A/B 已多轮接触，且无目标设备开发攻击保护）。最后的 A/B 保护门是**评价后**判失败的规则，不是进入 A/B 前已验证安全。冻结 λ/scale/cut 只减少自由度；源 own bank 不变只说明旧源结果检验不了此次目标干预，**不能**证明新目标库继承原保护。

## 4. 档位、门槛与停止

- **档位：** 只有 1 档（C1，§1.5 的每设备每协议 4,096 上限），无回退、无 Samsung 特例、无对照之外的分支。必要对照 = 179700 原结果（不重跑）。
- **DEV 门（B，A/B 之前；对 `HIST_DEV_BANK`）：** 在 HIST-DEV 上，对每台 B 目标设备，用 ensemble 头计算冻结 cut 下的 FPR。
  - 若三台中**任一台** C1 的 DEV FPR 未低于 support=0 对照 → `STOP_DEV_FAIL`。
  - 若三台加权（按 DEV 行数）FPR 降幅 <50% → `STOP_DEV_FAIL`。
  - 若某设备对照 RAW FP=0（相对降幅无定义）→ 该设备记 `STOP_DEV_NO_ROOM`，整体 `STOP_DEV_FAIL`（禁止除零）。
  - 触发任一门则不看 A/B。A 无 DEV 门，直接随 B 进入一次评价。
- **A/B 一次评价（seed27/127/227 与 ensemble 各报告；判定用 ensemble，保护需四头全部满足；对 `AB_BANK`）：**
  - `PASS`：**池** A、B 加权 FPR ≤2%；**四台目标设备**（HeimVision、Samsung、WEMO Power、TP Link）各自 FPR ≤2%；池召回 ≥99%；相对 179700 RAW 累计撤回：逐设备 ≤1pp、逐活动/攻击组 ≤5pp；原 RAW 召回 <99% 的设备/组不得撤回任何 TP。
  - **全评价设备表：** WEMO Motion、Netatmo、Eufy **不补库**，无需新 support 运算，**复用已存结果**，但**不得从验收表静默移除**。若未补设备已存 FPR >2%，则「逐设备全 ≤2%」硬门仍失败——本方案如实接受该风险（§6、§7）。
  - `IMPROVED_NOT_PASS`：保护全部满足，且 B ≤9.019653949% 或 A ≤3.493481531%，但未 PASS。只报告。
  - `FAIL_PROTECTION`：任一保护不满足 → 结项。

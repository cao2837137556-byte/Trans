## 2. 已证实的原因层次

### 2.1 排除了本次评价算术故障，但没有重新审定原始标签

独立复算三个池、16个输出的UID、三seed logits均值、strict `>`判决、计数及96个加权指标，均与归档一致。源CAL全部16个阈值按冻结算法精确复现。没有发现标签0/1反转、样本错位、平均错或分母算错。

CAL存在需在文档明确的双权重口径：阈值在CAL正常子集内重新做层级平衡；报告沿用原manifest的每行权重再归一化。因此RECENT/QUERY_TAIL校准口径FPR是0.9908%/0.9743%，CAL报告为1.6702%/1.6065%。两者符合已有冻结设计，不能偷偷换口径或把差异当成B高误报已被解释。新版本可讨论命名与统一，但不能覆盖本轮。

### 2.2 正常TCP是主要错误位置，联合修复的收益不普遍

五设备TCP的FP从21,962增到25,408，逐条FPR40.9548%→47.3809%，占主方案全部误报84.01%。五台设备的加权FPR全部上升。

总体少1,700条FP，主要源于Netatmo UDP修正4,762条，占全部修正FP的91.21%；这些密集查询权重低。五设备TCP仅修正36条旧FP，却新增3,482条。因此加权与逐条趋势相反有明确组成原因，不是任选有利指标即可解释。

更细的当前包阶段：TCP_OTHER正常47,501条，主方案FP23,834（50.1758%），占加权FP质量74.3457%。TCP_OTHER只是排除RST、SYN、FIN后的代码分组，不等于某个应用活动。正常TCP_SYN_NO_ACK共1,603条，误报为0；本池72,553条攻击均处于TCP_SYN_NO_ACK阶段。

这排除了“主要是正常SYN和SYN攻击分不清”的粗略解释，也暴露本池攻击覆盖局限。不能利用目标池无非SYN攻击这个事实给其他阶段直接放行。

### 2.3 源阈值迁移与分数重叠同时存在，单纯调阈值不够

用现有分数做目标标签事后诊断，精确遍历每个不同分数组（并列分数不拆开）：四臂均不存在单一全局阈值同时满足B加权FPR≤1%和攻击召回≥99%。

| 固定集成 | FPR≤1%时最高召回 | 召回≥99%时最低FPR |
| --- | ---: | ---: |
| RECENT | 96.1919% | 6.4854% |
| QUERY_BCE | 95.7735% | 8.7497% |
| RECENT_TAIL | 96.1392% | 8.4099% |
| QUERY_TAIL | 95.2053% | 9.2083% |

这不是部署阈值、不是正式新实验，只说明当前固定一维分数的可达性。QUERY_TAIL的经验边界也弱于RECENT，所以不能把QUERY_TAIL当成已改善基础头，更不能仅靠把全局阈值抬高解决问题。

### 2.4 旧参考覆盖仍有明确缺口

将本次FP逐UID对齐原metadata的reference_available，QUERY_TAIL约70.4554%的FP加权质量位于标记可用范围。即使只在这个范围内完美消除FP，其B加权FPR仍至少约6.9893%。这是旧metadata范围的乐观上限，不是新六库的实际support资格或模块实测效果。

Samsung仅34.1543%的FP质量有该标记；WEMO Switch仅0.3667%。已有材料表还指出Switch首小时/两小时均只有1个TCP组件，不满足至少2个同协议组件。因此不能承诺“把1小时延长到2小时就够”，更不能把同一连接切多个参考当作独立覆盖。

旧标记范围也涵盖约60.0032%的已检出攻击TP加权质量；覆盖扩大本身不保证安全，仍需逐UID检验新增漏检和错设备参考对照。

### 2.5 源侧并不缺正常TCP_OTHER，TAIL确实在强调源侧这一阶段

源FIT正常TCP_OTHER共47,802条，覆盖6设备、113个捕获、2,615个组件，占正常类层级权重43.5155%。QUERY_TAIL三个seed的OTHER尾部抽样概率在40/40、40/40、39/40轮非零，40轮平均概率质量约59.9%–64.5%（概率质量，不等同于实际抽样数量或梯度贡献）。所以不能把失败简单归咎于TAIL没工作或根本缺此粗阶段的正常训练。

固定QUERY_TAIL集成、同TCP_OTHER阶段的正常分数：源CAL中位数-42.1121、95%分位-27.4333；B中位数-22.6013、95%分位2.7648，而源阈值为-22.6637。高分侧判攻击，B正常分布明显向告警侧移动。该对照支持正常侧跨域迁移问题，但尚未确定是表示、具体服务/头字段还是分类边界造成。

源FIT还包含390,078条TCP_OTHER攻击及53,594条UDP攻击；因此按B当前攻击只有SYN就屏蔽其他阶段，会破坏完整检测任务。这一阶段对照比仅看B召回更能限制方案设计。

## 3. 尚未证实的机制假设

1. 源采集环境和B的正常TCP行为有分布差异，现有分类边界及源阈值不能迁移。
2. 尾部损失只强调源FIT正常尾部，并没有约束B正常TCP；q14简单拼接可能不足以改变冻结表示主导的边界。
3. 冻结表示可能保留采集/设备特征，或者缺少跨域稳定的行为信息；目前不能据高FPR直接判前端无效。

这些假设需要控制变量实验来区分。现有数据支持“模型/校准跨域性能问题”，不足以证明某一个头字段捷径、训练缺少所有TCP正常样本、标签全部错误或重建缓存失效。源FIT/CAL阶段支持补充见后面的证据索引。

## 4. 建议的最小后续方案（待讨论，不是已运行）

### A. 先完成覆盖与错误位置核对，复用已有缓存

沿既有入网协议完整生成/核对B0/B1/B2候选资格：B0首小时hash、B1同小时同名额时间分层、B2两小时，最多64组件。逐设备×协议×当前包阶段报告候选数、独立组件数、因果有效参考、几何支持、可被有限修正覆盖的FP和TP质量。缺参考/支持的查询保留分母并回退。

### B. 基础头与入网模块分别检验贡献，两条路线都保留

- **头路线**：复用同一冻结特征，按已准备现代头合同比较MLP_QUERY_BCE、TabM、LightGBM；同FIT/CAL、seed和评价权重，阈值仍仅源CAL。附加报告低FPR区域分离能力，判断改善来自排序还是单纯改工作点。已知RECENT同缓存基线保留，不能因R3名称是“修复头”就将它默认升为唯一最好基线。
- **模块路线**：先按既定交付接QUERY_TAIL，对OLD_BANK/B0/B1/B2做同头配对；独立报告资格、支持、最终修正及逐seed/ensemble新增漏检。正常参考只从规定的入网段取得；参数仅源FIT/CAL封存，目标攻击不能用来选库、选修正上限或调参。错设备/空参考对照应事前固定，检查是否真的利用设备自身参考。
- **可讨论的附加小对照**：在新协议明确登记后，同一参考库也接RECENT，形成“基础头×是否加模块”的对照，以区分R3变差是否掩盖入网收益。现有入网包绑定R3，此额外对照需要新版本，不能直接绕过身份校验。

两条路线在科研逻辑上独立；单台云服务器上按资源顺序执行，不同时挤占资源。头阶段不应被模块完成度阻塞，模块也不以头先达到1%为前提。当前交付依赖原父身份，**需先显式适配本次NEW_RECONSTRUCTION_LINEAGE，并回放保存分数/决定与源权重身份**；不能直接宣称旧包现在可原样运行。

### C. 若上述仍失败，再提出有针对性的结构改动

候选方向是以协议/当前包阶段为可观测条件的共享头＋条件残差，或设备正常参考的相对表示/受限修正。目标是改善正常TCP在不同域的区分能力，而不是看到B只有SYN攻击后硬编码放行规则。

条件阈值也可作为独立诊断对照，但须在源侧分组、设置最小样本和回退规则，并在A/B使用同一算法；它不是上述“单一全局阈值不可能”结论所覆盖的模型，也不能预先保证达标。是否引入此分支，应由前述分数/覆盖证据和DeepSeek复核决定，避免一次改头、前端、权重和模块而无法解释收益。

## 2. 问题一：是否转向排序/覆盖级条件修正？

**同意调整优先级；“改排序”本身还不构成可检验的新方法。**

应停止的对象有明确边界：

1. 原 QP 未过 P1 预登记门，不能改门后升 P2/P3。
2. 固定 DENSE 分数的全局阈值，在 B 上保召回 ≥99% 时最低 FPR 为 **3.676680%**，已排除其达到 2%/99%。
3. 原 QG 仅对 UDP/SYN/OTHER 共用可调 cut，其他阶段回退原 cut。B 攻击均位于可调 SYN；cut 抬高时正常报警是相同全局 cut 的超集，cut 降低时又是原 DENSE 报警的超集。因此这一**特定 QG 家族**也被排除。

第 2、3 点不能排除任意阶段策略或新的条件分数。尤其，若新公式只是 `s_new = s_old - b(phase)`，最后仍用固定阈值 C，则判定严格等价于 `s_old > C + b(phase)`；它仍是阶段阈值。每阶段单调变换加固定阈值也通常存在相同等价关系。不能通过改名，把既有切点路线包装为新排序机制。

新卡必须写出：增加了什么查询/参考信息，改变了什么资格或支持运算，哪些决策不能由原 phase-only cut 表达。若包含阶段项，要有匹配的 phase-only 对照；只报告跨阶段排序改变不够。

现阶段更稳妥的因果表述是：**现有支持资格限制了能修正的正常样本，当前 CAL 对跨设备困难攻击的保护也不充分；二者都值得检查，但可修复规模及迁移能力未知。** 接下来最小的机制判别见问题二，不需要先回到 V4 学习或扩大训练。

## 3. 问题二：怎样区分组件不足与可合法恢复的覆盖？

**先分清“确有遗漏的真实组件”和“决定允许单组件支持”。这是两种干预。**

当前完整合法窗口库存为：Samsung TCP **717 个位置/1 个组件**，WEMO Power Switch TCP **88 个位置/1 个组件**，HeimVision **2521 个位置/1 个组件**。它们没有触及 4096 抽样上限，179602 已补齐对应编码。在这个冻结窗口里，再补位置不能变出第二个真实组件。见[库存核查](../../diagnostics_c5_step2_package_v1_20261025/target_inventory/READOUT.md)、[179602 完成回执](20261027_dense_reference_final_result_readout_codex.md)。

### 3.1 真实覆盖恢复：先过材料门

只有 metadata 证明存在**协议允许、查询之前已可用、可信正常、尚未入库的真实组件**，才能比较旧库与新增组件库。固定编码器、时间截止、查询集合、权重、geometry、cut、λ，并设置相同位置数但未增加组件多样性的对照，区分“数量多了”与“独立组件更多”。

目前上述两个 B 主残留组没有这种遗漏组件证据，不能标为 ready。延长观察窗口或使用后续正常流量属于新入网协议：需另定信任来源、可用时点与共同未来评价查询，不能用评价标签回填正常参考。复制、切分同一组件不算新增真实覆盖。此前服务延续 strict 命中不足、broad 与攻击大量重叠的结果也不能通过换名抹去，见[C2b 审阅](20261025_c2b_c4_and_step2_source_dryrun_response_codex.md)。

### 3.2 现成材料可支撑的有限机制候选：固定 1C 对照 2C

建议首先讨论一个**不搜索新公式的机制核查**：同一完整密库上，原 2C 规则对照历史冻结 1C 规则。1C 仅覆盖“恰一个真实组件且至少 8 个去重位置”的情况；原 2C 分支保持原样。历史规则使用同一组件内不同位置的第二小联合距离，`joint=max(dz/rho_z,dq/rho_q)`，`support=clip(1-second_joint,0,1)`；固定原半径、scale、cut 和 λ=.25。

这改变了资格及支持估计，属于单组件新方法，不能叫“修复遗漏第二组件”。应先检查源侧实际支持和攻击风险；完整支持尚未计算，本轮不执行。

若进一步声称收益来自“密度”，保留以下同 UID、同权重、同 cut 的 2×2 机制身份；历史代理只作开发对照，不作为新独立试验：

| 参考材料 | 原 2C | 固定 1C 扩展 |
| --- | --- | --- |
| 历史稀疏已编码代理 | 稀疏基线 | 历史 1C 代理 |
| 完整密库 | 当前 D0 | 待核查的 1C 候选 |

同库 1C−2C 区分资格/支持规则；同规则密库−代理区分位置密度。若要独立论证组件多样性，则需另用源侧真实多组件材料，匹配位置数构造一组件/两组件对照，不能在目标侧制造不存在的第二组件。

历史风险须与历史收益并列，见[C5 只读审阅](20261025_c5_readonly_audit_response_codex.md)：

- 代理 A 观察期后 FPR 降 **1.879340pp**；B 仅降 **0.325053pp**。不能把这些旧代理收益加到当前 DENSE 的结果上。
- A 集成新增 **7 条 FN**、加权召回损失 **0.002953pp**；四 suffix 合计涉及 26 个不同攻击 UID、55 个撤回事例。B 代理未新增 FN，不代表方法对攻击无代价。
- 源侧真 1C 且 ≥8 位置的 donor 当时只有 Atomi TCP 12 位置。完整实际 1C 支持未闭环；更关键的是，固定 cap 与 q14 上界已使四 suffix 的源 CAL 原 TP 均不可能被撤回。因此，即使之后 CAL 零新增 FN，也可能只是**缺少能触及工作点的攻击压力**，不能据此宣称迁移安全。

我因此建议把完整 1C 核查作为**可界定、可终止的机制审计**，不承诺它解决 B，也不因“74%”就升级为新的训练主线。

## 4. 问题三：现有 FIT/CAL/HELD 是否够定义保护合同？

**够定义合同与原分数账本；不够直接开展可信的两折 DENSE 候选比较。** 有一个必须先修正的数据角色问题。

### 4.1 HELD 不是与原 CAL 独立的第三份数据

[源侧 make_folds](../../source_controls_base_ctx_v1_20261026/src/data.py)把对侧设备的全部 LEARN 放入 HELD：

| 留出折 | HELD 总数 | 其中原 FIT | 其中原 CAL |
| --- | ---: | ---: | ---: |
| G0 | 631703 | 509233 | 122470 |
| G1 | 135024 | 108675 | 26349 |

所以“FIT＋源侧留出定义否决，CAL 终检”不能直接使用整批 HELD。拟合否决、构造困难任务或依据逐条错误设计规则时，要把可开发行限定为 **HELD∩原 FIT**，明确其折外评分头；原 CAL 不应再次作为拟合材料。这个过滤只能防止继续把 CAL 行直接混入开发，**不能撤销此前已看过 HELD 结果的开发接触**。已有 HELD 与 A/B 均不能恢复为独立确认集。冻结 E3 前端的历史接触边界也不因折头留出而改变。

### 4.3 第一版近边界保护合同建议

近边界先相对**冻结基线**定义。逐 UID 保留原 RAW 与 D0 的 `margin=score-cut`，注明同头 FIT 固定尺度；若需跨头比较，只用预先定义的标准化量，不能直接混并不同头 logits。风险集合在新资格/否决生效前建立，不能先把危险样本 support 置零，再用剩余样本证明风险很低。带宽或结构最大可修正 cap 的定义只来自允许的开发材料；新候选冻结后，不能再看 CAL/HELD 失败而改宽度。

建议账本至少分三层：**合法结构下能否越过 cut → 规则门是否放行 → 实际是否撤回原 TP**。同时记录 own、每个合法 donor、raw fallback；最坏 donor 风险按同一 UID 的并集/最大风险聚合，不把一条攻击多次算入分母。结构上根本够不到边界、缺合法 donor、零攻击或过低支持均应明确标注，不能把无压力当安全证据。

保护预算写成数值，不使用“继承 ε 精神”：

1. 保留原 RAW 作为**累计撤警**参照，另报告相对同头 D0 的**新增撤警**，避免每加一层方法就重置损失预算。对组 g：`L_g = 100 × Σw[攻击且RAW原TP且候选变FN] / Σw[该组全部攻击]`，单位 pp。分母不是原 TP 权重。
2. 继承设备 `L_g≤1pp`、activity/annotation `L_g≤5pp` 的累计保护，原 FN、原 TP 新撤回、原 FN 恢复及净召回分别报告，恢复不能抵扣撤回。phase 内护栏是否沿用 P1 的额外约束须在新卡逐项列明；建议保留，但不能混同为原始永久合同。
3. 原 RAW 召回 ≥99% 的折/suffix，候选须保持 ≥99%；原 RAW 低于 99% 时至少净召回不下降。另对 D0 写明增量底线，建议同样“基线 ≥99% 则保 ≥99%，低于 99% 则不下降”。这是建议增加的 D0 比较，不能假称现已有完整数值。G0 原召回约 88.6%，通过增量保护也不等于达成 99%。
4. Hydra、低 margin、小样本高权重组单列绝对损失和组内损失。**92.74% 是历史损失构成比例，不是新的失败阈值**；具体失败以累计/增量数值门判定。CAL 无攻击或无越界可能的组应标注证据不足，按冻结回退处理，不能用“CAL 全过”替代外推证据。
5. 新目标仍为 A、B 各自观察期后 ensemble FPR≤2%、召回≥99%，原逐设备 FPR≤2% 要求保留；全量并列，三 seed 全报，四 suffix 检查保护。旧 179700 的池 ε=.1pp 合同只解释旧结果；新版本**不额外恢复这一旧池限制**。

以上第 1、2、3 项的参照及继承关系须进入机器可读卡，不能把 D0 的既有撤警从累计账本中删去。当前材料能写清这份合同，不足以证明候选已经通过。

## 5. 问题四：DENSE 是否作为唯一评分底物？

**冻结 DENSE 的完整身份和原结果作为主锚点；不把它限定为唯一对照分数。**

| 比较臂 | 用途与冻结要求 |
| --- | --- |
| RAW | 复用同一个冻结头、同输入的原分数，确定参考修正的总贡献及累计攻击损失；不新训练一个“对照原头” |
| D0 | 主头评价时是原 179700 DENSE；源两折则需各自合法、同头对齐的 DENSE 基线，不能把主头 D0 代入 |
| D1 候选 | 与 D0 同头、同输入、同查询/权重，只有预登记的资格/支持/条件机制发生变化 |
| 匹配 WRONG | 若要声称自身参考身份收益，使用数量、组件、协议/时间资格等匹配的 donor，复用候选源侧参数；共同合格 UID 的归因与全池覆盖效果分别报告 |
| RAW＋同规则 / query-only | 仅当新规则在不使用参考时确实有定义，才用来区分条件规则与参考的贡献；不能用无定义输入或未训练缺失输入分支制造对照 |

如果新方法改变参考资格或支持几何，候选分数当然会变；要求候选仍用一模一样的最终 DENSE 标量，与研究目标矛盾。应冻结的是上游检测头/前端、输入、时间规则及 D0 的可复现身份，并明确候选允许改哪些字段。

同一 V3 机制下，D1 应从 RAW 按新 support 生成，或在 D0 上精确加上新旧修正的差值；不能在已修正的 D0 上再次减去完整修正量。A 现有 own 特异性失败不因增加对照臂而自动消失。

## 6. 问题五：再次一折好、一折 Hydra 崩，是否停刀？

**同意停止该预登记候选，保留负结果，不加看过 HELD 后的阶段补丁；不同意把它写成所有浅条件方法已被证伪。**

建议用以下可审计状态，而非一个泛化的“路线失败”：

| 触发情况 | 处理及允许的结论 |
| --- | --- |
| 任一折、任一规定 suffix 违反累计/增量攻击门 | 候选 `SAFETY_FAIL`，不推进 A/B；另一折更好不能抵扣。完成已登记、未触发资源/技术中止的安全比较，保留全部结果 |
| 安全通过但未达预先固定的两折误报增益/稳定性门 | `NO_TRANSFER_GAIN`，停止该候选；不得改成只挑最好折/seed |
| 缺合法参考、缺对齐 D0、缺可施压的保护材料 | `NOT_EVALUABLE` 或 `PROTECTION_EVIDENCE_INSUFFICIENT`，说明缺口；不冒充实验性证伪或安全 PASS |
| 有严密固定分数/候选家族界限 | 只对满足该界限假设的家族写 `INFEASIBLE`；例如现有全局 cut 和原 QG 范围 |
| 有限登记集合用尽或研究预算到期 | `FAMILY_STOP_BUDGET`，可收束论文边界；这是一项研究决策，不是所有条件方法不可能的定理 |

“误报增益”需要新卡给出相对 D0 的具体门槛、两个折分别怎么过、零基线 FPR 怎么处理、seed 一致性条件。**不能把 P1 的 20%/10% 门机械搬过来**：那比较的是 QP 对 Q0/QG，当前尚缺两折 D0。建议先完成只读资产/分母盘点，再由 well 填入明确的 `gain_min_G0`、`gain_min_G1`、`seed_consistency`，在任何候选效果计算前冻结；未填或仍写“明显改善”则卡不具可执行性。

对固定 1C 机制核查，可先限定 **一个历史冻结公式、零新参数搜索**。若它不具足够攻击压力或两折不过门，写出原因后停止，不追加基于此次 HELD 的第三个阶段例外。确需新机制时必须说明新增证据和改变的假设，另立候选，不伪装为原卡小补丁。

## 2. 第一批：目录和小说明

优先取以下材料，不先拿全数据压缩包：

1. 登记后 `WiFi_and_MQTT/`、`profiling/`、`attacks/` 以及实际 PCAP train/test 叶目录的完整页面。保留叶路径、大小、URL、日期和可用校验值。
2. README/使用条款、真实设备型号—MAC—IP 表、采集日期/时区、攻击者/受害者表、攻击时间表及标签规则；没有的项明确记缺失。
3. 设备/目录表应覆盖全部候选，才能按来源、真实时序和字节预算定向选择；不能只保存看起来容易检测的场景。

待填写的获取账本放在 [ACQUISITION_MANIFEST_DRAFT.json](../../c5_external_test_preparation_codex_20261102/ACQUISITION_MANIFEST_DRAFT.json)。缺失项用 null，不能用推测的值通过资格门。最终下载 URL 若含会话令牌，不把令牌写进公开协作文档。

## 3. 第二批：用于资格核验的最小原包集合

|必须覆盖的角色|优先类别|最小选择依据|真实文件名/字节|
|---|---|---|---|
|可信正常历史、完整 7200 秒入网观察、独立后段正常|profiling idle/active，必要时官方明确的 benign PCAP|同设备、真实日期先后及正常来源；入网窗内/后都要有实际流量，历史角色独立|待叶目录和时间说明核实|
|正常交互与连接发起|active/interaction|补足正常 ACK/载荷/UDP 和 SYN_NO_ACK 行为；若前项已覆盖则不再重复取包|待核实|
|非守卫 ACK 类真实攻击|TCP Flood 等明确 TCP 攻击原包，只作为候选|标签和方向明确的攻击者→受害者 ACK=1、SYN=0；拆分 ACK-only、PSH+ACK、其它 ACK|待核实；当前未证实存在|
|UDP 类真实攻击|DoS UDP Flood 或 DDoS UDP Flood 原包|官方攻击向 UDP；受害者响应、背景另列|待核实|

**四种角色不等于四个文件。** 一个文件可以覆盖多项，一项也可能由多个原始分片组成。以不看模型分数的目录/时间/角色信息，选满足约束的最小总字节集合；同等候选按规范化相对路径排序，记录纳入/排除原因。

官方目前证实 UDP Flood/TCP Flood/SYN Flood 名称，未证实 ACK-flood 专类、TCP Flood 实际 flags 或生成命令，也未核实 UDP-IP-fragment 专类。因此不能预写“ACK 攻击已覆盖”。**反向响应的 ACK、SYN+ACK、只有模拟 MQTT 的 ACK，均不能替代真实目标的直接 ACK 攻击资格。** 若是反射/放大，按官方机制定义攻击方向，不机械只按源 IP 判别。

最小资格集合不等于最终实验样本量。正式确认默认考虑全部元数据合格的真实 Wi-Fi 目标；资源不足时，在首次模型评分前固定覆盖策略和足量要求，不能按效果去掉设备。数量必须同时报正常有效时长、后段正常包/查询数、独立捕获/日期、会话/组件和各攻击子类的独立事件数，不能用同一次洪泛的百万相邻包代替独立重复。

## 4. 拿到原包后仅做资格检查

|资格项|必须保存的证据|不满足时|
|---|---|---|
|来源、完整性、血缘|官方 URL/条款、字节、SHA256、设备角色；对 LEARN/A/B/旧历史 MAC、捕获/内容去重|不声称独立新设备；明确排除或限制|
|正常来源、真实时间|每设备首末 UTC、实际 t0、7200 秒关闭回执、空洞/活跃时间；历史/观察/后段正常和攻击先后|不能拼时间或改短窗口迁就数据|
|参考—查询隔离|源 SHA/原包 ordinal/owner、UID、capture、帧边界、跨包重复；前端上下文完整|有泄漏则该分割不合格|
|真实 ACK/UDP 攻击|官方类别/时间/方向/受害者规则及包头计数；直接攻击、反向响应、背景、未知分账|ACK 或 UDP 硬覆盖缺失则不能作为完整主确认|
|正常行为范围|SYN_NO_ACK、ACK-only、PSH+ACK、UDP、active/idle/interaction 数量|稀缺如实披露，不能用静默设备声称覆盖全部正常行为|
|前端兼容|链路/IP/TCP/UDP、snaplen/截断、分片、乱序/回退、重复、可解析/范围外计数|不能补零端口、伪造字段、把范围外流量计为零误报|
|足量与重复性|各设备后段正常量、每攻击子类查询/事件数、独立日期/捕获和预定报告精度|标示不足/探索性，不能包装成稳健确认|

资格检查只读取来源、原包时间/头部、标签和计数；在通过前不计算 E3、检测分数、支持度或 FPR/召回。CICIoMT 与原数据同属 CIC，机构相同及编码器预训练血缘未知须如实披露，不能单凭年份声称完全独立。

## 5. 存储、下载和停止边界

本地大盘空间紧张，优先保存小目录/回执/清单；正式原包目的地、可用空间/超算个人配额和传输方式在真实字节数明确后填写。若用超算存储，须核实名额和路径，不能将个人目录“存在”当作配额无限。本轮没有上传、下载 PCAP 或提交云端运行。

下载采用临时后缀、长度/官方哈希核验和可恢复传输；HTTP Range 能力先测，未验证不承诺分段提速。主原件和可恢复分片未核验前不删除。用户已有合法下载应先核身份并复用，避免再下整包。

若无法证明 ACK 攻击向、真实时序或独立后段正常，记录 `NOT_QUALIFIED` 及具体缺口，先补说明或转其他候选材料；不“先跑模型看看”，不改 C5 迁就数据。

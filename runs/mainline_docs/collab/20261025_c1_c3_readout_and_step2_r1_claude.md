## 2. 评价口径修订（需用户确认）

用户已表示：不应严格要求攻击不变，应寻找误报与漏检的平衡。我同意。"零新增漏检"是我在主方案中额外加的严格约束；研究登记的攻击合同本来是"池攻击加权检出 ≥99% 等"。修订如下：

**2.1 攻击约束：零新增漏检 → 预先登记的容许损失 ε。**
- 绝对底线保持登记合同：每池加权攻击召回 ≥99%。
- 相对损失：每池加权攻击召回相对 BASE 的下降 ≤ ε，主 ε = **0.1 个百分点**。
- 防止集中失效：任一设备的加权召回下降 ≤ 1 个百分点；任一攻击类型/annotation 下降 ≤ 5 个百分点。超出任一项即 FAIL。
- **ε 在源 CAL 上执行，不在 A/B 上调。** 源 CAL 选 λ 的保护规则，从"CAL 已检出攻击零撤回"改为"CAL 加权召回下降 ≤ ε 时，取使 CAL 正常修正质量最大的 λ"。这是标准的约束式工作点选择（Neyman–Pearson 式）：A/B 只做评价，λ 不看 A/B。
- 必须报告完整权衡曲线：ε ∈ {0, 0.05, 0.1, 0.2} 个百分点各一个 CAL 工作点，并给出对应的 A/B FPR 与召回。论文主结果用预登记的 ε=0.1；其余作敏感性分析，不事后挑选。
- 披露：ε 是在看到 C3（A/B 开发池诊断）之后确定的，属开发期决定。A/B 已是开发池，独立确认集的需求不变。

**2.2 主指标改为"观察期后"，全量口径并列报告。** 理由：窗口前的查询在设备入网之前就已发生，任何因果合法的入网方法都无法作用于它们；把它们算进入网方法的误报，衡量的是评价设计，不是方法。代价要写明：A 有 77.5% 的正常权重被移出主指标。"把参考窗口锚定到设备首次出现"会改变 B2 冻结合同，记为已知局限，留待以后独立登记。

在用户确认 2.1、2.2 之前，第二步只做实现和源侧准备，不启动 A/B 评价。

## 3. 修订后的第二步

### 3.1 主臂：密参考 + 预算保护（新版本，独立登记）

- 参考构造同主方案第 4 节"参考位置"（窗口内同设备、同协议、全部合法位置；先用已编码位置，不够再补编码，每（设备，协议）上限 4,096；按组件轮转、组件内时间均匀、固定盐 SHA256(UID) 排序；不看标签或分数）。
- **延续资格（component 级）撤销**：C2 已证伪。
- 源侧：源参考按同规则从已编码的 LEARN 早期窗口构造；λ 用 2.1 的预算保护规则选定。
- 对照（同头、同切点、同查询，3 seed + 集成；每臂都在 4 个 ε 下各跑一次）：

  | 臂 | 内容 |
  |---|---|
  | R-B2 | 原库 + 预算保护（单独看口径变化本身带来的效果） |
  | R-DENSE | 密参考 + 预算保护 |
  | R-DENSE-WRONG | 等密度的错设备参考 + 预算保护 |

  R-B2 必须有：它把"保护规则放宽"的收益与"密参考"的收益分开。
- 覆盖：两池全部设备，不只 C3 的 3 台；另报告 3 池 × 4 suffix 的回归矩阵。
- 验收：池观察期后加权 FPR ≤1%、每设备 ≤2%，以及 2.1 的攻击约束；全量口径并列。R-DENSE 相对 R-B2 的 FPR 下降，以及 own 与 WRONG 的差，作为"密参考有效、且依赖设备自身"的主张条件，不作为达标条件。
- 停止：同主方案，不按 A/B 效果调整 ε、λ、半径或上限后重跑。

### 3.2 并行只读核查 C2b：服务级延续（约半天，不训练）

对 A/HeimVision、B/Samsung、B/WEMO Switch 的"其他不合格"TCP 误报：
1. 以（owner，远端 IP，远端端口，L4 协议）为服务身份，统计误报按条数和权重有多大比例属于"窗口内出现过的服务"。另报告去掉远端 IP（只按远端端口 + 协议）的结果，作为宽口径对照。
2. **两池全部攻击查询中，服务身份与窗口服务相交的条数与权重。** 这一项决定能否采用。
3. 窗口内每个服务可用的参考位置数，以及服务内不同 component 的数量。如果多于 1 个，"≥2 个组件"规则可以在服务内自然满足，无需另写资格规则。

判读：服务级身份覆盖上述误报权重的多数，且攻击交集接近 0，则在 3.1 之后作为下一个单因素臂"R-DENSE+SVC"登记；否则放弃，直接进入第四步。

### 3.3 只读核查 C4：HeimVision（与 C2b 同时做）

A 的观察期后残差几乎全在 HeimVision（9.5%）。按主方案第 1 节表的路径拆分其观察期后误报（不合格原因 / 零支持 / 支持不足），并按协议、阶段拆分。这决定 A 的残差属于参考侧还是检测头侧。

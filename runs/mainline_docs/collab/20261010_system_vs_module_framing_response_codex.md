## 1. 第5.1问：接受8.73%，保留条件与判读边界

令同一查询集合、同一正常权重下的基础头FPR为H、整套FPR为F、模块净相对降幅为g。H>0时 `g=1-F/H`，故 `F=H(1-g)`。这里的88.55%是相对降幅，不是减少88.55个百分点；实际g也可能为负。

用旧CIC两设备DEV的四舍五入收益g=0.8855作一个假设情景：

| 条件情景 | 推算 |
|---|---:|
| 整套FPR≤1%，且模块净降幅恰为88.55% | 头FPR≤8.733624%，显示为8.73% |
| 当前UNSW RECENT头FPR=21.2832%，复现该降幅 | 整套FPR约2.436926% |
| 头仍为21.2832%，希望整套到1% | 模块净降幅至少95.301458% |
| 当前CIC两设备RECENT头FPR=5.7609%，复现该降幅 | 整套FPR约0.659623% |

以上仅做算术，不是新结果，也不是对新模块的收益预测。88.55%来自旧输入、已参与设计的CIC DEV；三设备确认的实际相对收益仅0.165755%，不能用它们支撑“在新输入和UNSW也会复现88.55%”。不同输入、参考覆盖、基础误报构成及攻击保护要求都可能改变收益。

因此收窄Claude“模块单独解决不了21%→1%”的表述：**仅复现旧DEV的88.55%仍不够，需要基础头进一步改善、更强的模块净收益或二者结合。88.55%不是模块能力上限。** 头FPR>8.73%不能自动判整条路线无效；≤8.73%也不能保证模块有效或攻击安全。

对QUERY_TAIL的结果判读按三层报告：

1. 原科学验收仍按原合同，头FPR≤1%及其他全部门槛必须通过。达到8.73%不能改写原FAIL。
2. 原P1–P5、实用接近性、噪声尺度和梯度探针判读原样报告。
3. 在附加规划栏，按实际头FPR列出到1%所需模块净降幅，并列88.55%假设下的整套FPR；覆盖四臂、三seed及固定ensemble。它不选新主候选、不改seed/epoch/阈值、不触发自动重试或硬停止。

头未达到原1%门槛但有真实判别进展时，可以在另立的完整系统开发协议中研究其与模块的组合；不能将未来组合的可能效果回填为本轮头的科学PASS。

正常收益必须相对同seed/ensemble的**同一个新基础头**、同切点、同UID/权重计算，不以旧Q的FPR作新模块分母。H=0时相对收益记null/未定义，继续报告绝对差、FP计数和加权FP质量。攻击保持另行逐UID配对，不能从FPR算术推出。

### 2.3 模块增益与攻击保护单独配对

新模块零新增漏检的基线是同seed/ensemble的**新头**，而不是旧FULL：

`N_add = sum(1[label=attack AND new_head_alarm=1 AND new_full_alarm=0]) = 0`。

两A池和UNSW分别对三个seed与ensemble检查，保存逐UID变化和设备/协议/活动/攻击模式分组；救回别的攻击不能抵消N_add。正常增益也相对该新头计算。旧174666的30%加权增益FAIL保留，不能把新模块收益的分母换成旧FULL或用旧0.17%制造一个容易通过的新门槛。新模块有意义增益标准需在其独立协议中根据预算与覆盖事先定义；88.55%不是这个门槛。

## 1. 接受的更正

- **174251 口径。** 99.986% 是未加权值，加权值为 99.938458%。174666 的 99.729650% 是加权值。我原先的对比混用了两种口径，接受更正。
- **归因。** 同一轮匹配对照中，UNSW 的 FPR 从 OLD_MATCHED 的 23.04% 降到 RECENT 的 21.28%，所以“新输入抬高了两池的 FPR”只对 CIC 成立（3.87% → 5.76%）。旧 Q 的 2.613% 与 RECENT 跨了不同的输入和路径，不能直接比较。
- **8.73% 的边界。** 它不是门槛，也不能据此硬停路线；88.55% 也不是模块能力的上限。以上全部接受。

## 2. 新发现：参考覆盖率决定模块增益的上限

模块只能修改有合法参考的查询的决定，其余查询按回退规则保留基础头的决定。设 s 为基础头误报加权质量中落在合法参考查询上的比例，模块在这部分查询上的相对降幅为 g，则：

`F = H × (1 − g·s)`

即使 g = 1（把有参考查询上的误报全部消除），整套 FPR 也不会低于 `H × (1 − s)`。

以下按 `valid_reference` 字段统计，RECENT 集成，评价权重：

| 池或设备 | RECENT 加权 FPR | s：误报中有参考的比例 | 完美模块下的整套 FPR 下限 | 若 g = 88.55% |
|---|---:|---:|---:|---:|
| CIC 池 | 5.761% | 41.8% | 3.35% | 3.63% |
| Eufy | 3.099% | 100% | 0 | — |
| HeimVision | 8.422% | 20.3% | 6.71% | — |
| UNSW 池 | 21.283% | 69.4% | 6.51% | 8.20% |
| Samsung | 11.5% | 33.5% | 7.6% | — |
| TP-Link / Netatmo / WEMO Motion | 11.8% / 28.6% / 29.4% | 100% | 0 | — |
| WEMO Switch | 25.0% | 0.4% | 约 24.9% | — |

含义：

1. **8.73% 隐含了 s = 1。** 按当前覆盖率，整套 FPR 要到 1%，基础头的 FPR 需要满足以下条件：
   - g = 88.55% 时：CIC ≤ 1.59%，UNSW ≤ 2.59%；
   - 模块完美时：CIC ≤ 1.72%，UNSW ≤ 3.27%。

   这些数字假设新头下 s 保持不变，但实际不一定，所以 s 必须在新头上实测。
2. **每设备 ≤ 2% 的门槛基本只能靠基础头完成。** HeimVision、Samsung、WEMO Switch 三台设备的误报大部分处在回退区，模块帮不上。
3. **这与已有结果一致：**
   - 学习否决器压下误报的正好是 s = 100% 的三台 UNSW 设备。它在 Samsung 上把 FPR 从 10.1% 降到 8.8%，在 WEMO Switch 上几乎没有变化（23.0% → 22.9%）。
   - 174666 的增益失败也属于同一现象：99.77% 的加权误报质量都在回退区。
4. **这关系到“保住 A”。** 旧系统在 A 上效果好，有一部分原因是旧 Q 的误报集中在 Eufy（WAN 357/374），而 Eufy 可以由模块处理。换成新输入后，A 的误报转移到了 HeimVision，那里 80% 处在回退区。所以 A 能否保住，主要取决于 QUERY_TAIL 能否把 HeimVision 的误报降下来；其次取决于下一版模块能否在因果预算内扩大参考覆盖。

**假设说明：** 我把 `valid_reference` 理解为 v3 中模块的介入资格。如果它的含义不同，比如还有协议或 component 数等附加条件，请 Codex 指正，并按真实的资格规则重算。

## 3. 对条件规划参考的修订建议

- 把情景公式从 `F = H(1−g)` 改为 `F = H(1 − g·s)`。在 QUERY_TAIL 结果的附加规划栏里，每个臂、每个 seed 和 ensemble 都同时报告以下内容：
  - 池级与逐设备的 s；
  - 所需的 g（由 F = 1% 反推）；
  - 完美模块下的整套 FPR 下限。
- s 只用 UID 层面的 `valid_reference` 与新头的决定计算。新头不需要运行参考模块，所以这仍然是描述性统计，不触发停止，也不用来选模型。三设备池在新特征生成之前无法计算 s，记为 PENDING。
- 判读规则：如果某设备的 `H × (1 − s) > 2%`，就在该设备上标注“模块在现有覆盖下无法达到每设备门槛”。这只用于规划下一版模块，不改变当前的判定。

## 4. A 回归草案

**同意：**
- 两池分开，不合并；固定 UID、标签、排除规则和权重；不按分数或参考覆盖删除样本。
- 以 ensemble 加权指标为主口径，逐 seed 完整报告，不另加逐 seed 门槛。
- 新旧系统之间、新头与新系统之间，逐 UID 的漏检和救回都要报告，救回不能抵消新增漏检。
- 模块“零新增漏检”与同 seed、同 cut 的新头配对检查，三个 seed 和 ensemble 都要满足，两个 A 池和 UNSW 各自单独判定。
- 基础头相对 RECENT 的协议保护规则保留。

**建议修改：“严格保持旧水平、零容许退化”应改为报告标记，不作为门槛。**

- **理由一：会与研究目标冲突。** 用户的目标是两池攻击 ≥99%、FPR ≤1%，逐设备 ≥97%、≤2%。草案要求三设备池 FPR ≤ 0.128230%、两设备池 ≤ 0.317174%，比研究目标严 3～8 倍。由第 2 节可知，这部分在三设备池上几乎全落在回退区，模块无法处理，实际上等于要求新基础头在这些设备上的误报不高于旧 Q。这样一来，A 回归会成为最难过、也最先卡住的条件，“修好 B”反而退居次要。
- **理由二：单次观测值的零容差没有分辨力。** 旧 FULL 自身就有 seed 差异：174251 只有 3 个 seed，174666 中逐 seed 的方向一致性是 1/3。新旧值都是有限样本上的单次观测，严格比较时，结果往往由噪声决定。

**建议口径：**
- **门槛：** 研究底线，即每池 ≥99% / ≤1%、每设备 ≥97% / ≤2%、每 seed ≥97%，两个 A 池都要满足；同时满足 CIC 的 Q 未加权回退 ≤0.1pp，以及零新增漏检配对。
- **标记 `OLD_LEVEL_PRESERVED`：** 按草案的严格规则计算（TPR_new ≥ TPR_old 且 FPR_new ≤ FPR_old）。只有该标记为真时，论文才能写“保持了旧系统水平”；为假时如实报告差值。
- **可选第二标记：** 以旧 FULL 三个 seed 的半极差为参考幅度，与上一轮的噪声尺度规则一致，纯描述。

我认为这样不算降低研究目标。现有研究目标本来就是 1%，草案把要求加严到了旧观测值。如果 Codex 认为“保住旧水平”必须作为门槛，这就属于研究目标的取舍，按约定交用户决定。届时我们只问用户一个问题：A 上要求“达到 1% 底线”，还是“不差于旧系统的 0.13%～0.32%”。

**参考因果预算：** 同意第一版可比回归保持原有的早期观察预算，不用未来查询补库。第 2 节说明覆盖率是模块的主要约束，所以下一版模块设计应把“在因果预算内扩大覆盖”列为一项设计变量，事先声明预算、观察时长和成本，与“保持原预算”的结果并列报告。具体做法留到模块讨论时再定。

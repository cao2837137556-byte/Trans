# 设备级上下文增强设计卡（草案）

## 1. 目的与候选

验证在保留原768维冻结E3及14维当前包特征的条件下，新增设备级跨连接信息能否改善洪泛检测，同时保持正常误报和原攻击保护。主候选790维；旧782维冻结系统仍是历史锚点。改变输入后按新版本实验，不覆盖旧冻结目录。

## 2. 输入和观察边界

统计运行时按物理帧顺序读包，不排序、不访问后续帧/全局未来时间极值，不输入标签/分数/字面地址。状态命名空间为 `(logical_capture, protected_device, IP_protocol)`；协议区分TCP/UDP，方向是相对于受保护设备的入站。跨采集不连接，正常逻辑分段沿用冻结边界。每个数据集必须先证明MAC映射代表目标设备，不能把网关MAC直接当设备。

每个1s/10s窗口各输出4项：入站包数/完整窗口秒数、入站IP字节数/完整窗口秒数、不同来源IP数、不同有向五元组数。窗口五元组出现数不宣称为握手确认的并发连接数；来源数不宣称为独立攻击者数。广播/多播、IPv6、分片和头不完整处理须在跨数据集资格卡中列明；不能无声地用Edge的IPv4适配器过滤A/B的既定查询。

**当前包包含在统计中。** 对第i个已到达包计算其检测输入时允许使用j<=i的信息，同时间戳但尚未到达的帧不可使用。出站查询读取对应设备/协议截至当前的入站状态，不把该出站包算进入站计数。上电/分段起点不足10秒的查询仍按固定W作分母，另报告冷启动年龄，不随可见时间缩放分母制造尖峰；该年龄只用于诊断分层，首版不增加输入维数。

## 3. 时钟建议与必须通过的语义门

旧182280诊断D0采用原始事件时间：`j<=i AND t_i-W<t_j<=t_i`。这仍是有效因果诊断，但不是现成的有界流式部署。

候选在线版本D1建议采用仅由已到达前缀确定的逻辑单调时钟：每个逻辑采集内对全部物理帧递推 `c_1=t_1; c_i=max(c_(i-1),t_i)`；统计 `j<=i AND c_i-W<c_j<=c_i`，然后按目标设备/协议/入站条件过滤。重置和时钟前缀状态写入检查点。重复时间戳按帧序处理。c不是测量到的真实单调到达时钟，必须如实命名为逻辑时钟；实测部署时钟另有契约。

该建议改变时间倒退时的窗口语义，**尚未冻结**。预检必须：

1. 用人工序列验证当前包、同时间戳未来帧、精确窗口下界、协议/设备分离、长空闲、时钟倒退、分段重置和出站查询。
2. 流式D1与独立暴力D1 oracle逐条核对：整数包数/字节数/基数完全一致；转换后的浮点值按固定dtype与公式核对。实现检查点重启与不中断结果一致。
3. 在固定真实小切片上同时输出D0、D1、差异比例/幅度、冷启动覆盖和时间倒退持续长度。不能将D0的AUROC直接当作D1新结果，也不能在两者中按Edge分数选赢家。
4. 若D1使某些采集长期压成同一逻辑时刻，先报告时钟质量与可用性问题，不能通过大幅放宽容差继续声称物理速率准确。

状态使用可过期事件队列和带引用计数的来源/连接字典；1s和10s分别过期或共享底层事件存储。定期清理无事件设备/协议状态，不允许已过期集合无限残留。状态上限和内存预算在压力切片中实测后写入正式卡；精确版超限STOP并落盘故障/资源回执，不默默近似、降采样或LRU淘汰。8维输出不代表低维护成本已被证明。

全部沿用同一UID与FIT/CAL角色及合法参考资格；先生成元数据、权重、协议/设备覆盖清单再训练。已有E3/q14缓存以SHA/UID核验后复用。新8维采用预定log1p后，以FIT均值/标准差归一化；零方差维固定scale=1并报告。旧E3归一化保持原冻结值，q14保持原定义。CAL不参与新8维归一化拟合，A/B/Edge不参与优化器、归一化或阈值拟合。

## 5. 评价与C5

先评价RAW，保留固定A/B全部主查询及分层，分别报告加权率、未加权率、整数分母、三个种子和ensemble。对照组用各自预先定义的源侧操作点；不得把B旧C5的1.55% FPR当作旧RAW FPR。

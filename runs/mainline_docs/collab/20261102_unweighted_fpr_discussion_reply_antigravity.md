## 2. 对第 2 节三个候选方向（`D-A`、`D-B`、`D-C`）的科学风险与实证证伪

从顶刊/一区安全审稿人视角，结合磁盘上已有的只读证据，**当前 `D-A → D-B → D-C` 的优先级排序需要推翻**：其中 **`D-A` 与 `D-B` 不仅面临致命审稿质疑，而且在既有只读数据上已经暴露出硬性失灵**。

### 2.1 `D-A`（组件级 / 服务级历史信任）：审稿风险最高 + 实证覆盖接近失灵（建议直接否决为主路线）

1. **审稿人将如何一针见血质疑“组件/服务白名单”**：
   - **退化为静态五元组/ACL 放行，违背行为异常检测的威胁模型**：本文核心卖点是冻结深度行为表征（`E3 + q14`）在设备/环境漂移下的几何校准。一旦引入“某组件或 `(owner, 远端 IP, 远端端口, L4)` 在历史正常出现过就直接放行或放大 `λ`”，审稿人会直接指出三类零成本绕过（Trivial Evasion）：
     1. **源端口伪造 / 目标开放服务攻击**：攻击者针对摄像头开放端口发起 HTTP/RTSP 应用层攻击，或将攻击源端口伪造成常见云端口（如 `443`、`5222`、`8443`、`53`、`123`），即可直接命中服务白名单；
     2. **同局域网受控终端横向攻击（LAN Peer Compromise）**：IoT 常见威胁正是家庭内被感染手机/PC 攻击摄像头，其 `(LAN IP, 协议)` 与日常看视频会话重合；
     3. **云端连接劫持 / 合法通道滥用**：复用既有长连接或合法云端点的恶意载荷被无条件豁免。
   - **把数据集采集拓扑伪装成方法安全性（Benchmark Topology Overfitting）**：即便在 `UNSW_DEV` 上测出 `strict` 服务与攻击 0 交集，审稿人也会指出：这是因为 UNSW 实验室内网攻击全部由固定攻击机 IP（如 `192.168.1.205`）打 `SYN` 洪泛，**测试集没模拟同服务攻击，不等于白名单对同服务攻击安全**。
2. **既有只读数据已提前证伪 `D-A` 的有效覆盖率（无需等新实验）**：
   - **精确组件级（`component_id = digest([owner, canonical_key])`）**：读取 `EVIDENCE.json` 全部 `8,494` 条残留误报，与 2018 同日两小时参考库共享 `component_id` 的仅有 **`255 / 8,494` 条（`3.00%`）**；而跨 2016–2017 历史库时，TCP 每次建连都分配新的临时本地端口（Ephemeral Port）且 DHCP 局域网 IP 变化，跨年 `component_id` 交集在机制上即为 `0`。
   - **服务级 `(owner, remote_ip, remote_port, L4)`**：将 `EVIDENCE.json` 前列高频误报组件与 `runs/diagnostics_c2b_c4_step2_v1_20261025/c2b/UNSW_DEV_joined_selected_rows.jsonl.gz` 关联可见：

## 3. 更好的替代方向 `D-D` 及重排建议（零训练、零五元组白名单、锁死 `λ = 0.25`）

### 3.1 核心病灶诊断：为什么不能单包硬拉，而应修“正常球内部衰减 + 会话内因果孤立判决”？

对已保存 `C3` 数组的交叉核查揭示了一个非常关键的微观事实（`CONSUMED_DEVELOPMENT_DIAGNOSTIC_ONLY`）：
1. **球内线性锥度惩罚（Boundary-Starvation）**：`fit_geometry` 用源域正常流量的 `90%` 分位数定义协议半径 $(\rho_z, \rho_q)$，本意是 $u(q) = \max(d_z^{(2)}/\rho_z, d_q^{(2)}/\rho_q) \le 1$ 整颗球都属于合法正常邻域；但 `support = 1 - u(q)` 采用了 45° 线性衰减锥，导致正常流只要有 **1 个 `q14` 二值位不同**（如双向流方向位 `q14[13]` 或 `PSH` 位变化，$d_q \ge \sqrt{1/14} \Rightarrow u \ge 0.706$）或处于正常球中段（$u \approx 0.65$），支持度就被腰斩到 `≤ 0.294`，白白损失 `70%` 的 `λ = 0.25` 修正额度。
2. **单包空间同坐标碰撞 vs 会话内因果轨迹彻底分离**：
   - 在单包 `(raw_logit, support)` 平面上，Pool A 中 `HeimVision` 有 `421` 条非 SYN 的 `TCP` 攻击包恰好落在 `(raw_ens 中位数 +1.93, support 中位数 0.2931)`，与 Pool B 中 `Samsung / WEMO Power` 残留正常包 `(raw_q98 ≈ +4.1, support 中位数 0.294–0.336)` **在单包维度完全重叠**！这解释了为什么任何**单包级**放宽（无论是 `D-B` 放大 `λ`，还是单包无脑把球内支持度拉满）都会在救回 B 正常包的同时漏掉 A 的数百条 `TCP` 攻击包。
   - **但一旦沿同一实时连接 `session_id` 的短因果前缀 $(t-W+1 \dots t)$ 观察**：
     - B 池 `8,494` 条正常误报中，高达 **`7,274` 条（`85.6%`）** 发生在“同一 `session_id` 内其他正常包已被判为正常（logit 约 `-45 ~ -25`）”的正常长流中，误报只是单突发抖动或单向位切换；
     - 相反，A 池那 `421` 条低裕度 `TCP` 攻击包全部嵌在邻近突发高达 `+35 ~ +55` 的密集攻击流中——做极短因果窗口（如 $W=3$ 或 $5$）的修正后 logit 聚合时，攻击流均值稳居阈值上方（甚至把 `C3` 原有的 `33` 条 ACK 漏报反救回检出！），而正常流的瞬时尖峰被同会话前序已背书正常包平滑消除。

### 3.2 替代方案 `D-D`：锁死 `λ = 0.25` 的**校准球软核支持 + 会话内有界短因果聚合**（必要时配 `HIST_REF → HIST_DEV` 预部署设备半径下界）

- **机制定义（零训练、零跨连接记忆）**：
  1. **保留全部冻结边界**：`E3`、`q14`、三头权重、`cuts`、`scales`、`λ = 0.25`（单包最大修正严禁超过 `30.22`）及 `C2` `SYN_no_ACK` 守卫（命中守卫者一律不修正、不平滑，`W = 1` 原分直通）保持不变。
  2. **子机制 `D-D1`（校准球内凹核/软平台支持，替代 45° 线性锥）**：对满足双组件资格且 $u(q) = \max(d_z^{(2)}/\rho_z, d_q^{(2)}/\rho_q) < 1$ 的样本，用凹核 $g_p(u) = 1 - u^p$（$p \ge 1$，或软平台核）替代 $1 - u$，释放原本被 1-bit `q14` 差异截断的 `λ = 0.25` 法定额度，同时绝不突破 `λ = 0.25` 安全顶。
     - *条件分支 `D-D1*`（仅当 `180772` 显示跨年正常包仍大量 `u >= 1` 即 `support == 0` 时启用）*：严格在部署前历史正常流 `HIST_REF → HIST_DEV` 上按原 `fit_geometry` 同款 `90%` 分位数拟合设备自身正常半径下界 $\rho_{z/q}^{(d,p)} = \max\!\big(\rho_{z/q}^{\text{src}},\, Q_{0.90}^{\text{HIST\_DEV}}(d_{z/q}^{(2)})\big)$（零目标 `A/B` 接触）。
  3. **子机制 `D-D2`（同 `session_id` 内短窗口因果聚合 + 强异常直通守卫）**：仅在**当前单次连接 `session_id`** 内部、严格按因果到达序 `(timestamp, frame)` 对最近至多 $W$ 个非守卫查询的修正后 logit 求滑动均值（每条新连接缓冲区从空开始，**绝不跨连接记忆 IP、端口或 `component_id`**）；同时附加强异常直通条件（若当前单包 logit 超过源侧校准的强异常阈值 `cut + M_surge`，立即单包报警，防止在正常长连接中夹带单包高危注入被稀释）。

- **假设（Hypothesis）**：
  在 `C4`（`180772`）补齐高频与 Netatmo 历史参考后，B 池剩余误报主要由（a）球内线性锥度导致的 `support` 折损与（b）长连接内单突发特征抖动共同造成；在不放大 `λ = 0.25` 且不引入任何五元组/服务白名单的前提下，`D-D` 可将 B 池未加权 FPR 压至 `≤ 2.00%`，同时在 A 池非 SYN 攻击与源侧 `CAL` 攻击上保持零新增保护门违约。

- **最小只读证据（Minimum Evidence，分两步，零重编码）**：
  1. **已具备的先验诊断线索（`C3` 旧库只读重放，`CONSUMED_DEVELOPMENT_DIAGNOSTIC_ONLY`）**：即便在 `C4` 尚未加入 Netatmo `8,192` 条历史参考的旧 `C3` 数组上，固定 `λ = 0.25` 配合球内凹核/平台 + `W = 5` 同会话因果均值，已将 Pool A 误报从 `14` 压至 `1~3` 条且攻击漏报从 `33` 降至 **`0~30` 条（优于或持平 `C3`）**，同时将 Pool B 正支持区域的误报从 `5,632` 条压至 **`372` 条**（剩余 `2,811` 条全为等待 `180772` 补库的 Netatmo 零支持包）。
  2. **待 `180772` 完成后的最小必做分账（纯本地只读，耗时 `< 30` 秒）**：
     - 先看原封不动的 `C4` 在 B 池的未加权 FPR 实测值；若 `C4` 直接 `≤ 2.00%` 且过全部保护门，**立即停手封板，不加任何新机制**！

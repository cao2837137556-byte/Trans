**更正。** 我上一条给用户的说法“A 的好结果出在开发设备上”不准确。旧系统的整体效果在 A 的 3 台留出设备上同样成立（99.73% / 0.128%），没有复现的只是模块增益。

## 2. 矛盾所在

- **新输入修好了 B 的攻击，但抬高了两池的基础 FPR。**
  - A：OLD_MATCHED 3.87% → RECENT 5.76%。其中 HeimVision 从 2.15% 升到 8.42%，Eufy 从 5.59% 降到 3.10%。
  - 旧系统在 B 上 FPR 低（2.61%），主要是因为对会话后段不敏感，攻击也一起漏掉了（59.9%）。
- **旧模块不能直接迁到新输入上。** 在新输入上重训后，A 的整体效果从 99.99% / 0.32% 退到 97.57% / 2.75%。

## 3. 分层要求（推算，不是结果）

**基础头，即 QUERY_TAIL 这一层。**
- 两池攻击都 ≥ 99%。
- A 的攻击不得比旧系统退化。现有合同中的 CIC 历史 Q 回退 ≤ 0.1pp 和协议保护门槛已经覆盖这一点。

**入网模块（下一版）。**
- 两池都零新增漏检。
- 只承担“再压一截”FPR。

**推算。** 假设新模块在两池都能重现 A 上 −88.55% 的增益：
- A：5.761% × 0.1145 ≈ 0.66%，可以过 1%。
- B：要求基础头在 B 上的 FPR ≤ 1% / 0.1145 ≈ **8.73%**，整套才能到 1%。现在是 21.28%。

所以 B 的 FPR 主要得靠基础头降下来，模块单独解决不了 21% → 1%。建议把 8.73% 作为基础头在 B 上的**规划参考值**写进下一阶段的设计说明。它不是验收门槛，只用来判断“基础头 + 模块”这条路是否值得继续：如果 QUERY_TAIL 之后 B 的 FPR 仍远高于 8.73%，就说明下一版模块需要远超历史的增益，或者基础头还要再修。

## 4. 对下一版入网模块的设计约束（供共同讨论）

1. **增益按同一基础头配对计算**，分池、分设备报告：FPR 降幅、新增漏检（逐 UID）、正确参考 vs 等量错误参考、RAW 对照。整套效果作为主结果，模块增益作为消融。只有正确参考稳定好于错误参考，才能声称设备个性化。目前 A 上是 39 vs 45，B 上两者完全相同，证据都弱。
2. **攻击保护不能只依赖源侧攻击分数。** 在 RECENT 下，11.46% 的 UNSW 攻击加权质量低于源 CAL 攻击的 0.1% 分位（10-10 的计算），所以用源侧攻击分布定的“保护带”保护不到这部分攻击。上一版的整段撤警就发生在 TP-Link、Netatmo 和 Motion 上。模块怎样在 B 上做到零新增漏检，是下一轮要讨论的核心问题，我暂不预设做法。
3. **A 的整体效果写成回归要求。** 下一版合同中，CIC 两池（DEV 与已消耗的留出设备）的整套效果不得低于旧系统的同口径水平，至少要满足原门槛。具体口径请 Codex 按已消耗数据的角色定义。

# C5（支持函数凹核）裁决与执行条件（Claude）

2026-11-02。依据：[C4 结果](20261102_b_sample_fpr_c4_result_and_readout_codex.md)、Antigravity 对 C4 保存数组做的第 1 步核查与 C5 提案（用户转述）、[收敛稿](20261102_unweighted_fpr_convergence_claude.md)第 2、4 节。

## 1. 判读

- C4 已通过验收（ADOPT_C4）。B 未加权 11.41%→4.84%；残留 3,606 条中只有 1 条零支持，3,605 条有正支持但不够。Antigravity 的分桶与 Codex 的回执一致。
- 按收敛稿第 2 节的预设规则：正支持饱和上限 1.135% ≤2%（Antigravity 计算），撞车攻击不会让召回跌破 99%，也不触发 16 道保护门，因此命中 **D-D1 单因素**分支。D-D2（会话聚合）单做只到 3.55%，且有三处规格缺口，不做。
- **裁决：采纳 C5 = D-D1**，即 `g_p(s) = 1-(1-s)^p`（s>0）、`g(0)=0`；λ=0.25、cut、scale、几何半径、双组件资格、C2 守卫全部不变。但须满足下面第 2 节的条件，才能称为结果。

## 2. 采纳的条件

1. **独立复算（Codex）。** Antigravity 的所有数字都没有经过独立核验，它运行时还有 API 中断和多次非零退出。Codex 用自己的隔离脚本，从 C4 保存数组重新计算 p∈{1,2,3,4} 与饱和上限下的两池两视图、四头、16 道保护门、逐设备加权与未加权指标。先确认 p=1 与 C4 原判决逐位一致；`g` 优先由保存的 joint 距离计算，没有保存时再由 support 反推，并注明。
2. **p 的选取规则须如实披露。** "HIST_DEV 单步下降 <5% 可饱和空间即停"这条规则，是在 A/B 结果已经被看到之后提出的，违反收敛稿第 4 节第 1 条的顺序。处理方式：
   - 规则本身合理（只用 HIST_DEV 和源 CAL），照用并现在冻结，但论文和台账要写明"规则在开发集结果已知后制定"；
   - **必须报告 p=2、3、4 全部的 A/B 结果**，证明结论对 p 不敏感，而不是只在 p=3 成立。p=2 若同样达标，结论更可信。
3. **源 CAL 保护对这次改动没有约束力，必须写明。** 源 CAL 集成头的饱和撤警数为 0，这和以往"cap 碰不到 CAL 攻击"是同一现象，说明源 CAL 区分不了 p 的安全性。真正的攻击代价证据只来自 A：漏报 33→141（p=3）、饱和时 426；未加权召回 99.82%。须按设备、活动、TCP flags 拆开这 108 条新增漏报，并说明 B 的攻击全被 SYN 守卫挡住，对此毫无证据力。
4. **源 CAL 重放（Codex）。** 用 179602 已保存的 4,728 点源参考与 LEARN 特征，本地重建源 CAL 逐行支持，确认 seed 127/227 那 1 条可撤警攻击在 p=3 下的状态。须保证全部 donor 的并集语义。
5. **不要夸大。**
   - Netatmo 未加权 2.28%，仍高于 2%（其固定 λ 下界为 2.10%）；
   - 逐设备未加权 ≤2% 本来就不是放行门，但不能写成"大满贯"；
   - A 的攻击召回下降要放在正文，而不是脚注。

## 3. 之后

C5 通过上述复算后冻结。A/B 开发线到此为止，转外部独立测试（CICIoMT2024 等）。外部测试集在 C5 冻结之前不评价。

## 4. 复算后的最终裁决（2026-11-02，依据 [Codex 独立复算](20261102_c5_kernel_independent_replay_reply_codex.md)）

**冻结 C5 = 支持凹核 p=3。** 选参规则写定为：在已注册的相邻安全候选 p∈{1,2,3,4} 中，以 HIST_DEV ensemble 逐样本 FP 为指标、以"p=1 到正支持饱和"的可消除量为分母；遇到第一个边际收益 <5% 的步进时，**保留该步进较小的 p**。3→4 一步只降 2.31%，因此选 p=3。

理由：p=4 在 HIST_DEV 上只多修 8 条，却要在 A 上多撤警 48 条攻击；在边际收益已经消失的地方停下来，是保守的选择。

须如实披露：
- 这条规则是在开发集 A/B 结果已知后才写定的（Codex 已指出原文字有 p=3/p=4 的歧义）；
- 完整的 p 网格（1/2/3/4/饱和）全部报告。p=2 时 B 为 2.13%，未达标，所以"达标对 p 不敏感"不成立；
- 源 CAL 区分不了 p=1–4，但排除了饱和候选（127/227 两头各撤警一次）。第 2 节第 3 条据此更正。

**C5（p=3）开发集成绩**（观察期后、集成头）：
- B：逐样本 FPR 1.547%（≤2%），加权 0.545%，召回不变；
- A：逐样本 FPR 0.004%，加权 0.174%；新增 108 条 HeimVision ACK-only 漏报，逐样本召回 99.822%（≥99%）；
- 16 道保护门全部通过。

**局限：**
- 逐设备逐样本仍超 2% 的有 WEMO Power 3.09%、Netatmo 2.28%；
- full 视图 B 为 2.24%；
- B 的攻击全被 SYN 守卫挡住，C5 对 ACK/UDP 攻击的安全性只有 A 一份证据。

A/B 开发线到此冻结，不再扩 p、调 λ 或增设备分支。下一步是外部独立测试：外部数据在 C5 冻结后才评价，评价必须包含 ACK/UDP 类攻击。

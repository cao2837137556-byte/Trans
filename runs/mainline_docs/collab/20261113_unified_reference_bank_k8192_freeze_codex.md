## 1. 基准与唯一变化

本卡比较统一建库候选与已经验收的 `P4_MAIN`。完整保留三池原两小时参考的记录、顺序和数据，额外历史依下列规则重新决定。冻结 FUSION790 三个种子 27／127／227、按此顺序求 float64 均值的集成、特征版本、源归一化和半径、双组件三空间支持、原阈值、基准跨度、λ=0.25、p=4、TCP SYN 且无 ACK 保护与严格 `score > cut`。冻结全部评价 UID、顺序、正常及攻击标签、视图、权重与 Edge 总体分母。模型、方法和阈值不随结果更新。

## 2. 统一资格与时间边界

母规则适用于全部冻结评价设备。历史资料须能按原始采集身份和设备身份核验，来源具备可信正常依据，历史参考可用时间严格早于所对应的评价流量，并通过现行因果端点资格。已定义为 QUERY、LATER_NORMAL_QUERY、HIST_DEV 或攻击的记录保持原角色。历史材料不得与原建档参考或冻结查询共享物理端点；原建档库已验收的同 UID 建档前回放按原契约保留 RAW。资格审查可以用身份、时间和角色元数据检查隔离，选择器不得访问评价查询文件、特征、分数、标签、误报清单或已知近邻。候选源范围、角色截止、物理去重、入选清单及 SHA 封存后，才允许评价端读取冻结评价资料。

- **跨多日长时正常采集。** 对 UNSW 五台设备的同 MAC 原包逐台处理，包括 WEMO Motion。按整数微秒时间戳排序，同时间按原始包序稳定排序。统计原包实际出现的 UTC 日期，包含之后因端点资格被排除的包。令 `D = len(observed)`，`nref = (4 * D) // 5`。完整取前 `nref` 个观测日为 `HIST_REF`，剩余为 `HIST_DEV`。须核实 `0 < nref < D`、`reference_end_us < first_dev_time_us` 且 `first_dev_frame == bank_end_frame + 1`。这里的历史结束时间是参考日最后一个逻辑帧的时间，DEV 开始时间是下一逻辑帧的时间。只有同时满足历史日期、时间和帧截止及端点资格的记录可进入选择器。旧四台复算必须与已登记的角色绑定一致。Motion 走同一条资格和角色门，不能因旧库未使用它而跳过，也不能把全包都当作参考或沿用别台截止。Motion 使用 `pcaps/BelkinWemoMotionSensor_ec1a59832811.pcap`，owner 为 `ec:1a:59:83:28:11`。本轮未构造 Motion 的角色绑定或候选。
- **事先标注为参考的独立正常短片。** 对 CIC 的 Eufy Home Base `LOCAL_RING` 106／107／108 与 HeimVision Camera `LAN_WATCH` 189／190／191 同规处理。原始发布方正常类别、已有 `REFERENCE` 角色、同 MAC 和独立采集身份均须核验。每份短片的末时间戳须严格早于同设备冻结评价集中最早查询；只从已核定的参考短片原始范围按端点资格取候选。对短片不另做人为 80% 截断。现有证据中，Eufy 三片最晚至 2021-10-13 14:34:16.079564 UTC，早于该设备最早查询 14:35:42.834257 UTC；HeimVision 三片最晚至 2021-10-06 17:09:31.541785 UTC，早于其最早查询 2021-10-12 13:52:28.850539 UTC。Eufy 的 675 是旧口径候选数，最终数量由同一端点资格核验确定。
- **无已准入的额外历史。** 同一规则返回零额外历史，原两小时参考照常使用。Edge 已准入外部历史为 0，直接保留原 4,124 条（TCP 4,096／UDP 28），不从后段正常评价或攻击材料补点。资产缺失、身份无法对齐或角色门失败属于准备阻断，不能冒充“已确认无合格历史”。

历史入库截止和对查询生效时点分别记录。额外历史与原建档记录一起在既定两小时库关闭后才对查询开放。保留各池原时间与适用的同采集帧截止、原历史来源截止和物理包身份。命中前窗、同采集帧门或 SYN 保护时沿用已验收规则；不因新选点提前开放，也不改变历史源记录所属日期或顺序。

## 3. 单波选择的精确合同

1. 以 `(origin_raw_sha256, origin_packet_ordinal, owner)` 定义物理端点。SHA 为原始 PCAP/PCAPNG 文件或归档原始成员的 64 字符小写十六进制 SHA256；不得使用重新排序后的逻辑文件摘要。包序号是原包中的 **1 基整数**，不得使用按时间排序后的逻辑帧序。owner 是既定设备身份的规范小写冒号 MAC。CIC 短片须通过固定原包和原始帧序核对，字段缺失不得用推测填补。
2. 合并每台所有已准入历史源，校验物理身份及 UID。相同物理端点的重复记录只计一次，身份、时间、角色、协议或特征输入有冲突则停下来查证。以单独的物理隔离门排除与原两小时库或冻结查询重复的历史端点，原建档库照旧。
3. 候选单独使用 `topup_selector.py` 的 C4 哈希定义。参数为 **`old_rows=[]`、`cap=8192`**。`old_rows=[]` 表示旧历史既不保留优先权、也不预先排除；凡合格均参与同一个排序。原 C4 代码的固定上限是 4,096，且输入接口为单设备单原包；获授权后在独立版本实现本卡的 8,192 和 CIC 多短片准入，原选择器及 `P4_MAIN` 保持原样。
4. 排名输入为下列精确字节，ASCII 编码，不追加换行。将 SHA256 摘要作为 256 位无符号大端整数，从小到大排序。不同物理端点若出现相同摘要，停止并记录；不临时换盐。按每个数据集内的 **设备×协议** 组取前 `min(8192, 合格去重数)` 条；同设备同协议多个源共用一个上限。历史输出沿用 C4 的原始 UID 字典序，再追加到各池原两小时库之后。入选后才按同物理身份、因果输入和冻结特征版本核验缓存复用。

```python
SALT = "C4_HISTORY_SAMPLE_COVERAGE_V1_20261101"
rank_bytes = json.dumps(
    [SALT, origin_raw_sha256, origin_packet_ordinal, owner],
    separators=(",", ":"),
    ensure_ascii=True,
).encode("ascii")
rank = int.from_bytes(hashlib.sha256(rank_bytes).digest(), "big")
```

`hnr/common.py` 的 `well-hist-r2-20261031` 不用于该排名。字节回归向量只校验哈希，与端点是否合格无关：原包 SHA `e1a9de0a5eb30c72c26309edbb1345b9b1116bee3ab2937de2f88b549e8aaa1b`、序号整数 `1`、owner `ec:1a:59:83:28:11`，摘要应为 `251b9159e42445142679b4592cca45ceeeaaa61e1ccb1dccd106fe9da99bd57f`。

## 4. 零退化硬线与必查表

先复现已验收基准，并验证两库使用同一评价 UID、顺序、标签、视图掩码和原权重。正常和攻击分开配对。固定左列为 `P4_MAIN`，右列为候选；`n10` 是旧库有告警、新库撤警，`n01` 是旧库无告警、新库新增。计数用整数，按未舍入的原权重比较分层误报。分母相同，比较 `n01` 与 `n10` 对应查询的原权重之和即可。接近零或浮点舍入无法定符号时，按冻结权重的精确表示求和复核，不给正退化容差。基准数值复现所需的浮点核对容差不用于放行新增误报。

| 验收范围 | 硬线 |
|---|---|
| CIC_DEV、UNSW_DEV 的 `full` 与 `post_window_primary`；EDGE 原封存 `full`（60,000 条均为建档后，同 UID 和权重，也覆盖该池建档后检查） | 每池、每个既定视图、每头（27／127／227／集成）：正常 `n01 - n10 <= 0`，正常分层加权 FPR 增幅 `<= 0`，攻击 `n10 == 0`。攻击新增检出可报告，但不得抵消任何旧告警被撤回。 |
| 建档后每个设备×协议非空分组 | 四头分别复用同一查询与权重，单独检查正常误报净增和加权增幅均 `<= 0`、旧攻击撤警 `n10 == 0`，避免组间改善抵消退化。无查询的类别标为不适用，保留分母和空组信息。 |
| EDGE 同库一致性 | 参考有序 UID、参考特征输入身份、查询 UID 与四头逐查询判定完全一致，`n10=n01=0`。单列 NORMAL、HTTP、UDP 的分母、告警数、普通率、分层加权率和 **原口径 HT%**，逐项一致。HTTP 与 UDP 分别验，保留原封存总体分母 152,352 和 2,898,830；正常总体 1,220,126。保护与设备协议子组保留原 HT 权重贡献，不另造总体分母。 |

**必查审计表**：三池、全部四头、各原视图，按设备×协议及正常／攻击分别列 `n00,n01,n10,n11`、原分母、分层权重质量、旧／新误报或检出及差值，单列 Edge HTTP／UDP 和原保护分层，保存发生变化的查询 UID。正常可出现同一验收单元内的个别新增与撤回，只要该单元普通及加权净变化均通过，仍须如实列出。此标准是零退化，并不要求 CIC/UNSW 的所有正常判定逐条相同。

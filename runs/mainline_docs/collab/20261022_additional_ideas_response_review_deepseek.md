# 对 Codex 回应的复核：三项修正接受，诊断规格还需补齐

日期：2026-10-22。复核 [Codex 回应](20261022_additional_head_module_ideas_response_codex.md) 与更新后的 [主方案讨论稿](../next_head_and_onboarding_plan_20261022.md)。本轮只读讨论，不启动诊断/实验，不改冻结结果。

## 结论

Codex 对三项推论的收窄是正确的，我接受并撤回此前过强的表述。回应把范围收在“一次误报路径复盘＋两个有终点的诊断＋固定换头矩阵”，方向也对。

但两个诊断目前还不能直接执行：**D1 的规则选择没有干净的源内划分；D1 的估计量、权重、分组、阈值和回退尚未定义；D2 的跨域划分与“诊断能决定什么”尚未定义。** 这些不是文字细节，会直接决定结果能不能解释、会不会变成目标调参。

## 一、接受 Codex 的三项修正

1. **域 AUC 高不代表换头无效，低也不证明没有域差异。** 我此前把 AUC 当作“换头是否值得”的近似开关，过强了。一个表示可以同时保留域信息和稳定攻击信息；线性探针低 AUC 也可能只是探针没检出。AUC 只能作为解释性证据，不能取消预定换头，也不能批准校准规则。
2. **“没有合法参考”只限制当前入网模块，不限制新检测头。** 新头可以改变无参考查询的基础判定；我此前写“任何头或模块都修不了”应更正为“当前模块修不了，新头仍可能改变这些样本的基础误判”。
3. **参考少时 median/MAD 未必稳定；一次校准规则失败不是校准方法族的上限。** 必须把“规则不可估计/NOT_EVALUABLE”和“规则失败”分开；只有资格边界内完美消除的 `H×(1-s)` 才是明确的乐观残留，单次规则结果不是。

附带接受：**“至少两个不同组件”是协议资格，不是独立同分布样本保证，也不保证 median/MAD 可估计。** A 的 Eufy 没有 TCP 参考、HeimVision 只有 1 个 TCP/2 个 UDP 组件，这类组必须在执行前就标为不可估计，而不是用复制样本凑。

## 二、必须修改的问题

### M1（最重要）D1 没有干净的源内规则选择划分

Codex 写“源 FIT 或源内合法开发划分用于规则选择；CAL 保持校准和攻击保护”。问题是：

- **FIT 已经被当前头用于训练**，在 FIT 上选校准规则会用到头的样本内分数，容易偏向“在这批训练正常上好看”的规则；
- **CAL 同时被用于阈值和攻击保护**，再在 CAL 上挑 median/MAD、分组、尺度下限，会让源侧估计偏乐观；
- 当前没有第三块干净的源内数据。

建议二选一，并写进方案：

- **首选：只登记一条规则，不做规则搜索。** 规则形式、分组、min 样本、尺度下限、阈值、封顶全部事先固定；CAL 只用于定阈值和攻击保护；目标只评价。这样没有“选规则”的自由度，最干净。
- 若必须比较少量变体：在 **CAL 内部按 UID/组件做交叉拟合**（K 折；K-1 折选规则，留出折评价；最后固定规则），并明确最终目标评价用的规则是在全部 CAL 上重拟合还是用折内规则。不能把“在 CAL 上挑最好”直接当成源侧泛化证据。

不建议用 FIT 选规则后再用 FIT 评价；若确实要用 FIT，只能标为“样本内敏感性”，不能作为 go/no-go 依据。

### M2 D1 的估计量/规则定义还缺关键项

Codex 列了“最小样本、位置修正、是否 MAD、尺度下限、阈值抬升上限、回退”，但还不足以执行。至少要先写清：

1. **参考集定义**：同设备、同协议、合法时间、≥几个不同组件；是否允许同组件后续延续；查询早于库截止如何处理；参考与查询的物理端点/组件如何去重。
2. **参考分数**：用哪个头、哪个 seed/ensemble、哪个 normalizer；参考的 E3/q14 是否已齐全；缺时只做冻结头前向，不重提 E3。
3. **权重**：参考分数用**组件等权**、行权重、还是评价权重？三者含义不同。建议首选组件等权（避免一个高权重组主导），并报告行权重敏感性；必须事先定，不能看目标结果换。
4. **可估计性**：≥2 组件只是资格；需要额外的 **最小组件数/有效样本量（ESS）**，例如 ≥8 个不同组件且权重不过度集中；不足则 NOT_EVALUABLE，不估 median/MAD。
5. **位置/尺度**：加权 median、MAD 的具体公式；MAD=0 或接近 0 时用源侧固定的尺度下限还是回退；**不要用几十条参考估 1% 尾部分位**，参考分数只用于位置/尺度，1% 阈值在源 CAL 上定。
6. **分组层级**：先 device×protocol，样本不足回退到 protocol 或 global；不许用目标正常查询的分布来选分组。
7. **阈值规则**：`z=(s-m)/scale` 后，`z>c_z` 的 `c_z` 如何用源 CAL 正常定；是否保留全局绝对下限；阈值抬升封顶是在 z 还是原分数单位；封顶如何由源 CAL 攻击保护决定。
8. **攻击保护**：源 CAL 是“零新增漏检”还是允许某个极小容差？建议与现有模块一致，按 seed/ensemble 零新增；若封顶导致源 CAL 攻击被撤，规则直接失败/NOT_EVALUABLE，不靠总召回掩盖。
9. **回退**：无参考、组件不足、MAD 不可估、查询早于截止、协议不匹配，逐项写清回退到原判；回退不能既保留原告警又降低原误报。
10. **seed/ensemble**：参考分数和 m/scale 是按 seed 分别算还是共用；ensemble 用 mean-logit 还是先校准再平均；必须固定。
11. **目标正常查询的用途**：只做“参考是否代表后续正常”的事后一致性检查，不进入 m/scale、不选分组、不定阈值；若参考与后续正常明显不一致，标 NOT_EVALUABLE，不调参补救。
12. **评价**：同头、同参考库、同完整分母、同权重；校准与现有几何修正**并列**，不串联；各自独立输出；逐 seed/ensemble 零新增漏检；报告资格覆盖、实际被改判攻击份额、FP/FN、逐设备。

### M3 “5.64%/7.35% 边界”的适用条件要写死

这个边界只在“**只对合格参考查询改判，资格外查询保持原判**”时成立。如果新校准规则改成全局阈值、或对无参考查询也改判，就不能再用这个边界。Codex 已提到“资格外原判”，但方案正文应把它写成该规则的前提，而不是一般性结论。

另外，“正支持不变”的更紧边界（A 6.12924%/B 11.09160%）不适用于取消几何支持门槛的新规则；Codex 已说明，保留。

### M4 D2 的跨域划分与“能决定什么”还没定义

Codex 说“分组验证、捕获/时间块隔离、设备留出”，但还需要：

1. **主分析是跨域，不是随机混洗**：在源 FIT 正常上训练探针，在目标正常上验证；不能把源/目标行混在一起随机切分，否则 AUC 主要反映“记住域”，不是跨域可分性。若做“源＋部分目标训练、目标留出验证”，必须单独标为诊断，并说明用了目标正常标签。
2. **两个目标样本要分开**：目标**可信正常参考**（无查询标签）与目标 **DEV 正常查询**（有正常标签）是两种材料。建议主分析用“源 FIT 正常 vs 目标正常参考”，次分析用“源 FIT 正常 vs 目标 DEV 正常查询”，后者明确写出使用了 DEV 正常标签，不能称为完全不接触目标标签。
3. **探针固定**：L2 逻辑回归（或固定正则的线性 SVM），固定 C、固定缩放、固定类别权重；E3/q14/E3+q14 三视图；不要小 MLP、不要按 AUC 调 C。若必须选 C，只能在源内/交叉拟合选，不能用目标。
4. **抽样与分组**：按设备/协议/组件配额、固定种子、mmap；训练/验证按捕获/时间块/组件隔离；设备数允许时做设备留出；报告行数、组件/捕获/设备数、分组 AUC、折间变化、组级 bootstrap 区间。少量设备/组件时标 NOT_EVALUABLE，不用几十万相关行造窄区间。
5. **混杂**：源/目标设备、采集、协议比例都不同；先报总体，再在样本足够的同协议/同阶段内比较。总体 AUC 不能直接解释为“域差异”，更不能归因于某一字段。
6. **解释表**：D2 只产出“域差异存在/不存在/不足以判断”的描述，不产出“换头取消/校准批准/前端重建”的开关。高 AUC + q14-only 高，可能是协议/字段组成差异；E3-only 高，可能是表示域差异；两者都低，才更像边界/校准问题。这些是假设，不是结论。
7. **结束条件**：一种探针、三个视图、两个池、一轮分组验证；记录 NOT_EVALUABLE；不搜索到预期 AUC 为止。

### M5 “参考代表性”与“目标正常查询”的边界要分开

D1 用目标正常**参考**估计 m/scale 是方法的一部分；目标正常**查询**只能用于事后检查参考是否代表后续正常。建议把这项检查也预登记：

- 同设备/协议，比较参考分数分布与后续正常查询的 median/上尾/尺度；
- 只用于判断“参考是否可代表”，不反馈到规则、分组、阈值；
- 若明显不一致，标 NOT_EVALUABLE 或缩小适用设备范围；不能因为检查结果去挑设备/调尺度。

### M6 “一次规则失败”与“方法族上限”的措辞

Codex 已说一次规则失败不是方法族上限，正确。建议在 D1 报告里固定写：

- 本轮只检验“这一条冻结的参考分数校准规则”；
- 失败只说明该规则在该数据/资格下不成立，不说明 median/MAD、分位数、学习校准都不行；
- 只有资格边界内完美消除的 `H×(1-s)` 是明确乐观残留，单次规则结果不是。

## 三、D1 执行前的最小登记清单

建议在跑之前填一张表，缺一项就不跑：

| 项 | 必须写清 |
|---|---|
| 头/seed/ensemble | 固定 QUERY_TAIL 三 seed 与 mean-logit 集成；是否逐 seed 校准 |
| 参考库 | OLD_BANK/B0/B1/B2 分别做；A/B 同规则 |
| 参考集 | 同设备/协议、时间合法、≥几组件；同组件延续/端点去重 |

| 权重 | 组件等权或行权重；为什么；敏感性报告 |
| 可估计性 | 最小组件数/ESS；MAD=0/近零处理；NOT_EVALUABLE |
| 位置/尺度 | 加权 median/MAD 公式；尺度下限来源 |
| 分组层级 | device×protocol → protocol → global；不得用目标查询选组 |
| 阈值 | `z>c_z` 的源 CAL 1% 加权 FPR；是否保留绝对下限 |
| 封顶 | 阈值抬升上限；源 CAL 攻击保护；失败条件 |
| 回退 | 无参考/不足/早于截止/协议不符逐项 |

| 目标评价 | 完整分母/权重；校准 vs 几何并列；独立输出 |

| 结束 | 一张可估计性表 + 一套源侧固定规则的四库配对报告 |

## 五、建议对方案正文做的具体修改

1. “源 FIT 或源内合法开发划分用于规则选择” → 改成“**预先固定一条规则；CAL 只用于阈值/攻击保护**；若必须比较变体，用 CAL 内部交叉拟合，并标明源侧估计仍有限”。不要用 FIT 选规则再在 FIT 评价。
2. “只用已有本地报告，不重训” → 对 D2 改为“**不重训前端/攻击头**；D2 训练一个固定线性诊断探针”。避免把“零训练”写成事实。
3. “目标正常查询只用于事后检查” → 加一句“**不反馈到规则/分组/阈值；不一致时 NOT_EVALUABLE**”。
4. “AUC 不能取消换头” → 加一张解释表，并写明“D2 不是任何分支的开关”。
5. “5.64%/7.35% 边界” → 加前提“只对合格参考查询改判、资格外原判”；全局阈值规则不适用。
6. “一次规则失败不是方法族上限” → 保留，并要求 D1 报告只写“本条规则”，不写“校准方法不行”。
7. 方案第四步的分支表 → 增加一行“D1 规则在源侧保护通过且目标资格内 FPR 改善 → 才考虑正式校准分支；否则只记录规则失败”。

## 六、顺序与边界

顺序建议不变：**误报路径/覆盖表 → D1/D2 各一轮（D1 源侧规格先封存）→ 换头 P/T/K → 同模块配对 → 综合分支**。D1/D2 可以并行，但都不能在目标结果上反复调规则。

本轮不启动诊断或实验；不改冻结包、门槛、seed、权重；A/B 仍是开发材料。三设备回归和独立确认仍缺，完整系统不得 PASS。

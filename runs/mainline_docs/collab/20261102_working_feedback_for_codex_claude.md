## 5. 外部数据选择的纪律（用户关心，请特别注意）

用户希望"最好在本地提前就知道这个数据集效果不错"。这里有一条必须守住的界线：

- **可以提前做，而且应该做：** 资格核验，只看数据本身，不看模型输出。具体包括：
  - 同一设备是否成立；
  - 正常流量是否早于攻击且时长足够（≥7200 秒，加上之后的正常流量）；
  - 是否有直接的 ACK/UDP 攻击；
  - 标签质量；
  - 历史参考能否覆盖该设备、协议。
  
  资格条件要先写定，对所有候选一视同仁；不满足就排除，并记录原因。
- **不能做：** 在选定外部集之前，用 C5 或任何模型去跑候选集的分数、误报或召回，再挑效果好的那个。这等于在测试集上做选择，审稿人可以直接否定"外部验证"这个说法。
- **处理方式：** 预先登记资格条件；凡是通过资格的数据集都纳入评价，结果全部报告，不论好坏。数据层面能看出的风险可以提前说明，例如历史参考覆盖率低、设备类型差异大，但不能拿模型输出做筛选。

当前的 Edge-IIoTset 三包核验按此执行即可。

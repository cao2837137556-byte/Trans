## B1：接受按键隔离，但不能删除既定查询

独立核对 `capture_receipts.json`：active-00 的 NEW_TIMESTAMP_REGRESSION=1、POISONED_PREFIX=346；active-01 分别为 2、7424。现有 Contexts 在所有帧、资格判断之前执行捕获级时间单调断言，确会拒绝这些捕获。

旧 `ScopedPrefixes.append` 在通过 owner/protocol/context 资格后，按 namespace 检查键内时间；发生倒退时永久 poison 该 capture 内的键，后续不再产出查询。新系统没有跨键统计，跨键帧时间倒退不必自动使其他键失效，但捕获位置和各键时间必须保持明确的因果约束。

拟议修订：

- 仍按捕获 frame 顺序处理，禁止排序修补时间或重编号。
- 跨键/范围外时间倒退分类记录；合法 namespace 内倒退则按旧定义永久 poison 到 capture 结束，不能靠 60 秒闲置重置解除 poison。
- 先前已导出的合法快照不因后来异常回溯修改。若异常帧或 poison 后帧出现在任何固定 reference/FIT/CAL/DEV UID 中，立即停止；不删查询、不补位、不改权重分母。
- 对固定 source SHA、原名单、旧比较语义复核两组已知计数，同时记录异常 frame/namespace 和目标交集。**仅总数相同不足以证明异常身份与目标影响相同。**整数纳秒与旧 float 时间比较的差异也不能靠忽略新倒退来凑计数。

这需要版本化修订原设计的“时间回退直接停止”，不是无科学含义的 try/except。现阶段未落地修改。

## B2：阻断成立，但“按旧代码排除上下文”不准确

独立核对 Job176975 enumeration：UNSW benign 的 INCOMPLETE_TARGET=14，mixed=2。新程序在相同已接受 context 范围内直接 STOP，确有风险。

关键源码顺序：`legacy_reference_sample_prepare_v1.ScopedPrefixes.append` **先 `prefix.append`，再检查 headers_complete 和 cap_len，最后将 valid=False 返回**。`legacy_reference_feature_adapter_v1.selected_flows` 对非目标行直接继续，但该行可能已经留在 prefix 内。故旧行为是“该帧不能当查询”，不能概括成“从上下文排除”。旧 bounded prefix 是否最终保留该帧，还取决于 burst 容量。

需要区分两类事实：

1. 仅捕获 payload 不全、所需 IP/TCP/UDP 头字段全部可见。我们不用 payload；这种包可能仍可合法更新头部上下文和基于头部的状态，不能仅凭 cap_len 更小就断言必须丢上下文。当前固定查询集合仍不得扩大。
2. 模型或状态所需头字段确实缺失。不能调用旧默认值填零来伪造完整头，也不能把直接跳过并继续说成与旧上下文等价。必须明确这一类上下文如何隔离、是否影响固定目标；若当前性/合法历史无法证明，应停在 P，而非删行跑通。

现有 14/2 聚合计数没有区分上述类型，不能据此证明某一种修复完整覆盖真实异常。建议把字段缺失类型、frame/namespace、旧 prefix 接纳情况及固定目标依赖作为 P 的前置审计输出，在新协议中明确不同类别的处理规则。请 Claude 核实其“排除并继续”建议究竟指查询资格还是上下文资格；不能仅对齐 INCOMPLETE_TARGET 总数后宣称输入等价。

## 其余意见

- 过期回收：物理状态延迟回收与统计在 >60 秒重置不是同一件事。现实现语义会在下一包重置，表满才清理及 tombstone 上限是内存策略；可记录清楚，不必仅为定时回收额外引入复杂度。不能把约 13GB 当已测的全作业内存上界。
- token 校验：同意增加独立手算 TCP/UDP/seq-ack 编码 oracle，避免“同一错误函数自证一致”；现验证仍能有效发现当前包被截断，两种验证职责不同。
- zero vector 计数按阶段取增量并标明调用次数；不把跨阶段累计误称该池独立样本数。无 rate 元数据应明确 NOT_AVAILABLE。gate 常数读封存合同，避免双份定义。
- 12 小时储备只是预算，不是性能保证；不因此新增未授权资源试验。

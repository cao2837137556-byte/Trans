## 2. 攻击查询：按场景定额，按流量头分层

B 保留了全部 72,553 条攻击，所以 B 本身没有攻击抽样的先例。Edge 有约 305 万条，必须抽样。规则如下：

- **每个场景的定额 A_s = min(N_s, 20,000)**，HTTP、UDP 各一份。
- **在场景内按"观察到的流量头类别"分层**，层的划分在本稿固定，只用包头，不用标签或分数：
  - HTTP 分为：SYN-no-ACK、PSH+ACK、纯 ACK、FIN 类（FIN+ACK 与 FIN+PSH+ACK）、RST、其他；
  - UDP 只有一层。
- **层内名额**：先按人口比例分配；每层设保底 min(该层人口, 1,000)，保底挤占的名额从最大的层中扣除。纯 ACK（7,817 条）是 C5 已知的弱点，保底能保证它有足够的样本。
- **层内选取**：按 (SHA256(salt|uid), uid) 取最小的若干条。盐值固定为 `edge-attack-query-v1-20261103`。
- 选取 20,000 的理由：召回率在 99% 附近时，独立抽样的 95% 区间半宽约 0.14 个百分点；按时间相关性放大 2 倍后约 0.3 个百分点，满足精度要求。

## 4. 规模调整规则（唯一允许的调整）

用 Linux 预检实测的单条编码吞吐量，加上距离计算的耗时，估算墙钟时间：

- 如果估算超过 24 小时，**三份定额（正常、HTTP、UDP）同乘一个统一系数 f 缩小**，每份不低于 10,000。f 只由吞吐量决定，必须在任何评分之前写进执行卡。
- 不按角色单独调整，不看任何输出后再调整。

粗算：约 64,000 次编码。C4 当时记账的 37,442 次编码累计用时约 4 万秒，按此估计在 18–20 小时左右；最终以 Linux 实测为准。

## 5. 报告口径（与 B 的配方一致）

- **逐样本**：选中样本上的精确错误数 / 选中数，明确标为"样本比率"。
- **人口估计**：正常为 Σ_g (N_g/m_g)·FP_g / N；攻击按层权重 N_layer/m_layer 加权。明确标为"估计"，并给出区间。区间用按时间块的 bootstrap 计算，块长在执行卡中固定。
- **攻击分层报告**：纯 ACK、PSH+ACK、SYN、FIN 类、UDP 各自的召回率。
- 论文中不得把样本数称为全部包数。另外同意 Codex 的纠正：B 的逐样本 FPR 也只针对选中的查询。今后 A/B 的数字也一律按这个口径表述。

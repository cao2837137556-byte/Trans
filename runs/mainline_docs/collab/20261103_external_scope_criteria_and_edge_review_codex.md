## 2. 难度描述：确为新服务端口，但不是新协议

下面“本地端口”始终指 Pi 一端，不能把正常出站访问对端的 80 端口混进来。

|目标所属包|全量正常|首 7200 秒|其后正常|
|---|---:|---:|---:|
|TCP|1,332,428|114,408|1,218,020|
|UDP|2,430|28|2,402|
|Pi 本地 TCP80|0|0|0|
|Pi 本地 UDP0|0|0|0|

正常 TCP 的 Pi 本地端口为 1883（1,330,654）、502（1,745）、44252（29）。攻击分别面向本地 TCP80 与 UDP0。**不能写“正常未见 UDP 协议”**；准确说法是同协议存在、攻击服务端口未出现。

这构成服务/流量分布改变，须与同服务内的攻击区分披露，但不能据此预言成绩。冻结 RECENT 的数值包头 token 没有直接包含端口值；端口参与组件身份，因此“新端口”本身也不能当作模型必然识别的特征。

## 3. 标签与报告单位：本次给出唯一方向规则

所有规则绑定原包 SHA、物理帧序、原始捕获区间、目标 IP/MAC；先读取完整上下文，再施加评价标签掩码。

- **HTTP 直接场景包**：固定 HTTP 原包中，`src=192.168.0.170`、`dst=192.168.0.128`、`eth.dst=dc:a6:32:fb:69:b5`、TCP、`dport=80`。全部观察到的 TCP flags 保留在会话人口，不以 flags 本身证明恶意。该方向共 **152,352** 包；其中 `ACK=1 & SYN=0` **88,262**，包含纯 ACK **7,817**、PSH+ACK **77,043**、FIN+ACK **3,003**、FIN+PSH+ACK **399**。另有 SYN 守卫包 61,641、RST 2,449。观察到的 GET 起始包 19,076 单列。
- **UDP 直接场景包**：固定 UDP 原包中，目标 IP/MAC 同上、UDP、`dport=0`，共 **2,898,830**。全量头部复查确认该数字全部是目标端口 0，不只是有界 Counter 的前缀。论文明确 hping3 可伪造源地址，因此不以四个示例 IP 限制来源。冻结端点范围允许端口 0，不为适配数据改规则。
- **反向与背景**：保留作原始上下文和独立审计，不算攻击或可信正常，不进参考。HTTP 中 `216.58.198.74:80` 对应 Pi 本地 42162 的背景通信；旧 88,280 的 ACK 候选混入其中 **18** 条，修正为 88,262。

主要报告同人口的逐包 FP/FN、FPR/召回；直接 ACK、PSH+ACK、GET/载荷、SYN、UDP 分层。纯 ACK/FIN/握手是攻击会话控制流量，**不是独立 ACK 洪水**。两份攻击文件只能称两个场景捕获组，真实重复事件数未知；不能把随机源 IP 或数百万包当独立攻击次数。加权口径拟按设备/场景捕获/组件登记，缺少官方独立事件时不编造事件门通过。

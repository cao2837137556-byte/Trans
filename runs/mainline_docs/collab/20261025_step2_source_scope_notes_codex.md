# Step2 源侧实现口径与已发现的数据缺口

2026-10-25。对应 Claude `20261025_c1_c3_readout_and_step2_r1_claude.md` 第 3.1、5、6 节；第 2 节已由用户确认。本文件先记录实现中发现的前提问题，不改主方案、原结果或评价合同。

1. **“从已编码 LEARN 早期窗口直接取密参考”目前不可兑现。** 全部 766,727 个 LEARN query 都严格晚于各设备原 `reference_end`。现成早期编码仅 SOURCE_REFS 的 104 个点，因而只复用已编码资产的源 DENSE 与原库完全相同。完整源 CAL dry-run 能验证保护器，但不能据此宣称密参考校准就绪。
2. **源窗口不是目标侧统一两小时。** 原源合同是 6 台 LEARN 设备、13 个正常 REFERENCE capture 的并集，并保留原逐设备截止时间；Philips 的两段短 capture 相隔约 84 分钟。实现显式传入每份 capture 的 source SHA／时间／frame 范围，不能自行用 `reference_end-3600/7200` 造新窗口，也不能把后来的 FIT/CAL 正常查询挪入参考。窗口长度/组成若要改变，由 Claude 另立修订。
3. **当前可完成的准备：** 实现不看 label／score 的确定性位置规划器，保留原 B2/SOURCE_REFS，encoded 优先，再按组件轮转、组件内时间均匀选位，固定盐 `claude-dense-reference-r1-20261025`，每设备协议 ≤4096。选后另作可信正常与 CAL component 隔离审计，不把攻击或 CAL 行静默重标正常。
4. **补编码预算先做合法位置 census。** 13 份源 PCAP 共 4,771 个原始包，已在本地、无需云端下载；原包数只给 ≤4,667 个额外位置的保守上界。正在用当前生产 decoder/context/query_allowed 链生成真正合法位置与逐 UID 补编码清单；不会把历史 `old_candidate_count` 当当前合法数，也不会运行 E3。目标侧当前只报已编码去重数量及上界，未经完整合法枚举不报假精确数。
5. **预算保护的具体化：** 固定原 λ 网格、几何、尺度、切点、strict `>` 和集成加法顺序。CAL 攻击沿原规则对合法 donor 撤警 UID 取并集，每个 UID/suffix 计一次，再用源类层级权重执行 ε、99% 绝对底线、设备和 annotation 损失限制；正常目标取四 suffix 的自身参考加权误报修正量均值。ε=0 选择严格复用旧保护器，新增绝对/分组验收另列，避免基线本身不达 99% 时为了“兼容”伪称新合同 PASS。

完整回传将链接 C2b、C4、单元测试、源 CAL 和补编码清单。云端运行尚未授权；真正密源库补编码及对应 CAL 保护完成前，不把“原库源 dry-run PASS”当成完整矩阵入口已通过。

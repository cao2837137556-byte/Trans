## 3. 集中推进的流程：补一次材料，检验一个固定候选

1. **材料资格。** A使用已核实历史参考及当前编码；B取得上述具名设备原始材料，核验SHA、身份、可信正常、真实时间、捕获/连接依赖、现前端合法性及新增组件。先报告到底补了哪些行为；大量同连接包不算丰富覆盖。B若不能取得或不增加有意义覆盖，直接记录此缺口，不继续无目标下载其他数据集。
2. **冻结一个“可信历史＋现有密库”候选。** 统一按来源、时间和组件规则合库，保留现有参考，不凭A/B误报标签或近cut分数挑点。固定容量与抽样规则，不试500/2000/5000三档；源/目标都报告有无历史和回退。精确容量、源折角色和运行预算在实际候选数量明确后一次封包。
3. **复用当前表示，验证攻击保护。** 仅新增缺少的参考编码；当前查询E3不重建，首轮不同时改检测头、cut、距离和训练损失。新库可能让攻击也获得正常支持，必须评估相对RAW累计撤回、设备1pp/活动或annotation5pp、三seed与ensemble及既有适用保护。旧CAL安全不能替新库背书。
4. **通过源侧检查后，一次固定A/B评价。** 保持179700原观察期后查询、权重与设备分母；新参考必须早于其可作用的查询。报告池/设备FPR、召回、原FN/新增FN及覆盖，目标仍为池与设备FPR≤2%、池召回≥99%和原保护。未达目标或安全失败如实结项，不按A/B成绩挑库、删设备或调窗口再试。

**当前尚缺的是可核验的B原始包和与新合库规则一致的源角色安排。** 现有六源设备库是早期REFERENCE，Active里大量点已有FIT/CAL角色，并无可直接照抄的六源B2库；不能为了做源门，把同一查询当参考或把HELD∩FIT用作校准/选型后再当独立S。完整输入、角色和预算未闭合前，不把本文称为可直接sbatch的执行卡。

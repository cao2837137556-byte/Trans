# 换头之外：三条更低成本的支线

日期：2026-10-22。补充 [下一轮联合比较复核意见](20261022_next_head_and_onboarding_plan_review_deepseek.md)。只讨论方案，不启动实验，不改冻结结果。

## 为什么还要想别的

Codex 的换头比较值得做，但它的定位应是“排除分类器家族假设”。当前证据更像三个具体问题，而不是“分类器不够复杂”：

1. **分数整体平移**：B 的 TCP_OTHER 正常分数，源 CAL 中位数 -42.1121，B 中位数 -22.6013，而源阈值是 -22.6637；B 正常分布整体向告警侧移动。
2. **阶段高度集中**：B 主方案 TCP_OTHER 占加权 FP 的 74.3457%；不是正常 SYN 与 SYN 攻击分不清（正常 SYN_NO_ACK 1,603 条，FP 0）。
3. **A 的参考覆盖不足**：A 新库只覆盖原 FP 的 8.4122%、正支持 0.4699%；这更像参考采集/资格设计问题，不是换头能修的。

因此，除了换头，我会优先做下面三条低成本支线。它们主要用已保存的分数、参考和特征，不需要重训前端。

## 支线 1：用参考库的“正常分数”做校准，而不只用表示距离

### 想法

当前入网模块只用 E3/q14 距离算支持度，再对 logit 做有限下调；它没有使用**参考样本自己的头分数分布**。但 B 的问题正是正常分数整体平移。可以做一个“参考分数校准”：

对查询 q 的同设备、同协议、合法参考集 R（≥2 个独立组件，早于查询）：

- 用当前头给 R 打分，得到参考分数 `s_r`；
- 用稳健位置/尺度：`m = weighted median(s_r)`，`scale = max(1.4826*MAD(s_r), floor)`；
- 校准分数 `z_q = (s_q - m) / scale`；
- 告警规则改为 `z_q > c_z`，`c_z` 只在源 CAL 上定；同时保留一个全局绝对下限或原阈值作为回退；
- 参考不足、协议不支持、查询早于库截止时，回退到原全局阈值。

这相当于把“这个设备正常的分数大概在哪”直接学出来，而不是假设所有设备共用一个绝对分数。它和当前模块可以二选一，也可以串行：先做表示支持修正，再做分数校准。

### 为什么值得先试

- 直接对应“分数平移”证据；比换头更贴近病灶。
- 只用可信正常参考的分数，不用目标攻击标签；参考库身份、时间、资格规则不变。
- 参考数量是几十到几百条，给参考打分是一次很小的前向，不需要重训头或重做 E3。
- 可以按设备/协议/阶段分组；组太稀疏时逐级回退，不会强行造覆盖。

### 风险与验收

- 如果参考分数本身很高，阈值会被抬高，可能漏攻击；必须用源 CAL 攻击做保护，并对目标做同头零新增漏检配对。
- 参考太少时估计不稳；设置最小参考数、稳健尺度下限和回退。
- 这是新的决策规则，必须事先登记；不能看了 B 的结果再选分组或分位数。
- 先做离线诊断：用已保存的目标分数＋参考分数，算“如果按设备/协议校准，FPR/召回会到哪”；如果连乐观上限都不够，就不进入部署实现。

## 支线 2：先做“源/目标正常域可分性”诊断，决定换头有没有用

### 想法

在同一个 E3/q14 表示上，训练一个很小的分类器区分“源 FIT 正常”与“目标正常参考/正常查询”，看 AUC：

- AUC 很高（例如 >0.8）：说明表示里仍保留很强的域/设备信息，换一个同输入的分类头大概也难跨域；应优先做表示/域适应，而不是继续堆头。
- AUC 接近 0.5：说明源/目标正常在表示上重叠，FPR 高更像是分类边界/校准问题；换头和分数校准更值得试。

这个诊断只用正常样本，不使用目标攻击标签；如果使用目标正常查询，必须标明是诊断用途，不进入部署模型。

可以再做两个更细的版本：

- 按设备/协议/阶段分别做域分类，找出哪一块最可分；
- 用线性探针或特征重要性看 q14（尤其 TCP 标志位）与 E3 各占多少；如果域分类主要靠 q14 的少数位，说明“当前包描述”可能是捷径而不是稳定证据。

### 为什么值得先试

- 它能提前回答“换头是不是在白费力气”，比跑完三个头再猜便宜得多。
- 现有特征和标签都在本地，训练一个线性/小 MLP 域分类器成本很低。
- 如果域可分性很高，论文的叙事也应从“换头”转为“跨域表示/正常覆盖”，否则容易把负结果解释错。

## 支线 3：按当前包阶段做条件校准，而不是一个全局阈值

### 想法

B 的误报 74.35% 集中在 TCP_OTHER；但全局阈值把所有阶段混在一起。可以先做**诊断性**的条件阈值：

- 在源 CAL 正常中按阶段（UDP、TCP_RST、TCP_SYN_NO_ACK、TCP_SYN_ACK、TCP_FIN、TCP_OTHER）分别定 1% 加权 FPR 阈值；
- 每个阶段要求最小正常样本/权重，不足则回退到全局阈值；
- 用源 CAL 攻击检查各阶段攻击保护；
- 在 A/B 上用同一套规则报告，不按数据集开关。

如果条件阈值能把 B 的 1% FPR 召回上界明显抬高，再考虑把它做成正式的条件校准；如果抬不动，说明问题在分数排序/表示，不在阈值位置。

### 为什么值得试

- 证据直接：错误集中在 TCP_OTHER，单一全局阈值天然会被其他阶段稀释。
- 只用源 CAL 正常定阈值，不看 B 的攻击标签；目标阶段只用于评价。
- 计算成本几乎为零：已有分数＋阶段标签即可做离线诊断。
- 它和换头不冲突：换头改变排序，条件校准改变工作点；两者可以分开归因。

### 风险

- 条件阈值是新的决策规则，组内样本少时不稳定；必须有最小样本和回退。
- 不能用 B“攻击全是 SYN”来给其他阶段放行；源 FIT/CAL 的其他阶段攻击仍要保护。
- 先做诊断，不直接改冻结系统；如果有效，另立协议版本，A/B 同规则。

## 支线 4（数据/协议，稍后）：A 的参考覆盖重新设计

A 的新库只覆盖 8.41% 的 FP，正支持 0.47%；这不像模型问题，更像参考窗口/资格问题。可以在不改前端的前提下检查：

- 全局 t0 起 1h/2h 是否错过了某些设备首次正常活动；若设备在 t0 后很久才出现，考虑“每设备从首次可信正常活动起算，最多 2h”的锚定窗口；
- 同一设备/协议在窗口内是否真的有 ≥2 个独立组件；如果没有，任何模块都修不了，应如实报告材料限制；
- 在 64 个组件预算内，用 E3/q14 的多样性（k-center/聚类）选参考，而不是只按时间/hash；仍然只从可信正常段选，不看查询标签；
- 对长捕获，考虑“查询前最近 2h”的滚动参考，而不是全局固定库；这仍是因果的，但属于新协议，必须单独登记。

这些是数据/协议设计，不是换头；如果 A 的 FP 多数落在硬性无参考区，换头和模块都救不了，补正常材料或改资格才是正路。

## 支线 5（更后）：小型、受约束的学习修正

如果换头/覆盖/分数校准之后，仍有大量“有支持但修不动”的 FP，再考虑学习修正；不要直接复活旧深度校验器。建议：

- 特征只用：头 margin、支持度 a、D2、阶段、参考分数统计；
- 模型用单调/低容量（逻辑回归、单调 GBDT、少量分箱），约束“支持越高，最多只能把分数降到某个上限”，不允许升分；
- 训练只用源 FIT/CAL，目标只评价；源 CAL 攻击保护 + 目标同头零新增漏检；
- 先做源内交叉验证，确认不是过拟合源设备，再上目标。

它的目标是学“什么时候参考支持可信”，而不是再学一个攻击分类器；旧 A 的正向结果说明参考信息有价值，但旧深度模块在 B 撤攻击的教训不能忘。

## 和 Codex 方案的关系

- 换头比较仍然做，但把它当筛查；上面三条支线可以作为**并行/前置的低成本诊断**，不改变换头矩阵。
- 支线 1、3 是决策规则变化，必须另立版本、事先登记；不能直接塞进已冻结的 QUERY_TAIL/入网结果。
- 支线 2 是纯诊断，不进入部署，不产生新模型效果声明。
- 支线 4 是数据/协议设计，等覆盖普查结果再决定；不在本轮改 B0/B1/B2 定义。
- 支线 5 放在最后；如果前面的证据显示“支持足够但修正不足”，它才值得投入。

## 我建议的最小顺序

1. 先做支线 2（域可分性）＋A 覆盖普查＋B 支持/修正余量：都不需要重训，能决定后面往哪走。
2. 同时做换头 P/T/K 筛查。
3. 如果域可分性低、B 仍有大量可修正 FP：做支线 1（参考分数校准）和支线 3（阶段条件校准）的离线诊断。
4. 如果 A 覆盖是硬缺口：转向支线 4，不继续堆头。
5. 只有前面都显示“支持足够但固定规则修不动”，再上支线 5。

这些不是替代 Codex 的方案，而是增加“换头之外”的可证伪路径；哪条先做，取决于覆盖普查和域诊断的结果。

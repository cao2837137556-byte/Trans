# 阶段条件校准 v1：源侧最小验证与密参考组合方案

2026-10-28，Codex制定。依据[新目标判断](20261028_next_direction_2fpr_99recall_codex.md)和[数据核查](20261028_phase_feasibility_data_readout_codex.md)。用户本轮要求制定方案；本文和对应PLAN.json是可交实现的规格，**本轮没有执行新校准、距离计算、训练、编码或云端作业**。后续本方向以本稿为准，旧实验仍按旧合同记录。

## 1. 核心假设与本次只改的因素

保留QUERY_TAIL、密参考V3的表示、参考库、窗口、资格、几何、scale、λ=.25及固定三seed集成，只改最终判定阈值层。假设：不同包阶段的正常分数偏移不同，共用一个阈值会把其他阶段的正常误报与SYN阶段的攻击保护绑在一起；源侧条件阈值可能减少这种跨阶段混排。

这是可证伪假设。B当前99%描述性边界剩余FPR3.676680%，全部来自FIN／OTHER；继续抬总阈值造成的新增FN全部是SYN_NO_ACK。但B所有攻击原本都属于SYN_NO_ACK，不能因此直接放行其余阶段。源有OTHER和UDP攻击，必须用它们验证；阶段内的正常／攻击混叠仍可能使本路线失败。

不新增检测头、训练前端或学习型修正器。本次校准是新的完整判定规则，允许某阶段阈值向上或向下移动；原V3的减分函数保持不变。每次必须分别报告修FP、新增FP、修FN、新增FN。

## 2. 目标、预算与证据等级

下一版主部署对象仍是固定27／127／227集成，不选最好seed。**A、B各自观察期后加权FPR≤2%、攻击加权召回≥99%；逐设备FPR≤2%的原要求保留。** 全量并列。3个单seed全部报告；四suffix均检查攻击保护，主目标是否达成以预先固定的ensemble判定，不能事后切换聚合方式。单seedFPR与稳定性另列，不冒充ensemble结果。

新版本以绝对99%召回为池底线，**不再叠加旧池相对ε=.1个百分点限制**；否则不能探索用户认可的99%区间。旧179700仍保留原ε合同。设备≤1个百分点、activity／annotation≤5个百分点的撤警护栏保留；由于现在允许恢复原FN，保护量明确为**原BASE已检出的TP中被新规则撤回的权重质量**，恢复其他FN不得抵扣。另报告净召回变化。

在源校准与后续评价中还增加phase内分组撤回护栏，是本版保守选择，不声称它原来就属于合同。每phase绝对99%及LOW_SUPPORT零撤回仅用于CAL；HELD和A/B的绝对召回按各自整池／整折要求判断，不能误用完整CAL门。A/B只能作冻结规则的开发评价，不能选cut、阶段定义、资格或回退；仍需独立确认数据支持泛化。

## 3. 固定阶段与支持等级

沿`query_tail_core_v2.py`的互斥优先级：UDP → RST → SYN_NO_ACK → SYN_ACK → FIN → OTHER。从封存window.stage取值，并以q14二值flag复核。它是当前包标志类别，OTHER不是“正常业务”或经状态机确认的连接状态。

每次校准仅用**该次CAL元数据**生成支持等级，对所有seed和ensemble完全相同，不按某个头已检出多少攻击改变等级。分别统计正常／攻击的设备、原始capture、component；capture身份用`source_sha256`，component用`(device, component_id)`。

| 等级 | 元数据条件 | 规则 |
|---|---|---|
| FROZEN_NO_EVIDENCE | 该阶段正常为0，或攻击为0 | 严格使用该头原cut；不参与阈值优化，记保护信息不足 |
| LOW_SUPPORT | 两类都有样本，但任一类的设备／原始capture／component任一项少于2 | 可校准，但该阶段原TP必须零新增撤回；其他绝对与组护栏仍执行，明确标为低支持 |
| SUPPORTED | 两类的上述三种计数均至少2 | 可按第5节预算校准 |

计数是覆盖描述，不是统计独立性保证。G0 CAL OTHER的21条攻击来自1台设备，固定进入LOW_SUPPORT，采用零撤回；这样可以检验其跨设备迁移，同时不把稀疏材料当成充分保护。RST／SYN_ACK／FIN因源攻击为0进入FROZEN_NO_EVIDENCE。未知阶段、缺失phase字段或协议非法属于输入错误，停止，不猜测类别。

LOW_SUPPORT仍有错误迁移风险，必须由HELD检验；源侧零撤回不等于目标安全。不得看到HELD或A/B结果后，在“冻结／低支持可调”之间择优，本版已固定上述规则。

## 4. 三个同分数对照

对每个独立头／suffix，使用相同CAL与评价查询、相同输入分数和支持等级：

| 臂 | 阈值规则 |
|---|---|
| Q0 | 原冻结cut，精确复现已有结果 |
| QG | 所有非冻结阶段共享一个新cut；FROZEN阶段仍用原cut |
| QP | 各非冻结阶段分别选择cut；FROZEN阶段仍用原cut |

QG准确名称为“同回退范围的共享阈值”，并非改变全部样本的无条件全局阈值。QG与QP的可改范围完全相同，差别仅在cut是否随phase变化；不能把不同回退范围的收益算成条件校准收益。

cut按每个suffix各自分数尺度在源侧确定。主头和折头的cut、scale、normalizer不能互相搬用；ensemble分数沿各自产物的原算术路径生成，不能平均seed的cut或先阈值再投票。

## 5. 确定性阈值选择算法

### 5.1 分数与权重

正常目标始终使用本次输入分数的正常查询：原头探针用保存raw分数，密参考组合用own参考修正后分数。权重按该CAL、该label内的原`device→activity→capture→session→row`层级重建。对phase／设备／攻击组的条件指标，只条件化这些已有权重，不重新改变层级。

攻击约束使用第7节规定的安全分数／场景。原TP基准均为该头**原BASE在原cut下的判定**，不以QG或其他候选为新基准。主DENSE的绝对召回由候选实际TP算出，不用“原TP减新漏报”代替，以便正确记录旧FN恢复。

### 5.2 候选与约束

在需选择cut的CAL集合上构造有限候选：原cut、所有有限正常own分数、攻击`worst_donor_safety_score`（原头探针就是raw攻击分数），以及这些观察值的float64前驱`nextafter(value,-inf)`；去重排序。不得用密参考攻击own分数替代安全分数。禁止NaN／Inf、拆分同分组和ROC插值。判定固定为`score > cut`，比较数组显式为float64；保存的float32原头分数先无损提升，避免弱标量类型转换把float64前驱折回同分数。QG用所有可调阶段的候选并集；QP分别用本阶段候选。

每个可调phase必须同时满足：

1. 该phase的安全攻击加权召回≥99%；
2. 对该phase内每个有攻击的设备，原TP新撤回质量／该设备该phase全部攻击质量≤1%；
3. 对该phase内每个有攻击的activity和annotation（字段存在且非空时），上述撤回比例≤5%；
4. LOW_SUPPORT阶段所有原TP新撤回数必须为0。

这里1%和5%的撤回比例分别对应召回损失1和5个百分点。QG的同一个cut须满足所有可调phase的约束；QP各phase独立满足，因此无需高维联合搜索。完成后在**整个CAL、四suffix**再验证绝对召回≥99%及原设备／攻击组撤警护栏。冻结阶段无攻击记NOT_EVALUABLE_FROZEN，不虚报其保护PASS；它们的判定须与Q0完全一致。

在可行候选中按固定字典序选择：

1. 正常加权FPR最低；
2. 安全攻击加权召回最高；
3. 与原cut的绝对移动最小；
4. 数值更小的cut。

QP按phase使用此顺序；QG在可调阶段整体上使用此顺序。若原cut已正常0误报、攻击0漏报，保留原cut，不为了利用攻击分数间隙无收益地大幅抬阈值。只有LOW_SUPPORT／无证据等实际状态，不按人工指定“B的SYN需要保护”设置特殊cut。

候选不可行或全CAL绝对召回门不通过时输出`SOURCE_CAL_INFEASIBLE`，保留Q0供报告，不能把Q0替代成该候选的成功评价，也不能静默放宽约束后继续；其他登记臂照常完成。指标用未舍入权重及`math.fsum`复算；临界预算用元数据生成的有理数权重核对，不用可调epsilon容差改门。排序前缀和可用于加速，最终选择必须与小规模穷举参考实现一致。

- 每折CAL依第3—5节独立生成QG和QP；全部四suffix结果均保留。总共2折×3臂×4suffix=24个对照格，每格CAL／HELD两份指标，共48份指标报告，没有新头。
- 阶段、回退、算法、推进判据均在看新结果前冻结。当前已见旧BASE／CTX结果，此probe属于开发验证，不宣称新的独立确认集。

### P1推进判据（在本轮方案中事前固定）

先检查全部身份与输入门，完成所有登记对照。以固定ensemble衡量正常收益：

1. 两折QP的HELD FPR均不高于Q0，也不高于QG；
2. **至少同一折**同时达到QP相对Q0的FPR下降≥20%、相对QG下降≥10%；在这个折至少2/3 seed也同时低于各自Q0和QG；
3. 两折四suffix均通过全折设备≤1个百分点、activity／annotation≤5个百分点的原TP撤回护栏，并通过各phase内设备≤1个百分点、activity／annotation≤5个百分点的撤回护栏。HELD**不照搬CAL的“每phase绝对召回≥99%”门**；CAL的LOW_SUPPORT零撤回也不扩展为HELD零撤回，HELD按上述加权护栏评价并单列低支持阶段迁移损失；
4. 对原Q0召回≥99%的折／suffix，QP须保持≥99%；原Q0召回<99%的折／suffix，QP净召回不得低于Q0。后者只表示增量保护通过，**不表示已实现99%目标**。

20%／10%是相对FPR降幅，不是百分点。Q0或QG FPR为0时，该对应正向降幅条件记无改善空间，不得除0或据此造成功。G0原ensemble召回约88.6%，可降低某些cut修FN，但不要求一个只撤警规则完成不可能的绝对99%验证；修FN、新增FP必须完整报告。

全部满足则为`SOURCE_SIGNAL_PASS`，推进P2；保护或不退化门失败为`SOURCE_SIGNAL_FAIL`；无可调阶段、缺必要分数或校准不可行分别记明确原因，不自动选另一套算法重跑。若QG有效、QP没有额外收益，应记录“仅支持共享校准”，不把QP升级，也不临时把本轮主方法换成QG。任何科学FAIL仍完成所有P1登记对照，保留原因分账。

## 7. P2：主密源逐UID分数重建与组合校准

### 7.1 必须保存两种语义

- **own全CAL分数**：正常用同partition／device／protocol的own参考；攻击从供体矩阵取对应own列，无own列则支持0。保存UID、CAL索引、label、phase、权重、raw三seed及ensemble、own support／eligible、修正后三seed及ensemble、原判定。

当阈值仅依查询phase、λ／scale固定时，可缓存合法场景的最小分数为`worst_donor_safety_score`来加速约束；先验证它与逐供体判定完全等价。它是保守保护分数，**不得叫own部署分数或混入own ROC**。每个suffix先沿原精度路径得到场景分数，再求最差值。

## 10. 成本与执行界限

本轮仅制定方案。下一步实现优先P1和合成测试；P1是现成分数排序与统计，预计分钟量级，无GPU。建议首包上限4 CPU、进程树RSS8GiB、30分钟、输出512MiB，最终以实现后的有界实测执行卡为准。

P2只重算源参考支持与落盘分数，原179602的两臂源CAL耗时207.47秒可作历史参照；新序列化和运行环境会影响耗时，不直接当新ETA。拟上限4 CPU、RSS8GiB、60分钟、输出1GiB；若云端用Slurm申请16GiB给解释器及系统余量。原环境不具备时先解决环境问题，不自动提交替代作业。P3仅保存分数评价，独立给预算。均无自动重试、无AI持续轮询，若运行则用普通隐藏进度程序显示阶段、终态、失败原因。

本轮预期得到的近期答案是：**phase条件校准是否比同范围共享校准具有可迁移的额外收益。** P1过关只支持进入主系统组合，不保证2%／99%必达；P1不过关就凭具体失败原因停止这一候选，而不是继续堆训练轮数。

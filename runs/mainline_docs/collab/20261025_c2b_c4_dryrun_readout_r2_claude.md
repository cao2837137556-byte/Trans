# C2b / C4 / 源侧 dry-run 判读与第二步 r2（Claude）

2026-10-25。依据：[Codex 回传](20261025_c2b_c4_and_step2_source_dryrun_response_codex.md)。修订 [r1](20261025_c1_c3_readout_and_step2_r1_claude.md) 第 3、5 节；r1 第 2 节口径（ε=0.1pp、观察期后主指标，用户已确认）不变。Codex 的实现、测试和停止位置都符合要求，接受全部更正。

## 1. 判读

1. **服务级延续：放弃。** 按 r1 第 3.2 节的既定条件：严格口径只覆盖 0.65%，宽口径与 B 池 60% 的攻击权重相交。不再从这个方向改身份规则。
2. **Samsung、WEMO Switch、HeimVision 的 TCP 是结构性残差。** 三台设备在窗口里都只有 1 个真实 TCP 组件，"至少 2 个组件"规则把它们整块挡在外面：B 约 7.0 个百分点，A 观察期后 2.74 个百分点。密参考增加的是位置，不是组件，修不到这一块。
3. **源侧"无需补编码"的前提不成立。** 更正为补 4,624 个冻结位置，约 13.5 MiB。接受 Codex 的冻结清单，以及"缺任一 UID 即拒绝、不重新选位"的规则。
4. **源 CAL 的保护目前几乎不起约束作用。** 四个 ε 都选在网格上限 λ=0.25，源侧全部攻击召回 100%。这与问题简报瓶颈 4 一致：cap 碰不到 CAL 中已检出的攻击。因此 C3 那 3 条漏检，源 CAL 预先发现不了；目标侧的攻击损失要靠评价时的 ε 验收来把关。λ 网格和 cap 维持不变。保护信息不足这个事实，要在结果中如实报告。

## 2. 第二步 r2 执行

**2.1 补编码（需要用户授权云端运行）**
- 源：按冻结清单补 4,624 个 E3 编码，验证原 104 个参考的数值身份，再在真正的密源库上重跑四个 ε 的源 CAL。
- 目标 A/B：先精确枚举每个（设备，协议）组的完整合法位置，替换 48,463 这个上界；再按 r1 第 3.1 节的规则补编码到 4,096 上限。
- 正式编码前，先用一小批跑出实际吞吐，给出 wall-time 估计，写进授权申请。

**2.2 并行只读核查 C5：单组件资格（不编码、不训练，与 2.1 同时做）**

这一项针对第 1 条的结构性残差，做法与 C3 相同：先诊断，再决定是否登记成新臂。
- 规则变体"1C"：只有 1 个真实组件、且该组件参考位置 ≥ 8 的（设备，协议），用该组件内第 2 近的**位置**代替"第 2 个不同组件"计算 joint。V3 的距离、半径、scale、λ 都不变。
- 范围：B 的 Samsung、WEMO Switch TCP，A 的 HeimVision TCP。参考用 B2 库加窗口内已编码查询（与 C3 的代理相同）。
- 报告：误报中获得正支持、被修掉的条数与权重；两池全部攻击 TP 中获得正支持的条数与权重、新增漏检数，以及对应的加权召回下降（按 r1 第 2.1 节的三个层级）。
- 源侧：Amcrest TCP、Atomi、Globe 也是单组件。报告在 1C 规则下，源 CAL 攻击能否获得合法支持对，即源侧对 1C 是否有保护信息。

判读：
- 若误报质量明显下降，且攻击损失在 ε 预算内、源侧有保护信息：登记 R-1C 和 R-DENSE+1C 两个单因素臂，与 r1 的三臂同批运行。
- 若攻击损失超出 ε，或源侧没有任何保护信息：不登记，这块残差转交第四步。
- 不按 A/B 结果调整 1C 的阈值 8 或"第 2 近位置"的定义。

**2.3 完整矩阵**
r1 第 3.1 节的 R-B2 / R-DENSE / R-DENSE-WRONG（若 C5 通过，再加 R-1C / R-DENSE+1C）× ε{0, 0.05, 0.1, 0.2} × 3 seed + 集成，三池四 suffix 回归。观察期后为主，全量并列。

## 3. 第四步提前准备

按目前所有证据，参考侧（密参考，加上可能的 1C）做到最好，B 仍会剩几个百分点；HeimVision 的 UDP 零支持也可能需要检测头侧处理。第四步大概率要做。补编码运行期间，我起草第四步设计（主机级上下文 vs 增加源正常多样性），写在 collab，供 Codex 审阅。第二步结果出来后，按残留分账二选一，不等第二步结束才开始设计。

## 4. 给 Codex 的顺序

1. C5 只读核查，回传。
2. 准备补编码作业包：目标侧精确枚举、小批吞吐测试、wall-time 与资源估计，写成授权申请。用户授权后运行补编码与密源 CAL。
3. 密源 CAL 通过后，运行 2.3 完整矩阵（同一授权内可连续执行；若资源或时长超出申请，另行申请）。

### A/B为何变差：必须把参考库变化和三维变化分开

B在同一两小时库的二维+OLD就已有22636条正常误报（30.406749%），三维+OLD为22772条（30.589436%），增加136条。A二维+OLD为89条（加权4.520671%），三维+OLD91条（加权4.669480%）。因此相对现行C5的大退化主要关联历史覆盖被去除；三维附加约束还会缩小支持，不能归因为“3D提升了误报抑制”。

Edge相同参考库下：二维+当前1158条FP→三维+当前1163条；二维+OLD17条→三维+OLD24条。降低正常误报主要来自较强OLD尺度；三维的核心价值是减少给攻击的错误支持，使使用较强尺度时HTTP损失大幅减小。这是2×2对照直接支持的机制，不是两个改动都各自降低误报。

本轮没有计算“历史扩充库+三维+OLD”，不能宣称该组合已能保住A/B。

## 4. 任务3/4：能否收敛及下一步

**不能仅靠三维C5+尺度完成当前目标，也不应继续源FIT加权硬压正常风险。** 后处理已修复主要HTTP撤警机制；UDP的绝大多数RAW漏检仍处于高流量，单靠扣分式C5不可能新增检出。当前RAW上限HTTP99.83%、UDP98.66%，都低于99.9%。

建议按两个问题分开推进，下一轮须另行封存执行卡：

1. **先完成零重训的历史参考对照**：保留A/B现行C4历史正常参考资格、时间边界和UID，因果重放补齐各参考context，校验同库二维完全复现当前成绩，再做三维×两尺度。继续复用本轮源rho_c，不利用目标攻击重新拟合。它用于判断三维后处理能否在不丢历史覆盖的条件下改善Edge并保住A/B；不能预先承诺结果。
2. **RAW训练修复优先查context分支的负向依赖**：在源FIT上预注册与原FUSION790对照的紧凑物理单调分支/导数约束候选，明确哪些量有可辩护单调性及固定其余输入时的含义。重点检查10s源数方向，但不能把Edge上的诊断事后包装成独立泛化证据，更不能简单把当前MLP某一层权重截零称为全网单调。
3. **E3块遮盖作为独立消融**：原头、仅context约束、仅E3块遮盖、两者组合，固定源数据/训练预算/三种子。是否使用其组合由源FIT/CAL预定保护门决定，不靠Edge选轮次。编码器继续冻结；E3遮盖必要性尚未由这轮证明。

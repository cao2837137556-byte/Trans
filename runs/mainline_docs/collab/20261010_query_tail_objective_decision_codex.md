# Codex 对 Claude 跟进第 2.1 节的决定

日期：2026-10-10。回应 `20261010_query_tail_assessment_followup_claude.md`，重点为是否在新版去掉目标函数的 `/2`。本轮只核对已有代码、合同和协作意见；没有模型前向、训练、超算连接或旧诊断重跑。

**决定：同意。下一版 R2/R3 采用 `L = L_BCE + L_tail`。这是目标函数与训练观测的联合修订，应另立版本、合同和交付包。当前没有改动封存 v1 或实现新版。两边在这一选择上没有分歧，无需将技术分歧交用户再次裁决。**

## 1. 为什么同意

最直接的理由是对照清晰：让四臂的 BCE 系数均为 1，改变排序项时不再同时把原 BCE 系数减半。

| 臂 | 封存 v1 | 下一版决定 |
|---|---|---|
| R0 RECENT | `L_BCE` | `L_BCE`，复用已完成基线 |
| R1 QUERY_BCE | `L_BCE` | `L_BCE` |
| R2 RECENT_TAIL | `0.5 L_BCE + 0.5 L_tail` | `L_BCE + L_tail` |
| R3 QUERY_TAIL | `0.5 L_BCE + 0.5 L_tail` | `L_BCE + L_tail` |

BCE 内部原有正常/攻击各占 0.5 的 FIT 权重继续保留，TAIL 的攻击条件权重 `p_i=2w_i` 也保持。改变的是两个损失分量的外部系数 0.5→1，而不是更改类别、设备或活动的分层权重。两分量相对比例仍为 1:1，整体优化尺度发生了实际变化，不能称作纯日志改动。

现有 `query_tail_core_v1.py` 确实返回 `(bce+pair)/2`；`query_tail_train_v1.py` 使用 AdamW，`eps=1e−8`、`lr=3e−4`、解耦 `weight_decay=1e−4`。固定梯度历史整体乘以常数 c 时，理想化 Adam 梯度更新项为：

`c*m_hat / (c*sqrt(v_hat)+eps) = m_hat / (sqrt(v_hat)+eps/c)`。

因此 c=0.5 相当于有效 epsilon 加倍。在相同状态的这个对照中，梯度更新量相对于未缩放项的比例为：

`(sqrt(v_hat)+eps) / (sqrt(v_hat)+2*eps)`。

只有在 `sqrt(v_hat)` 远小于 eps 时，该比值才趋近 0.5；远大于 eps 时趋近 1。解耦权重衰减的规则不会跟着损失缩放。因此 `/2` 确有可能改变梯度更新相对于权重衰减的作用。去掉它可以减少一个不必要的对照差异，不需要先证明该影响在本次真实训练中已经很大。

## 2. 同意变更时保留的三个限定

1. **尚未证明本项目后期处在 epsilon 主导区。** 平均在线 BCE 约 1e−11，不等于参数梯度或 Adam 二阶矩也约为 1e−11。参数梯度包含批权重、输入和网络导数；二阶矩还包含历史。Claude 将其列为推断而非实测是合适的，新日志应验证它。
2. **非饱和区的缩放近似不变性有条件。** 上式要求全部历史梯度保持整体比例、比较点的参数相同，并忽略浮点等差异；不能由此说 R2 与 R0 完全等价。TAIL 本来就可能改变梯度方向和之后的轨迹。新版与 v1 的数值差异大小也不能预先保证可忽略。
3. **新目标在 TAIL 为零时，恢复的是当前位置的 BCE 目标/梯度。** 早期 TAIL 已经造成的参数、Adam 一阶矩和二阶矩差异仍会留下来；不能承诺后期动力学或终点等于 R0。这不妨碍该对照检验“加入 TAIL 的总效应”，但阶段归因仍须结合轨迹。

这项修订改善的是实验解释，不保证 UNSW FPR 下降，不改变原科学验收门槛，也不额外增加一个损失系数搜索或新候选臂。

## 3. 同意补记 Adam 状态，并明确记录时点

分量梯度与 cosine 在既定探针 batch 的 **更新前**、同一参数与同一前向图上测量；Adam 二阶矩摘要建议在该 batch 的原 `optimizer.step()` **之后**读取。

后者使用每个参数实际保存的 step 和 `exp_avg_sq`，按本组 beta2 计算：

`sqrt(v_hat_t) = sqrt(exp_avg_sq_t / (1-beta2**step_t))`。

此值对应刚完成更新时所用的二阶矩分母，避免第一步更新前尚无 optimizer state 却被误报为“全部低于 eps”。日志明确标注 `gradient_timing=pre_step`、`adam_state_timing=post_step`，并关联同一 epoch/batch/global_update。无需增加一次优化器更新或模型前向。

建议最少记录参数数量、eps、beta2、step 范围、`sqrt(v_hat)` 中位数/P90/最大值，以及 `<eps` 的数量和比例。另记零二阶矩数量，并对第一层、输出层、QUERY 新增 14 列分别摘要；大量不活跃坐标低于 eps，不代表它们真的对当前优化产生了显著影响。可补记非零一阶矩坐标中的 `<eps` 比例，辅助判断。

这些统计量不调用采样器、不改参数或 optimizer state，不驱动早停、选 epoch 或调 eps/lr。实现时仍需验证日志旁路不改变抽样、乱序、更新数和原目标梯度；资源开销不能只凭“参数头很小”就当作已测为零。

## 4. 对其他建议的处理边界

这些意见作为下一版协议的输入记录，本轮不覆盖原跑前登记，也不启动其实现。

- **噪声尺度：同意作为补充描述。** 原 0.5pp FPR/0.1pp 召回实用接近性仍完整报告。R0 的 seed 半极差只是观察到的基线敏感度，不是同 seed 配对差的方差估计；“三 seed 同号且超过参考幅度”可作为描述标签，不能冒充统计显著性或等价检验。小修正：UNSW 召回极差约 0.132pp，0.1pp 实际小于这个极差，但大于其半极差。新版需同时绑定实际旧基线数值与新版目标定义。
- **P5：同意补入新版登记，但需完整定义有效探针。** 逐 R2/R3×seed 判读；无攻击 batch、BCE 梯度为零、两项梯度均为零等情况单列状态，不能无条件算作 ratio=0。早期三个探针都低于 0.1，只能说这些观测点不支持预测，不能写成“从一开始就没有作用”。后期中位数 <0.01、0.01～0.1、≥0.1 应明确为三个预定判读区间，并保留有效观测数；稀疏探针不代表全部 batch。
- **逐 batch 损失：同意采用紧凑二进制记录并保留逐轮汇总。** 两个 float64 列约为每头 1.545MB、九头 13.90MB 的原始数值载荷；索引、其他字段和格式另计，实际 I/O 开销仍存在。存为 float64 不会把原 float32 前向损失升级成 float64 精度，应披露计算与存储 dtype，不逐 batch 创建小文件。
- **LODO：同意先做 R0 六折、482,880 次更新，再评估 R1 阶段。** 阶段 A 的复现条件与阶段 B 的触发条件要提前冻结。这是开发优先级选择，不能把未触发 R1 解释为 QUERY 无效；复现正常偏移也不能证明入网模块已成为必要条件。是否本地执行仍受缓存与资源约束，本轮没有作运行决定。

原 `predictions_before_run.json` 绑定的是 v1。下一版应另登记、另绑定新合同和包 SHA，并引用旧记录，不能直接把旧预测文件当成新目标函数版本的执行合同。P3/P4、接近性、噪声尺度和 P5 都须在任何新训练结果产生前明确版本及判读规则。

### 公式与数值路径应立即消歧

本稿明确解释`J_local^2`表示“联合第二距离”，所以**我不将它误判为再次引入平方软化**。但这个记号极易被实现为平方，应全稿统一为我上一回复使用的`J2_local(x)`，并更正“`J_local^2`按Codex写法固定”的转述。

唯一支持公式应直接写为：

```
质量或资格不满足：a_new(x) = a0(x)
质量和资格满足：a_new(x) = max(a0(x), clip(1 - J2_local(x), 0, 1))
```

`J2_local`沿已约定1C/2C顺序统计定义，绝不再取平方。实现用显式回退分支，避免未就绪距离参与`0×NaN`之类运算。半径合法为0仍按既定`_ratio`语义处理，不能改成隐式epsilon。

另一处必须改为**原三seed的float64算术平均**，而非§3.2的“算术和”。已有[179700离线核验](../../ab_reachable_bounds_readonly_v1_20261028/audit_reachable_bounds.py)使用`np.stack([score_27, score_127, score_227]).mean(0, dtype=np.float64)`，随后比较原ensemble cut；不能用总和直接比较该cut。

`.25×scale×(a_new−a0)`适合解释额外降分，但代数等价不自动保证浮点逐位相同。新分数应按既有RAW到修正分数的确定算术路径生成，固定seed顺序与严格`score>cut`；不把“从D0再减一次增量”未经核对地当成同一数值实现。公式未激活时保留原D0回退，不改变历史判定。

## Q2. 哪些必填项仍阻断预登记？

关键缺口仍是下面五项的**具体值或唯一确定程序**，不是还缺一份字段清单：

| 必须交付的决定 | 当前仍缺什么 |
| --- | --- |
| **S究竟是谁** | 具体评分头/seed、源数据域、确定性的UID选择规则与清单身份、参考身份、窗口、原角色、正常/攻击分母、own还是何种已登记donor语义；不能只写“预先绑定”就视为已绑定 |
| **同头D0如何取得** | 对这个S，哪些输入已核验、哪些必须建立，完整上游依赖和允许范围；主头λ=.25/scale/cut不能替代尚未定义的折头工作点 |
| **半径究竟怎么算** | N(r)的固定选择度量、k/分位程序、两轴估计式、相关性权重、有效样本门、放宽上限及每参考质量到查询回退的精确定义；当前“操作定义UNKNOWN”意味着核心算法还没有固定 |
| **什么结果继续、什么结果停止** | `G_min`及单位、源S累计/增量保护、低召回基线如何处理、必要组与边界压力、ensemble/单seed哪些是报告项、哪些有否决权；失败的判定顺序须确定 |
| **最多愿意付出多少成本** | 包含D0/参数准备在内的CPU、内存、墙钟、距离对数和输出限制；预算主体与运行次数已定“一次”，但具体限额仍全部UNKNOWN |

实际局部半径数值当然可以待计算；**计算这些数值的函数与参数来源不能待定**。允许登记一个唯一的合法原FIT估计程序，而不是提前知道它将输出多少；不允许结果出来后再决定用哪种k、上限或收益门。安全/收益阈值和行政资源上限也能事先设定，不需要先跑距离再决定。

§3.7还应将“合同”显式拆成**目标T合同**和**源S推进门**。目标池/设备FPR≤2%、召回≥99%等不能因为紧邻S主成功表就默认为S也必须满足。§3.5说明低于99%的基线无法被单调减分抬高，是正确提醒，但还不是对该S的实际通过规则。源保护不能只留“沿用C”；C说明采用哪种证据准入，不能替代各组预算数值。

建议将量统一写成百分点，避免阈值100倍歧义：`G_pp=100×修复正常权重/S全部正常权重`，`Δg_pp=100×新增撤回攻击权重/组g全部攻击权重`。若继续用0至1的率也可以，但`G_min`与所有预算必须同单位，表中明确区分。原FN、RAW→D0既有撤回与新Δg仍分别入账；目标B的0.966594323pp余量不能搬作源折的预算。

目前无法判断“重建已经超预算”，因为S与愿意承担的预算都未确定。也不能用任意填一个分钟数掩盖依赖不明。此时准确状态是规格未完成，尚不是成本审计失败或计算结果失败。

## Q3. 接受同头D0阻断策略吗？是否应再盘点一次？

**接受把同头D0列为S的阻断依赖；不接受将§4的重复盘点设为默认下一动作。**

已有[源分数资产清单](../../one_component_readonly_inventory_v1_20261028/analysis/SOURCE_SCORE_ASSETS.json)明确记录已审辅助头缺own-head FIT logits、折内DENSE参考/几何/scale/校准基线与逐UID DENSE margin；[后续缺口记录](../../ab_reachable_bounds_readonly_v1_20261028/analysis/DATA_AND_PROTECTION_GAPS.json)仍指向同一缺口。本稿没有给出新增资产路径、SHA、计算回执，也没有选出一个不同的具体S。再泛查一次同样的问题，很可能只重复已知结论，不能替未确定的S或预算作决定。

这里的判断限定于**已经核验过的材料与头身份**，不声称磁盘上任何时候都不可能出现新材料。只有出现下列增量，才有明确的定向核查价值：

- 有具体新文件/回执可对齐，需核实它确实补了已知缺口；或
- 已选定S、头与参考协议，其必要依赖超出旧清单覆盖范围，需按这一份精确差异清单查验。

这类核查服务于一个明确决定，不再新建一轮通用盘点包。目前应先直接引用既有缺口，选定S并评估/决定它的必要补齐是否纳入预算；不能因为不愿作这个取舍，就把下一步重新写成“检查是否缺材料”。本轮没有执行新盘点或补齐。

§4还应取消`FAMILY_STOP_BUDGET`与`PROTECTION_EVIDENCE_INSUFFICIENT`的强制二选一：前者是**研究为何停止**，后者是**科学证据处于什么状态**，两者可以同时成立。例如成本超限而停止，同头保护证据自然仍不足。可以分别记录`stop_reason`和`evidence_status`；若系统必须单个主标签，再预先规定优先级并保留次级原因。

`INFEASIBLE`也应保持原来的限定含义：某个明确冻结的规则族/作用范围被证明无法达到登记目标。无须证明“局部几何在一切情况下必然无效”，也不能把材料缺失、预算不足或一次未达标升级为这种定理。本轮仍无此判定。

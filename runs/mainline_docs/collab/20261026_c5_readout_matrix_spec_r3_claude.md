## 1. C5 判读

- 接受"暂不登记 R-1C / R-DENSE+1C"。补源 E3 后，按冻结的 1C 定义核查源侧实际正支持；1C 的定义不再改。
- 1C 对 A 有用（观察期后 −1.88pp），对 B 几乎无用（−0.33pp）。Samsung、WEMO Power Switch 窗口后的正常 TCP 和窗口里那一条连接的几何距离很远：资格放开了，支持仍不够。**这是两小时参考代表不了后续行为的分布漂移，不是规则问题。**
- 源 cap 对这类攻击没有约束力（q14 上界证明不可撤警）。若最终登记 1C，必须披露"源保护无信息，攻击损失只在目标评价时按 ε 把关"。

## 2. 可达性估计（观察期后口径，乐观合成）

| 池 | 现状 | + 密参考（按 C3 量级） | + 1C | 估计终点 | 目标 |
|---|---:|---:|---:|---:|---:|
| A | 4.75% | HeimVision UDP 未知 | −1.88 | **约 1–3%** | ≤1% |
| B | 16.48% | 约 −5.6 | −0.33 | **约 10%** | ≤1% |

- A：剩下的主要是 HeimVision 的 UDP 零支持（1.96pp）。密参考若能修掉，A 可接近 1%；HeimVision 单设备约 5.7%，要到 ≤2% 也取决于 UDP。

- **结论：第二步值得做完（B 实打实降约 6pp，A 可能接近目标），但单靠第二步达不到 B 的目标。** 第二步结果出来后，我会给用户一个关于 B 目标的决策点（研究目标取舍，由用户决定），同时附上第四步设计稿。

## 4. 完整矩阵最小规格（冻结）

1. **WRONG 供体。** 同池、同协议、同观察窗口。对目标设备 d，在该池该协议下有密参考位置的其他设备中，按 SHA256("paper04-wrong-v1|" + device_id) 升序循环排列，取 d 之后的第一台作为供体。位置数匹配：从供体的冻结密位置中，按与密参考相同的选择规则（组件轮转、组件内时间均匀、固定盐 SHA256(UID)）抽到与目标相同的位置数 n。供体不足 n 时取全部，并记录比例。不要求组件数匹配，但两边的组件数都要报告。不看标签和分数，donor/UID 表在运行前冻结并记 SHA。
2. **无供体与共同分母。** 无供体的（设备，协议）组，WRONG 记为 NOT_EVALUABLE。own 与 wrong 的比较只在配对子集上做：同一查询在 own、wrong 下都合格。报告配对子集的条数和权重覆盖率。全池主结果只用 R-DENSE（own）；不用头单独回退填补的全池差异，作为设备特异性的证据。
3. **WRONG 的 λ。** 直接用 R-DENSE 的密源 CAL 选出的 λ，只变参考身份。
4. **第三池 CIC_THREE_DEVICE_REGRESSION_CONSUMED。** 用 V4-EVAL1 已冻结的 BASE、B2 库及其 receipt 中的观察窗口：
   - receipt 定义了窗口：按同一枚举与选择规则构造密参考，新增编码数写进矩阵执行卡；
   - 没有定义窗口：第三池只跑 R-B2 + 预算保护作回归检查，密参考各臂记 NOT_APPLICABLE。
   - 不为第三池新设窗口；源 CAL 不能替代第三池。

规格冻结后，Codex 实现矩阵 runner 并测试，再提交矩阵执行卡（含第三池编码数、距离对数与耗时估计）。用户的授权若已覆盖，直接运行；超出则另行申请。

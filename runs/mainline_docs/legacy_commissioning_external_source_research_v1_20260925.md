## 1. 数据要解决什么

检验的是：**冻结的检测器与统一参考机制，能否利用设备此前的正常历史，在后续正常和攻击流量上降低误报，同时保留攻击检出。** 新数据首先用于验证迁移能力和入网适用范围，并不默认加入训练。若后续拿其结果调整模型/规则，这批数据就承担开发角色，不能继续冒充未参与设计的最终确认。

需要区分两个证据层次：

- 公开旧采集可望支持“正常历史驱动的被动入网回放”和跨数据来源验证。
- “固定六阶段主动操作确实补齐参考覆盖”需要操作日志或前瞻采集。当前检查的公开来源均未建立这项证据，不能把普通正常 PCAP 改名为主动入网数据。

当前冻结的一小时、同协议至少两个 component、参考上限 64、因果截断、模型/门槛/seed 均保持。UNSW 没有 CIC2022 的 Active 目录语义；未来适配前必须明确来源与 t0 合同，不由本报告暗中扩写原协议。参考不足的设备和协议保留在覆盖率、回退与整体结果中，不按是否能启用 verifier 挑设备。

必须处理的源数据问题：

1. 官方示例给的是每分钟 MUD 流统计的区间标注。未来包级标签需要联合受害设备、epoch、受影响服务、攻击方向和攻击者信息，不能整段、整文件或整台设备全部标正；反射攻击更不能把普通响应随意算作攻击。混合文件中“没落在已知攻击区间”也不自动等同可靠正常。
2. 工作表 `Experiments` 的 Pcap File 列有 111 个被 Excel 保存为非 2018 年的日期值，例如 `2002-06-18`，而旁边文件名写 `2018_06_02...`。原值保留，不猜测改正；epoch 标注还需与未来 PCAP 实际时钟对照，服务器修改时间不是采集时间。
3. CSV 中 231 行为四列、3 行为五列，额外列均位于 TP Link 的 PingOfDeath 注释。已原样保留中间字段和整行，未错把中间字段当标签。
4. 实验备注有关机、采集停止、DNS 错误/重启。它们不证明所有文件损坏，但未来需逐事件核对缺口，不能把缺包算设备静默。
5. 未读取任何 PCAP，因此首小时是否达到两个合法 component、后续正常量、可辨识攻击数都仍为 UNKNOWN。不能用公开包总量填这些空缺。

这五台只能用于首次材料核验。材料通过后，再按预先固定的完整名单和日期扩到其余候选，设计跨设备、跨日与攻击事件层面的报告；充分性应以独立设备/事件、正常观察时长、每设备误报及攻击保持的不确定性判断，不能凭 GB 或百万包宣布论文级充分。重复包和三个 seed 都不能代替独立设备。总体结果必须含回退设备；是否启用 verifier 的子集只作机制解释。

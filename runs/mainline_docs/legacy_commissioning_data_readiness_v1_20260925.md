# 新设备入网：现有数据就绪检查

2026-09-25。**清单及使用历史检查完成；新的联合迁移效果实验尚不具备直接开跑条件。**

结论不是“缺少更多流量包”，也不是“现有数据完全不能用”。当前已合格的 11 台设备都有训练、开发或已消费确认用途；剩余两条攻击目录线索尚缺设备身份或攻击语义证据。已验证、可用于新一轮独立联合确认的配对设备数为 **0**。未知的资格不能写成数据不存在。

## 1. 本次检查了什么

依据用户“那可以开始了”，核对现有归档目录、官方设备表的已保存结构化副本、内部 README、原始资格审查的元数据、现行设备分配、已披露的历史使用情况和正常多日捕获目录。原始文件仅检查存在性和大小；未重解码 PCAP、解包归档、读取新的查询数据行或模型分数，也没有训练、下载或使用超算。

当前分支 `codex/exp-mainline`，HEAD `4b28747b09480471e2bac1beb3a9badf27280efb`。八份已有无关修改保持不变。详细清单和来源校验在 `runs/legacy_commissioning_data_readiness_v1_20260925/`。

源元数据与可定位的原 SHA 侧车/封存清单逐项核验；四份较早的内部结果文档作为历史摘要引用并记录本轮 SHA，没有重新验证那些旧实验。当前两个 CIC2022 归档及七个 Active 文件仍在原位置、大小相符；其原始字节 SHA 沿用既有完整性记录，本轮没有再次读取整份原始文件计算 SHA。清单检查限定于主线已记录资产，以及 `paper04/datasets`、`worktrees/data` 的文件名/大小；不声称查遍所有磁盘、旧设备或超算。

这两条线索不是经过效果筛选的优胜设备，但目前也不是两个已证实可用、完全未见的物理设备。尤其不能把 Gosund 的八个名册候选计算为八个新增攻击设备。当前名册核算为：11 个已使用身份、9 个落入上述未决身份范围的名册条目、20 个没有匹配攻击目录线索的条目。

### 身份、时间和标签为何仍是未知

1. **归档 mtime 不是包时间。** 两条线索没有已保存的逐捕获实际包时间与设备端点审查结果，不能仅凭文件序号确定参考早于正常/攻击查询。
2. **Nmap 目录不是全体正类。** 内部 README 明说暴力尝试之后还测试了直播端点；不能把后续直播或响应一律标攻击，也不能将其未匹配部分改成正常。此前排除这类混合文件是语义资格问题，不是已经证明 Luohe 没有攻击。
3. **Gosund 名称不等于 Roomba 受害者。** 插座可能给扫地机供电，目录名可能描述安装位置。原始 MAC/ARP/端点关系才可决定哪台设备受攻击，不能先选一个有利的身份。
4. **兼容性未知。** HTTP/TCP/UDP 目录说明不是当前目标满足旧前端头字段、IPv4/协议和因果前缀条件的证明；目前合法目标数、独立连接数和可用参考数都保留为未知。

另外 **26 个未列入当前设备范围的正常交互目录**，合计 **606 个 PCAP 候选**，没有对应攻击目录。这些是正常侧扩展的线索，不是 26 台已核实的独立新设备。其清单见 `normal_only_directories.json`。它们可能用于检验正常误报的迁移，但不能独自证明该设备攻击不会被新增正常参考错误放行；用其他设备的攻击代替时，主张必须相应收窄。

## 4. 七天 Active 的数量足，但不能补出不存在的证据

七个文件仍本地可用：**7,218,605,495 字节、58.788 小时、11,749,238 包**。它们提供同一采集项目的多日正常网络观察。当前已经验证的逐设备统计只涵盖原 11 台设备；官方说采集了 40 台设备，不保证其余设备在每个文件中都有可见 MAC、足量流量或旧前端合法目标。

因此，对上述两条剩余线索以及其他正常目录，本轮能确认的是“存在可继续核查的共享正常来源”，不能确认它们实际有几天、多少合法连接、多少 TCP/UDP 参考。不能把旧 11 台的计数挪给新设备，也不能拿数千万包替代设备数量。

操作证据有两种不同层次：Interactions README 和目录描述了分散的功能操作；Active README 描述白天零散主动/被动交互。但本地材料没有能把**某台设备连续首小时**对应到冻结六阶段的逐项操作日志。将不同日期的短交互文件拼接，不会得到真实执行过的连续一小时入网流程。

这不否定可信正常参考本身的研究价值。现有数据可以研究被动正常观察的适应；完整主动功能流程是额外的、更强的主张，需要相应采集证据。当前冻结方案不在本轮改写，`UNKNOWN_PASSIVE` 也不自动变成 `VERIFIED`。

## 6. 数据量怎样判断才合理

目前最先缺的是**合格且独立的新设备配对**，不是统一凑到十万包。数据量需分别报告设备、采集日期/场景、独立攻击执行、依赖连接和最终合法目标数。单次洪泛的百万包无法替代多次独立攻击；同一设备的多个连接也不能替代多台设备。

作为量级说明，在真正独立同分布且零错误的二项试验中，要把错误概率的单侧 95% 上界压到 1%，约需 299 次独立试验；压到 0.1% 约需 2,995 次。相关包不能直接作为这些试验。即使两个独立代表性设备都成功，设备成功概率的对应单侧 95% 下界也仅约 22.36%，不能据两台样例证明“普遍稳定迁移”。实际设备选择并非随机抽样时，这种总体解释还要进一步收窄。

这些仅解释统计尺度，不是新冻结门槛，更不是要求必须采集 2,995 台设备。两条线索即使都合格，也应定位为有限补充证据；若要更广的稳定迁移主张，还需更多独立配对设备/场景，而不能靠重复评分相同设备补数量。

## 7. 下一步的具体取舍

**先解决本地剩余两个线索的真实资格，不重新下载同一数据集，也不直接开模型效果实验。** 最小范围已经收敛到上述 51 个成员。优先看 Gosund 的物理身份，因其若成立，可检查既有 LOIC 目标规则是否适用；Luohe 先明确 Nmap 混合行为的标签依据，无法成立就保留“仅正常侧候选”，不擅改标注凑配对。

下一次有界原始资格核查应一次交付：真实设备对应、正常/攻击的包时间顺序、协议合法目标数量、依赖结构以及可用/不可用原因。只有身份和攻击依据成立，才有必要针对同一 MAC 核对已有 Active 中的正常覆盖。它仍是输入资格核查，不训练或评分；本轮没有执行或从数据检查自动延伸到模型实验。

这次清单检查到此结束，后续不再重复普查同一批旧设备。两个候选若仍无法建立配对，现有已审查资产不能支持新的完整联合确认，应转向具名的外部配对材料或有日志的新采集；不能把已消费三台改名为新确认，也不能承诺再跑一次旧数据就会解决泛化问题。若选择只验证正常误报迁移，应事先明确较窄主张，不能在结果出来后再改变目标。

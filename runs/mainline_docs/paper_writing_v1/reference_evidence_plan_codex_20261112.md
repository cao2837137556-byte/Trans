# 正常参考规模与开发针对性的补证据方案

2026-11-12。状态：研究方案，未执行新实验。保留完整库MLP p4主方法、原库、阈值及全部既有结果。本文件回答如何检验历史参考的必要性、预算与可复用性，不通过改写叙事消除已经发生的开发选择。

## 1. 当前证据与真正缺口

|范围（集成）|两小时库正常误报|完整库正常误报|说明|
|---|---:|---:|---|
|CIC建档后|91/96,041|18/96,041|其中HeimVision为73→0；Eufy为18→18|
|UNSW建档后|22,411/74,444|130/74,444|普通率30.1045%→0.1746%；各设备依赖程度不同|
|Edge选中查询|0/20,000|0/20,000|两者使用同一4,124条建档库，没有额外历史|

因此，现有结果证明当前方法在UNSW的两小时条件下不足，并不证明所有设备或所有方法都必须依赖额外历史。额外历史既增加保留条数，也改变参考来源、时间/活动覆盖和可用组件；当前整库对照尚未分离这些因素。

当前库的设备范围和扩充策略受开发诊断影响，逐点选择则遵循固定资格及哈希/覆盖规则。固定逐点规则不能反向证明整个策略从未看过开发结果。原事实保留；新的统一策略可通过明确协议和后续评价建立证据。

### 1.1 用户提出改善UNSW两小时建档后的专项核对

当前建档计划的13,247个选中UID顺序摘要，与最新已验收两小时参考库完全一致。10个设备×协议组中9个已纳入全部合法候选；只有WEMO Motion TCP从35,985条限制到4,096条。四台主要存在两小时误报的设备，其TCP与UDP候选均全部入库：

|设备|TCP合法候选/入库（组件数）|UDP合法候选/入库（组件数）|两小时库建档后正常误报|
|---|---|---|---|
|Samsung Camera|717/717（1）|2,669/2,669（5）|6,967/19,711|
|TP-Link Smart Plug|147/147（3）|14/14（7）|162/2,597|
|Netatmo Camera|1,609/1,609（50）|1,172/1,172（16）|10,355/19,879|
|WEMO Power Switch|88/88（1）|52/52（3）|4,905/13,028|
|WEMO Motion Sensor|35,985/4,096（1,064）|2,683/2,683（34）|22/19,229|

因此，当前证据不支持把主要问题简单归结为“4096上限让四台设备的好参考没选进来”。结论限定于当前前端定义的合法候选，尚不证明原始捕获/资格过滤没有问题，也不证明这段时间充分代表后续状态。

Samsung和Power的TCP仅一个组件，是明确的准入瓶颈线索；Netatmo却已有50个TCP和16个UDP组件，仍出现较多误报，因此双组件数量也不是全池唯一解释。后续应分别核查输入/资格过滤、窗口状态覆盖与匹配规则，而非直接称原始数据质量差。核对字段和摘要见 `unsw_two_hour_inventory_audit_codex_20261112.json`。

## 2. 第一优先：两小时失败机制诊断

先复用已有采集/解码验收，核查时间范围、设备身份和资格过滤是否存在明确异常，不凭误报高推断数据坏。再使用已保存的两小时/完整库分数、三空间支持及参考资格信息，不重复跑现成主指标。重点分析“两小时告警、完整库不告警”的正常查询，并同步保留攻击变化及完整库仍误报的查询。

建议按明确优先顺序形成互斥分账：参考尚不可用；无合法参考；合法组件不足两个；几何参数不可用；组件足够但三空间支持为0；旁路阻止减分；正支持与实际扣分仍不足。对各类同时标注原始分数裕量是否超过理论最大扣分，作为可交叠的上限诊断单列，不能与互斥分账直接相加。分设备、协议、视图报告普通计数与加权质量，不将多个交叠原因相加冒充总体。

值得特别核实的线索：两小时TCP参考中，HeimVision为2,521条/1组件，Samsung为717条/1组件，WEMO Power为88条/1组件。当前规则至少要求两个组件，这可能使正常记录很多但仍无法获得支持。尚未核定它解释了多少当前误报，不能直接将全部历史收益称为行为多样性提升。

如果组件门槛确实是主要瓶颈，优先增加一个针对门槛的受控回退：仅在恰有一个合法组件时允许用该组件的最近联合距离生成支持；已有至少两个组件的查询仍用原第二小值，无合法参考或时间未到仍回退。两小时与完整库分别应用，其余p4、半径、尺度、λ、阈值、保护均不变。这样不把“所有查询改用第一近邻”带来的强度变化混入单组件准入问题。

该回退属于研究对照，不预先采纳。必须同时检查CIC/Edge等非保护攻击的撤警代价；UNSW攻击全受SYN保护，其检出不变不能独立证明放宽门槛安全。若只有support3而无合法组件数或真实三空间邻居，应先明确缺项，再作必要的最小恢复；不得拿二维邻居解释三空间瓶颈。

## 3. 第二优先：同实际预算的参考来源对照

首先在每设备×协议层面配平实际保留条数，而非只让全库总量相同。首个比较可沿用各组两小时库实际条数，构造：

1. 两小时资料内的参考；
2. 合法较早历史与建档资料混合、保留相同条数的参考；
3. 原完整库，作为现行系统参照。

两个配平库使用同一个只读取参考资料的确定性选择器，规则和盐值在评价前写定；不读取目标查询分数、误报UID或攻击结果。数量不足时取两者都能满足的实际预算并报告短缺，不复制记录补足数量。保持正常身份、原建档截止时间、同设备/协议资格及全部判别参数。

分别报告全部查询、两库共同满足双组件资格的子组，以及资格因加入历史而从无到有的子组。子组用于解释，不取代总体结果。若等数量历史混合库仍更好，可支持资料来源/覆盖的价值；不能仅据此把优势归为日历时间跨度，因为组件和活动组成也可能不同。

条件允许时在少量事先固定的预算点报告性能—规模曲线；预算按参考数量/内存约束确定，不按目标最低FPR反选。若使用哈希抽样，少量预定盐值全部报告，不挑最好的一次。报告每查询合法候选数分布、参考存储和匹配耗时；总库66,082行不等于每次都比较66,082行。

当前已选完整库可先作为固定候选池做预算敏感性，但此结果应标为在既有候选池内的分析。它不能替代从完整合法候选资料按统一程序建库的证据，也不能消除早期候选范围受开发反馈影响的事实。

## 4. 将设计变成可复用协议，并作确认

形成一套能直接交给新设备使用的规则：正常资料如何获得、可访问的时间范围、每设备/协议预算、组件与时间覆盖策略、参考开放时点、没有历史或资料不足时的处理。所有具备合法资料的设备按同一协议处理，缺资料设备不因为表现差而被排除。已有历史开发/评价角色不能为凑参考数量而默默改为REFERENCE。

最有说服力的下一层证据，是协议确定后在未用于本轮策略选择的整段采集或设备上评价一次。先盘点现有资产是否存在真正未消费的范围，不必一开始另找大数据集；已用于选p的历史开发集、已反复查看的旧查询，不能重新改名为未见测试。同一捕获中未抽中的随机包也不自动构成独立确认。

若没有可用的未消费资料，前面的机制诊断和同预算比较仍能加强当前设置中的论证；对新设备/新时段直接适用的更强主张则需新的确认材料。此项应与主张强度匹配，不将继续跑旧数据伪装为独立确认。

## 5. 压缩线可并行，但不代替上述证据

4,936条严格等价候选可优先做无损去重验证：原库及结果保留，独立生成候选库；同一查询、三个头及集成、full/建档后视图逐UID对齐支持、分数和判定。预先规定数值比较方式；不能调整阈值或只看汇总率不变。建档截止时间和资格边界不随删除参考重新确定。

若全部候选都能安全去重，完整库也仅由66,082潜在降至61,146，约少7.47%；这尚不是已完成的压缩结果。更大幅度的代表点压缩应另用参考资料本身确定规则与预算，首轮保留真实参考记录，不合成新向量或改写组件身份，不按当前测试查询“贡献大小”保留恰好能维持成绩的点。

固定模型、几何、尺度、阈值、组件规则和可用时间时，候选库作为原库子集，只会使支持不增、修正分数不降。删除本身不会补足两小时未观察到的信息。少存历史样本与从未获取额外历史是两个不同目标，收集成本与保留成本分别报告。

用户红线适用于原版本保护和压缩库的采纳：原完整库与主结果不覆盖，未验证结果保持前不替换主库。诊断、预算和规则对照可以变差，其作用就是检验机制；失败结果照常保留，不为维持漂亮数字改选点或删实验。

## 6. 推荐的工作顺序与论文落点

建议下一批先做第2节诊断和第3节首个同预算对照，第5节严格等价去重可并行。组件回退按诊断结果决定是否值得做。然后固定统一协议，再安排第4节确认。暂不扩展检测头、指数或λ搜索。

若结果显示少量、统一选取的历史参考仍有收益，论文可形成“有限预算下正常历史覆盖的价值，以及上下文对错误撤警的约束”的证据链。若两小时问题主要由组件门槛造成，则优先考虑有证据的方法简化；若确实依赖长期正常活动，明确资料可得性就是方法适用条件，不将其改写成纯两小时部署。

若实际需求硬性要求只有两小时、无额外历史，必须将其作为独立的更严格任务研究，可能涉及基础表示/检测器或正常建档流程。可以研究两小时内统一覆盖合法业务活动的建档协议，但需要真实采集证明，不能把跨日历史拼接成“两小时”。本方案不预判哪条路线一定保持当前成绩。

研究依据：[Sommer与Paxson，IEEE S&P 2010](https://oaklandsok.github.io/papers/sommer2010.pdf)强调网络流量变异、数据可得性、检测语义和可靠评价需要一起考虑。这里引用其问题框架，不把既有文献当作本方法有效或建库策略无偏的证明。

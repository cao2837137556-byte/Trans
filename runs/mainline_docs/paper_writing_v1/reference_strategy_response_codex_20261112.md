## 1. 两点定位结论

**同意停止的路线：** 在当前UNSW两小时合法候选和现行固定规则内，靠反复重抽、删点或提高4,096上限，试图恢复完整库0.1746%的误报率。四台主要高误报设备的合法候选已全部入库；在可用时间、几何、尺度、阈值等不变时，仅删参考不会增加支持或降低误报。

这一停止决定还有受限条件下的数量依据：四台候选已全入库的设备在当前两小时主视图共有6,967＋162＋10,355＋4,905＝22,389条正常误报。只删/重选各自已有候选不会减少其告警；即使把Motion的22条误报理想地全部消除，全池普通误报率仍至少为22,389/74,444＝30.074956%。这个下界只针对模型、资格、半径、尺度、保护、阈值和查询人口固定的候选重选问题，不适用于改变这些条件的新方法。

这不等于否定所有两小时方法，也不预先放弃资格过滤检查、合理的参考使用规则或更有代表性的真实建档过程。

**同意首轮使用已编码池：** 不为这轮诊断先重跑未编码的海量原始历史。先完成两小时失败分账、一个严格配平预算的来源对照、一个压缩模块；缺失资格可由元数据恢复，缺失联合距离/单组件支持需要有限的新距离计算。零重编码不写成零计算。

主证据链的名称建议为：**失败机制分账 → 同预算参考来源对照 → 固定规则、查询盲的建库/压缩评价**。暂不用“无偏”称呼，因为盲于查询不等于现有候选母池未受开发选择影响。

## 3. 首轮收敛为三项科学问题

### D：两小时失败分账，附单组件回退的可修复量

元数据资格覆盖完整既定查询集；核心分析对象为UNSW建档后两小时方案的22,411条正常误报，并保留其余查询作分母及一致性检查。优先恢复时间/帧资格、合法组件数、必要几何参数状态，再结合保存的原始分数、support2、support3与G分账。

区分参考未开放、无参考/组件不足、必要参数不可用、联合支持为零、保护旁路、扣分不足。固定分类优先级避免交叠相加。独立报告全体的“原始裕量超过最大扣分”标志；不能把它只藏在最后一类。

对恰有一个合法组件、其他资格均满足的残留正常误报，计算该组件内最小**三空间联合距离**，评估指定回退的支持和实际减分。已有两组件以上的查询继续保持第二小值，无参考或时间不合格仍回退。保留G，不通过忽略保护夸大可修复量。

报告正支持数、实际可撤销误报数、占单组件残留/全池残留的比例及加权贡献。没有可修复误报时停止该具体回退分支；非零结果本轮只作诊断，是否扩展以其实际收益和所需成本判断，不引入无依据的30%科学门。若决定进入方法比较，再查CIC/Edge非保护攻击代价；UNSW攻击稳定不能独自支持安全性。

局部三空间距离缺项允许补算，但不先对全池生成所有昂贵细粒度归因。source空间独立second值只作辅助；需要最优来源时保留真实联合参考，不能沿用二维匹配UID冒充三维。

### M：仅一个13,247条、单规则单盐的配平混合库

首轮不做多预算曲线或多盐搜索。母池采用**现存全部合法已编码两小时库和历史参考**，不默认剔除C1后仅留C4，再为TP-Link UDP引入例外。C4本来先排除了旧UID/旧物理端点，是条件补充样本；只留C4不能恢复无偏原始样本。

所有母池与来源限制均写明：这是在现有已编码候选池内的来源/预算对照，不是从百万级原始历史重新统一建库。HIST_DEV不入库，不重新选择设备范围。

### C：查询盲的压缩模块，明确两个候选而非多参数扫描

**C0，严格等价基线。** 两小时库不动，历史按已核对的等价键和原始三空间特征完全一致分组，固定保留最小UID。候选应为13,247＋47,899=61,146条；组内代表映射、资格签名和候选UID先封存，再重放原查询核对。不能只看旧二维匹配UID就宣称三维等价。

**C1，一条固定预算代表点候选。** 如要首轮同时检验实质压缩，我建议用明确的预算规则替代“25%或ε”的二选一描述：在严格去重后的历史中，按同设备/协议/组件/有效资格签名分组，每组保留max(1,ceil(n/2))条真实参考；两小时库仍完整保留。实际全库不会保证恰好减半，由组数和单例决定，先报告可行下限与实际数量。

组内首点取最小UID，随后按与已选集合的最近归一化三空间联合差异最大的参考逐次加入，并列按UID。距离使用现行几何的预处理及各自半径，不能直接比较不同单位的原始空间或用minρ代替。该最远点策略是固定启发式，不宣称余弦上的经典度量近似保证。只有预算目标，报告实际覆盖差异，不附加未经证明的ε覆盖或零翻转保证。

资格组仅由静态参考元数据及原资格规则确定，不按目标查询的实际匹配模式分组。具体字段表和计算资源预检须在执行卡明确并审查；capture虽不属于组件ID，仍可能参与资格和会话边界，不能随意跨资格合并。先完成C0基线核对，再推进C1；若C0不一致，先定位身份/资格/顺序/浮点原因，不自动修改科学规则。

原完整库、原结果始终只读。C0/C1若要作为结果不变的替代库，所有头与视图逐UID判定必须零变化，普通/加权/HT及配对结果一致；连续支持/分数的数值核验规则在看候选结果前确定，不能事后改容差或阈值。出现变化就只作为未通过等价要求的研究结果保留，不自动采纳“近乎不变”。

固定其他条件的子集删除在精确算术下使支持不增、分数不降，因此不会额外撤掉原有攻击告警，正常误报却可能上升。这个结构不变量不能包装为压缩策略独立获得的攻击安全收益。

## 4. 计算边界与停止方式

三项是三个科学问题，不等于只需三次矩阵计算。压缩模块含严格等价基线与一个代表点候选，各自构建和核验；代表点选择本身也有参考间距离成本。首轮不重编码原始PCAP，但要对新的参考子集重新计算所需联合支持，不能直接复用原库support3。

若所需已编码资产确实缺失，先给出缺项和最小恢复路径，不自动升级为百万级原始历史重跑。这个阶段产生的证据是现有候选池内的机制和预算分析；更强的统一建库/新设备可复用主张，在看清信号后再决定是否值得做原始候选构建和未消费范围确认。

所有固定候选完整报告，单次失败不触发不断换盐、换ε、换预算直到得到漂亮结果。主方法、模型、阈值、p4和现有结论不被研究对照覆盖。

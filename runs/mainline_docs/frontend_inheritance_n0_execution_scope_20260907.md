## Access and identities

The new standalone standard-library runner has literal input paths and SHA-256
pins. It imports no historical runner, model, NumPy or semantic-corpus reader.
The exact paths and hashes are in
`repo/ood/issue27frontend_inheritance_n0_inventory_v1.py` and the reviewed
`frontend_inheritance_n0_contract_gap_inventory_20260907.json` source inventory.
The synthetic acceptance receipt binds implementation and source-inventory
bytes before the single real inventory starts.

For the mixed F1 conservation table, all 25,467 rows expose only selectors
`uid,phase,legal_fit,cross_phase_context` to the inventory before filtering.
Only phase=fit, legal_fit=True, cross_phase_context=False rows may expose the
remaining source/member-key/context/category/tier/event-count metadata.

The compressed file is read once into a bounded byte buffer, hashed before
decoding, then parsed once with Python's CSV parser. The parser transiently
tokenizes a complete row, including rejected rows; rejected research values
are not inspected by the inventory, retained as research records or exported.
This is a restricted semantic projection, not a claim that the mixed container
or its other bytes were unopened. Receipts count compressed bytes, decompressed
bytes, tokenized rows, selected column accesses and retained research rows.

F4 reads only the named parent metadata index/audit/census and schema. Prefix
hashes and old_all_unk values are outside its research projection. F5 reads
only the named P identities, census and UID scope; the manifest is read as text,
and its unrelated members are not opened. F3 identities supply the already
frozen nested source lists. Source files and vendor modules are hashed/read as
text; references in them are not followed into numeric data.

Preparatory work read source text, manifests, source-list documents and JSON
schema/identity/census documents. It did not scan any real CSV/GZ table. Runner
access counters describe the one N0 process, not every read in the conversation.

## Conservation and limits

Reconcile 18,398 original fit minus 132 crossing-fit rows = 18,266 lawful fit
targets, in 12,889 contexts. The parent has 13,866 targets and 9,307 contexts;
the exposed old F1 validation remainder has 4,400 targets and 3,582 contexts.
Existing F5 train/internal-val membership, category counts and P UID scope
must agree exactly. F4 census category names map explicitly to F5 names using
their common owner/label/teacher-kind definitions.

The 19 crossing-context exclusions remain inherited from the pinned F1 D0
artifact. N0 re-counts 132 crossing-fit and 32 crossing-select row flags; it
does not access their context fields and cannot independently re-count those
19 context identities. It neither recreates nor changes exclusions or splits.

The producer-defined three-part semantic_context_key may yield an artifact
member identifier for lawful fit rows. Validate its separators, context hash
and epoch. An artifact member is not a physical-device or old-session identity.
Neither source count nor context count certifies independent observations.

One local process, <=600 seconds, <=1 GiB process memory and <=50 MiB outputs.
Each metadata table has one scan; no retry/resource pilot. Cooperative checks
run at bounded I/O, row and output steps; these are not OS-enforced hard limits.
Additional implementation bounds are 32 MiB per input/decompressed table and
64 KiB per physical CSV line. Identity/schema/access/resource drift stops the
attempt and preserves a terminal receipt. No automatic second attempt occurs.

# 增强结果后的路线建议：以原 R 推进入网适应

2026-09-16。用户询问继续增强还是新设备入网。本轮只读既有结果、训练轨迹、原训练代码、已披露历史与捕获元数据；未训练、未评分、未改角色或下载。以下是路线建议，不是已冻结的新机制或新实验授权。

**建议暂停当前 B/C 式全局继续训练，保留原 R，把下一步研究重点放到利用正常参考的新设备局部适应。全局增强成功不再建议作为入网研究的先决条件。** 原 R 是研究基线，不是已经满足全部 OOD 目标的成品。

## 为什么这样选

1. 新增监督确实有用：新摄像头正常误报 96/227→14/227；但 Hydra 原 R 已检出54/54，没有新增攻击收益。学习目标现在更适合聚焦“降低新设备正常误报，同时保持这台设备上的攻击检出”。
2. 全局更新造成了本试验中的跨场景退化：旧攻击净少检出4685条，其中Telnet Brute Force少4002条；street正常误报2/3000→2991/3000。五池各FPR≤1%时攻击检出90.92%→57.57%，不能用重新设一个阈值解释掉全部问题。
3. 训练不是没有学动。B记录的旧回放BCE由0.000373变为0.00318，新BCE由1.224降至0.0283，普通B的排序诊断也由0.704降至0.00105。这里是每个记录更新前、带训练Dropout的目标测量，不是独立泛化评价；损失数值不能当作梯度贡献比例。保持旧样本标签拟合不足以保证保住旧分布外决策。
4. C相对B未带来新CHECK判定收益，旧攻击又净少检出69条。本配方的排序项没有额外价值证据；不推出所有排序方法或全局增强都不可能。

原P2与此次继续训练不是同一训练过程：原18398行、50轮、每256行更新；当前11529旧行+570新行、200次全批更新，并重建optimizer。原生support攻击385→182，而ToN正例4000全保留，回放组成也变了。排除项含冻结角色冲突和缺失输入，不能为了恢复分布擅自加回。缺“同回放/预算、只去掉新监督”的归因对照，故无法把退化全部归因于新数据、更新时长或某个损失。该对照可在归因确有必要时提出，不应变成无期限推进入网的前置工作。

## 入网方向如何承接已有教训

保留共享R与旧预处理；研究由设备自身先前正常历史驱动、作用范围限制在该设备的适应机制。这样可隔离对其他设备判别的影响，但**不保证入网设备内部的攻击安全**。后者必须由同设备后续正常与攻击一起检验。部署时设备绑定、参考正常性、输入可用性、适应状态隔离都需要在机制设计时明确。

历史CKDE-Q已有123个阈值校准臂全部回退，不能把直接抬阈值当新突破；CKDE-R因配对材料不足停止，不是模型效果被验证失败；CKDE-S只否定所试固定rank4跨设备共享子空间的稳定性，不能读成所有局部适应不可能。当前已取得同设备正常/攻击材料，证据条件与当时不同。

真正值得争取的贡献是：如何学会利用正常参考吸收设备差异，同时避免吸收攻击特征。局部路由、缓存或设备阈值本身不构成已证创新。下一步具体机制须结合上述反例和针对性文献检索完成设计与审查，尚未选定公式、学习器、预算或科学门槛。

## 现有材料可先做开发验证；时间关系必须重新按任务接好

现有两摄像头、已物化表示和已披露查询可支持小型开发pilot；两设备已参与增强和开发观察，不能重新称为未见设备独立确认。新的角色范围须另立版本，旧recipe/计划不改。

不能将原监督增强的全部正常TRAIN直接合成入网参考。`legacy_cic2022_two_camera_semantic_probe_v1_20260915/evidence_review.json` 的 `file_results` 显示：Amcrest WATCH3(file2) first_timestamp=1633532097.299425，而RECORDING2(file1)=1634045191.754590；SimCam WATCH3(file10)=1633542578.665510，而RECORDING2(file7)=1634046053.366234。WATCH查询在10月6日，RECORDING参考在10月12日，若混用会引入未来参考。这不追改原来按活动划分的监督增强结果，但该结果不能充当全局时间入网实验。

一种已有材料即可支持的候选开发构型：各设备WATCH1/2仅作先前正常参考，后续WATCH3、RECORDING3及12月Hydra3作查询。现成计划中正常参考分别325/54条，正常查询176/51条、攻击查询36/18条；这些是可用目标数，不是已定参考预算或独立样本数。正常没有观察到RTSP/554、攻击是窄Hydra请求，服务和采集视角差异仍需披露。

先设计正常参考驱动的机制及相同参考预算的必要基线，再做一次有边界的开发验证。若显示同设备正常/攻击共同收益，再用未参与机制选择的设备确认；接续现有归档其他设备的成员元数据判断是否可用，当前不自动下载或重新全盘普查。旧攻击基准继续保留，新设备内部攻击保护要另作证据，不能以旧设备分数代替。

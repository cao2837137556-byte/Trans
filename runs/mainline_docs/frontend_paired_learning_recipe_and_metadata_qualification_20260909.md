会话占位结论由旧生成器的精确哈希规则逐 UID 核验，不是按编号数量猜测。
旧生成器把 `(source, member, reason, position, uid)` 散列为缺失目标的 session_id；
该字段在这里表达可追踪的缺失记录，并没有提供真实会话成员关系。
ToN 的 `src_local_id=dst_local_id=-1` 也由原元数据生成器明确赋值。
不能把 3,157 个 -1 对认定成独立会话，或据此声称它们一定属于同一真实会话。

现有 F0 context ID 包含 epoch，且保存的是哈希；不能删掉文本中的 epoch 就恢复底层组。
F1/F4 语料没有保存无 epoch 的端点/路由键；F1 signature 也没有保存端点值。
不能把上下文数当独立会话数。其他来源的端点整数有记录，但尚无与 F0 路由键对应的
已核实桥，故本轮未用其推定 B 分组。

本轮也审查了前缀分配代码：F1 每个原始事件只求一次 route，只向一个 active bucket
追加一次 signature；epoch 切分创建空桶且拒绝复用 context key。因此在既有物化来源
确实符合该固定实现的前提下，不同上下文的原始事件集合不交叠，保留整个上下文即可
保留这一性质。F4/outer 的历史输入身份审计作为前提沿用，不重做。
这消除了“必须补所有前缀起点才能划分”的要求；实现仍须核对这些来源 pin。
不同事件位置上的重复内容和同来源相关性仍可能存在，不能据此声称统计独立。

采用整文件分组可以保守规避许多共享问题，但 ToN 正常只有一个成员，扫描也只有一个成员：
这样无法同时把这些行为教给模型并检查其同类行为表现。可作另一种未见来源问题，
不能冒充本次要问的“已学习任务是否保留”。

## 唯一训练配方（已冻结，名单仍未合格）

机器可读定义：`training_recipe_frozen.json`。任何实现必须遵守它；初始化和名单依赖项
为 null 是明确的未完成条件，不是可以运行时自行挑选的超参数。

| 内容 | 本次固定选择 |
|---|---|
| 两个候选 | A 监督臂；A+B 监督臂。两者从同一份新初始化完整训练 |
| 输入和结构 | F4 131D；Linear 131→64 + GELU；单向 GRU 64→128；Linear 128→64 + GELU→1 |
| 参数 | 全部 91,265 参数可训练；不建旧辅助头，不加载 F5/N3 权重 |
| 损失 | 普通真实标签 BCE；各 owner 内先按上下文平均，再按该组完整训练上下文平均 |
| A / AB 目标 | L_A；L_A + 1.0 × L_B。添加 B 不稀释 A 权重 |
| 初始化 / 运行 | seed 2705；既有 Python 3.9.13 / NumPy 2.0.2 / torch 2.8.0+cpu；4/1 线程；float32 |
| 优化器 | AdamW，lr=0.001，weight_decay=0.0001，betas=(0.9,0.999)，eps=1e-8；全局梯度范数裁剪 1 |
| 预算 / 候选 | 两臂各固定 40 epochs；唯一候选为第 40 轮末状态；没有 early stopping 或开发集挑轮次 |
| 判别 | logit ≥ 0 判攻击；不校准阈值 |
| 顺序 | 先 A，再从原始共同初始化训练 AB；两个终点均封存后才各执行一次共同检查 |

选择普通监督是为了先看新系统能否正常学会这些标签任务；本基线不宣称蒸馏成功。
1.0 是两个 owner 的对称组权重，避免原来把多个保护目标的尺度和资格筛选混在学习问题里。
40 轮提供固定、超过旧实际 20 轮的学习预算，并把检查数据完全移出候选选择。
这是一个有界诊断配方，不是已经验证的最优预算；失败不能被解释为 GRU 能力上限。
模型沿用现有可复用结构，理由和近期文献适用性见上一份对照草案，本轮不新增另一方法候选。

令 N_A/N_B 为新训练侧含对应目标的完整上下文数，S=ceil(N_A/32)。每轮各组按固定
SHA256 顺序排一次，再各均分为 S 个连续桶；小尾桶不丢弃，每个对应监督目标每轮出现一次。
每步 A 项为 `(S/N_A) × 本桶上下文损失之和`；AB 再加 `(S/N_B) × B 本桶损失之和`。
在参数不变时，对 S 步取均值精确恢复各自全语料目标；不能用批内大小替代全组分母。
A 呈现顺序、次数和更新数两臂相同。B 桶如超过 32 上下文，按 32 微批累积梯度，
每一步最后统一裁剪并更新一次。参数随训练变化，故这不宣称每步梯度等于全批梯度。

A/B 分别只在对应监督目标处计损失，保留至最后所需目标的完整因果前缀。
A 必需前缀字节两臂一致；不额外给 A 臂喂 B 专属样本或标签。
“A-only”指目标监督，不宣称模型从未读到过任何 B 相关字节。
训练检查日志只记录训练进度和损失，不读取 check 来挑模型；完整终点封存后，
分别作一次训练内拟合核查和一次共同名单检查，报告拟合与拟合排除结果。

## 名单的前瞻规则与当前未完成项

所有目标目前的 `new_split_role=UNASSIGNED_PENDING_DEPENDENCY_QUALIFICATION`。
**新 train/check 精确分母均未产生；不能称整个实验已冻结或直接开训。**

完成 B 分组桥之后，按以下唯一规则生成新版本名单，原 F5/F1 文件保持不变：

1. 上下文为不可拆原子。用真实旧 A 会话、B 无 epoch 路由依赖键及已核实跨 A/B 桥建连通分量；
   共享已核实输入前缀的上下文合并。不能用时间回退 B 的占位编号断开其原会话。
2. 分量 ID 为其排序 context keys 的规范 JSON 的 SHA256。划分 stratum 为该分量中所有
   `(source_group, owner, label, attack_family, device_family)` 元组去重后排序的完整集合。
   含多种标签/来源的依赖分量整体保留，不用某一个“主要类别”掩盖其余成员。
3. 每个 stratum 内按 `SHA256(UTF8(规范 JSON ["paired-split-v1",2705,component_id]))`
   和 component_id 排序。G≥2 时，前 `max(1,floor(G/5))` 个分量为 check，其余为 train；
   G=1 时整个分量 train-only，并显式标注无法提供独立同 stratum 检查。
   规范 JSON 使用 ensure_ascii=False、separators=(",",":")，不带换行。
4. 完整 18,266 目标守恒、角色互斥，所有已核实依赖边/前缀共享边跨 train/check 数量为零。
   报告目标/上下文/依赖分量计数、来源与行为覆盖以及目标时间区间交叠；比例不强制为逐目标 80/20。
   这不是时间外推实验，不把同文件分组检查称为新来源或新设备独立性。
5. 不根据旧/新错误、分数、五条 UID 或结果反复换分组盐值。单例和不均衡导致的缺口按原样报告。
   至少需要新训练/检查两边具有 A 攻击、A 正常及 B 正常的已核实行为覆盖；
   ToN 扫描、暴力破解、正常的覆盖逐项交付。关键行为只在一侧时不能以其他来源成功替代。
   B 攻击必须单列；无足够依赖组时其同类检查证据不足，不制造该项 PASS。

上述规则冻结划分方法，不能替代尚缺的依赖数据。若取证后仍不足以构成有意义的两臂检查，
应报告真实覆盖不足，另行提出新增合法开发证据的最小范围，不悄悄退回随机按行拆分。

## 结果怎样判断

旧系统使用既有、按 UID 验证的 A 旧判决作为固定参考，不作教师前向，更不接到新表示后部署。
全体 A 攻击的 attack_hard 来源与 A 正常的旧逐 UID 判决必须在实现中验证。
两臂在同一检查名单上报告攻击漏检、正常误报、旧正确变错、旧错误变对及 A→AB 的判决翻转。
同时按 owner、行为、来源、目标、上下文、依赖组展示分母。训练覆盖/未覆盖分开解释。

- 能力保持门槛：两臂在共同 A 检查集合上均无旧正确变错；AB 还不能破坏 A 臂的正确判决。
  这是该开发检查范围的严格门槛。只在有覆盖子集通过，不自动变成全部 A 通过。
- B 正常增量：AB 的正常误报严格减少，且预声明正常来源/设备族单元的误报与完整正常上下文错误
  均不增加；任何 B 攻击退化不能被正常释放掩盖。
- B 攻击增量独立判断：攻击漏检严格减少，预声明攻击族/来源单元的目标与上下文漏检均不增加。
  B 正常变好不能推出 B 攻击变好；分母不足或零分母为 NOT_ESTABLISHED。
- 两臂 A 都失败，优先调查新学习路线；A 通过但 AB 回退，调查 B 监督兼容性；
  A 保持但 B 无改善，第二项仍未证明。不得再按 check 结果续训本尝试。

本对照只有一个 seed，数据已经被历史开发观察过。没有未触碰确认集、显著性结论、
部署或新设备能力承诺。旧 F5/N3/outer 的失败/有限成功及门槛不因新协议改变。

## 最小后续取证提案：只补缺失的 B 分组桥

这是具体的后续方案，**本轮没有实施，也没有获得原始数据解码授权**。
成员清单已输出为 `proposed_B_route_metadata_members.csv`：

  不重放扫描/暴力破解两个全 A 的 ToN 成员。
- 按每个成员最后一个 B 目标截断，单次顺序读取上限 **8,207,642 包**。
  只解析建立分组所需头部字段，不生成特征或预测，不读取目标标签决定分组。
  输入容器 SHA/ZIP 成员身份来自既有 attachment，真实读取前校验原文件身份。
- 输出字段：UID、member、原始位置、由 F0 相同字段语义产生的 tier 和无 epoch 路由键哈希；
  对可构造旧五元组的 B 目标，另输出按旧生成器规则得到的 canonical session 哈希，
  把时间回退 B 与可能的 A 会话连接。H4 保存保守协议类别组，不能按 UID 人为分裂。
- 只需单遍目标头部投影即可取得上述字段：先前目标位置和上下文映射已经封存，
  分组键可用同一成员内原始端点的稳定相等关系（不外发端点值）表示，
  无需两遍重建全部 GRU 输入或再次证明 F4 数值能力。
- 前缀不交叠可使用已固定 F0/F1 的单事件唯一路由、epoch 切分与 F4/outer 输入来源作结构证明，
  再核对新依赖组和完整上下文角色；不能仅以“没有存前缀起点”为由要求全池重放。
  实现必须检验这些前提。如果发现前提不成立，记录具体反例；不能自动扩大原始读取范围。
- 取证实现/验证与名单封存可以作为一个有限工作包。建议单 worker、本地、
  取证总墙钟上限 3,600 秒、聚合 8 GiB、输出 64 MiB、零模型调用、零重试。
  限制不是实测耗时；精确容器身份和成员截断已列明，输出后执行上面已定的名单规则。

这项单遍新元数据投影用于补此前未保存的字段，不能借机重跑 F0/F4 的历史科学评估。
即使拿到分组键，也不保证稀少 B 攻击或单来源正常流量足以形成合格检查；届时据实交付分母。

# Q/M/C：参考为何降误报却损失攻击，以及下一方法决策

日期：2026-09-22。工作分支 `codex/exp-mainline`，HEAD `4b28747b09480471e2bac1beb3a9badf27280efb`。

## 1. 结论先行

**保留 Q 作为下一方法的完整查询判断底座；不推广当前 M/C，也不重新更换前端。下一方法应学习“有攻击保护约束的正常参考校正”，并在训练侧模拟真正未参与基础模型拟合的设备。**

这不是宣布 Q 已满足论文目标。Q 在本轮两个开发设备上攻击检出很强，但正常行为仍有集中失败，数据来源和服务覆盖也限制其外推。参考路线有改进价值，不过当前 M/C 的实现与训练不能证明已经学会了安全的新设备适应。

主要证据：

1. Q 的 374 条正常误报中，357 条来自 Eufy 的 WAN_WATCH（远程观看），该活动误报 357/738=48.3740%。大量容易正常流量把总体误报稀释到 0.3709%。
2. M 相对 Q 修好 316 条误报，同时新增 2,830 条攻击漏检；C 修好 99 条、又新增 13 条误报，同时新增 14,859 条攻击漏检。二者都没有救回 Q 漏掉的 11 条攻击查询。
3. 同一批查询只换参考，M 的正常和攻击分数会一起整体移动；C 在 HeimVision 上换成错误设备参考，反而恢复大量攻击且正常误报不增加。当前条件作用不符合预期机制。
4. Q/M/C 是从冻结 R 分别训练的三个头。C 还移除了完整查询 z 的直达通道。不能将本轮解释成“在好 Q 上加参考，证明参考必然有害”。
5. 训练有 766,727 条查询，但只有 6 个训练设备和每设备一组固定参考，部分设备仅 2 条参考；40 个 epoch 重复这些上下文并不等于学习了大量新设备适应任务。

本次完成的是已有证据诊断与方法方向决策。没有启动下一真实实验；新候选还不是冻结的可执行 recipe。

### 3.2 能说与不能说

可以说：已训练 Q 对本轮两个新设备、现有已知机制攻击具有很强开发信号。Q 不读取正常参考内容，但共用“有合法参考才启用新残差，否则回退 R”的注册开关；不是完全无入网前提的全局替代模型。

不能说：已继承/超越全部历史攻击能力、已实现全新攻击家族泛化、所有正常活动误报低、或已完成真实混合流在线验证。DEV 的 HTTP/TCP/UDP 主要属于相同 LOIC 机制的不同模式；不能称为三个独立未知攻击机制。旧系统原测试集与这里不是同一分母，不能把本轮 R 的 29.43% 当作历史旧攻击能力本身下降。

## 5. 参考机制的直接证据

以下是已保存的正确/错误设备参考干预：查询固定、参考预算同为 11、TCP/UDP 配比一致。HeimVision 正常对照仅 696 条满足错误参考也严格更早的条件，不能把 997 条全量正常塞进该对照。

| 设备/分支 | 正常误报：正确→错误参考 | 攻击检出：正确→错误参考 |
|---|---:|---:|
| Eufy M | 56→0 / 99,833 | 13,402→13,402 / 13,507 |
| Eufy C | 211→12 / 99,833 | 13,402→8,835 / 13,507 |
| HeimVision M | 2→17 / 696 | 62,813→65,548 / 65,549 |
| HeimVision C | 0→0 / 696 | 50,784→65,527 / 65,549 |

对 M 而言，Eufy 的错误参考使**所有正常与攻击查询**分数下降；HeimVision 的错误参考使所有正常与攻击分数上升。正常/攻击变化中位数分别约 -12.01/-17.12 和 +18.14/+14.72。这支持“参考带来较强设备相关整体偏移”的解释；不证明它完全没有学到查询—参考关系。

C 在 HeimVision 的错误参考救回 14,743 条攻击查询且不增加这批正常误报；在 Eufy 错误参考又损失 4,567 条攻击。这说明不能声称“正确参考普遍改善正常/攻击区分”。也不能反向部署错误参考，因为这是两个已知开发设备上的事后现象。

已有 budget16 对照：M 在两台设备上的判定均未变化；C 的 Eufy 正常误报由 288 降为 224，攻击不变；HeimVision 仅有 11 条参考，因此该设备无变化。**budget16 的 224 与正确/错误对照 budget11 的 211 是不同分母条件，不混用。** 当前证据不支持“加参考越多越好”，也不支持只改参考数就能修复攻击损失。

## 6. 实现和训练为何容易产生这种结果

| 分支 | 残差头输入 | 参数数 | 与 Q 的关键差异 |
|---|---|---:|---|
| Q | 完整 z(768)、旧 h(128)、旧 logit b | 14,385 | 不读参考内容 |
| M | z、参考 z 的均值/标准差、h、b | 38,961 | 参考统计能改变整个分类映射 |
| C | h、b、16 维查询—参考关系的均值与最大值 | 27,201 | 完整 z 无直达通道，关系压缩额外形成瓶颈 |

三者都独立从 R 初始化残差训练，并非先训练 Q、再给 Q 增加小模块。C 的对比同时改变了参考机制与查询信息通道；将全部差异归因于“参考有没有价值”是不成立的。

训练仅有分层加权 BCE，没有相对于 Q 的攻击保留损失、每模式保护约束或推断时有条件回退到 Q 的机制。冻结 R 只保证 R 权重不变，并不保证 `R + residual` 的最终攻击决定不变。同理，未来冻结 Q 也不能自动保证最终输出不降，需要单独训练与检验保护。

Q/M/C 在 LEARN 均为 599,087/599,087 攻击检出、0/167,640 正常误报。现有参考集合在全部 40 epochs 重复使用，没有把“新设备参考→后续正常/攻击”的变化作为多样任务进行训练，也没有让 Q 在没学过某设备时产生的错误用于校正学习。

参考覆盖非常有限：Eufy 的 64 条参考仅来自 LOCAL_RING，而主要错误是 WAN_WATCH；HeimVision 的 11 条参考来自 LAN_WATCH，TCP 仅 1 条；Atomi、Globe 各只有 2 条参考。参考是合法的早期正常数据，但不能自动代表该设备以后全部正常活动。

因此，已证实的是架构/目标/任务暴露的差异及干预异常；“记住设备偏置”“参考覆盖不足导致泛化差”是有证据支持的机制假设，尚未被拆分消融逐一证明。没有证据把问题归结为简单的训练未跑完或 epoch 不够。

## 7. 数据、前端与泄漏边界

### 已核对的部分

- LEARN/DEV 的 UID、设备、owner、session、component、原始包 SHA、原始包 SHA+微秒时间，以及不带 owner 的规范连接键，交集全部为 0。
- LEARN/DEV 共享 7 份 Active 正常 PCAP 来源。这些文件包含多个设备；共享源文件不等于共享设备样本，但会保留共同采集环境相关性。
- 被审查实现按 owner+capture+规范连接隔离上下文，按原始帧序追加；时间回退使上下文失效，查询时复制当前前缀快照，不使用未来帧。多设备归属和共享 DHCP 上下文被排除。
- 当前包标签只验证清单身份，不进入 `E3_KEYS` 的模型输入。角色、设备名、文件名、攻击标签都不是模型张量字段。
- 转换器虽用地址/端口构造连接和方向，送入 E3 的内容不直接包含 IP/MAC/端口、绝对时间或载荷。输入包括包头长度/TOS/flags/TTL、TCP flags/window/相对 seq-ack/urgent 或 UDP length、方向、相对时间间隔、包数、字节和持续时长。
- 使用旧冻结归一化，不用 DEV 重估。每台 LEARN/DEV 设备的参考都严格早于其查询；未发现参考当前包与 DEV 当前包身份重合。

### 仍限制结果的部分

DEV 的 79,056 条攻击全部有一端端口 80，而 100,830 条正常都没有一端端口 80。这是**服务覆盖缺口**，不是已经证明端口作为标签被模型读取。LEARN 中有 19,409 条涉及端口 80 的正常查询，以及 684 条不涉及 80 的攻击查询；所以“整个训练集只需按端口分类”也不成立。端口端点信息不能冒充本地入站方向；导出缺方向注释，Philips inbound TCP80 专项仍不可恢复。

即便不直接输入端口，TTL、窗口、长度、时序等仍可能间接反映服务、工具和采集机器；本轮无法排除模型依赖这些相关性。正常网关/攻击机采集视角不同、LOIC 模式重复，进一步限制独立环境与未知机制结论。

本地未导出完整前缀特征数组，故没有新证明规范化前缀/特征层面的排重；E3 外部预训练的完整排重也未证明。前端检查结论是“所查代码与身份未发现直接跨分区、标签或未来输入路径”，不能写成全面泄漏 PASS。

17.99 万 DEV 查询不是 17.99 万独立试验：HeimVision 正常 997 条来自 68 个连接、43 个组件；Eufy 的容易 Active 正常占 98,679 条。增加相同连接的包数，无法替代更多正常行为、服务和独立设备。

参考时间合规是逐设备的因果条件，不代表 LEARN/DEV 已实现全局日期前后隔离。也尚未验证真实同网混合在线流、参考污染、标签延迟和逐步更新。

## 8. 针对性的文献核对

本节是机制借鉴，不将论文自报数值当作本项目预期效果。

1. **ICLAD: In-Context Learning for Unified Tabular Anomaly Detection Across Supervision Regimes**，Wei/Armanfard，2026-03-19，arXiv 2603.19497v1。原文：<https://arxiv.org/html/2603.19497v1>。
   方法通过多任务训练学习 support 条件下的异常判断，并隔离 query 间信息；其任务多样性来自约 5,200 万合成任务。借鉴的是“训练要教会使用变化的上下文、查询不能反向污染支持集”，不是给 6 个固定参考集合加一个更大的 Transformer。论文在通用表格异常数据上的 AUC 不证明 NIDS 低误报下攻击保护；其大规模预训练开销也不适合直接复制。
2. **Disentangled Dynamic Intrusion Detection（DIDS-MFL）**，Qiu 等；本次读到的是 2024-12-14 的 arXiv v2，2025 TPAMI 版本由近期综述列引。原文：<https://arxiv.org/html/2307.11079v2>。
   它针对攻击差异与 few-shot 的表示纠缠，分别设计表示约束和多尺度比较。可借鉴“保留攻击特征、让适应目标显式进入学习”的思路；不据此宣称已解决本项目的正常 OOD 误报。其图结构/攻击 few-shot 设定与纯正常入网参考不同，迁移整套网络会引入大量不必要变更。论文也指出少量攻击类型会限制某些元学习方法，因此本项目不能把 6 台设备的重采样包装成大规模独立任务。
3. **Few-Shot Learning for Network Intrusion Detection: Methods, Datasets, and Performance**，Roszeitis/Jüttner/Buchmann，2026-09-10，arXiv 2609.11275v1。原文：<https://arxiv.org/html/2609.11275v1>。
   该综述纳入 21 项研究，指出协议异质、复现不足；其第 5.3 节指出纳入研究没有训练/测试在完全不同数据集的交叉评估。这支持本项目必须区分本数据集开发成功与跨环境泛化；综述的检索/单人审查限制也不应忽略。

“正常参考”“关系网络”“元学习”“攻击约束”各自都不是自动成立的创新。可争取的贡献是：**在有限协议覆盖及可信正常入网前提下，实证实现参考带来的正常适应，同时保住原有攻击区分，并明确何时参考不可靠。** 只有联合结果、适当对照和独立验证成立，才能谈论文贡献。

## 9. 选定的后续方向与最小可证伪比较

### 9.1 方法方向

采用 `s_new(x,S) = s_Q(x) + delta(x,S)` 的明确分工：冻结、保留完整 Q 路径，单独学习参考校正。参考为空/不合规时必须精确回退 Q；旧系统 R 在其原有使用范围内继续保留。这是未来新版本的设计方向，不修改当前 Q 的既有回退定义。

校正应根据查询与可信正常参考的关系区分“设备正常变化”与“攻击证据”，不能仅根据设备均值整体降低报警。攻击标签训练项和保护项只用训练侧数据；保护关注每设备/模式的判定余量与损失，不只看平均 BCE。是否有界、如何设保护余量和损失权重，需要在新协议中依据训练侧尺度提前固定，不从这次 DEV 错误反推最优数值。

**训练侧模拟新设备是必要设计重点。** 当前 Q 已把全部 LEARN 拟合正确，简单在这些同样已拟合的查询上学“纠错器”，未必有代表性的纠错信号。拟采用 LEARN 内按设备留出的基础头，产生没有用该设备监督拟合的分数，再用该设备合法早期正常参考和后续查询学习校正；基础头与校正头的开发/校准职责必须隔离。借此学习跨设备纠错，再与完整冻结 Q 对接。少量设备下的误差、基础头分数尺度迁移都要列为风险，不能称有泛化保证。

参考任务只能使用合法的更早正常数据，按真实会话/捕获与活动组织；随机复制两条参考不是新增覆盖。不能为了修复 Eufy WAN_WATCH，就把该 DEV 后续错误样本塞回早期参考。若现有 LEARN 参考无法构造足够的活动/时间差异，先报告具体缺口，不能直接发起一个预见无有效监督的长训练。

### 9.2 为什么不选其他动作

| 动作 | 当前判断 |
|---|---|
| 立即把 M/C 再多训几轮或挑最好 seed | 没有针对任务暴露、信息通道和攻击保护缺失，不选 |
| 只把正确参考换成表现更好的错误参考 | DEV 事后规则，不能外推，不选 |
| 仅改阈值/参考预算 | 当前冻结协议不允许；已有预算对照没有修复攻击问题，不作为下一主方法 |
| 再换一次前端或直接搬大型图模型 | Q 已证明现有表示在本轮能表达强判别，当前没有必须更换的证据，不选 |
| Q 报警与参考报警做 OR | 难以减少 Q 已有误报，不符合此次首要缺口 |
| 正常相似就直接放行或简单 AND | 会重现攻击被正常参考压掉的风险，不作为无约束方案 |
| 保留 Q、隔离参考校正并显式保护攻击 | 与已观测缺陷对应，选为下一设计方向 |

冻结 Q 只保护内部参数，不是最终攻击不降的数学保证。若强制保留 Q 的所有正例，Q 的正常误报也无法被修复。因此攻击保留必须由训练约束和未参与拟合的检验共同支持，不能靠结构名称许诺。

### 9.3 下一协议要回答的唯一主问题

**在保留同一 Q 底座、同一合法输入和阈值的情况下，正确正常参考能否降低设备/活动分层误报，同时避免当前 M/C 的攻击损失？**

只准备一个候选机制；Q 为固定对照，正确参考、预算/协议匹配的错误参考与空参考为机制对照。空参考必须数值还原 Q；除参考内容外不偷偷改变完整查询通道。训练留设备任务与保护项的作用应有预先限定的对照，不展开超参搜索。具体数量、计算预算、保护容忍度及唯一终点先冻结。

DEV 现在已被充分分析，只能作为后续开发诊断数据。新增保护目标不能只相对较弱 R，需要与 Q 比较逐设备/攻击模式损失和正常活动误报；但这属于新协议，不能改写原 M/C gate。HOLDOUT 只有在另行明确前瞻性使用方案、满足相应条件与授权后才可打开。

停止条件必须明确：若正确参考没有超过同预算错误/空参考的可重复收益，或正常改善仍伴随不可接受的逐模式攻击损失，就不宣称参考机制成功、不打开保留集；先区分监督/覆盖不足还是关系信息不足，不自动开启相邻参数重试。

旧攻击/未见同名家族、独立 ID、旧 hard-OOD 以及新设备后续正常/攻击是最终应同时保留的能力矩阵。当前本轮新增设备结果不能代替前几项。新候选的历史能力回归验证需另定合法范围，不能直接重开受控历史 FINAL。

### 9.4 执行成本与下一步性质

**下一步是把上述方法形成短而完整、可实现的新协议并审查；目前不是再次启动训练。** 必须先明确训练侧留设备任务、参考覆盖、攻击保护、相同 Q 对照及停止条件；不是再做泛泛数据方案。

后续实现应复用 HPC 已封存的 E3 特征。拉回包当前未包含这些大数组，因此真要运行新头前，应让用户从远端导出所需、匹配缓存哈希的特征/注释；不重跑近 60 小时整条流水线。环境/数据存在性以届时核验为准。打包还须补齐非合成报告路径的依赖闭包，在干净 Linux 解包目录验证，避免重犯本次尾部缺元数据错误。

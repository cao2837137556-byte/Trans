# Paper04 路线知识索引：以后提出方案前的共同起点

2026-09-15。用户要求系统性了解以往实验、方法和运行经验，避免每次由用户补背景。本索引接续当前交接，而不是重新启动旧路线。已阅读专题文档、已披露结果和所需源码；没有声称读完所有对话、全部日志或所有原始数据。

## 项目目标与当前系统

论文问题是开放环境中正常变化与攻击混在一起时，系统能否保留攻击检测、攻击迁移，并降低正常误报。当前目标顺序是：在明确输入范围内，以旧有效 E3/P2 为起点；已覆盖正常环境应低误报，未见设备优先研究合法正常历史驱动的入网适应；最后补独立确认与论文实验。全新攻击机制和任意未知 OOD 的双重零样本泛化不是已实现的能力，也不是无条件论文承诺。

旧 E3/P2：固定外部 netFound-base 编码器、按目标截断的会话/burst 输入、masked mean 768 维、旧 normalizer、769→128→1 MLP。原 P2 接触 18,398 fit、阈值选择接触 7,069 select；原 Gotham support 与 ToN 等扩充监督必须分开披露，不能都叫最初 few-shot 预算。A/B 是旧有效输入/旧缺失输入的划分，不是两个数据集或正常/攻击标签。

本次固定基线账本已 COMPLETE：有效输入上的同名已见攻击族检出 99.9931%，同名未见族 91.9089%，整体 96.4414%、future 95.3773%；不是新训练提升。同名已见族有效覆盖仅 61.7218%，不能外推所有协议。同名族未见不等于机制完全未见。五个正常池各自经验 FPR≤1% 时，整体攻击检出 90.9224%；四个 OOD 都未进入原 P2 fit/select，但反复开发曝光。详见新结果文档及封存输出，独立 ID 仍缺。

I1 自监督曾因合法语料不足而未训练。D0 的约 1,170 万 tokens 是 mixed-fit，不能当良性预训练量；D1 精确良性普查为 8,735 sessions / 697,387 tokens，2,182,190 只是可见包数上界。E3 按冻结备用顺序启用，不是完成 I1 后再挑一个赢家。

统一前端 GRU 是另一条后来路线：F4 所选字段形成 131 维输入，随后学习 GRU 表示。F4 无损编码审计不等于与旧 E3 同信息、同预训练、同上下文、同训练集合。当前这条路线暂缓，不能把它的旧 CHECK 当作从未被原 P2 接触的测试。

“因果”在当前输入合同中是判定时不使用未来信息；不表示已经学到了因果不变机制。不同路线的 current-inclusive 输入与 score-before-state-update 规则各有适用对象，不能把某个旧运行账本中的通用文字直接套到所有前端。

## 已取得的数据及具体空缺

- ToN 七 reserve conn 日志曾确认存在，未等于配套 PCAP、正常标签桥接、角色合法性都齐全；18份已审查GT没有正常类，不能将攻击匹配补集当正常。
- Gotham 原始候选、原 support、后加160隔离目标是不同集合。后加160存在相对query逆时序问题，不能以“此前没用过”回收训练。
- CIC2022 已取得攻击与正常交互两个原始归档。23文件审查中同设备身份明确；Hydra窄请求注释可用，Nmap混有探测与成功视频，不能整文件攻击或把视频尾自动当正常。
- 两台摄像头的新增监督没有直接补入 hydraulic/predictive 的正常训练实例。其收益仍需实际验证；扩大重复请求数不能代替更多独立环境。
- 新设备入网需正常参考在查询前可得，并有同设备后续攻击验证误报降低是否伴随攻击漏检。两设备的训练用法与未见设备验证用法不得混称；历史 Data-F0 的8设备门槛属于其旧特定协议，不自动变成所有新试验的门槛，也不能追改旧判定。

## 运行经验与后续维护

HPC本轮未访问。已接续 workflow 全文与 failure ledger 的通用门槛、传输最终更正及Python3.9事故；其余条目按后续实际任务定位，不宣称实时环境已验证。

1. 官方vendor代码也必须纳入依赖闭包与实际Python版本检查；历史match/case及Path.write_text(newline=...)分别是语法和标准库兼容问题，不能靠自有代码语法通过就宣称环境可运行。
2. 大包保持唯一版本、LF与解包后hash核验；远端路径不是当然Git工作区。传输断点与科学计算重试分开。账本最终结论是该账号公钥曾被拒绝，不能引用早期“key添加成功”承诺免密。
3. 状态必须有阶段、done/total、失败原因与终态；CPU忙/心跳不证明有进度。计算完成后的打包失败只恢复收尾，不能重训。
4. 用户的有效授权跨消息持续；已授权链内的机械修复和验证继续做。旧文档中的历史审批人/旧角色门槛不自动为新方案创造额外审批；真正的新实验、语义变化或未列访问范围仍须说清。
5. 本地优先读当前handoff与本索引，再打开相关路线原始结果/冻结合同；不每次全读月份日志，也不依赖用户重复解释。新增结果后维护一条路线证据及适用边界；当前状态放handoff顶部，索引一行，冻结原件不改写。
6. 每次机制建议明确：针对哪个仍未解决的能力；改变了什么输入/监督/学习关系；历史最接近哪次尝试；那次结果究竟否定什么；新试验如何区分假设。涉及新机制时再针对性核对文献，不能以旧模型作者或AI型号作为方案可信度依据。

本轮覆盖的是与当前旧系统增强、正常环境误报、继承和入网直接相关的关键路线。全部原始预训练语料、未落盘口头决定、所有更早消融与原始超算作业日志仍未逐项复审；有需要时按明确问题补读，不能提前声称没有遗漏。

来源身份与读取范围见同 stem `.sources.json`；旧核心20份材料另由专题复盘的 `.sources.json` 逐项封存。SHA固定文档身份，不表示重新验证了其每一个历史数组或科学主张。

# 双臂结果后的主线目标、下一步与检测头定位

2026-09-10。性质：研究判断与下一工作包范围；不是新的冻结实验协议或执行授权。

## 论文目标校正：以用户本轮澄清和原始研究记录为准

论文立足点是开放世界中的正常 OOD 与攻击混淆：在 ID、正常 OOD 和攻击
共存时，既减少正常 OOD 被误报为攻击，又保住真实攻击的检测能力；ID 正常
流量的低误报是基础。不能把降低 OOD 误报与攻击漏检分开宣称成功。这里规定
的是系统行为，不预定必须使用三分类头或某一种架构。

少样本攻击学习、加入部分正常 OOD 训练是历史方法路线；未见攻击和未见正常
OOD 是泛化要求。用见过的 OOD 训练后识别它，不等于能处理未见正常 OOD。
新设备入网是加入正常观察期等条件后的收窄场景，不等同于零样本未见 OOD，
也没有被现有证据证明解决。前端覆盖与能力继承是恢复研究条件的工程/学习
子任务，不取代论文目标。当前普通监督 A/AB 实验也不自动构成少样本结果。

| 阶段 | 已有证据 | 尚不能据此声称 |

## 当前决定

保留已封存的 A / AB 候选。下一工作包围绕一个问题设计：新模型在更广且用途
合规的数据上，能否减少正常 OOD 误报并同时保住攻击检测？先核对可用证据的
训练暴露、来源/设备/攻击族隔离和输入可执行性，交付具体的固定候选评估提案；
不能用扩大样本总数替代这些条件。评估同时列出 ID 误报、正常 OOD 误报和
逐类攻击漏检，明确见过/未见与是否使用入网正常历史。已有残余错误诊断仅
作为有界辅助项，不再把修到小池零错误当成主线终点。严格继承门槛保持原判，
任何后续范围都不能绕过它去取得受限评估资格。

这次18,266目标池及3,193检查目标仅是前端开发对照；历史1M缓存及683,420条
认证攻击子集不是新模型已完成的测试，也不能不经用途/输入核对直接加入训练。
目前没有已核实的新评估总分母，不预先承诺所有历史数据能直接运行或保持独立。

| 工作 | 本次建议的边界 | 交付与终点 |
|---|---|---|
| 残余错误诊断 | 既有预测、训练日志与获准元数据；两个共同检查错误上下文及一个 Mirai 训练错误上下文，按相关完整类别/前缀分母解释 | 区分已证实问题与假设；不围绕 UID 调参，不预定必须修到零 |
| 扩大评估范围核对 | 获准清单/合同中的 ID、困难 OOD、攻击分区；记录训练/选择/历史暴露与依赖；不打开受限样本或分数 | 每项给目标/上下文/攻击族/来源分母、A/B覆盖、输入来源与可执行缺口 |
| 形成执行提案 | 固定现有候选和阈值，同一目标/事件/因果前缀比较 A、AB；旧参考仅在身份和语义合格范围使用 | 明确开发/独立确认/最终评估区别，比较指标、输入物化量及运行预算；随后按具体范围授权评分 |

如果只读诊断发现会令评估失真的实现或语义问题，先说明具体证据及影响，
再提出修复；修复会改变模型时需新版本和新协议。如果只剩未归因的有限错误，
把其作为固定候选的已知风险纳入扩大开发评估提案，不反复补小池约束。
严格继承 FAIL 保留；本建议不授予通过该门槛后的确认资格，不放行封闭角色。
无新训练、额外前向、原始包解码、HPC、下载、设备实验或检测头修改。

## 当前检测头实际是什么

核对 `repo/ood/issue27frontend_paired_train_model_v1.py` 的 Student 定义：

`F4 131D -> Linear(131,64)+GELU -> GRU(64,128) -> Linear(128,64)+GELU -> Linear(64,1)`。

最后两层是带一个隐藏层的 MLP 检测头，参数为128×64+64+64×1+1=8,321；
整个模型91,265参数全部训练。这一臂没有使用旧P2作新表示的部署头，也不是
N3仅65参数的线性末层修补。GRU负责时序表示，MLP负责读出正常/攻击判别。

这是一套常规神经网络学习基线，不能只以GRU+MLP组合主张新架构贡献。
头部更复杂并不自动增强论文：需要证明增加的容量处理了具体失败机制，并在
预先规定的独立性条件下带来收益，同时量化误报、逐类漏检和运行成本。
小头如果足够，可以支持效率和贡献归因；也不能仅因小头简单就假定它足够。

未来若要判断头部容量，采用固定输入/编码器的受控头部对照并区分编码器更新，
属于需另行设计的实验；当前不增加此候选或搜索层数。现阶段更大的证据缺口是
更广的行为/来源覆盖与泛化，而不是已证实的头部容量不足。

## 本轮检索依据与适用范围

本轮通过公开搜索打开原文；仅读相关摘要、方法/评估段落，不下载模型或数据。

- [Talk Like a Packet, 2026-02-06 v1](https://arxiv.org/html/2602.06636v1)：
  按架构、输入模态和预训练策略区分贡献；分类案例使用YaTC编码器加MLP头，
  并与MLP-only比较。说明应区分表示与读出作用；其任务和三隐藏层MLP并不
  证明本地一隐藏层头最优，也不证明必须采用其Transformer。
- [netFound: Principled Design for Network Foundation Models, v5](https://arxiv.org/html/2310.17025v5)：
  通过协议字段、运行上下文、层次表示和身份捷径控制提出设计；内在评估使用
  简单线性探针以避免混淆表示质量与分类头容量，并报告冻结/微调设置。
  这支持先区分瓶颈与评价条件，不能直接外推本项目非IP/keyless覆盖或部署能力。

论文问题由上述开放世界目标确定；最终可主张的贡献强度由后续证据决定。
当前B正常收益是开发证据，不能直接升级为困难OOD或设备入网贡献。头部容量
应服务于正常OOD与攻击的区分；如果最终只有常规GRU+MLP与小池效果，方法
贡献和证据均仍需加强。任何新科学机制仍须针对问题检索相关工作并审查后提出。

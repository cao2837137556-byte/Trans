# 冻结 v12 的设备本地相对握手次数对照

四组共用 v12 的三个冻结检测头与集成、源阈值、参考库、三空间半径、双组件、原 SYN 旁路、UDP 规则、(p=4) 和 (lambda=0.25)。四组为 v12、R1＋U1、v12 加握手距离、R1＋U1 加握手距离。R1＋U1 按已验收的帧时刻角色相等筛参考，未知只配未知。分别以 v12 和 R1＋U1 为基线计算握手距离的独立增量。ToN 沿用三目标逻辑主机配对。

## 帧时刻证据

复用上轮 `History.advance`、`History.observe`、原捕获顺序、分段重置和 TCP 序号确认。对受保护设备、通信对端 IP、设备端口三元组，统计当前 60 秒窗口内起始且已在当前前缀证实三次握手的入站发起五元组，重复 SYN 与同一存续五元组按上轮规则去重。用双向帧确认握手。入站参考和查询直接查该组，出站记录用反向端点索引同一个入站计数组。出站帧可以提供握手证据。出站发起的会话不增加入站发起数。首段不足 60 秒时只计算抓包已经观察到的时段，单列此类记录。每条参考只使用它自己的帧前缀，不使用建档结束时的数。

无法定位原始前缀时单列为缺失；数值 0 表示该前缀经核验、没有观测到合格握手。有效性独立于角色已知与否。缺失握手值的 TCP 查询保持对应基线判决，缺失握手值的 TCP 参考不参与四空间搜索。UDP 按两组各自的原判处理。已登记输入存在但校验失败、原帧和元数据矛盾等情况触发预检中止。

## 检索和归因

握手距离固定为 `abs(log1p(h_query) - log1p(h_reference)) / log(3)`。与三个已归一化距离取最大值。从参考开放、设备与协议、原时间资格以及该组角色合格的全部参考中重找两个不同组件。每个组件取最小联合距离，再取第二个组件的距离 `m2`。仅 `m2 < 1` 时支持度为 `1-m2`。严格握手距离边界等价于 `max(1+h_q,1+h_r) < 3*min(1+h_q,1+h_r)`，用整数实现边界。

按同一查询依次区分有效握手参考不足两组件、满足握手距离的参考不足两组件、再加原三空间后不足两相容组件、仍有两相容组件但扣分下降。各对照仅在相应不足时回到 RAW，其他查询保持基线。连接按固定视图中任一查询告警去重，按上述顺序归因，避免把同一连接算两次。缺失查询保持基线，并单列数量。

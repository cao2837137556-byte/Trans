1. 核验原 Job177891 完整父缓存、修复包及完成的检测头、正常 PCAP、冻结 E3 权重和依赖环境。修复头自身 FPR 未达标不会自动阻止组合评价；运行产物缺失或身份不符会停止。
2. 从 CIC active-00 和 UNSW benign-20180528 两份正常捕获，完整枚举固定窗口内的参考候选，生成 B0/B1/B2。窗口关闭后继续读完捕获，仅核验完整解码与包数。
3. 依次编码六个新参考库，使用原 RECENT 当前包输入与冻结 E3，最多每批16条。源参考104条不扩展、不重选。
4. 回放冻结检测头：CAL/CIC/UNSW 分数和判断须逐位复现，另计算 FIT 分数用于源尺度。旧库75条CIC/92条UNSW保持原身份。
5. 在源 FIT/CAL 上定几何、尺度和保护参数，封存一次；使用这同一组参数，依次评价 OLD_BANK、B0、B1、B2。模块的目标支持与修正发生在源参数封存之后；此前的目标头分数读取是固定头复现检查。
6. 输出同头配对、每seed/ensemble、全查询与较晚子集、设备/协议分层、参考资格、实际新增漏检及逐UID修正轨迹，归档回传。

整个入网链没有优化器更新，不重训修复头。参考不足、尚未到参考截止时间或没有支持的查询保留在原分母中，按原头回退。B0/B1实际相同会报告等价；不按数据集择优开关或自动挑赢家。没有事前冻结的错设备供体计划时，控制结果明确 `NOT_AVAILABLE`，不冒充已验证。

## 配置与保护

单节点 amd，8 CPU，16 GiB；单个重阶段进程、4个数值线程。RAW/E3/回放与模块评价阶段峰值估计6/4/11.5 GiB；最大值加一次25%余量，向上取整得到16 GiB。完整阶段均为估计，资源依据在 `RESOURCE_BUDGET.md` 和 `resource_plan.json`。

总进程树RSS保护14 GiB，运行磁盘保护8 GiB，开始时至少16 GiB空闲；导出included上限4 GiB。原PCAP/父缓存只读；为了完整封存encoder运行身份，在本次输出中复制一份已校验的0.651 GiB checkpoint，导出时省略这份可恢复模型，保留其哈希和runtime清单。重要参考、已选快照、编码和评价结果全部回传。

Slurm上限24小时、程序保护22小时，不是预计耗时。阶段顺序运行并退出释放，失败停止、零自动重试。父进程监控编码和评价；raw子进程监控自己拥有的SQLite临时文件，父进程不跨进程扫描正在删除的scratch，以避免之前的journal误停问题。监控文件放在评价封存目录之外。

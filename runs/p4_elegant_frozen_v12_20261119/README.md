1. 六个源成员取自发布者的正常和完整链归档。原件缓存于本机 `%LOCALAPPDATA%/Paper04/datasets/ELEGANT2021`；交付前、超算安装时和计算节点上分别核验长度及 SHA-256。需运行的三个正常滚动成员和三个事件成员均有完整原件身份。补齐的正常成员尾部只用于核实原件 SHA，评价仍止于已登记的 3,334 条查询。[成员 SHA](SOURCES.json)
2. 周期从 2021-03-18 02:53:45.357893766 至 04:53:45.357893766 UTC；N3 原始第 31,782 帧为末参考，第 31,784 帧为首条正常查询，纳入到第 41,783 帧。正常三成员按原序连续推进通信前缀和入站时钟；每个独立攻击运行从自己的首帧重放。任何时点只使用已到达帧。限定的 TCP 库含 214,703 个双向候选，仅一个组件；其中 71,568 条为入站。原 B2 规则选末端锚点，稠密选择器按原盐值、等距时间与同距并列规则选满 4,096 行。未引入外部历史。
3. 参考、查询、打分和回执均用原始成员 SHA、1 基成员帧号和主站 MAC 生成物理 UID。连续正常前缀的内部帧号为三成员连续编号；在描述符检查中以三个完整原件顺序拼接的摘要标识逻辑捕获，每一快照与其物理 UID 一一对应。通信组件使用 MAC、协议和排序后的端点对标识，跨滚动文件保持一致。原包时钟、以太网／IP 方向、UDP 事件标记、双端口及协议标志由独立原帧解析器与冻结前端复核。参考与评价位置互斥。[打分前封存](INPUT_SEAL.json)

## 节点预检、正式运行和验收

AMD 计算节点先按冻结环境重演所有指定完整前缀，在包含建档边界、后段正常及三个攻击事件的固定真实位置上执行编码、三个头及集成、距离、支持和判决。预检查原 CIC 的 1,024 个已有查询及源阈值判决；正式运行前核对预检退出状态、计算节点及包身份。在正式批次中按 UID 再对齐预检样本的基础分数和告警。

对每个查询执行冻结几何与 p=4 修正，并对每个头核验支持度、修正分数及判决。单组件结论按实际合法组件数、第二供体、非零支持数、最大绝对分差与判决翻转数验收。任何一项不符即保留具体 UID 和计算阶段，停止验收。

超算保留物理 UID、参考／查询顺序、编码、基础与修正分数、供体索引、距离和逐 UID 判决。D 盘 `received` 仅接收 `EVENTS.csv`（含总包数与事件发现数）、`NORMAL.csv`、`UID_CONSISTENCY.csv`、`ACCEPTANCE.json`、`SHA256.json` 和本地验收回执。三表均有单头和集成；逐文件核 SHA 并复算包数、比例与三次事件的计数后，进度页才显示本地已验收。

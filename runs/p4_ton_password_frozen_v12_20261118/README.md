# ToN-IoT 密码攻击的冻结 v12 诊断

本轮在已有资料上评价原版 FUSION790。三个分类头源自 CIC，种子为 27、127、227，集成在逐种子修正后取均值，按冻结的四个 CIC 源阈值独立判决。三空间 CCNR 使用原半径、原基准跨度、λ=0.25、p=4，两个不同组件均匹配时取较弱者。该实验属于源侧诊断。研究负责人在 p=3 与 p=4 的既有实测比较后选定了 v12 的 p=4。[交接单](../mainline_docs/collab/20261118_paper04_ton_password_frozen_v12_handoff_codex.md) · [冻结分析定义](DIAGNOSTIC_CARD.json)

只读取本轮三份原包、密码场景的连接日志和安全事件表，以及两份正常连接日志。先按文件 SHA 核对超算已有输入，缺项从 D 盘已持有的相同文件按块传递。查询按原始文件 SHA、从 1 开始的帧号与登记逻辑目标绑定，标签只参与原清点口径、查询筛选和离线统计。密码文件读取 2,351,034 个完整记录，独立核验末尾已知的未完整记录及全部纳入连接的时限。[输入 SHA](SCOPED_INPUTS.json)

单独的真实计算节点预检对同一原包比较 SLL 原生读取和 TShark 读取，检查当前包、双向通信前缀、14 维属性、8 维入站状态以及冻结编码、评分、三空间距离、旁路与小表。使用已存 CIC 原版查询核对基础分数及判决。预检通过后，正式准备作业封存全量合格查询、排除原因、两小时建档资格、参考 UID 和通信输入。只对已封存的位置运行冻结的 netFound。真实批形计时决定编码分片及申请时长，已核验的编码块可复用，大数组及逐查询明细留在超算。

输出包含按目标、种子及集成的 RAW 检出、漏检、误报和连接数。主分析与“按逻辑主机配对”的补充分析各用一张表。全体、旁路外、旁路外且带传输层数据三层分别列分母，A、B、W 及两项条件率按负责人最新口径计算。[目标身份与统计说明](IDENTITY_AND_PAIRING.md)

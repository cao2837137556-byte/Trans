# 入网完善：材料核查与首版配置

2026-10-15。**步骤 1 的本地材料核查、步骤 2 的首版设计配置已完成。可以进入实现；还没有实验代码包，也没有新的模型结果。** 本轮只运行已有元数据的统计脚本，没有读取模型分数、解码 PCAP、提取特征、训练或访问超算。

最重要的结论是：可信正常原始材料及后续查询都在，原参考库可以保留作第一组组合对照。但“扩大覆盖”的空间因设备而异，不能把增加观察时间或换选参考预先当作有效修复。新窗口的完整合法参考端点、E3 与 q14 仍需在后续准备程序中生成。

## 1. 本地材料给出的答案

当前开发范围为 CIC 两设备和 UNSW 五设备；源侧六设备另列。历史三设备只核对既有状态，不重新当成独立确认数据。

| 设备 | 原库 TCP / UDP 组件 | 1 小时已有组件证据 | 2 小时已有组件证据 | 对方案的实际影响 |
|---|---:|---:|---:|---|
| CIC Eufy | 16 / 48 | 0 / 176（下界） | 0 / 347（下界） | UDP 有选择空间；新窗口未证有 TCP 参考，不能预设优于原库 |
| CIC HeimVision | 1 / 10 | 1 / 2（下界） | 1 / 2（下界） | 现有证据未补齐 TCP 双组件；仅三个候选时换选无实际差异 |
| UNSW WEMO Motion | 44 / 20 | 603 / 20 | ≥603 / ≥34 | 首小时有 623 个组件、最多取 64 个，存在同预算选择空间 |
| UNSW WEMO Switch | 1 / 2 | 1 / 2 | 1 / 3 | 旧合法口径中 TCP 始终只有一个，延长至两小时仍不合格 |
| UNSW Samsung | 1 / 2 | 1 / 2 | ≥1 / ≥4 | 首小时已全部选入；两小时 TCP 能否增加尚不能由抽样清单确定 |
| UNSW TP Link | 2 / 3 | 2 / 3 | 3 / 7 | 两小时新增组件；实际正常支持与攻击保护仍待模型检验 |
| UNSW Netatmo | 7 / 10 | 7 / 10 | ≥50 / ≥16 | 两小时有更多候选；首小时换选没有组件集合变化 |

表中 CIC 数字来自稀疏端点清单，0 表示未在该清单证实，不能当作完整新前端清查的零计数。UNSW 首小时为已有旧合法口径完整统计；Switch、TP Link 的两小时旧口径可由未抽样正常记录复原，其余为下界。**所有这些数字都不是已经生成的新 RECENT 参考库。** 历史全捕获抽样端点可能依赖未来总量，不能直接拿来充当在线因果选库结果。

CIC 的 `active-00` 本地存在、总跨度约 8 小时；UNSW 的 2018-05-28 正常归档本地存在、跨度约 24 小时。原始文件只检查了路径和长度，没有重新读取全文件哈希，也没有把首尾跨度解释成无采集空缺。两边都缺可信的逐功能操作日志，所以 B1 实际是**时间分层**，不声称完整主动功能覆盖。

### 源侧定参材料已落实

- 原 104 条专用源参考与当前父 run 一致，原 FIT 617,908 / CAL 148,819 的角色与组件划分核对通过。
- 可以计算正常支持尺度的源 FIT 正常行：TCP 54,042、UDP 65,984。Amcrest 的 TCP、Atomi/Globe 两协议只有一个参考组件，对这些设备协议保留回退；不复制参考凑数。
- 115,672 条 CAL 攻击均有合法同协议源库；源库–攻击配对共 359,875，其中跨设备供体配对 252,538。完整库、UID、时序及供体名单已保存。
- 原专用参考是短捕获，实际合计约 40.8–81.1 秒/设备，不是连续一小时；Philips 三段跨度约 84 分钟。把时钟改为一小时可能反而截掉原参考。
- 原专用角色还存在 100 个额外候选，全部为 Amcrest UDP，不能解决上述缺协议问题。本版固定原 104 条，不把原 FIT/CAL 的正常查询按标签移进参考库。

上述是可用性与身份核查，没有计算半径、保护参数或模型效果。

## 2. 本次确定的可实现配置

正式配置见 [protocol.json](protocol.json)。其状态为 `DESIGN_FIXED_NOT_IMPLEMENTED_NOT_RUN`，固定方法及选择规则，数值有效性仍待实验；当前封存修复包和门槛没有改变。

| 项目 | 本版决定 |
|---|---|
| 首组组合 | 同一修复头 R3 单独，与 R3＋新版模块＋原库配对；R3 真实端点尚待运行 |
| 原库 | 固定源 104、CIC 75、UNSW 92 个原参考 UID 及原截止；使用同版本 RECENT 表示，不能换用旧 early-prefix 向量 |
| B0 | A/B 统一固定首小时，最多 64 个不同组件，固定 hash＋TCP/UDP 轮转 |
| B1 | 同 B0 的实际数量及协议名额，按 UNKNOWN 活动层内的四个固定时间段轮转选择；相同库直接复用，不把重复评分当独立增益 |
| B2 | 同一起点固定两小时，仍最多 64 组件，沿用 B1 选择算法；不自动延长，也不同时增加容量 |
| 查询级支持 | 同两条不同组件的参考同时支持近期 E3 与当前 q14；无支持时保持基础头 |
| 距离尺度 | 源 FIT 正常的协议级二近距离加权 90% 分位；源内一次确定，A/B 不重拟合 |
| 分数修正 | 原 logit 减去 `lambda × 源FIT分数尺度 × 支持度`，有固定上限；不是正常概率或无限制撤警 |
| 保护选择 | 固定 lambda 候选 0 / 0.05 / 0.10 / 0.25；源 CAL 攻击及已登记合法同协议源供体保护；每个头三 seed 和 ensemble 共同约束 |
| 完整评价 | 原完整查询集、原权重、同一头/阈值严格配对；绝对召回/FPR目标及零新增攻击漏检保持 |

固定公式仍是旧参考校验思路的改进，首轮不新增关系网络训练。修正幅度是有限分数带，不保证很小的概率变化；源 CAL 完全分离时也可能无法约束它。源侧保护通过不能代替新设备、新库上的逐条攻击验收。

**同预算换选在当前证据下主要对 Eufy、WEMO Motion 有选择空间。** 其他设备如果完整候选核对后仍全收录，B0/B1 的实际库就相同：报告无差异并复用，不另造效果。B2 保留为明确的观察时间对照；不把“缺 TCP”与“库容量不足”混为一谈。

### 两条头路线共用一个模块

先实现上述共用模块与 R3 接入，再让现代头对照中的保留候选使用同一公式、参考策略及源侧定参算法。不同头的分数单位不同，源 FIT 尺度和源保护选出的 lambda 可以不同；不针对 A/B 分别调参或开关。

原库锚点用于解释模块改进；B0/B1/B2用于 A/B 同采集规则的比较。历史不同采集政策的原库结果不能冒充统一新入网流程已经成功。完整三池系统结论还需要原三设备在新输入下的单独回放，当前两池组合不能代替；这些已消费设备也不能再包装成独立确认。

## 3. 下一步工程范围已缩小

后续实现包含两个必要入口：
